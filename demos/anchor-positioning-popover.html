CSS Anchor Positioning lets you tether any element to any other element with a single CSS rule. Combined with the HTML Popover API, you can build tooltips, dropdown menus, hover cards, action menus, and context popovers with zero floating-ui, popper.js, or Radix positioning logic. The browser handles scroll, clipping, viewport-edge flip, and stacking. Baseline 2026, ~91% global traffic.

The 4-line tooltip CSS

/* HTML — wrap trigger and tooltip in same parent */ .tip-wrap { position: relative; } .tip-wrap > .anchor-btn { anchor-name: --tip-anchor; } .tip-wrap > .hover-tip { position: absolute; position-anchor: --tip-anchor; top: calc(anchor(bottom) + 10px); left: anchor(center); translate: -50% 0; /* ...and then any visual styles */ } .tip-wrap:hover > .hover-tip { opacity: 1; /* show */ }

What just disappeared: the floating-ui computePosition call, the update() listener on scroll/resize, the autoUpdate middleware for iframe scroll, the z-index stacking logic. Browser owns it all.

3 The 4-Property Recipe

Every anchor-positioned element needs exactly four things:

  1. An anchor element with anchor-name: --my-anchor.
  2. A positioned element with position: absolute (or fixed) — its containing block is the nearest positioned ancestor or the initial containing block; anchor positioning works from either.
  3. The positioned element declares position-anchor: --my-anchor (for implicit binding) — or pass the anchor name as the first arg to anchor() for explicit binding.
  4. Place the positioned element using top/bottom/left/right + the anchor() function (or use position-area for grid-style placement).
/* Implicit binding (single anchor, simpler) */ .anchor-btn { anchor-name: --my-anchor; } .positioned-popup { position: absolute; position-anchor: --my-anchor; top: anchor(bottom); /* sit below the trigger */ left: anchor(left); /* align left edges */ margin-top: 8px; /* small gap */ } /* Explicit binding (one positioned element → many anchors) */ .positioned-popup { top: anchor(--my-anchor bottom); left: anchor(--my-anchor right); bottom: anchor(--other-anchor top); /* mixed anchors! */ right: anchor(--other-anchor left); }

Logical property mapping

For RTL / i18n-aware layouts, use the logical equivalents:

/* physical logical equivalent */ top → inset-block-start bottom → inset-block-end left → inset-inline-start right → inset-inline-end /* anchor() function uses physical sides — but the value side is keyed off logical block/inline */ calc(anchor(--tip inset-block-end) + 10px) /* under the trigger, RTL-aware */

4 Old Way vs New Way

Before anchor positioning, this required floating-ui, Popper.js, Radix Popper, Reach UI Popover, or hand-rolled getBoundingClientRect() math on every scroll event. The new way is one CSS block.

❌ The Floating-UI approach

// JS — every consumer pays this cost import { computePosition, autoUpdate, offset, flip, shift } from "@floating-ui/dom"; const trigger = document.querySelector('.anchor-btn'); const tip = document.querySelector('.hover-tip'); const cleanup = autoUpdate(trigger, tip, async () => { const { x, y } = await computePosition(trigger, tip, { middleware: [offset(8), flip(), shift()], strategy: 'absolute', }); Object.assign(tip.style, { left: `${x}px`, top: `${y}px`, }); }); // And you still need to escape overflow:hidden ancestor clipping // using FloatingPortal (portals to body), which itself requires React Portal.

~10 KB JS · re-runs on every scroll/resize · breaks in iframes · portal needed for overflow escape · add ~150 lines for accessibility (ARIA, focus management, keyboard return-focus)

✅ The Anchor Positioning approach

/* CSS only — no JS dependency */ .anchor-btn { anchor-name: --my-anchor; } .hover-tip { position: absolute; position-anchor: --my-anchor; top: calc(anchor(bottom) + 8px); left: anchor(left); /* position-try-fallbacks handles viewport flip */ position-try-fallbacks: --flip-top; } @position-try --flip-top { bottom: calc(anchor(top) + 8px); top: auto; }

0 bytes of JS · no scroll/resize listeners · works inside iframes · browser handles top-layer placement (no Portal escape needed) · viewport flip declarative

Six failure modes the floating-ui library had to handle — anchor positioning just works

  • Scroll: floating-ui re-runs computePosition on every scroll event from any ancestor (RBs-100 listeners for a deep tree). Anchor positioning auto-tracks scroll because the anchor ref invalidates on scroll.
  • Resize: autoUpdate listens for resize on the trigger. Anchors recompute automatically.
  • Iframe scroll: floating-ui needs ancestorScroll: true + cross-frame postMessage. Anchors work across frames natively.
  • Transform/Motion: floating-ui caches positions on transform; you need elementContext: 'transform'. Anchors re-invalidate on transform.
  • Overflow clipping: floating-ui needs FloatingPortal (React Portal escape). Anchors are placed in the browser's top-layer — no clipping by ancestor overflow.
  • RTL/i18n: floating-ui needs explicit RTL config. Anchors use logical inset properties that flip automatically.

The popover=manual escape-hatch (HTML popover attribute)

For menus that need to escape overflow: hidden ancestors (sliding panels, scrollable cards, transforms), use the HTML popover attribute. The popover renders in the browser's top layer — above all other content, escapes all clipping, gets focus management for free, and closes on outside click or Escape automatically.

<!-- Anchor is just a button — popovertarget toggles it --> <button id="menu-trigger" popovertarget="menu-pop">⋯</button> <!-- Popover is just a div with a popover attribute — anchor positioning done in CSS, JS only wires the trigger; nothing else --> <div id="menu-pop" popover="auto"> <button>Edit details</button> <button>Duplicate</button> <button class="danger">Cancel</button> </div>
#menu-trigger { anchor-name: --menu-anchor; }
#menu-pop:popover-open {
  position: absolute;
  position-anchor: --menu-anchor;
  top:  calc(anchor(bottom) + 8px);
  left: anchor(center);
  translate: -50% 0;
  /* Browser owns top-layer placement, escape, focus, and Esc-to-close */
}

Why popover=auto over popover=manual: auto gives you free outside-click-to-close and Esc-to-close (light-dismiss). manual requires you to wire that yourself.

7 Live Demo — Viewport-Edge Flip with @position-try

Here's the killer feature that floating-ui's flip middleware took 200 lines of JS to provide: the browser flips the popover to the opposite side automatically when it would overflow the viewport edge. And you can supply multiple fallback positions in priority order.

Open any popover near the edge of its row, then resize the window narrow — the popover follows the anchor and flips to keep itself visible. No JS, no scroll listeners, no IntersectionObserver.

Open popovers, scroll the window, resize — popovers flip automatically
Default — sits below-end of the trigger.

If clipped at the bottom of the row container, browser flips to above.

Multi-direction fallback.

Tries below-end first → above-end → below-start → above-start.

Horizontal flip too.

Right-edge triggers flip the popover to the left side of the anchor.

Notice: the popovers stay visible even when you'd expect them to clip the right edge — @position-try prefers the earliest non-clipped fallback.

The @position-try declaration block

/* Define a named fallback position */ @position-try --above-end { bottom: calc(anchor(top) + 8px); /* flip above the anchor */ top: auto; left: anchor(right); /* re-anchor left edge */ } /* Reference it as a fallback — browser tries declared first, then listed fallbacks */ .popover { position: absolute; position-anchor: --my-anchor; top: calc(anchor(bottom) + 8px); left: anchor(left); /* Fallback chain — browser tries these in order */ position-try-fallbacks: --above-end, --right-side, --top-spanning; }

Pair with @container queries: the spec defines anchor-positioned @container queries — so you can also conditionally style the popover based on which fallback position was selected. e.g., @container anchor(--flip-top) { … } rotates the tooltip arrow when the popover is flipped above.

The 1-line position-area pattern

/* Same effect as 4 anchor() calls, in one declaration */ .popover { position: absolute; position-anchor: --my-anchor; position-area: top span-all; /* spans the entire top row */ } /* Available area keywords: */ /* top-left top top-right */ /* left center right */ /* bottom-left bottom bottom-right */ /* Spanning variants: */ /* top span-all — entire top row */ /* left span-all — entire left column */ /* block-start span-all (logical) */ /* Or use logical equivalents: */ position-area: block-start span-all; position-area: inline-start;

anchor-size() — Resize the popover to the anchor

Popovers often need to match the width of their trigger (buttons of varying widths, full-bleed menu anchors). anchor-size() resolves to the anchor's measured width or height. Combine with calc() for ratios.

Decision matrix — when to use what

✅ Use CSS Anchor Positioning when:

  • You'd otherwise reach for floating-ui, Popper.js, or Radix Popper
  • You want zero JS for tooltips, menus, hover cards
  • The popover needs to escape overflow: hidden (use popover="auto")
  • The popover needs to flip at viewport edges (@position-try)
  • You'd otherwise wire scroll, resize, IntersectionObserver listeners
  • i18n / RTL matters (use logical inset-* properties)
  • The popover lives across iframe / popup window boundaries

⚠️ Keep the JS positioning library when:

  • You need pixel-perfect positioning in a non-Browser-supporting env (Playwright, Puppeteer before 2024)
  • The positioning target is itself animated with CSS transforms that change every frame (rare; usually targets the anchor directly, so this doesn't apply)
  • You're forced to support IE11, Safari < 17.4, or Chrome < 114 (vanishingly few users in 2026)
  • You have an existing toolchain (Radix Popper, Headless UI) and migration isn't worth it

Modern CSS popover ecosystem — how it composes with everything else

  • CSS Custom Highlight API (P1, 2026-07-02) — anchor positioning + Highlight API = search-highlight popovers, inline tooltips on glossary terms.
  • :state() (P4, 2026-07-07 morning) — drive :state(open) on the trigger so the popover can show/hide without any JS toggling at all (menu-trigger:state(open) .menu { opacity: 1; }).
  • View Transitions (P2) — anchor-positioned popovers that persist across navigations (the "sticky cart button" pattern across the entire checkout flow).
  • WebGPU (P2) — markers as WebGPU instanced meshes on the airspace canvas. Anchor positioning handles the 2D overlay popover above the canvas; the canvas handles the 3D scene.
  • Container Queries (P2, layout trilogy) — anchor-positioned @container queries let you style the popover conditionally based on which fallback position it landed in.
  • Field-sizing (P2, 2026-07-01) — input fields that grow with content. Combined with anchor positioning: an auto-growing search-input with an anchored suggestions popover.
  • @scope (P2) — scope the popover's CSS rules to the component tree; escapes become perfect with no global pollution.
  • color-mix() (P3, 2026-07-04) — derive hover/focus variants for popover surfaces without needing paired color tokens.

Why P4 (not P1/P2)

Most anchor-positioning wins are incremental — replacing ~5–10KB of floating-ui with one CSS rule. That's a big perf win but doesn't unblock ship-today client deliverables. The real production wins come when you compose it with:

  • OpenDrones Mission Control map popovers (section 8) — production use, ship now
  • Sellable Molt Studios "anchored component library" deliverable — recurring revenue line
  • Combined with :state() (P4 same morning) + Popover API for zero-JS popovers — composable with all P1/P2 entries

P4 is correct: foundational, broadly useful, pairs with everything. The Interop 2026 commit (Apple, Google, Microsoft, Mozilla, Igalia all converged in March 2026) means this is here to stay. Adoption curve is the gating factor, not the spec.

Recap

Anchor Positioning is the third pillar of the modern CSS UI ecosystem:

  1. Anchor Positioning — places element B relative to element A (this research).
  2. Container Queries + Subgrid — sizes and aligns element B based on container A.
  3. View Transitions + :state() — animates element A↔B state changes.

Combined with HTML Popover API (light-dismiss, top-layer, focus management for free), you can ship every tooltip/menu/popover pattern with zero positioning JS. Interop 2026 — Baseline 2026 — ~91% traffic. Ship today.
