Fullscreen API + Screen Orientation — The Kiosk Tier

The only API that removes the browser chrome entirely: requestFullscreen() promotes an element to the top layer, sizes it to the viewport, and unlocks kiosk/wall-display UX — while screen.orientation is the rotation contract next to it. Zero prior catalog coverage (Wake Lock keeps the screen on; this makes it fill the screen). Every claim is an executable chip, live-probed on this engine.

§01 · Anatomy & the activation wall

Four members: Element.requestFullscreen() (enter), Document.exitFullscreen() (leave), Document.fullscreenElement (who is fullscreen), Document.fullscreenEnabled (is it allowed here). The wall: entering requires transient user activation — a real gesture. Nothing programmatic passes.

The contract

el.requestFullscreen()        // → Promise<undefined>
  .then(() => document.fullscreenElement === el)
document.exitFullscreen()     // → Promise<undefined>
document.fullscreenEnabled    // policy gate (iframe!)

Both promises resolve with undefined — the events are the real signal.

§06 · iframe policy — the default-allowlist wall

fullscreen is a Permissions-Policy feature with default allowlist 'self': same-origin nested documents inherit it; cross-origin iframes need allow="fullscreen" or they are locked out — document.fullscreenEnabled reads false inside the child. §08 · Screen Orientation — type, angle & the lock that isn't

screen.orientation exposes type (landscape-primary …) and angle (degrees, clockwise). lock() is the kiosk dream and the honest disappointment: on most desktops it simply does not exist.

The read side

screen.orientation.type   // 'landscape-primary'
screen.orientation.angle  // 0
matchMedia('(orientation: landscape)')
window.orientation        // legacy — removed?

§09 · Legacy surface & the iPhone caveat

A decade of prefixed APIs left sediment. Probes for what still exists on this engine, plus the one platform divergence that still ships: iPhone Safari historically allows fullscreen only on <video> (via the old webkitEnterFullscreen), not arbitrary elements — iPad and every other platform accept any element.

BCD (Sept 2026): unprefixed Fullscreen API — Ch 71+ / FF 64+ / Safari 16.4+ = Baseline ≈ 96%. screen.orientation.lock: Chromium only, lockable-form-factor devices only. Detect with 'lock' in screen.orientation and always catch.
