§1 · The overflow trap the #1 silent killer

A sticky element tracks its nearest ancestor scrollport. Any ancestor with overflow: hidden | auto | scroll becomes that scrollport — and if the ancestor has auto height (content fits, it never scrolls), the constraint rectangle never moves and the sticky is silently dead. No error, no warning, in any engine.

THE OVERFLOW TRAP. overflow: hidden / auto / scroll on ANY ancestor — parent or grandparent, any distance up the tree — retargets the sticky to that ancestor’s scrollport. An auto-height ancestor never scrolls ⇒ the sticky never pins. Measured 4/4 engines, pinned=false in every one.

Live matrix — every card is an independent 170px “viewport” you can scroll. The dashed box is the ancestor with the labeled overflow value. Scroll each one and watch the bar:

THE ONLY REAL FIXES. (a) remove the overflow from the ancestor, (b) switch it to overflow: clip (§2 — same clipping, no scroll container), or (c) make that ancestor the actual scrolling surface (give it a height and let IT scroll). A wrapper div does NOT fix it — measured: a wrapper under an overflow-x: hidden ancestor stays dead (−300px at scrollY 400). Wrappers extend the range (§4), never the scrollport.

§2 · The clip exception & the one-axis propagation

overflow: clip clips paint exactly like hidden — but it does not create a scroll container. The sticky keeps tracking the real scroller. And the single-axis trap: writing one axis as hidden forces the other axis’s computed value to auto.

THE CLIP EXCEPTION. Ancestor with overflow: clip (either axis, or both): sticky ALIVE, 4/4. overflow-x: clip leaves overflow-y computed visible — no propagation.
THE ONE-AXIS PROPAGATION. overflow-x: hidden ⇒ computed [hidden, auto] — even when you explicitly write overflow-y: visible, it is overridden to auto ⇒ scroll container ⇒ dead. Measured 4/4. The fix that keeps the clip: overflow-x: clip.

§3 · The root combo: html, body { overflow-x: hidden }

The most-shipped global CSS rule on the web, pasted into a million resets to kill horizontal jank. What it does to a sticky header depends on which selectors carry it — via the one-shot root propagation rule.

THE ROOT PROPAGATION LAW. html { overflow-x: hidden } alone: html’s overflow propagates to the viewport — the viewport is still the scroller, page scrolls, sticky ALIVE. body { overflow-x: hidden } alone: body’s overflow propagates up to the viewport too (body is not a scroll container while html is visible) — sticky ALIVE. 4/4.
THE COMBO KILL. html, body { overflow-x: hidden }: html takes the propagation, so body keeps its own overflow and becomes a REAL scroll container. Auto-height body never scrolls ⇒ every window-tracked sticky on the page is DEAD — while the page itself still scrolls normally. Nothing looks broken; the header just doesn’t stick. Measured 4/4: elTop −480px at scrollY 600.

§4 · The pin-range formula when does it stick, exactly

A window-tracked sticky with a top inset is pinned for scroll positions in a closed interval you can compute from three numbers: the element’s natural top, its parent’s bottom, and its own height.

THE RANGE FORMULA. pinned ⇔ scrollY ∈ [elNaturalTop − inset, parentBottom − elH − inset]. Below the first bound it hasn’t reached the edge yet; above the second the parent’s end has caught up and the element releases and rides away with the parent. Measured: release lane pinned through y=1300 and gone by the parent’s end (1400 − 50 = 1350), 4/4.
THE SHORT-PARENT FALSIFICATION. “The parent must be taller than the viewport” is false. A 300px-tall parent in a 900px viewport pinned across y ∈ [100, 360] — a 260px stick range. The only failure is an empty range (parentBottom − elH − inset < elNaturalTop − inset). What matters is range > 0, not viewport comparison. 4/4.

§5 · The inset grammar — horizontal edition

Scroll this lane horizontally (the box is 500px of viewport over a 1600px rail). One sticky element per card, each with a different inset — the bar shows where it binds.

THE OWN-EDGE LAW. An inset binds only at its own edge: left holds the element when it would exit the left edge as you scroll forward; right-only is inert forward (the element exits the left edge first, which has no inset) — measured: it tracks static exactly. 4/4.
THE OVER-CONSTRAINT LAW. Both left: 0; right: 0 on a fixed-width element: the start inset wins in LTR (left), the other is ignored — measured elLeft 0 the whole sweep. Same for top+bottom vertically (top wins). 4/4.
PERCENT + NEGATIVE. left: 10% resolves against the scrollport width (measured 128 = 10% of a 1280 viewport — not the parent). Negative insets pin outside the edge: left: -40px ⇒ elLeft −40. 4/4.
← scroll horizontally → left:0 right:0 left+right no inset left:10% left:-40

§6 · Bottom insets, the over-tall trap & the reveal recipe

A bottom inset works in the mirror direction: it binds while the element would exit the bottom edge — i.e. while scrolling into content that hasn’t reached it yet. The “sticky section footer” rides the viewport bottom until the parent’s end arrives.

THE FOOTER LAW. bottom: 0 on an element at the parent’s end: pinned at the viewport bottom (top 840 / bottom 900 in a 900px viewport) while the parent’s body scrolls under it; releases when the parent’s tail catches up (measured: release at y≈1400), then settles into its natural slot. 4/4.
THE OVER-TALL TRAP. top: 0; bottom: 0 on an element taller than the viewport (1100px in 900): the start inset wins and the element’s tail hangs below the fold the entire stick range — bottom 1100 > vh 900 — the last 200px are unreachable until release. 4/4.
THE REVEAL RECIPE. For a tall sticky sidebar: top: −(elH − vh). Measured with elH 1200, vh 900: top: -300px holds the box at [−300, 900] through the whole range — the bottom edge glued to the viewport bottom, no dead zone. 4/4.

§7 · Tables — the falsified folklore 3 falsifications

The decade-old guidance: “sticky doesn’t work on thead / tr; put it on the th instead.” Measured in 2026 on four engines with border-collapse: collapse: all three stick.

THE TABLE FALSIFICATION. Sticky on <th>, on <thead>, and on <tr> — pinned in CfT 149, CfT 148, Brave 156 and WebKit 26.5 (12/12 lanes). The th-only workaround is dead weight; style the row you actually mean.

§8 · The flex-stretch trap & the grid-area law

Two container families, two different surprises — both invisible in review, both instantly visible in production.

THE FLEX-STRETCH TRAP. A sticky item in a flex row with the default align-items: stretch is stretched to the flex line’s full height (measured: 1800px) — it fills its whole constraint range, so there is nothing to stick: it scrolls like static. One line fixes it: align-self: flex-start (measured: 19.6px item, pins normally). 4/4.
THE GRID-AREA LAW. A sticky grid item’s containing block is its grid area, not the grid container. Measured with an auto-row grid whose spanning column distributed 780px into each auto row: the item’s pin range is bounded by its row track. A tall sibling in the same column can’t save it; a short track = short range. 4/4.

§9 · The flow law & the two-coordinate split

Sticky never leaves the flow — and both geometry APIs report the stuck position, which quietly falsifies the “offsetTop is layout-only” assumption.

THE FLOW LAW. Flipping the sticky to position: static leaves every sibling’s position byte-identical (measured: sibling top 160.0 in both states) — sticky occupies its layout slot the whole time; the shift is paint-time only. 4/4.
THE TWO-COORDINATE SURPRISE. While stuck at top:0 with scrollY 600: getBoundingClientRect().top = 0 and offsetTop = 600 (the stuck document position) — while as static, offsetTop = 200 (the flow slot). offsetTop carries the sticky shift — there is no API that reports the flow slot of a stuck element; flip to static to read it. 4/4 engines, identical numbers.

§10 · The interaction census — what does not break sticky

For position: fixed, a transformed ancestor captures the containing block and wrecks it. Sticky is immune to the whole family — plus two grammar notes.

THE IMMUNITY LAW. Ancestors with transform: translateZ(0), filter: blur(0), will-change: transform, and contain: paint: sticky pins normally in every lane, 4/4. The fixed-position capture rules do not apply — no containing-block capture for sticky.
THE INLINE LAW. position: sticky on a display: inline element (a span mid-paragraph) is inert — it scrolls away exactly like static text. 4/4. Sticky needs a block-ish box; check for an accidental display: inline from a reset.
—
MINOR GRAMMAR. In a scroll-snap-type: y proximity scroller, sticky pins normally (measured 0, 300, 700 — no snap interference on programmatic scroll). In RTL, left stays the physical left edge — insets never transpose with direction.
