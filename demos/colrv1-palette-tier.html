COLRv1 color fonts — the palette tier

OpenType COLRv1 + CPAL + font-palette / @font-palette-values / palette-mix() — 18 measured engine truths, live-probed on Chromium 148 (CfT) & Brave 154, pixel-verified via CDP screenshots. This page re-probes every claim in your browser.

§1 — What COLRv1 is (and why it matters here)

COLRv1 is the modern OpenType color-glyph format: vector layers, gradients, clips and effects painted per glyph, plus a CPAL palette table that themes every color in the font. One .woff2 ships an entire color typography system — no images, no per-letter spans, no canvas.

  • Molt: one file = a whole campaign's colored headline system; re-theme per client via palettes (this page's hero buttons).
  • OpenDrones: HUD/alert numerals in brand colors with zero image assets; palette-swap for day/night cockpits via a dark-flagged palette.
The fixture law — Google Fonts serves css2 files split by unicode-range subsets. A subset that lacks your glyphs renders silent fallback (black system text), not an error: we measured a 'latin-ext' file with 154 glyphs and no M. Inspect cmap coverage before shipping any subset.

§2 — The support census (live)

The grammar: font-palette takes normal | light | dark | <dashed-ident> — integers and undashed idents are rejected at parse in Chromium. Safari 16.4+ / Firefox 128+ ship the same core (palette-mix is Chromium-first).

§3 — @font-palette-values: the rule surface

@font-palette-values --brand {
  font-family: 'Bungee Spice';
  base-palette: 1;              /* or light | dark */
  override-colors: 0 #ff2d78;   /* per-entry recolor */
}
h1 { font-palette: --brand; }
The dashed-ident law — the rule name and the font-palette value must be dashed (--x). An undashed name kills the whole rule at parse (0 rules); a bad descriptor only drops that descriptor silently.
The silent descriptor-drop law — base-palette: banana or : -1 → the rule survives, descriptor stripped from cssText. Unknown descriptors (color: red) are stripped the same way. Only the name is fatal.

§5 — override-colors: recolor without touching the font

BRAND SWAP
The override laws — partial overrides compose over the base palette (unspecified entries keep their colors); an out-of-range index (99 #f0f) is silently ignored; transparent punches real holes (we measured coverage drop 1866→986 colored pixels); and file-side CPAL alpha is honored — we crafted a font with entry α=100/255 and measured the translucent gold live.

§6 — light / dark keywords: the CPAL-flag law

This Bungee copy was re-compiled with CPAL paletteTypes flag 0x2 (dark-background) on palette 2 (Lagoon). The engine resolves the keywords through those flags — not through prefers-color-scheme.

DAY / NIGHT
The keyword law — dark picks the palette flagged dark in the font file (green here); light finds no light flag → silent fallback to default, pixel-identical to normal. And under an emulated prefers-color-scheme: dark page, normal never auto-switches — the keywords are the only auto-respecting path, and they only see file flags. Most fonts ship zero flags: for them light/dark are both no-ops.

The mix law — Chromium accepts font-palette: palette-mix(in oklab, --p1, --p2) as a first-class settable value and renders a true per-entry interpolated palette. One font + two palettes = every intermediate brand color, computed in OKLab.

§8 — Transitions: it interpolates, it doesn't flip

The transition law — transition: font-palette animates by interpolation, not discrete flip: mid-flight computed style reads palette-mix(in oklab, --p1 50.0023%, --p2) — the engine serializes the running blend, percentage included. Same via WAAPI (element.animate([{fontPalette:'--p1'},{fontPalette:'--p2'}]) — accepted, kept in getKeyframes()).

§9 — Canvas: color glyphs, palette steering & the fillStyle wall

—
The canvas laws — fillText rasterizes COLRv1 in full color, pixel-identical to DOM rendering (measured: 1866 matching pixels, both lanes); the canvas element's own font-palette steers the rasterized colors (green when set to --p2); override-colors reaches canvas text too; and fillStyle is ignored by color glyphs — the palette always wins. Metrics match DOM (measureText ≡ element width).

§10 — The family-mismatch law

NABLA + BUNGEE RULE
The mismatch law — that element asks for --mismatch, a rule scoped to Bungee Spice, while rendering Nabla. Result: pixel-identical to Nabla's default (2648 matching pixels in the lab) — a family-gated rule silently no-ops. The font-family descriptor inside the rule is the match key, and a rule with no font-family never matches anything (inert, parses fine). Bonus: same name, two families resolves per-font — one name can carry different palettes for different fonts.

§11 — The shadow-DOM wall

HOST (light DOM)
—
The shadow wall — inside a shadow root, @font-palette-values fails in both directions on Chromium 148: document rules can't resolve by name inside the shadow, and the shadow's own rules fail to affect rendering (computed carries the name; pixels stay default — verified three ways, including rules present from t=0). Web components that need palettes must inject their rules into the document stylesheet. (The wall stands in Brave 154 too — re-probed live below.)

§13 — Capstones

  • OpenDrones HUD kit — one COLRv1 numeral font; base-palette per flight mode, override-colors for critical alerts, dark-flagged palette for night ops, canvas telemetry digits steered by the canvas element's palette (§9), zero image assets.
  • Molt brand-in-a-file — client-colored headline systems: ship one font + a 3-line @font-palette-values block per client; palette-mix for campaign gradients. Sellable as a "color-type brand system" line item.
  • Pre-flight checklist — verify cmap coverage on any subset; declare entry indices against the real CPAL; test dark mode with a flagged palette (keywords no-op otherwise); keep palette rules in the document sheet if components are involved.
