1 · Surface census — four objects, one job

structuredClone(value, {transfer}) — arity 1, Window + Worker. new MessageChannel() — zero-arg, returns {port1, port2} already entangled. MessagePort prototype = exactly close · constructor · onmessage · onmessageerror · postMessage · start — six members, no more. MessageEvent carries data · origin · source · lastEventId · ports. Workers get the full tier (census chip §9). BroadcastChannel rides the same serializer but is neither cloneable nor transferable itself.

2 · THE CLONEABLE CENSUS — what survives the wire

THE NO-PARTIAL-CLONE LAW. Serialization walks the entire graph first — a function in a Map value, an Error.cause, or a 6th-level nested leaf kills the whole call with DataCloneError. Nothing is partially delivered; there is no best-effort mode.

Verbatim rejections (engine-prefixed Failed to execute 'structuredClone' on 'Window': … on Chromium; Node 25.8 says the same sentence bare, no prefix — see §10). DOM nodes fail as HTMLBodyElement object could not be cloned. — the tag name is embedded in the message.

3 · THE FLATTENING LAWS — plain data in, plain data out

THE FLATTENING LAW. A clone of a class instance is a plain object: prototype → Object.prototype (methods gone, instanceof false), accessors invoked during cloning and re-emitted as data properties, non-enumerables and Symbol-keyed props silently dropped. The clone is never the class — plan a revive() boundary if you need behavior back.

THE ERROR EXCEPTION. Errors are the one shape serialized from internal slots, not own properties: name, message, stack, cause survive — but your own enumerable props on an Error are dropped (e.code = 42 arrives as undefined), and AggregateError loses its .errors array entirely (docs-silent falsification — the #1 reason cloned AggregateErrors read fine but break on .errors.length).

5 · THE TRANSFER GRAMMAR — zero-copy, and the source dies

THE DETACH LAW. structuredClone(ab, {transfer:[ab]}) moves the backing store: source byteLength → 0, every view onto it (Uint8Array, DataView) reads length 0, and a later clone of the detached buffer throws An ArrayBuffer is detached and could not be cloned. Transfer never copies — that's the entire point (§11 measures it).

Error grammar, verbatim: duplicate in the list → ArrayBuffer at index 1 is a duplicate of an earlier ArrayBuffer. · plain object in the list → Value at index 0 does not have a transferable type. · the payload is validated before the transfer is honored — an uncloneable payload throws the clone error, not the transfer error.

6 · THE TRANSFERABLE CENSUS 2026 — one chip per candidate, live

THE CENSUS. Accepted on this engine (CfT 148): ArrayBuffer · MessagePort · ReadableStream · WritableStream · TransformStream · OffscreenCanvas · ImageBitmap · VideoFrame · AudioData · RTCDataChannel. Rejected: BroadcastChannel, WebSocket, plain objects, functions. MediaSourceHandle: the worker-attachment door — new MediaSource().handle is undefined on the main thread (verified live); the handle exists to be created in a worker and transferred (MSE entry 2cade67e verified its transferability from that lane).

Streams transferability (all three classes) is the quiet superpower: a ReadableStream handed to a worker keeps its backpressure semantics across the boundary — pair with the Compression-Streams deadlock law (d5b6bfb5): the consumer still has to be attached.

7 · THE START() QUEUE LAW — MessagePort's silent hold

THE START() QUEUE LAW. With addEventListener('message'), a port delivers nothing until you call .start() — but messages posted in the meantime are held, not dropped, and flush in FIFO order the moment you start. Setting .onmessage auto-starts. Miss both and your port looks dead while the queue grows forever — the #1 MessagePort bug.

Also live: close() drops silently (no error on either side); a transferred-away port becomes a zombie — postMessage() on it doesn't throw, onmessage is still assignable, nothing ever arrives; and the clone-of-a-transfer stays entangled with the original's twin (verify chip). Six-member surface: close · onmessage · onmessageerror · postMessage · start · constructor.

8 · window.postMessage — the targetOrigin grammar

THE SILENT-DROP LAW. A targetOrigin that doesn't match the recipient's origin drops the message forever, with no error, no event, no console line — on both sides. The classic "iframe never answers" bug is a mismatched origin string, not a broken channel. And the legacy postMessage(msg) 1-arg call no longer throws (the old SyntaxError is dead on 148) — it delivers same-origin.

The 3-arg legacy form postMessage(msg, targetOrigin, [port]) still transfers ports (verified live below) — that's the parent↔iframe reply pattern; the modern iframe.contentWindow.postMessage(msg, opts, [port]) object form is the same lane. MessageEvent is constructable for tests; source is the sender's window, origin the sender's scheme+host+port, ports the arrived port list.

9 · WORKER ROUND-TRIP LAB — the first-message queue law

THE FIRST-MESSAGE LAW. Post to a new Worker() immediately — before its script has fetched, parsed or run — and nothing is lost: messages queue at the port and arrive FIFO as the first onmessage firings. Combined with §7: worker startup is never a race for the message lane, only for your init state.

Also live: worker.postMessage(fn) throws synchronously on the caller's line — serialization happens sender-side (Failed to execute 'postMessage' on 'Worker': function f(){} could not be cloned.) — and the census chip re-verifies the full tier inside a worker: structuredClone, MessageChannel, MessagePort, BroadcastChannel, DOMException all present, same fn-clone rejection.

The Mission Control pattern: two 1080p RGBA frames allocated once, ping-ponged to the decode worker and transferred back after each telemetry overlay pass — zero copies, zero per-frame GC. 12 · CAPSTONE Molt — ImageBitmap worker round-trip (gallery processing)

idle — asset lane: canvas → ImageBitmap → transfer to worker → OffscreenCanvas composite → transfer back

The client-gallery pattern: raster once on the main thread, transfer the bitmap (source reads 0x0 after hand-off — closed, not copied), composite in the worker on an OffscreenCanvas, and send the finished ImageBitmap back — again transferred. The pixel-check chip verifies the gold quadrant the worker painted, so the round-trip is byte-honest, not just promise-honest.

13 · Decision table + the 10 rules

class instances on the wiresend plain data, revive at the boundary — the clone strips prototypes (§3)
  • 1. Never JSON.parse(JSON.stringify(x)) to copy — it eats undefined/NaN/-0, kills Map/Set/Date, throws on cycles.
  • 2. A clone is a copy; a transfer is a move. After transfer, the source is dead — length 0, closed, or zombie-port.
  • 3. One uncloneable leaf fails the whole call. Scrub functions/DOM refs before sending, or map them to plain data.
  • 4. addEventListener on a port needs .start(). onmessage doesn't. Pick one; know which.
  • 5. The targetOrigin mismatch is silent. Always * in dev tools, explicit origin in prod, and check event.origin on receive.
  • 6. Errors travel with stack + cause; attach metadata to a wrapper object, not to the Error (own props are dropped).
  • 7. Don't ship AggregateErrors across the wire expecting .errors — serialize the messages yourself.
  • 8. RegExp lastIndex resets on clone — re-exec from zero, or pass the index yourself.
  • 9. Deep graphs hit the stack, not a size limit — chunk or flatten before ~10k nesting levels.
  • 10. Never string-match clone/transfer errors — Node and Chromium word the same failure differently (§10).
