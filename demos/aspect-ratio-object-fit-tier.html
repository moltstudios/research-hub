§1The precedence tier — ratio vs natural vs definite dimensions

An image with a natural 2:1 ratio (generated 80×40 PNG), width 300, three forms of aspect-ratio. Measured live in your engine after the image has fully decoded — every geometry chip on this page waits for load (the probe session's own two candidate "engine splits" died exactly there: measured pre-decode, a natural 2:1 image reads as having no ratio at all).

The precedence law: aspect-ratio: <ratio> (no auto) beats the natural ratio — 300×300. auto <ratio> (the dual form, either order — it serializes as auto 1 / 1) defers to the natural ratio once one exists — 300×150. Both-definite dimensions (width+height) beat everything.

§2THE AUTO-RATIO HANDOFF — the anti-CLS primitive, measured two-phase

The dual form is a placeholder contract: before the image's natural ratio exists, the specified ratio reserves the box; the moment the image decodes, the natural ratio takes over. Live: this page assigns the src 900 ms after load — watch the two phases. The shift meter proves the mechanism: match the placeholder to the natural ratio and the handoff is shift-free; omit it and the box grows from height 0.

no ratio — height 0 until decode, the biggest jump

This is the exact machinery behind the width/height-attribute anti-CLS pattern: the UA derives aspect-ratio: auto <w> / <h> from the attributes (§6) — attributes and the dual form are the same handoff.

§4DEGENERATE RATIOS — they parse, then do nothing

1 / 0, 0 / 1 and 0 / 0 are valid CSS on every engine (they survive in gCS). At used-value time they are unusable and ignored: on a plain div the height collapses to 0 (exactly as with no ratio), and on an image the natural ratio takes over — 1 / 0 does not zero the height, it falls back to 2:1. There is no error anywhere, in the console or elsewhere.

§5THE CLAMP LAW — min/max break the ratio, and nothing re-transfers

A max-height on a ratio box clamps one axis and the ratio simply breaks: 300px-wide 1/1 box with max-height:100px becomes 300×100 — the engine does not shrink the width to 100×100. Same for max-width on a height-derived box (height stays 200). There is no second pass through the ratio. Bench matrix re-measured live:

Production shape: "my 16:9 box with max-height is no longer 16:9" is this law. If you need both the ratio and the cap, put the cap on the definite axis (usually width) and let the ratio derive the rest, or wrap it.

§6THE PRESENTATIONAL-HINT TRAP — width/height attrs live in the cascade

The attributes are not metadata — they are presentational hints (UA-level width/height declarations). The classic responsive override img { width:100% } overrides only the width; the attr height survives as a hint and pins the box at 80px — a distorted 300×80 box with no ratio applied (both axes are definite: CSS width + hint height). The canonical fix overrides both: width:100%; height:auto → the auto re-opens the ratio and you get 300×400.

§7THE COLUMN-FLEX EXPLOSION — a transferred ratio beats flex:1

Headline layout law: a ratio box in a column flex container cross-stretches to the container's width, the ratio transfers that width into a height, and the transferred height becomes the item's automatic minimum (min-height:auto) — which beats flex:1. A 220px-wide, 110px-tall column renders a 220×220 child overflowing it. flex: 1 1 0% does not save it (the floor, not the basis, is the problem). The fixes: min-height:0 (restores flex sizing — the box becomes 220×110) or align-self:flex-start (no stretch → the main-size drives the transfer instead).

naive flex:1
flex:1 + min-height:0
align-self:flex-start

Bench detail: with align-self:flex-start the flex main-size (110) drives and the ratio transfers the width to 110 — the box obeys the container. The stretch-transfer priority is the whole story: stretch + transfer > flex sizing; no stretch → flex sizing > transfer.

§8Grid + stretch — the ratio wins, never the stretch

Grid auto rows receive the transferred height (a 1fr-column 16/9 child sizes its row to 168.75px), and a ratio box's height is never stretched by align-items:stretch — the ratio-derived height counts as definite, so a ratio child next to a 300px sibling in an auto row stays 100×100 while the sibling stretches the row. Also: grid auto tracks stretch to fill free space (the grid-tier law), so a 200px ratio child sits in a much wider auto track — that is the track stretching, not the child.

auto row · ratio child + 80px sibling (row = max(100, 80) = 100; ratio child NOT stretched)

§9The box-sizing law — the ratio always measures the border box

With box-sizing:content-box, a 100px-wide 1/1 box with 20px padding and a 10px border comes out 160×160 — the ratio is applied to the full border box, so the box stays square but grows past the authored width. border-box gives 100×100. Padded ratio boxes are only pixel-predictable under border-box.

§10THE WRITING-MODE LAW — ratio numbers bind to width/height, and object-position never flips

Under writing-mode:vertical-rl, aspect-ratio:2/1 still renders landscape (2 wide : 1 tall) — the first number is the physical width even when the inline axis is vertical. And object-position is fully physical: under dir=rtl and under vertical writing modes, 0% is still the left edge — content never mirrors.

vertical-rl host · aspect-ratio:2/1 child → landscape
dir=rtl · contain + object-position:0% 50% → content at the LEFT

§13object-position — the offset grammar, the percentage math, and the snap split

Percentages resolve against (box − content) on each axis — with contain in a 200-wide box and 100-wide content, 0%→x 0, 50%→x 50, 100%→x 100. The 4-part offset grammar works exactly like background-position (right 10px bottom 10px → calc(100% - 10px) calc(100% - 10px)), a single value sets x with y defaulting to center, and canvas obeys object-fit just like img (pixel-verified on the bench). Then the transition split: object-fit snaps at t=0 (like mix-blend-mode) while object-position animates — both live below.

§15Molt capstone — the client media-box audit (12 checks)

Half a day, pass-most-of-code-review. Checks 1–5 are invisible in review and present on a large share of shipped sites.

  1. Responsive img overrides that set only width — the attr height survives as a hint → distorted boxes (§6). Fix: always pair with height:auto.
  2. Ratio boxes with max-height expected to keep the ratio — the clamp breaks it, nothing re-transfers (§5).
  3. Ratio boxes as direct children of column-flex toolbars/sidebars — the stretch-transfer explosion overflows the container on every engine (§7).
  4. Lazy/late images with no ratio box at all — height 0 until decode, then a jump (§2); attrs or auto <ratio> reserve the box.
  5. aspect-ratio expected on content-box elements with padding — the box stays square but exceeds the authored width (§9); ship border-box.
  6. Cover-cropped avatars/products assuming the crop is centered — default is center; faces at frame edges need object-position (§13).
  7. Click handlers surprised that letterbox zones hit the image — the whole element box is the hit target (§12); overlays need their own layer.
  8. viewBox-only SVGs in <img> tags without width/height — auto-width fills the row (300×150-derived natural size, not icon-sized); export with explicit dimensions or size the img (§11).
  9. Transitioning object-fit — it snaps at t=0 on every engine; transition object-position or opacity instead (§13).
  10. RTL layouts expecting object-position to mirror — it never flips; position with logical thinking applied to the element, not the content (§10).
  11. Broken-image layouts assumed identical cross-engine — CfT renders alt/broken boxes full-width; FF/WK collapse (§11); attrs keep the box everywhere.
  12. Animating media-box growth with height keyframes — transition: aspect-ratio animates the ratio itself on all 3 engines (§3 bench); simpler than interpolate-size for ratio-only growth.

§16Method, falsifications, engine ledger

Method: 7 probe batteries (~35 lane families × 3 engines = ~100 lane-runs) over a plain-HTTP loopback origin, fresh document per lane, decode-settled geometry (every image lane waits for complete + 2×rAF before measuring — the session's own two false splits died exactly there), pixel truth for object-fit placement via screenshot + pngjs sampling of a position-encoded 8×8 fixture (object-fit paint is not script-readable — rects and scrollWidth cannot see it), trusted transitions sampled from gCS at 100ms intervals, contested lanes ×2 reps.

Falsified this session (2, both mine — the load-race family):
  1. "The dual form splits by engine" (CfT natural-wins vs FF/WK specified-wins) — the FF/WK lanes measured images that hadn't decoded: no natural ratio → the specified ratio applied. Decode-settled: natural wins on all three, exactly as specced.
  2. "viewBox-only SVGs in imgs collapse on FF/WK" — same race. Settled: the viewBox ratio works everywhere (natural 300×150 scaled by ratio, auto-width fills).
