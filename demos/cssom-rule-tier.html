The CSSOM Rule Tier

CSSStyleSheet · cssRules · insertRule · constructable & adopted sheets — what parses, what mutates, what lies. Every verdict below re-measures in your engine on load.

§1 The parse census — stylesheets recover, insertRule throws

21 edge-case rules live in this page's <style>. A real stylesheet drops only the bad rules and keeps going; insertRule() with the same text throws on your caller. Three engines, three different drop sets.

THE FF DROP SET: Firefox silently drops input::checkmark and select::picker-icon rules from real stylesheets (parse-refused), while keeping input::-webkit-inner-spin-button (it parses the legacy names, refuses the new ones). CfT+WK keep all three. Unknown pseudo-classes/elements (:bogusnever, ::BOGUS-NEVER) and unknown at-rules are dropped by everyone. A sheet that "lost its styles" on one engine may be 100% intact on another.
ERROR RECOVERY IS PER-RULE: a malformed selector (.. {}) or a bad declaration (bogus-property: 1) never kills the sheet — the bad rule dies, the neighbors survive. An @supports (bogus-prop: 1) block still parses into a CSSSupportsRule everywhere (parse ≠ match).

§2 insertRule acceptance — and the honest feature-detect

The same rule text, two doors: stylesheet error recovery vs a throwing API. Modern at-rules (@container @scope @property @position-try @starting-style @layer) insert on all three engines.

ONE RULE PER CALL: two rules in one insertRule() string → SyntaxError everywhere. A bare declaration, or a selector without a block → SyntaxError. An unterminated '.x { color: red' parses fine on all three — the parser auto-closes.
THE PARSE-vs-SUPPORTS GRAMMAR: CSS.supports('selector(...)') denies the -webkit- pseudo family on Firefox while insertRule parses those same selectors there — when you need parse-truth, try/catch an insertRule into a scratch sheet; supports() measures a different thing.

§3 The index grammar — the default-index trap

insertRule(rule, index) — the omitted index is 0, not the end. Out-of-range → IndexSizeError; -1 wraps to 4294967295 (the message leaks the unsigned coercion). Float indexes floor.

—
THE INVERSION TRAP: a CSS-in-JS loop calling insertRule(text) without an index stacks every rule at the top — the first-inserted rule lands last in cascade order, so at equal specificity the earliest insert wins. Universal 3/3. Always pass sheet.cssRules.length to append.

§4 The @import tier — silent strip vs loud throw

Constructed sheets refuse @import — but the two APIs refuse differently, and the rule-CSSOM surface (href/media/layer/supports) is fully live.

THE SILENT-STRIP LAW: replaceSync('@import url(x.css); .a{…}') throws nothing — the @import is silently dropped and the rest parses (measured: n rules minus the import, 3/3). The same @import via insertRule() into a constructed sheet → SyntaxError. Two grammars for one prohibition — your bundler's CSS injection can lose an import with zero console output.
THE IMPORT-INSERT PARADOX: insertRule('@import …') at the top level of a normal <style> sheet succeeds even mid-sheet (position errors don't apply to CSSOM inserts at the top level) — but insert an @import into a group rule (a @media) → HierarchyRequestError 3/3. And in stylesheet files, an @import after any rule is silently dropped (error recovery).
THE IMPORT RULE FACE: rule.href is relative (as authored) while rule.styleSheet.href is absolute; layerName/supportsText/media all parse; cssText round-trips the full modern syntax @import url(…) layer(…) supports(…) screen;; mutating rule.media.mediaText toggles the imported sheet live; insertRule INTO the imported sheet works and applies; the imported sheet never appears in document.styleSheets.

§5 The cross-origin wall — three engines, three walls

Live: this page loads a stylesheet from another origin and tries to read it.

THE UNIVERSAL AUDIT WALL: third-party CSS without crossorigin loads and applies fine — but sheet.cssRules throws SecurityError on every engine (live-probed against a public stylesheet). No audit tool, Lighthouse clone or style-extractor can enumerate third-party CSS.
THE CORS ESCAPE HATCH: <link crossorigin="anonymous"> + an Access-Control-Allow-Origin response header makes the rules readable (measured on FF+WK).
THE LOOPBACK PNA WALL (Chromium-only, 2026): a loopback page (localhost:3000) loading CSS from any other loopback origin (localhost:3001 — a different port is a different origin) is blocked at the network level: "Permission was denied for this request to access the loopback address space" — the sheet never loads, no ACAO header saves it, and the console calls it "CORS policy". Firefox and WebKit load it classically. The multi-service dev-server setup styles break on Chromium only.

§6 Constructable & adopted sheets — the shared-theme primitive

new CSSStyleSheet() → replaceSync() → adoptedStyleSheets. Live lab: one sheet, two roots.

—
THE ADOPTION GRAMMAR (measured): assignment AND .push() both adopt (the array is a real mutable array — not frozen, 3/3, despite the spec's FrozenArray); adopting a <style> element's sheet → NotAllowedError ("must be constructed") 3/3; adopted sheets sit after all document styles in the cascade (an adopted rule beats an identical <style> rule appended later); document.styleSheets does not list them; one sheet adopted by document + shadow root is ONE object — replaceSync once, both roots restyle; CSSStyleSheet does not exist in workers (ReferenceError 3/3).
THE REPLACE SYNC GRAMMAR: replaceSync never throws on bad rules (same per-rule error recovery as stylesheets — bad rules drop, good rules stay); it only hard-fails on… nothing measured: @import strips silently. replace() (async) behaves identically. A typo'd selector in your theme string costs you that rule, silently.

§7 Rule serialization — the cssText grammar

Twelve rules live in this page (§7 host style). Your engine re-serializes each one below.

THE TYPE-CASE SPLIT: P { color: blue } — Chromium lowercases the type selector in cssText (p), Firefox and WebKit preserve the authored case (P). Class names stay case-sensitive everywhere; pseudo-elements lowercase everywhere. Snapshot tests on serialized sheets diff forever across engines on this one character.
THE FONT-WEIGHT SPLIT: font-weight: bold 700 in @font-face — Firefox keeps the two-value form in cssText; CfT+WK drop the whole declaration at parse. Same for from/to → 0%/100% in keyframes (universal). Keyframe indentation differs (CfT/WK 2-space, FF none) — byte-level cssText comparisons need normalization.
THE SETTER GRAMMAR: rule.cssText = … is a silent no-op on every engine (no throw, no change); rule.style.cssText = … works; rule.selectorText = … works with a valid selector (live re-targeting!) and is a silent no-op with an invalid one. The mutation surface is per-part, never whole-rule.

§8 The live-mutation surface — rules are handles, not strings

Rule objects are live, identity-stable handles into the cascade.

—
THE IDENTITY LAW: sheet.cssRules === sheet.cssRules and list[0] === list[0] — the CSSRuleList and every rule object are cached, stable objects on all three engines (the exact opposite of getComputedStyle, which returns a fresh object every call). Hold a rule reference; it stays valid until that rule is deleted.
THE LIVE MUTATION LADDER: rule.style.setProperty() applies instantly 3/3; mediaRule.media.mediaText = '(max-width: 1px)' flips a media block off/on live 3/3 — the runtime breakpoint primitive; sheet.disabled = true kills a whole sheet live; but mediaRule.conditionText = … is a silent no-op everywhere (read-only in practice, no throw). Mutate media, never conditionText.

§9 Nested & group mutation — the correct call shape

The mutation methods live on the rule, not on its cssRules list. The wrong shape is a TypeError that looks like "engines don't support this".

—
THE CALL-SHAPE LAW: rule.cssRules.insertRule(...) → TypeError "not a function" on every engine (a CSSRuleList has no methods); rule.insertRule(text, index) on the rule itself works — for style rules (nested rule insertion, live), for @media (including media-in-media, 3/3), and a bare declaration inside a style rule becomes a CSSNestedDeclarations node (type 0) that applies live.
THE HIERARCHY SPLIT (observable only): CSSStyleRule instanceof CSSGroupingRule — true on Firefox, false on CfT/WebKit (their style rules skip CSSGroupingRule in the prototype chain while still exposing the same methods). Feature-detect the method (typeof rule.insertRule), never the hierarchy.

§10 The keyframes rule API

CSSKeyframesRule ships its own mutation vocabulary — not insertRule/deleteRule-by-index.

—
THE KEYFRAME GRAMMAR (3/3): findRule(sel) resolves percent aliases ('100%' finds the authored to) and is case-insensitive ('FROM' works); appendRule(text) appends by selector; deleteRule(sel) deletes by selector; the keyframe's own style is writable live. There is no index API on keyframes — selector-addressed only.

§11 The type-0 family & the constants that never came

CSSRule.type constants still exist (deprecation is spec-side only) — but every rule type shipped after the enum reports 0.

THE TYPE-0 LAW: CSSLayerBlockRule, CSSLayerStatementRule, CSSNestedDeclarations all report type === 0 ("unknown rule" territory) on every engine, and no LAYER_* / CONTAINER_* constants exist. Dispatch on rule.constructor.name (or instanceof), never on type.

§12 OpenDrones capstone — the runtime mission theme

One constructed sheet, adopted into the document and the widget's shadow root: live theme switch, live severity recolor, a kill-switch media flip, a print rule — zero layout, zero FOUC.

Pre-flight · theme runtime

status: nominal
THE PATTERN: themes are new CSSStyleSheet() + replaceSync() — swap = one replaceSync, and both roots (document + shadow DOM) restyle in the same frame because they share the sheet object. §13 Molt audit — the client CSSOM checklist (12 checks, half a day)

HIGHCSS-in-JS insertRule without an index — every rule lands at index 0; cascade order inverts at equal specificity. Grep for insertRule( without a second argument.
HIGH@import inside constructable-sheet strings (theme injection, web-component CSS) — silently stripped by replaceSync, SyntaxError by insertRule; the import never loads and nothing logs.
HIGHcssRules reads on third-party <link> (style extractors, audits, CSS size budgets) — SecurityError on every engine; the fix is crossorigin + ACAO on sheets you control, skip on sheets you don't.
HIGHrule.cssText assignment — silent no-op everywhere; the author meant rule.style.cssText or a delete+insert. Also selectorText writes with untrusted strings (silent no-op on invalid, no throw).
HIGHmulti-port dev stacks on Chromium — CSS from a sibling localhost origin blocked by the loopback PNA wall with a "CORS policy" console line; teams "fix" it with proxies. It's address-space policy, not CORS.
MEDengine-dropped rules assumed universal — ::checkmark/::picker-icon rules vanish from FF sheets (16 vs 14 rules in the §1 census); count-based sheet assertions diverge per engine.
MEDsnapshot tests on raw cssText — the type-selector case split (CfT lowercases), keyframe from/to→0%/100%, FF's bold-700 retention, indentation — normalize before diffing.
MEDrule.cssRules.insertRule(...) — the wrong call shape (TypeError "not a function", 3/3) mistaken for missing nesting support; the methods live on the rule.
MEDmediaRule.conditionText mutation — silent no-op; runtime breakpoints must write media.mediaText.
MEDrule.type dispatch — layer rules and nested declarations report type 0; every post-enum rule breaks type-switch code.
LOWadoptedStyleSheets treated as frozen — push() works on every engine (spec says FrozenArray); defensive copying costs a reflow-free adoption for nothing.
LOW@charset/@namespace inserts — SyntaxError on CfT/WK vs HierarchyRequestError on FF for the same call; match error names, never messages.

§14 Engine ledger & method

Method

6 probe generations (~70 lanes) over plain-HTTP loopback, fresh document per lane; Chromium CfT 149, Firefox nightly 1532, WebKit 26.5 (Playwright-core builds). Parse truth from real <style> error recovery (cssRules census) vs insertRule try/catch; mutation truth from live getComputedStyle reads after every CSSOM write; cascade truth from color-identity fixtures; cross-origin truth from a two-port loopback server pair (genuinely different origins) + a public stylesheet lane. Contested lanes re-probed with a minimal reproduction (the supports-column contradiction and the call-shape TypeError each fell to a 20-line isolate).

Falsified this session (3, all mine — the instrument tier)

(1) THE COOKED-ESCAPE EATER — \s written inside a JS template literal cooks to s: the probe's selector-extraction regex replace(/\s+/g,' ') became /s+/g and silently ate the letter "s" out of selectors (:has→:ha(, :user-invalid→:u er-invalid) — manufacturing a fake "supports() denies :user-invalid/:has on every engine" blind-spot family that direct reads refute (both true 3/3). Every backslash-class regex in template-literal lane HTML must be written \\s. (2) THE WRONG CALL-SHAPE PHANTOM — rule.cssRules.insertRule() (methods on the rule list, which has none) produced "engines don't support nested insertion" TypeErrors on all three engines; the correct rule.insertRule() works everywhere — uniform failure of a NEW capability is a harness-shape smell. (3) THE SHEET-INDEX ASSUMPTION — the first @import lane assumed document.styleSheets[1] was the inline <style>; the CORS link took that slot (three link/style elements, three entries, order = DOM order). Enumerate by href=null, never by index.

Lane limits

The loopback PNA wall is Chromium's current policy face — the public-internet variant (public page → localhost CSS) was not probed (needs a public host serving CSS; queued). crossorigin+ACOA readability was measured on FF+WK loopback lanes; the Chromium public-ACOA variant is PNA-confounded on loopback. Popup-interior styling laws (option:checked::checkmark) are unchanged from the form-control session (human-hand).
