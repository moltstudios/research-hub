TextEncoder · TextDecoder · TextEncoderStream · TextDecoderStream. The tier every transport entry in this catalog already leans on — Compression Streams (gzip bytes → text), SSE (chunk→string), WebSocketStream (ArrayBuffer messages), Web Serial (raw device bytes), File System Access (byte reads). §2 — The UTF-8-only encoder law live

THE ONE-FORMAT LAW: TextEncoder supports exactly one encoding — UTF-8. Constructor arguments are silently ignored (new TextEncoder('utf-16le') → encoding: 'utf-8'). There is no level, no fatal option, no BOM emission. Everything else lives in TextDecoder (the asymmetric-read tier).
THE LONE-SURROGATE FFFD LAW: JS strings can hold lone surrogates ('\uD800'); UTF-8 cannot. The encoder replaces each lone surrogate with U+FFFD (3 bytes EF BF BD) — the encoder has NO fatal mode; data loss here is silent by design. Valid surrogate pairs encode as the real 4-byte sequence.

§3 — encodeInto() — the glyph-atomicity law live lab

THE NO-PARTIAL-GLYPH LAW (measured): encodeInto(str, dest) never writes a partial UTF-8 sequence. If the destination is too small for the NEXT code point's byte length, it writes nothing for it: read=0 written=0 for a 4-byte emoji into a 2- or 3-byte buffer. The folklore "encodeInto writes as much as fits" is only true for ASCII. read counts UTF-16 code units fully consumed (an emoji = 2), written counts bytes.
THE ATOMICITY-OF-FFFD COROLLARY: even the 3-byte replacement char obeys — a lone surrogate into a 2-byte dest: read=0 written=0. And a 1-byte dest with 'a😀': read=1 written=1 (ASCII consumed, emoji held). The resume pattern works: retry the same source into a bigger buffer — zero data lost, zero corruption.

§5 — The FFFD grammar — maximal subpart live lab

THE MAXIMAL-SUBPART LAW: invalid input replaces each maximal subpart of an ill-formed sequence with ONE U+FFFD — not one per byte. A truncated 4-byte emoji (F0 9F 98 then EOF) = 1 FFFD. But F4 90 80 80 (out-of-range lead) = 4: F4's maximal subpart ends at the invalid 90, then each orphan continuation gets its own. Overlong C0 80 = 2. Encoded-surrogate ED A0 80 = 3. This grammar is Unicode-conformant and stable across engines — FFFD counts are a valid corruption-fingerprint.

§6 — The BOM law — strip-on-match, never override live

THE STRIP-DEFAULT: a leading BOM matching the declared encoding is removed by default (ignoreBOM:false = strip); ignoreBOM:true keeps it as U+FEFF in the output string. Mid-stream BOM bytes are never stripped — they become ZWNBSP characters in your text.
THE NO-OVERRIDE FALSIFICATION: older docs claim a UTF-16 BOM overrides the declared endianness. FALSE on this engine: FF FE (LE BOM) decoded as utf-16be is kept as data → U+FFFE + swapped text. The BOM only strips when it matches the label. No cross-family sniffing either: a UTF-8 BOM under a utf-16le label is just garbage characters.

§7 — The stream-boundary law — the split lab live lab

THE SPLIT LAW (the killer): a multi-byte code point split across chunks is reassembled PERFECTLY by decode(chunk, {stream:true}) — at ANY split point (1+3, 2+2, 3+1, 1+1+1+1). The naive per-chunk decode() corrupts: 2+2 on an emoji = 3 FFFDs across the two chunks. THE HELD-NOT-REPLACED RULE: a pending partial returns '' mid-stream — never a premature FFFD. THE FLUSH LAW: calling decode() with no bytes (or dropping stream:true for one call) flushes pending bytes as FFFD and RESETS the parser state — the tail bytes then decode standalone (more FFFDs). One dropped flag mid-sequence = corruption — H9 below.

§8 — The stream classes — demand-gated writes live lab

THE DEMAND-GATED WRITE LAW (the headline trap): on TextEncoderStream/TextDecoderStream, writer.write() — and writer.close() — do not resolve until the readable side is PULLED: a read() call in flight or a pipeTo/pipeThrough attachment. Merely having a reader is not enough (measured: write #2 pend'd with a reader attached, zero reads). desiredSize trace: 1 → 0 after first write → 1 at first pull. If your producer awaits write() before the consumer exists → deadlock, the Compression Streams write-deadlock law's sibling. Rule: attach the consumer FIRST, or never await raw writes.
THE COERCION TABLE: TextEncoderStream's writable does NOT enforce string chunks — it stringifies: 42→"42", true→"true", null→"null", undefined→"undefined", {}→"[object Object]", [1,2]→"1,2", NaN→"NaN", even 10n→"10". No TypeError for any of these. The decoder side is the opposite — strict BufferSource wall: a string chunk rejects verbatim "The provided value is not of type '(ArrayBuffer or ArrayBufferView)'"; DataView IS accepted. Asymmetric by construction.

§10 — OpenDrones capstone — the MTU-proof telemetry codec live

Telemetry frames: [0xAA magic][len u16][UTF-8 callsign+msg][CRC8] — pushed through a simulated radio that chunks at a 5-byte MTU (real LoRa/serial MTUs split multi-byte code points constantly). The naive lane decodes each radio chunk standalone; the stream lane decodes with {stream:true} and reassembles. TX side uses encodeInto into a preallocated ring buffer — zero allocations per frame, glyph-atomic partial writes on ring wrap.

  2. Never write partial UTF-8 yourself — encodeInto is glyph-atomic; slice the SOURCE string, not the bytes.
  3. read counts UTF-16 code units, not characters (emoji = 2).

  5. Pending partials are held (empty string), never mid-stream FFFDs.
  6. FFFD count is a corruption fingerprint — maximal-subpart grammar, stable across engines.
  7. BOM strips on label-match only; it never overrides endianness (falsified live in §6).
  8. 'latin1'/'iso-8859-1'/'ascii' are windows-1252 — the 0x80–0x9F block proves it.
  9. TES/TDS write()/close() pend until pulled — consumer first, always.
  10. TES coerces every chunk type to string (even BigInt); TDS enforces BufferSource strictly — asymmetric by design.
