01The primitive graph, not a function list

A CSS filter like blur(8px) is one canned pipeline. An SVG <filter> is a dataflow graph: named steps, each consuming the previous result (result="x" → in="x"), mixing up to five source streams:

<filter id="lens" color-interpolation-filters="sRGB">
  <feTurbulence type="fractalNoise" baseFrequency="0.006 0.011"
                numOctaves="2" seed="7" result="n"/>
  <feGaussianBlur in="n" stdDeviation="4" result="soft"/>
  <feDisplacementMap in="SourceGraphic" in2="soft"
      scale="46" xChannelSelector="R" yChannelSelector="G"/>
</filter>
  • SourceGraphic — the element's own paint.
  • SourceAlpha — its alpha silhouette (tint it, dilate it, blur it: shadows & outlines for free).
  • FillPaint / StrokePaint — the element's own paint servers (gradients as map inputs).
  • BackgroundImage — dead. SVG 2 removed enable-background; probing it renders nothing (no crash, just silence).
measured: SourceAlpha composite → tinted silhouette ✓ measured: BackgroundImage → empty output (ignored) ✗

The payoff: this graph runs on HTML elements via filter:url(#lens), on SVG content via the filter attribute, and — the headline below — on backdrops via backdrop-filter:url(#…).

02The linearRGB default is a silent color thief

Every <filter> defaults to color-interpolation-filters:linearRGB — colors are linearized before your matrices run and re-encoded after. CSS filter functions compute in sRGB. Same matrix, different pixels:

linearRGB (default): …
sRGB: …

Luminance matrix on pure red, measured in Chrome for Testing 148:

  • linearRGB lane → [127,127,127] — 0.2126 in linear light re-encodes to ~50% sRGB
  • sRGB lane → [54,54,54] — 0.2126×255, the number you actually meant
  • hue-rotate() misbehaves the same way: red→90° gives [0,161,0] in linear vs [0,91,0] in sRGB — and only the sRGB lane matches CSS filter:hue-rotate(90deg) pixel-exactly.
Rule: unless you are doing physically-correct light math, put color-interpolation-filters="sRGB" on every filter you author. It is the #1 “why do my SVG filter colors look washed out” answer.

  • Deterministic: same seed → pixel-identical output, every render. Seeds are a design tool: ship one number, get the same texture everywhere.
  • Never 0–255: measured R-channel of fractalNoise on CfT 148 spans ≈ [101,235], mean ≈187 — no octave count reaches the rails. Need a full-range height map? Stretch it with feComponentTransfer (linear slope ≈ 255/(max−min)).
  • Cliffs: baseFrequency="0" and huge values (≈5) both render a flat field at 187 — no error, no texture. Your noise “disappearing” is usually a baseFrequency typo.
  • Two numbers = anisotropy: baseFrequency="0.006 0.011" stretches noise horizontally — the cheap glass look.
  • stitchTiles="stitch" makes the tile seamless for feTile repeats (grain wallpapers).

04feDisplacementMap — the half-scale law

Displacement per pixel: P′(x,y) = P(x + scale·(Cx − 0.5), y + scale·(Cy − 0.5)). Map value 0.5 (mid-gray) = zero; white = +scale/2; black = −scale/2. Measured with a striped source and constant maps:

#808080
80
expected shift: 0.0 px
  • Measured: scale 40 + white map moved the red/white boundary exactly 20px (scale/2); mid-gray moved it 0px; black −20px. Pixel-exact law.
  • Channel selectors matter: xChannelSelector="R" yChannelSelector="G" reads an RGB map; "A" reads an alpha ramp (transparent map edge = −scale/2 — free vignette warp).
  • Feed it feTurbulence → organic glass; feed it a blurred radial gradient → a lens. That’s the entire liquid-glass refraction recipe:

05Backdrops can go through the primitive graph

The claim every “SVG filters can’t touch your backdrop” thread makes — falsified in Chromium 148: backdrop-filter:url(#lensRefract) runs the full primitive graph over everything behind the element, measured pixel-identical to the equivalent CSS blur lane.

If the top panel looks like a warped, liquid lens and the bottom looks like plain blur, your engine supports url() in backdrop-filter. If the top panel looks flat, it silently ignored the reference — degrade gracefully (blur is the universal fallback).

  • Chromium 148: verified applied, pixel-read ✓
  • Safari / Firefox: treat url() in backdrop-filter as unverified — always ship the blur fallback beside it.
  • Cross-origin external filter files are silently ignored (measured: zero effect, zero console error). Same-origin filters.svg#id references do work on HTML elements in Chromium — ship a filter-library file, keep pages lean.

06The vanishing-element bug: filter regions & bbox units

A filter’s default region is x="-10%" y="-10%" width="120%" height="120%" — percentages of the filtered element’s bounding box. Anything your filter pushes outside that rectangle is clipped. No warning, no error — the content just stops existing:

20
off
region covers …
  • Drag dx past ~110 and the purple rect vanishes entirely — it slid out of its own region. Toggle “fix region” (explicit x/y/width/height in user units) to rescue it.
  • Same law, second face: primitiveUnits="objectBoundingBox" (default!) makes primitive values fractions of the bbox. feMorphology radius="3" on a 20px element = 60px — measured: element erased. Use primitiveUnits="userSpaceOnUse" for pixel-sized effects.
  • Percent region = bbox of the element, not the canvas — a 10px icon filtered with width="100%" gets a 10px region. That’s why small icons need oversized regions most.

07Pipeline recipes (all live, all SVG-native)

duotone — luminance → feComponentTransfer table remap
heatmap — luminance → 4-stop R/G/B tables
outline — feMorphology dilate on SourceAlpha (userSpaceOnUse!)
film grain — turbulence alpha 0.6, stitchTiles on

Four production looks, zero images, zero JS at runtime — and each is deterministic (seeded), so it matches across renders and devices in a way WebGL noise shaders never quite do.
