The clock: how fine is performance.now()?

Post-Spectre, browsers coarsen high-resolution timers. The spec floor is 0.005ms when cross-origin isolated, 0.1ms otherwise — and engines may add jitter. This probe samples 4,000 consecutive now() readings and measures the lattice the deltas land on.

Marks & measures — your own breadcrumbs

performance.mark() / measure() are the only timing primitives you fully control. They land synchronously in the timeline buffer (unlike observer delivery) and carry an arbitrary detail payload that survives the round trip.

PerformanceObserver

Observer mechanics: async, drainable, disconnectable

getEntriesByType() polls a buffer; a PerformanceObserver receives entries as they're recorded — after your current task yields. takeRecords() drains pending entries synchronously; disconnect() stops delivery. Unknown types in entryTypes are silently ignored (console warning only).

The Buffer Wall — why polling silently stops

The resource buffer holds 250 entries by default. When it fills, getEntriesByType('resource') silently stops seeing new entries — but an active PerformanceObserver keeps receiving every one. This probe shrinks the buffer to 12, fires 16 fetches, and shows the wall.

Timing-Allow-Origin

Cross-origin: the zeroed middle

Fetch a cross-origin resource without the Timing-Allow-Origin header and you get the shape of the fetch but not its innards: start, fetchStart, responseEnd and duration are real; everything between (DNS, TCP, request, response) and all sizes are zeroed. Third-party scripts can't hide their existence — only their cost breakdown. Probe target: the Mission Control API (different origin, no TAAO header).

Navigation Timing

This page's own load, phase by phase

getEntriesByType('navigation') returns exactly one entry — the document itself — with the full load waterfall from startTime 0 to loadEventEnd, including activationStart (non-zero only for prerendered pages) and the document's own size trio.

Event Timing · the INP source

Slow interactions, measured from the input to the paint

Every real interaction emits PerformanceEventTiming entries. startTime ≈ when the user acted; processingStart–processingEnd = your handler; duration = startTime to the next paint, rounded to 8ms. Default threshold is 104ms; you can ask for as low as 16ms. Click the pad — the slow button burns ~113ms synchronously.

RUM

Drop-in INP — computed live from this session

INP = the ~98th-percentile worst interaction duration, where an interaction = all event entries sharing one interactionId, scored at that group's max duration. This page computes it from the entries your clicks generated above.

This session

// Drop-in field INP (Chromium-family; Safari/FF ship Event Timing basics)
const byInt = new Map();
new PerformanceObserver(list => {
  for (const e of list.getEntries()) {
    if (!e.interactionId) continue;
    byInt.set(e.interactionId, Math.max(byInt.get(e.interactionId) ?? 0, e.duration));
  }
  const durs = [...byInt.values()].sort((a, b) => a - b);
  const inp = durs.length >= 50 ? durs[Math.floor(durs.length * .98)] : durs.at(-1);
  // send on tab hide — not on unload (browsers discard it)
  document.onvisibilitychange = () =>
    inp != null && document.visibilityState === 'hidden' &&
    navigator.sendBeacon('/rum', JSON.stringify({inp}));
}).observe({type: 'event', durationThreshold: 16, buffered: true});
Threshold matters: with the default 104ms you only see already-bad interactions; 16ms is the floor. Pairs with long-animation-frame to attribute the slow frames.
