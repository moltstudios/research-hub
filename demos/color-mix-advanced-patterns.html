CSS color-mix() — Advanced Patterns + Perceptual Palette Tools

Mix any two colors in any colorspace, replace Sass mixins, generate perceptually-uniform palettes, and create mesh gradients — all with a single CSS function.

Browser: Chrome 111+, Firefox 113+, Safari 16.2+, Edge 111+ (~93% traffic) Priority: P4 (High — completes the CSS color toolkit)

1 · Live Color Mixer

color-mix() takes one or more colors and returns the result of mixing them in a given colorspace by a given amount. The colorspace determines how the mix behaves — sRGB is linear light (good for physical mixing), OKLCH is perceptually uniform (good for gradients), and HSL is polar (good for hue rotation).

2 · Sass Replacements (No Preprocessor Required)

color-mix() replaces Sass mix(), lighten(), darken(), and tint() with native CSS. No build step, no JavaScript color utilities.

Before (Sass)

mix() — blend two colors
$primary: #6c5ce7; $secondary: #00cec9; $blend: mix($primary, $secondary, 50%);
lighten() — nudge up
$brand: #6c5ce7; $light: lighten($brand, 20%);
darken() — nudge down
$brand: #6c5ce7; $dark: darken($brand, 20%);

⚠️ Sass lighten()/darken() work in HSL, which is not perceptually uniform — the same 20% change looks different depending on the starting color. OKLCH is perceptually uniform.

After (Native CSS)

mix() — blend two colors
color-mix(in oklch, #6c5ce7 50%, #00cec9 50%);
lighten() — nudge up (OKLCH)
color-mix(in oklch, #6c5ce7 80%, white 20%);
darken() — nudge down (OKLCH)
color-mix(in oklch, #6c5ce7 80%, black 20%);

✅ OKLCH is perceptually uniform — the same 20% change looks consistent across the color wheel.

3 · Perceptual Uniformity (OKLCH vs sRGB)

The same numeric change in OKLCH looks the same everywhere. sRGB is not perceptually uniform, so the same 20% change looks different depending on where you start.

OKLCH is perceptually uniform: Each step looks like the same perceived brightness change. Great for gradients, tints, and shades that should feel consistent.
sRGB is NOT perceptually uniform: The same numeric change (20%) looks different at different parts of the color wheel. Use OKLCH for design tokens, not sRGB.

4 · Perceptual Palette Generation

Generate a complete palette from a single brand color using color-mix() and oklch(). Each shade is perceptually uniform, so the visual gap between steps feels consistent. 

/* Single brand color, 8 shades */
:root {
  --brand: #6c5ce7; /* OKLCH(0.55 0.25 260) */

  /* 8 shades, 12.5% steps */
  --brand-100: color-mix(in oklch, var(--brand) 12.5%, white);
  --brand-200: color-mix(in oklch, var(--brand) 25%, white);
  --brand-300: color-mix(in oklch, var(--brand) 37.5%, white);
  --brand-400: color-mix(in oklch, var(--brand) 50%, white);
  --brand-500: var(--brand);
  --brand-600: color-mix(in oklch, var(--brand) 62.5%, black);
  --brand-700: color-mix(in oklch, var(--brand) 75%, black);
  --brand-800: color-mix(in oklch, var(--brand) 87.5%, black);
  --brand-900: color-mix(in oklch, var(--brand) 100%, black);
}

5 · Mesh Gradients

color-mix() is the key to creating smooth mesh gradients without using pre-sliced PNGs. You can mix colors in any space, then layer them with radial-gradient(). 

.mesh {
  background:
    radial-gradient(circle at 20% 30%, color-mix(in oklch, var(--brand) 0.6, white) 0%, transparent 50%),
    radial-gradient(circle at 80% 70%, color-mix(in oklch, var(--brand) 0.6, white) 0%, transparent 50%),
    radial-gradient(circle at 50% 50%, color-mix(in oklch, var(--brand) 0.4, white) 0%, transparent 60%);
  mix-blend-mode: overlay;
}

6 · Advanced Patterns

Hue rotation (HSL)

/* Rotate hue by 30° */
color-mix(in hsl, hsl(200deg 50% 80%) 80%, hsl(230deg 50% 80%) 20%);

/* Same color, different hue */
color-mix(in hsl, hsl(260deg 50% 60%) 70%, hsl(300deg 50% 60%) 30%);

Longer hue path (HSL)

/* Go the long way around the color wheel */
color-mix(in hsl longer hue, hsl(0deg 80% 50%) 50%, hsl(180deg 80% 50%) 50%);

More than two colors

/* Blend 3+ colors */
color-mix(in oklch, teal 20%, olive 30%, blue 50%);

/* Blend 4 colors */
color-mix(in oklch, red 10%, orange 20%, yellow 30%, green 40%);

Relative color syntax (OKLCH)

/* Nudge channels of a single color */
color-mix(in oklch(from #6c5ce7 l c h, l 0.05, c 0.02, h 10deg));

/* Same color, different perception */
color-mix(in oklch(from #6c5ce7 l c h, l + 0.05, c + 0.02, h + 10deg));

Relative color syntax lets you modify individual channels of a color without specifying the full color value. This is useful for tweaking specific aspects (lightness, chroma, hue) while preserving the rest.

Page background:

The mark highlight color is derived live from --page-bg via color-mix(in oklch, var(--hl-brand) 30%, white) and the text color via contrast-color() against the same mix. Switching the page background re-themes the highlights with zero new CSS. 

/* Single source of truth for search highlight theming */
:root {
  --hl-brand: #fdcb6e;          /* amber */
  --page-bg: #0a0a0f;           /* swap per page */
  --hl-bg: color-mix(in oklch, var(--hl-brand) 35%, var(--page-bg));
  --hl-fg: contrast-color(var(--hl-bg));
}
::highlight(search) {
  background: var(--hl-bg);
  color: var(--hl-fg);
}

Why this is the missing link in the CSS color toolkit

All four pieces together complete the CSS color toolkit that replaces design tokens, Sass mixins, and JS contrast helpers with pure CSS:

oklch() Perceptually-uniform color picker. Choose a brand color once and the rest of the palette can be derived without guesses.
color-mix() This entry. Mix any two colors in any space. The bridge between brand color and derived surface colors. Replaces Sass mix(), lighten(), darken().
light-dark() Theme-aware tokens. One token, two color values; browser picks based on color-scheme.
contrast-color() Always-readable text. One color in, two-color decision out — browser computes the WCAG-optimized black/white.
