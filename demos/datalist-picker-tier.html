§1The surface — the list contract & the typeof lie

One <datalist> is shared state: input.list resolves it for any number of inputs; a list pointing at a non-datalist (or missing) id reads null. And showPicker reports typeof "function" on every input type — checkbox, radio, submit included — the census lies; behavior gates on type + state.

§2THE FIREFOX DISABLED-OPTION EXCLUSION

On Firefox, datalist.options hides disabled options from the collection itself — options.length 3 while children.length is 5 — and it's live: un-disable one at runtime and the collection grows back, re-disable and it shrinks. CfT + WebKit keep all 5. The split extends into the popup: Firefox never suggests a disabled option; WebKit lists it but Enter refuses to commit it.

Dev face: never read datalist.options to count "all suggestions" — on Firefox your disabled entries are already gone. Feature-detect the engine by the exclusion itself (below), not by UA string.

§3THE GESTURE WALL — error grammar & the 5-second fuse

showPicker() requires transient user activation on all three engines. Outside a gesture: NotAllowedError 3/3. On disabled/readonly controls: InvalidStateError 3/3. Inside a gesture but 6 seconds late (activation expired): NotAllowedError again 3/3 — at +2s it still passes. Match the error name, never the message: three engines, three message shapes.

The no-gesture call ran the moment this section rendered — read its verdict above (expect NotAllowedError everywhere).

The no-list call is the silent-ok wall: it throws nothing — "ok" on all three engines — it just can't show suggestions that don't exist. A missing datalist is not an error state; guard it yourself.

click to arm — the call fires 6.1s after your click

Measured 3/3: click → +6.1s → showPicker() → NotAllowedError (transient activation burned). Positive control: +2s after click → opens fine. Pair: the User Activation tier's 5-second fuse, picker edition.

§4THE PICK GRAMMAR — what Enter commits, and the CfT automation void

The suggestion popup is browser chrome — the DOM never sees it. Truth instrument: drive it with a trusted keyboard and read what Enter commits. The grammar that fell out: typing opens the popup with NO pre-highlight — Enter commits your typed text (ff/wk); press ↓ first to enter the list. On CfT under automation the datalist popup never materializes at all — AX tree flat, keyboard inert, headless AND headed — while its date calendar opens fine (§8). FF/WK popups are fully automation-drivable.

§6THE SELECT SPLIT — showPicker() on <select>

select.showPicker() exists on CfT + Firefox and is missing entirely on WebKit 26.5 (TypeError: not a function). Where it exists, under automation the call returns "ok" but the popup never materializes — CfT AX tree stays flat (35 nodes → 35), ArrowDown/Enter go nowhere. Native-surface popups: undriveable through synthetic paths; verify with the real-hand lane or AX.

§7THE DATE-PICKER LANE — :open is the only observable

The date calendar is the one picker every engine opens under automation, and while it's open the input matches :open — measured true on all three engines. On CfT the open calendar balloons the AX tree 35 → 213 nodes, keyboard drives it (↓+Enter committed 2026-11-17 from a fresh input), and Enter closes it (:open falls back). There is no toggle/open event for input pickers — poll :open, or read the AX tree.

§8THE HIDDEN-DATALIST RENDER TRAP

The UA hides datalist with display:none — and any author rule beats it. One datalist { display: block } (a reset stylesheet, a * { display: block } sweep) renders the suggestion list as page content: a full-width block listing every option. Worse: re-adding hidden does not re-hide it — [hidden] is only a UA rule, your display:block outranks it. Measured 3/3.

§9inputmode + enterKeyHint — the grammar tier

THE NUMBER FACE: numeric suggestions surface and commit in document order (typed “5”, ↓+Enter → 5, ↓↓+Enter → 50 — ff/wk measured). But non-numeric options never surface on type=number — ↓ falls through to the native stepper (7 → 6). The client pattern: type="text" inputmode="numeric" keeps the numeric keyboard on mobile and the datalist working, without number-input's quirks (badInput voids, scroll-to-change, leading-zero loss).

§11The Molt client audit — 12 checks, half a day

Pass these against every client form. Checks 1–5 pass code review and ship broken.

  • HIGH 1 — the reset un-hide: any global display normalization that includes datalist { display:block } renders every suggestion list as page content; [hidden] will not save you (§8). Grep design systems for bare datalist display rules.
  • HIGH 2 — the disabled-count lie: dashboards reading datalist.options.length as "options available" undercount on Firefox by the disabled entries (§2) — count children, or state which you mean.
  • HIGH 3 — showPicker without a gesture plan: programmatic showPicker() from load/state-change (React effect, open-on-focus UX) throws NotAllowedError on 100% of engines; it needs a live gesture chain, and a ≥5s-old gesture is dead (§3).
  • HIGH 4 — select.showPicker on Safari: the method does not exist on WebKit 26.5 — feature-gate or TypeError on every iOS/macOS Safari visitor (§6).
  • HIGH 5 — e2e datalist suites on Chromium-only CI: CfT suppresses datalist popups under automation — interaction tests silently pass-through (typed text "commits"); run interaction asserts on the FF/WK lanes and DOM-level asserts only on CfT (§4).
  • MED 6 — Enter-commits-typed assumptions: typing never pre-highlights; "press Enter to accept the first suggestion" UX copy is wrong unless you call showPicker() (which pre-highlights on Firefox only — and is void on WK text inputs).
  • MED 7 — suggestion-order asserts: a label on an option reorders Firefox's walk (§5); strip labels from fixtures or drop order asserts.
  • MED 8 — error-message matching: QA matching showPicker failure text breaks per-engine (three message shapes); match e.name.
  • MED 9 — inputmode as validation: inputmode changes keyboards, never parsing — invalid values read back "" from the IDL but the attribute still does nothing on desktop; pair with pattern/parse, never assume the grammar enforced anything (§9).
  • MED 10 — type=number + text suggestions: datalists feeding serials/codes into type=number never surface (↓ hits the stepper instead); use text+inputmode (§9).
  • LOW 11 — picker-open detection: no events exist for picker open/close; poll :open (works 3/3 for date pickers) instead of listening for phantoms (§7).
  • LOW 12 — disabled-option UX: a disabled suggestion on WebKit is visible-but-refused (Enter no-ops — a dead-end for keyboard users); on Firefox it's hidden entirely. Prefer filtering the datalist over disabling entries.
