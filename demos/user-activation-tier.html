The one-consumer cascade — one click buys ONE

The law that breaks real flows: a single click funds exactly one consuming call. Click below — the handler asks for fullscreen and opens a popup in the same tick. One wins, one loses — and which one loses is an engine split measured on the bench: Chromium checks the gesture at call time (first caller wins — fullscreen OK, popup null); Firefox/WebKit check fullscreen's gesture later, asynchronously — so the synchronous window.open steals the window even when it runs second.

§8

Birth & survival — popups and navigations

Two lifecycle splits measured on the bench. Popup inheritance: a WebKit child opened by window.open() inherits the opener's live window at birth (isActive:true at load); Chromium and Firefox children start cold. Navigation stickiness: after a same-origin full navigation, Chromium keeps hasBeenActive:true in the new document; Firefox and WebKit reset both flags. §9

The evaluate-is-a-gesture law — the harness meta-finding

Measuring this tier through automation is a trap: every page.evaluate() / Runtime.evaluate call arms a full transient-activation window (~5000 ms, measured 4999/5003/4992 ms on Chromium/Firefox/WebKit) and latches hasBeenActive forever. A fresh page reads false/false for eight silent seconds — then ONE evaluate read returns true/true, and an in-page watcher catches the window arming at the evaluate and expiring five seconds later. Consequences: any e2e suite that reads userActivation via evaluate measures the harness, not the user; any activation-gated API called within ~5 s of any evaluate succeeds — fake-green; and activation reads in test code must be made by in-page samplers, never by the driver.

This is the generalized form of the Pointer Lock session's "privileged-caller law" (evaluate bypasses the lock gate) and the Fetch Metadata session's userGesture:true artifact — all three findings are the same harness lane: the automation driver IS a gesture source.

OpenDrones — the arm sequence

Two-step arming is the canonical activation race: ARM (click) → confirm. If confirmation does anything async first — fetching a mission manifest, asking the link monitor — the five-second fuse can burn before ENGAGE fires the failsafe-critical call. This capstone runs the real sequence with a configurable async step. The rule it ships: no await between the last click and the gated call — pre-fetch before the click, or re-solicit the click.

  • Ship rule 1 — between the last user gesture and any gated call, zero awaits. Pre-fetch everything; re-solicit the click if you can't.
  • Ship rule 2 — one gesture, one consumer. Sequences (fullscreen → open → share) need one real input each.
  • Ship rule 3 — "press any key" is wrong: Escape and bare modifiers are dead keys for activation. Say Enter or Space.
  • Ship rule 4 — a failed gated call may still have burned the fuse (share validation throws AND burns). Retry flows need a fresh click, always.
  • Ship rule 5 — in tests, treat userActivation as unreadable from the driver: sample in-page, or you measure the harness (§9).
