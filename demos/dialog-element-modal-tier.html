<dialog> — The Modal Tier

The native modal engine: showModal() lifts the dialog into the top layer (above every z-index), makes the rest of the page inert, installs a focus trap and a focus-restore — for free. Probed live on this page: the cancel/close/requestClose() closing gauntlet, the new closedby light-dismiss dial, nested-modal LIFO, method="dialog" forms, and the traps (non-modal show() is NOT in the top layer; modal inertness is not the inert attribute; display:none vs open).

1 · State of the platform

Three support waves. Core <dialog> (show/showModal/close/returnValue/cancel/close events, ::backdrop) is Baseline since Sep 2022 — Chrome 37(!)/Firefox 98/Safari 15.4 — effectively universal, ship ungated. The close-request wave landed 2024–25: requestClose() Chrome 134 / Firefox 139 / Safari 18.4 (all engines shipped), toggle/beforetoggle on dialogs Chrome 132 / Firefox 133 / Safari 26, closedby Chrome 134 / Firefox 141 / Safari preview only. The popover-crossover wave: popover attribute on a <dialog> (non-modal + light dismiss + declarative popovertarget buttons) and Invoker commands show-modal/close/request-close.

2 · Anatomy — three ways in, two ways to be

3 · The top layer — above every z-index, outside every clip

Modal dialogs render in the top layer, painted after (and therefore over) everything in the document, no matter the z-index — and they escape ancestor clipping and stacking contexts entirely. The rival below is z-index:2147483647 (the max 32-bit int). The clipper traps a non-modal twin in overflow:hidden.

4 · The free focus machine — in, around, back

showModal() runs a focus algorithm: the element with autofocus wins; otherwise the first focusable descendant; otherwise the dialog element itself. On close, focus returns to the previously-focused element. No focus-trap library, no tab-cycle JS, no restore bookkeeping.

d6 needs a REAL Tab key (synthetic keydown doesn't move focus) — press the button, then the harness sends three real Tabs and presses it again to collect.

5 · Inertness — the outside world is dead (but .inert is false)

While a modal is open, everything else is inert: clicks land nowhere, focus calls bounce. But this is modal inertness, not the inert attribute — el.inert still reads false. Feature-detect via behavior, not the property.

6 · The closing gauntlet — cancel → close, and who fires what

Three closers, one event grammar. Esc and requestClose() fire cancel first (preventable → dialog stays open), then close. Plain close() closes directly — no cancel event, no veto. Two engine truths probed live below: requestClose() is gated by closedby just like Esc (f8 — it's a programmatic close request, not a developer bypass; close() is the unconditional path), and the close event fires as a queued task — asynchronous, so don't read dialog state in the same tick (f3).

7 · closedby — the light-dismiss dial (Ch 134 / FF 141 / SF preview)

Three values: closerequest (Esc/platform close — the behavioral default for modals), any (+ light dismiss: click outside closes), none (developer-mechanism only — Esc and requestClose() dead). Missing/invalid values fall back to the modal default — and note the g1 divergence: the IDL getter returns "none" for missing even while Esc still works. Light dismiss runs the same cancel gauntlet (g3) — veto it to guard unsaved state. Safari stable doesn't ship closedby — degrade means "no light dismiss", which is the pre-2025 status quo.

8 · Nested modals — LIFO stack, outer goes inert too

Modals stack last-in-first-out. While the inner modal is open, the outer dialog is inert as well. One Esc closes exactly the top one. This is the confirm-inside-modal pattern that custom implementations always get wrong.

9 · show() — the sober twin (and its traps)

Non-modal show(): no backdrop, page interactive, Esc dead — and not in the top layer, so a z-index rival can paint over it and ancestor clipping applies. For "non-modal + light dismiss + declarative buttons" use <dialog popover> instead (popover tier).

10 · Forms — method="dialog" closes + returnValue for free

A form with method="dialog" inside a dialog closes the dialog on submit and sets returnValue to the submitter's value — the confirm/cancel button pair with zero JS. formmethod="dialog" on a single button does the same per-button.

11 · Entry/exit animation — @starting-style + allow-discrete

Dialogs (and their backdrops) animate with the discrete-property pattern: transition-behavior: allow-discrete on display/overlay keeps the element painted through the exit transition, and @starting-style provides entry keyframes for something that pops into existence at display:block. Cross-links the @starting-style catalog entry.

12 · Capstones — OpenDrones arm guard & Molt lightbox

OpenDrones — the arm guard

A safety modal that refuses to close until the checklist is confirmed: closedby="none" (no Esc/outside escape), cancel vetoed while unchecked, requestClose() on ARM runs the gauntlet and only passes when the box is ticked. Telemetry behind it is inert — the pilot physically cannot click past it.

DISARMED — throttle locked

Molt — the lightbox

Gallery lightbox as a real modal: focus lands on the close button (autofocus), arrow buttons stay reachable, close returns focus to the thumbnail that opened it. Zero focus-management JS.
