HTML Drag & Drop API — DataTransfer, the three-mode store & the acceptance contract

The web's oldest input API (IE 5.5 lineage, spec'd in HTML §6.11) is still the only native way to accept OS file drops and cross-app drags. Under the friendly draggable attribute sits a three-mode drag data store that seals your own data from you mid-drag, a dropEffect × effectAllowed handshake, and an acceptance contract where canceling dragover is the only thing that sustains a drop. Every chip below is a live probe — synthetic stores fire on click; native-loop truths flip from real trusted drags (drag with your mouse, or the CDP battery drives them).

03 · The #1 gotcha

Protected mode: your data reads "" mid-drag — and files reads 0

The classic production bug: an onDragOver handler calls getData('text/plain') to decide whether to accept — it always gets the empty string, and a file drag reports files.length === 0 while types simultaneously lists "Files". Gate on types/items[i].kind during dragover; read data at drop.

07 · The acceptance contract

Cancel dragover or nothing happens — canceling only dragenter demotes you

To receive a drop, the last dragover on the target must be canceled (preventDefault() — note listeners must be {passive:false}). Chromium live-verdict on the granularity: a zone that cancels dragenter but not dragover is immediately demoted — dragleave fires and the drop never comes. Canceling dragover alone is fully sufficient.

08 · The ending

dragend always fires — the outcome receipt

Drop, rejection or Esc-cancel — the source always gets its dragend, and dropEffect is the receipt: 'copy'|'move'|'link' if the drop landed and was accepted, 'none' if the drop was rejected (uncanceled dragover) or canceled (Esc). The store at dragend is protected again — you can't read data, only the outcome.

09 · Files

Files seal until drop — getAsFile() timing & getAsString is async

During dragover a file drag advertises "Files" in types, but files.length is 0 and file-kind items[i].getAsFile() returns null — sealed, by design, until the drop commits. At drop the File objects materialize with real names and byte-exact sizes. On text items, getAsString(cb) delivers asynchronously — never expect a return value.

10 · The mobile truth

No touch initiates HTML5 drags — the pointer-capture fallback

draggable works with mice and pens — but on touchscreens, no mobile engine turns a touch into a native HTML5 drag (the events exist; the initiation never fires).
