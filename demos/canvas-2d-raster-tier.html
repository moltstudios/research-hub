Canvas 2D — The Raster Tier: CanvasRenderingContext2D

The 2D raster engine beneath every OpenDrones HUD capstone this catalog has shipped (DPR-exact telemetry, mission DVR overlays, waypoint canvases) — and it had zero dedicated coverage: OffscreenCatalog covered the transfer mechanism, never the drawing API itself. Every claim below is an executable chip, live-probed on this engine.

§01 · The context contract — one canvas, one context, forever

getContext('2d') returns a singleton per canvas element — the same object every call. The context-type door is one-way: once a canvas has a 2D context it can never produce a WebGL, bitmaprenderer or 2d-with-different-attributes context, in either direction.

Identity & the one-way door

const a = c.getContext('2d'), b = c.getContext('2d');
a === b;                    // true — singleton
c.getContext('webgl');      // null — door closed
// fresh canvas: webgl first → getContext('2d') also null

getContextAttributes() — richer than documented

MDN documents alpha / colorSpace / desynchronized / willReadFrequently; current Chromium also reports colorType and toneMapping — docs-drift, read defensively.

willReadFrequently: true hints the engine to keep the backing store in CPU memory (software canvas) — pass it for pixel-read-heavy pages (OCR, analysis), not for animation. ctx.canvas is the back-reference to the owning element.

§02 · The state stack & the path myth

save()/restore() manage a stack of drawing state (transform, styles, alpha, composite op, filter, clip, line dash, shadow, text props). The current path is NOT part of it — the #1 misconception in canvas code review. restore() past empty stack is a silent no-op, never a throw.

The path is not state

x.beginPath(); x.rect(0,0,10,10);
x.save(); x.beginPath();        // wipes path
x.restore();                    // does NOT bring it back
x.isPointInPath(5,5);           // false

Underflow & what IS state

x.setTransform(2,0,0,2,0,0);
x.restore(); x.restore();       // empty stack — no-op, no throw
x.getTransform();               // still (2,0,0,2) — transform is state,
                                 // but unbalanced restore never throws

Pattern: wrap every drawing unit save() → set styles/transform/clip → draw → restore(), and treat beginPath() as the start of every shape — the missing beginPath() (connected-lines bug) and the missing restore() (leaked transform) are the two classic leaks.

§03 · The silent-ignore wall — setters absorb garbage, methods throw

Invalid values passed to attributes are silently ignored — the previous value survives. Invalid values passed to methods throw. Two disciplines, one API — and the reason a typo'd globalAlpha = 2 renders “fine” (it keeps the old value) while a negative roundRect radius explodes.

Setters: ignored, no exception

x.globalAlpha = 0.5; x.globalAlpha = 2;   // stays 0.5
x.globalAlpha = -1;                        // stays 1
x.lineWidth = -5;      // stays 1
x.shadowBlur  = -1;    // stays 0
x.miterLimit  = 0;     // stays 10
x.globalCompositeOperation = 'bogus'; // stays prev
x.filter = 'nonsense(3px)';           // stays 'none'
x.setLineDash([-1]);                  // dash unchanged

Methods: throw, three error types

x.roundRect(0,0,10,10,-1)   // RangeError
x.roundRect(0,0,10,10,[r,r,r,r,r]) // RangeError — 5 radii!
x.arc(cx,cy,-5,0,1)          // IndexSizeError
x.ellipse(cx,cy,-1,5,…)      // IndexSizeError
g.addColorStop(2,'#f00')     // IndexSizeError (0..1 enforced)
g.addColorStop(NaN,'#f00')   // TypeError (non-finite)

Live-falsified expectation: “5 radii array → extras silently ignored.” Wrong — Chromium throws RangeError: 5 radii provided. Between one and four radii are necessary. The setter/method asymmetry means validation code belongs around geometry calls, not around property assignment.

§04 · Geometry — the auto-line, the windings & the Infinity trap

arc() draws a connecting line you never asked for

If the path has a current point, arc() adds a straight segment from it to the arc's start — the “why is there a line to my circle” classic, live-proven:

x.beginPath(); x.moveTo(0,0);
x.arc(50,50,40, 0, Math.PI/2); // start point (90,50)
x.isPointInPath(45,25);  // true — on the invisible
                          // (0,0)→(90,50) connector

roundRect() radii contract

Radii follow CSS corner order [tl,tr,br,bl], overlap auto-scales down (measured: [60,60,60,60] on 100×50 → effective r=25, the min(w,h)/2 pill cap) — but Infinity does NOT clamp to a pill: it silently paints zero pixels. CSS border-radius:∞ intuition dies here — pass the number yourself.

Path2D + winding + stroke hit-tests

const p = new Path2D();
p.rect(0,0,20,20); p.rect(5,5,10,10);
x.isPointInPath(p,10,10,'nonzero'); // true
x.isPointInPath(p,10,10,'evenodd'); // false — the donut
x.isPointInStroke(p,10,0.2);        // true — edge only

Why it matters

Path2D objects are reusable, transformable (addPath(p, domMatrix)) and hit-testable without painting — the OpenDrones waypoint layer keeps hover targets as Path2Ds and tests pointer events against them, no redraw needed.

§05 · Gradients — straight-alpha interpolation & the conic's 3-o'clock start

Transparent stops interpolate straight, not premultiplied

A gradient from rgba(255,0,0,0) to rgba(0,0,255,1) passes through visible red at the midpoint — live-read [125,0,128,129]. CSS gradients blend premultiplied-alpha colors; canvas blends straight RGBA. Transparent→color fades must route through the same hue to avoid the ghost tint.

createConicGradient() starts at 3 o'clock

CSS conic-gradient starts at 12 and sweeps clockwise; canvas starts at +x (3 o'clock) with angles measured screen-clockwise (y-down). Live-read: right=stop-0 color, top=75% around, left=the 0.5 boundary.

Also probed: addColorStop offsets are strictly enforced [0,1] — IndexSizeError outside, TypeError for non-finite (§03). Patterns carry their own transform: pattern.setTransform(new DOMMatrix()) — there is no .transform property.

§06 · Composite ops — the punch-out toolkit

Twelve blend modes via globalCompositeOperation. Three earn their keep constantly: destination-out (punch alpha holes — live: 10×10 hole → [0,0,0,0], surrounding pixels untouched), lighter (additive, live: rgb(100,100,0) + rgb(0,0,255) → [100,100,255] clamped at 255), and source-over discipline (always restore — it's state).

x.globalCompositeOperation = 'destination-out';
x.fillRect(5,5,10,10);   // alpha hole — eraser,
                         // respects anti-aliasing
x.globalCompositeOperation = 'lighter';
x.fillRect(0,0,20,20);   // additive glow — HUD bloom

§07 · The text engine — metrics that tell the truth

measureText() is two boxes

width is the advance; actualBoundingBox* is the ink (live: 'Ay jelly' @40px → advance 126, ink ascent 28.7 / descent 8.6); fontBoundingBox* is the font's line metrics (37/9). Size layout to the ink box when trimming to visible glyphs, to the font box when stacking lines.

letterSpacing bills the trailing gap

Live: 'AB' with letterSpacing='10px' grows 20px — spacing is added after every glyph including the last. Centering math that assumes between-only will sit left by half a spacing unit per line.

maxWidth condenses, never clips

fillText(str, x, y, 60) on a 218px-wide string → exactly 60 columns of ink (live-measured). It's a horizontal squeeze (unspecified algorithm), not an ellipsis.

Also live: fontKerning support ('auto' default), textBaseline='alphabetic' default means descenders draw below y — the #1 “my text renders too low” bug. direction + textAlign='start'/'end' are logical, not physical.

§08 · The pixel wall — premultiplied storage, raw blit

getImageData un-premultiplies

The backbuffer stores premultiplied color; getImageData returns straight RGBA. Live: fill rgba(0,255,0,.5) → read [0,255,0,128] — green survives at 255 because un-premultiplication restores it. Cost: precision loss on extreme alphas (values round), so putImageData(getImageData()) is stable but not always byte-identical for every color engine-wide — verify round-trips for forensic pixels.

putImageData ignores the entire pipeline

Live: globalAlpha=0.1 + translate(20,20) + putImageData(red, 5,5) → the pixel lands at (5,5), full [255,0,0,255]. Raw blit: no transform, no alpha, no composite, no clip-affect — the two directions of the pixel wall are asymmetric by design.

Zero-size reads are zeros; out-of-bounds regions read as transparent black. For read-heavy pages pass {willReadFrequently:true} at getContext — §01. Pixel work at scale belongs on an OffscreenCanvas in a worker (see the transfer-tier demo).

§09 · Shadows & filters — the output-space layer

Shadow offsets skip the transform

Live under scale(2,2) with shadowOffsetX=10: the shadow band measures ~10 device pixels past the shape — the offset is applied in output space, not scaled by the CTM (spec-conformant, surprising). Shadows render for shapes, text and images alike (live: red shadow pixel behind a rect).

ctx.filter — CSS filters on raster

x.filter='blur(4px) grayscale(1)' applies to everything drawn while set; reset with 'none' (it's state — save/restore scoped). Invalid strings are ignored silently (§03). Safari 18 completed the engine set — safe to use behind a feature check on older support.

§10 · Buffer lifecycle — the invisible resets

Two ways to lose your pixels

Any assignment to canvas.width/height — even the same value — clears the bitmap and resets context state (live: transform back to identity, pixels zeroed). ctx.reset() (Baseline-adjacent: Ch 99 / FF 113 / SF 17.2) does the same deliberately: default state, empty stack, cleared bitmap — live-verified on all three axes.

Sizing truths

Default buffer is 300×150 (the replaced-element default — live-read), CSS stretches the bitmap (blur trap → set buffer = CSS × DPR, setTransform(dpr,0,0,dpr,0,0)); a true 0×0 canvas exports 'data:,' (live) — the empty-data URL, not a PNG.

// the DPR pattern (every HUD ships this)
c.width  = cssW * devicePixelRatio;
c.height = cssH * devicePixelRatio;
x.setTransform(dpr,0,0,dpr,0,0); // draw in CSS units

§11 · The export tier — toDataURL / toBlob

Encoder ladder, live-measured

Same 100×60 gradient+text frame: JPEG q0.05 = 1,155 data-URL chars · JPEG q0.95 = 2,687 · PNG = 3,790. PNG ignores the quality argument entirely. WebP: requested and received data:image/webp on Chromium — Safari historically falls back to PNG silently, so verify the returned MIME prefix, never assume the requested type.

Sync vs async & the taint wall

toDataURL() is synchronous (jank on big buffers — prefer async toBlob(cb, type, q) for downloads and uploads). Drawing an image without CORS approval taints the canvas: both export APIs then throw SecurityError — the anti-exfiltration wall. Cross-origin assets need crossOrigin='anonymous' plus a permissive server.

Worker-side export = OffscreenCanvas.convertToBlob() (see the OffscreenCanvas transfer-tier entry). A 0×0 canvas toDataURL() returns 'data:,' — check buffer size before exporting.

OpenDrones — layered telemetry HUD

One canvas, four layers, zero frameworks: conic radar sweep (§05), roundRect gauge panels (§04), additive glow via lighter (§06), DPR-exact buffer (§10). 30 Hz-ready — repaint only the dynamic layer.
