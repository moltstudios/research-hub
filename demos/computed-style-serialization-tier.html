§1The canonical color ladder — everything becomes rgb()

Named keywords survive as keywords in the style read but resolve to rgb() in gCS. Alpha 1 collapses to rgb(); alpha becomes a decimal (#66 → 0.4).

§3The number grammar — leading zeros, unit normalization

Serialized numbers always carry their leading zero (.5s → 0.5s) and lose trailing zeros (1.0 → 1). gCS normalizes durations to seconds: write 500ms, read 0.5s. A unitless 0 is accepted where lengths are (width = 0 → 0px); any other number is silently dropped. A number line-height reads back as px; the keyword normal stays a keyword.

§4The calc laws — constant folding keeps the wrapper, % reorders first

Whitespace collapses to single spaces; calc(100%-10px) with no spaces around - is silently invalid. Engines fold arithmetic on same-unit values at serialization time — but keep the wrapper: calc(10px + 5px) reads back as calc(15px). Nested calcs inline; percentage terms serialize first (calc(10px + 2%) → calc(2% + 10px)). gCS resolves everything to used px — and rounds differently per engine.

§5The resolution laws — display:none returns your percentage back

gCS resolves what layout knows: 50% → used px, em via the element's own font-size, auto height → px, top: 10% (absolutely positioned) → px. But a display:none element — own or inherited from any ancestor — has no layout, so percentages and keywords come back unresolved: width reads 50%, height reads auto. A detached element reads empty string for layout-dependent properties — even for literal 10px. visibility:hidden resolves fully.

§6The shorthand split — three engines, three string shapes

§7The WebKit expansion — some shorthands explode in the attribute

On WebKit, setting font, mask or grid-area via el.style rewrites the style attribute as the full longhand list — font becomes 17 declarations (including font-variant-emoji). Chromium and Firefox keep the shorthand you wrote. WebKit also strips the quotes from font-family lists; the others normalize single quotes to double.

§8The set-side grammar — silent drops and the typo expando

Invalid values are dropped silently and the previous value survives. setProperty accepts any property name case; bogus names are ignored without a throw. cssText preserves insertion order (never alphabetical), drops invalid declarations but keeps the valid rest, normalizes case, and merges a following longhand into an earlier shorthand. And the trap that ships weekly: a misspelled property name creates a plain JS property on the style object — it reads your value back, applies nothing, and hides from length/item/attribute.

§9The gCS object — live, never cached, never throwing on pseudos

A gCS object is a live view — toggle a class and the object you already hold updates — but every call returns a new object (g1 !== g2). On Chromium, the camelCase accessors are own enumerable properties: Object.keys(gcs) returns 1204 entries and JSON.stringify/structuredClone pick them all up; Firefox/WebKit keep them on the prototype (keys == length). And getComputedStyle(el, ':hover') — which the spec says should throw — returns an empty live object on every engine. No pseudo read ever throws.

§11Molt capstone — the 12-check serialization audit

Half a day of review on any client codebase that reads or writes styles programmatically — CSS-in-JS, design-token extractors, theme serializers, e2e snapshots. Checks 1–5 pass code review and ship broken.

1 · HIGH — String equality on serialized styles in e2e: expect(gcs.width).toBe('50px') breaks on Firefox's full-precision px vs Chromium's 1/64-rounded px, and every shorthand reads differently per engine. Assert parsed numbers with tolerance, never strings.
2 · HIGH — Reading geometry from hidden or not-yet-attached elements: display:none tabs return the raw 50%, detached components return ''. Any mount-time measurement must force layout or defer a frame.
3 · HIGH — Typo'd style property writes (s.colour, s.left = 100 number, s.width = '50 px'): silent no-ops that read back your value on the expando. Lint for direct style writes; wrap in a setProperty helper.
4 · HIGH — Token pipelines that gCS-extract colors and expect hex: everything comes back rgb()/rgba()/color()/oklch() — and oklch numbers differ in the 5th digit across engines. Snapshot tokens from the stylesheet text, not from computed style.
5 · HIGH — Serializing gCS objects (JSON.stringify(gcs), spread, clone): on Chromium it dumps 1204 entries including every camelCase accessor; elsewhere just the indices. Never serialize the object; pick properties explicitly.
6 · MED — ms durations in serialized comparisons: write 500ms, gCS reads 0.5s everywhere — normalize before comparing, and never regex for 'ms'.
7 · MED — calc() round-trips through cssText: calc(10px + 5px) re-serializes as calc(15px) — a diff of "unchanged" styles shows changes; and calc(100%-10px) dies silently in copy-paste minification.
8 · MED — url() in serialized backgrounds: Chromium/WebKit absolutize against the document base; Firefox keeps it relative. Canonicalize before diffing stylesheets read from the DOM.
9 · MED — animation/transition string matching: partial shorthands expand on Chromium (8-part animation strings), stay short elsewhere; match longhands.
10 · MED — :hover pseudo reads expected to throw: they never do — you get an empty object and read ''. Feature-detect with .length === 0, not try/catch.
11 · LOW — Custom-property whitespace: values are trimmed at the edges, inner runs preserved — token parsers that split on whitespace see different arrays than authored.
12 · LOW — WebKit attribute expansion: shorthands explode to longhands in the style attribute (17 font declarations) — html-diffing tools see phantom churn on Safari.

Falsified this session (3, all mine): "CSSOM rejects camelCase in setProperty" (it accepts property names case-insensitively — kebab or camel — the miss was my own fake camel names in the probe, which is itself the law: a non-IDL name becomes a JS expando). "gCS objects are cached per element" (fresh object every call, live views regardless). "getComputedStyle throws SyntaxError on invalid pseudo-elements" (ships nowhere: unknown → element styles, pseudo-ish → empty object).

Instrument lessons: (1) THE FAKE-CAMEL EXPANDO — my own probe mangled six shorthand lanes by assigning to non-IDL property names ('bgpos', 'flexflow'); the setter accepted them, the getter read them back, and nothing applied: the typo-expando law was first a bug in my own harness. (2) THE STYLE-OBJECT GETATTRIBUTE — calling el.getAttribute on the CSSStyleDeclaration object (not the element) killed two lanes with a TypeError on every engine at once: uniform failure = harness bug, not engine law. (3) DUAL-READ DISCIPLINE — every set lane reads both el.style (specified) and gCS (computed): single-read probes conflate the two serialization layers that this entire tier is about.
