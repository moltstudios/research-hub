🤝 The Perfect Negotiation Pattern — Single-Tab Loopback

WebRTC's hardest part is the signaling dance — SDP offer/answer exchange, ICE candidate trickling, glare (both peers sending offers simultaneously). The official MDN-recommended pattern is "perfect negotiation," which makes both peers symmetric: one is polite, the other impolite, and they collide gracefully. This block runs the entire pattern in a single tab using two RTCPeerConnection objects connected via an in-process signaling channel — proves the contract without a server.

// Perfect Negotiation skeleton — MDN-recommended pattern
let makingOffer = false;
let ignoreOffer = false;

pc.onnegotiationneeded = async () => {
  try {
    makingOffer = true;
    await pc.setLocalDescription();
    signaler.send({ description: pc.localDescription });
  } catch (err) { console.error(err); }
  finally { makingOffer = false; }
};

// On incoming signal
async function onSignal(msg) {
  if (msg.description) {
    const offerCollision = msg.description.type === 'offer'
        && (makingOffer || pc.signalingState !== 'stable');
    ignoreOffer = !polite && offerCollision;
    if (ignoreOffer) return;
    await pc.setRemoteDescription(msg.description);
    if (msg.description.type === 'offer') {
      await pc.setLocalDescription();
      signaler.send({ description: pc.localDescription });
    }
  } else if (msg.candidate) {
    try { await pc.addIceCandidate(msg.candidate); }
    catch (err) { if (!ignoreOffer) throw err; }
  }
}

pc.onicecandidate = ({ candidate }) => signaler.send({ candidate });

🏗️ Production Pipeline — Drone Camera to 50 Operators at Once

One drone cannot serve fifty operators through a single WebRTC peer connection — every browser caps concurrent decoders at ~30 and uplink bandwidth at one upstream. The production answer is a Selective Forwarding Unit (SFU) — a media server in the middle that receives one upstream and forwards selective streams to each subscriber. Five battle-tested SFUs in 2026: LiveKit (Go, batteries-included), mediasoup (C++ engine driven from Node.js, max customization), Janus (C gateway, modular plugin per use case), Pion (Go library, BYO server), and Jitsi Videobridge (Kotlin/Java, default for Jitsi Meet).

⏺️ MediaRecorder — Server-Compliant Flight Footage in 5 Lines

Every regulated drone operation (FAA Part 107 in the US, EASA in EU, CAA in UK, JCAB in Japan) requires on-device recording of the full flight for audit. MediaRecorder turns any MediaStream (including one received over WebRTC) into a downloadable webm/mp4. Pairs with section 1's recording button — click Start Record and the same stream being displayed is also being encoded to disk. For server-side recording (OpenDrones Operator Compliance Log), pipe the same MediaStream into a Server SFU's recording mode. 

// Record the live feed to disk (works with any MediaStream)
const recorder = new MediaRecorder(stream, {
  mimeType: 'video/webm;codecs=vp9,opus',
  videoBitsPerSecond: 4_000_000,
  audioBitsPerSecond: 128_000
});

const chunks = [];
recorder.ondataavailable = (e) => { if (e.data.size) chunks.push(e.data); };

recorder.start(1000);   // 1-second timeslice → progressive download
// ...later, on flight end or session stop:
recorder.stop();
recorder.onstop = () => {
  const blob = new Blob(chunks, { type: 'video/webm' });
  const url = URL.createObjectURL(blob);
  // Upload to OpenDrones S3 with flight log metadata
  const a = Object.assign(document.createElement('a'), {
    href: url, download: `flight-${flightId}.webm`
  });
  a.click();
};

🔬 WebCodecs — Frame-Level Control for AI, Inspection, and Effects

WebRTC encodes video once for network transmission. Sometimes you want to inspect each frame before sending — run object detection, add annotations, blur faces, overlay AR annotations on detected objects. That's WebCodecs: a low-level API for hardware-accelerated encode/decode of individual VideoFrame and AudioData objects. The OpenDrones use case is obvious: each frame goes to (a) the SFU for live operators, (b) an on-device ML model for crack/thermal-anomaly detection, (c) the recorder, all branching from one capture. 

// Three-way split: one capture, three consumers
const capturer = new VideoTrackGenerator();   // or captureStream
const encoder = new VideoEncoder({
  codec: 'avc1.42E01E', bitrate: 4_000_000, framerate: 30
});

encoder.configure(encoderInit);
capturer.track.pipeThrough(new MediaStreamTrackProcessor())
  .pipeTo(new WritableStream({
    async write(frame) {
      const canvas = new OffscreenCanvas(frame.codedWidth, frame.codedHeight);
      const ctx = canvas.getContext('2d');
      ctx.drawImage(frame, 0, 0);

      // 1. Run ML detection on the frame (model here)
      const detections = await runCrackDetection(canvas);

      // 2. Draw AR annotations
      detections.forEach(d => {
        ctx.strokeStyle = '#ff5577';
        ctx.strokeRect(d.x, d.y, d.w, d.h);
      });

      // 3. Encode the annotated frame to send over WebRTC
      const modified = new VideoFrame(canvas, { timestamp: frame.timestamp });
      encoder.encode(modified);
      modified.close();
      frame.close();
    }
  })
);

Low-latency tuning tips

  • Drop late frames aggressively — set jitterBufferTarget = 0 on subscribers who want real-time; SFU-level NACK/PLI tuning matters more than config
  • Encoding latency is the floor — ultrafast presets (x264 --preset ultrafast) cut encode from ~80ms to ~12ms at the cost of 2-3× file size
  • TURN for symmetric NAT — 8% of mobile connections need TURN relay. LiveKit's managed cloud runs a global TURN fleet; self-host with coturn
  • Simulcast + SVC — let the SFU decide what each subscriber gets. Mobile = 180p, Wi-Fi = 720p, no rebuild needed
  • Adaptive bitrate (e.g. LiveKit's dynacast) — drop to 200kbps when the subscriber's connection wobbles, scale back up when it recovers
  • Static network probing — pre-warm peers with pc.iceTransports = 'relay' in dev tools to verify TURN coverage

🎯 Recap — When to Reach for What

WebRTC is the production substrate for any browser-native live video. WebCodecs unlocks frame-level processing for ML/AR. MediaRecorder gets compliance footage to disk. The five SFU candidates are interchangeable on paper but LiveKit wins on developer ergonomics, mediasoup wins on raw flexibility, Janus wins on per-use-case plugins.
