URL + URLSearchParams — the address tier

The parser behind every fetch, redirect, link and share your app will ever make. One constructor family (new URL / URL.parse / URL.canParse) normalizes input according to the WHATWG spec — and that normalizer is a security surface: it strips tabs from schemes, folds backslashes into slashes, rewrites 0x7f.1 into 127.0.0.1. This page measures every contract live, including the family that quietly corrupts marketing analytics: the + law.

01Engine introspection — the smallest surface in the catalog

Live census on the page you are reading. URL is 4 statics + 13 prototype members; URLSearchParams is 12 members + size. No events, no observers, no promises — the whole tier is synchronous, which is exactly why it can run anywhere: main thread, workers, and even inside other APIs' option parsing.

The everywhere-tier. Not secure-context-gated, no permissions, no Permissions-Policy — ships identically in dedicated workers (typeof URL === 'function' measured below in §01b) and in cross-origin iframes. The only tier in the catalog with zero gating surface, because a URL parser leaks nothing about the user.

02The three doors — new URL vs URL.parse vs URL.canParse

Three ways in, two failure shapes. The constructor throws TypeError; the two statics (Chrome 126+, Baseline 2024) return null / false instead — built exactly for hot paths and && chains. And the base-URL argument has a footgun of its own: not every absolute URL can be a base.

The about:blank base trap. new URL('x', 'about:blank') throws — and so does data:. Opaque-path URLs (about:, data:, mailto:) cannot serve as a base. This bites inside sandboxed iframes and srcdoc frames whose document URL is about:blank — resolving a relative link there needs a real base passed explicitly, or it dies.

03The href normalizer — what you put in is not what comes out

The parser doesn't store your string; it re-serializes a parsed structure. Along the way it strips tab/newline/CR from anywhere (including inside the scheme), trims C0 controls and spaces, folds \ into / — but only for special schemes — and clamps dot-segments at the root. This is the same machinery that makes hand-rolled URL regexes a security incident.

inputnormalized hreflaw
The parser-differential family. A server-side regex sees https://x.com\a\..\..\admin; the browser sees https://x.com/admin. Tab-stripping means java\tscript:-shaped strings normalize differently per layer. If you validate URLs anywhere, validate them post-parse — the same normalizer that will fetch them.

04Host & port — parse throws, setters silently no-op

The asymmetric validation law. At parse time a bad port (:abc, :0x50) fails the whole URL; at set time the same junk is silently ignored and the href keeps its old port. Same for protocol: changing a special scheme to a non-special one is a silent no-op, while the reverse direction works.

input hostparsed hostrule
The IPv4 shorthand rewrite. Anything IPv4-shaped gets normalized to dotted-quad: 0x7f.1 → 127.0.0.1, 2130706433 → 127.0.0.1, http://1/ → 0.0.0.1 — but an out-of-range part (999.1.1.1) is a hard parse failure. Host allowlists that string-compare raw input are comparing the wrong string.

05Punycode — convert everything, validate nothing

Every non-ASCII host is IDNA-processed to punycode on the way in — emoji included, Cyrillic homoglyphs included — and the readback never re-unicodes. But the reverse is unguarded: xn-- labels are accepted without checking that they decode.

inputparsed hostnamerule
The homoglyph survives the parser. https://аpple.com (Cyrillic а) parses to xn--pple-43d.com — legal, distinct, done. Confusable blocking is a display policy in the address bar, not a parse rule: your fetch-layer allowlist must compare punycode, and if you mirror user-typed hosts into links, punycode is what you store.

06Origin & scheme census — six schemes, four origin rules

Special schemes (http, https, ws, wss, ftp, file) get default-port elision and host parsing; everything else is opaque — host '', origin 'null'. Except two engine truths: file: origins read back as the string file://, and blob: URLs borrow the origin of the URL they wrap.

schemeprotocolhostorigin
Credentials survive, encoded in place. https://user:pa@ss@x.com/ → password pa%40ss — the serializer rewrites the @ so the href round-trips. But credentials in URLs are a phishing surface and are stripped by fetch on cross-origin redirects; never build URLs with embedded passwords.

07The five percent-encode sets — there is no one encoder

Every URL component has its own escape set. Below, the same spicy string   !*'();:@&=+$,/?#[]"<>\^`{|}~% is written through seven serializers. Note where +, &, #, % come out raw — that's the entire bug family.

serializeroutput (spicy string in, serialized out)
encodeURIComponent leaves !*'() raw. It follows RFC 2396-ish unreserved marks, so those four survive unescaped — fine for query values, wrong if you then re-parse with something stricter. URLSearchParams escapes them (%21*%27%28%29 — * is unreserved in the form set), and the raw search setter escapes almost nothing. Match the serializer to the component or your round-trip breaks.

08The + law — read as space, written as %2B, corrupted only by hand

The single highest-frequency URL bug in marketing stacks. The engine's own round-trip is safe both ways: + decodes to space on read, and a literal + is escaped to %2B on write. Corruption enters exactly two ways — hand-built query strings and pre-encoded values.

The two corruption lanes, measured. Hand-built: ?name=loreal+spa typed into a template literal reads back “loreal spa” — the + was never yours to use. Pre-encoded: set('x', encodeURIComponent('a&b')) serializes as a%2526b and a server's single decode layer yields a%26b, not a&b. Both lanes are live in the UTM lab (§11).

09The URLSearchParams engine — ten methods, five footguns

Iteration order is insertion order (not sorted), sort() sorts in place by key and returns undefined — not chainable — and the constructor has four overloads that coerce aggressively: 123 becomes the key 123=, null becomes null=, undefined means "empty", and a Symbol throws.

10The sync laws — one live searchParams, detached copies, phantom ?

u.searchParams is a live singleton (same object every read) whose writes re-serialize the entire href — query re-inserted before the hash. new URLSearchParams(u.search) is a snapshot that writes nowhere. And the phantom-? has a lifecycle of its own: the constructor preserves a bare ? in href, but any params write regenerates the href without it.

setter callresulting href / componentlaw
search never re-delimits. Assigning u.search = 'a=b#f' does not create a hash — the # is percent-encoded to %23 and stays inside the query. Delimiter characters are structural only at parse time; setters always encode their way out of ambiguity.

12OpenDrones capstone — the mission deep-link

A cockpit state (vehicle, lat/lng, zoom, battery, mission time) encoded into a shareable URL and round-tripped with an FNV-1a checksum — the parse-back must be byte-identical. Plus the telemetry-host warning: IPv4 shorthand hosts normalize, so http://2130706433/ is a real URL that will fetch 127.0.0.1.

Deep-link rule. Always build state URLs with searchParams.set and parse with searchParams.get — the same serializer on both ends. Checksum the state before you trust the parse; a user-mangled URL should fail closed, not fly a ghost waypoint.

14The ten-rule ship checklist

1Parse before you trust: every external URL string goes through URL.parse/new URL — validation happens post-parse, on components.
2Use canParse/parse statics in hot paths; reserve new URL try/catch for edges you want to surface.
3Never hand-build query strings — searchParams.set both directions, one serializer, zero surprises.
4Never pass encodeURIComponent output into searchParams.set — that's the double-encode lane.
5Compare hosts via .hostname (punycode), never the raw input — 0x7f.1 and 日本.jp both rewrite.
6Remember setters are forgiving: bad ports, empty and non-special protocols are silent no-ops. Re-read the href after writing.
7u.searchParams is live; new URLSearchParams(u.search) is a snapshot — pick deliberately.
8Opaque URLs (about:, data:, mailto:) can't be bases and carry origin === 'null' — branch before resolving or comparing.
9URLSearchParams sort() returns undefined; delete(name) removes all values; set replaces all — read §09 once per quarter.
10The normalizer is a security surface: tabs stripped, backslashes folded, IPv4 rewritten. Any URL filter that runs on raw strings is a differential waiting to be found.
