Instant Page Loads via
Speculation Rules  — Prefetch + Prerender

Tell the browser which pages a user is likely to visit next — and it will fetch (and even render) them in the background. Hover a link, the next page is already warm. Click, and it activates instantly. Native, declarative, zero JS.

The OpenDrones store can prerender the Arc battery detail when the pre-order card is hovered for 200 ms. The Molt Studios portfolio can prefetch every case-study link the moment a user reaches the index page.

02 The 5-Line JSON Recipe

The entire API is a JSON object inside a <script type="speculationrules"> tag. Two top-level keys: prefetch (download) and prerender (download + render in invisible tab). Each key holds an array of rules with where or urls and an eagerness. 

<script type="speculationrules">
{
  "prefetch":  [{ "urls": ["/store","/about"], "eagerness": "immediate" }],
  "prerender": [{ "where": { "href_matches": "/*" }, "eagerness": "moderate" }]
}
</script>
Why this beats <link rel="prefetch">: speculation rules prefetch is navigation-aware (only fetches whole documents the user is likely to navigate to), automatically downgrades priority under memory pressure, respects Battery Saver / Data Saver modes, ignores pages with Cache-Control: no-store, and stores results in a per-document in-memory cache for activation. Use it for navigations; keep <link rel="preload"> for subresources.
CSP users: if your script-src directive is locked down, add "inline-speculation-rules" as a source — or hash/nonce the JSON. The browser will refuse to parse the script without one of these.

03 Eagerness Levels — When Does the Browser Fire?

Four levels control how aggressively the browser speculates. The same where matcher can be lifted from "only on click" to "right now" with a single string.

most aggressive

immediate

The moment the rule is parsed. Best for static urls lists of truly critical pages — your pricing page, your Arc battery detail, your pre-order confirmation.

page load
Cost: full prerender from row 1. Use sparingly.

hover
+200ms

pointerdown

Chrome FIFO limits: the eager/moderate/conservative pool allows only 2 simultaneous prerenders and 2 simultaneous prefetches. immediate gets a larger pool (50 prefetch / 10 prerender) but burns bandwidth proportional to your rule size. Track in DevTools → Application → Speculation Rules → Speculative Loads.

8B DevTools Diagnostics — What You Can See

Speculation Rules is fully observable. Chrome ships a dedicated DevTools panel that surfaces every active prefetch, every prerender, the trigger that fired it, and the lifetime budget remaining.

Application → Speculation Rules

Live list of all active speculation rules with: where matcher, eagerness, limit, current status (Pending / Ready / Activated / Discarded), lifetime remaining (prerenders are auto-discarded after 30 s in Chrome).

Filter by status to find warm-but-not-activated prefetches — useful for diagnosing "I expected this to be fast" UX regressions.

Network → Speculative loads

Filter the Network panel by request-initiator-type: speculation. Every prefetch and prerender shows up with a Teal row in the waterfall — distinct from the regular document fetch.

Sort by Start Time and you'll see the user-visible click triggered after the spec had already fetched / rendered the response — the activation is "free" because the cache is hot.

Performance Insights: the modern Performance Insights panel (Chrome 132+, replaces the legacy "Performance" panel) shows prerender activations as zero-time paint blocks in the waterfall when the spec fires correctly. A blank "This activation cost 1.8 s" hint means your prerender wasn't ready when the click happened — either eagerness too conservative, or the target page has heavier-than-expected subresources.

HTTP response hints you can set

# Server-side: tell intermediaries the response is prerender-friendly
Cache-Control: public, max-age=300
Supports-Loading-Mode: fenced-frame, prerender     # opt-in for cross-site prerender (Chrome 121+)

# Disallow speculation on sensitive paths
Cache-Control: private, no-store
Supports-Loading-Mode: none

05 OpenDrones: Hover-Prerendered Product & Mission Pages

Two production patterns where Speculation Rules turn the marketing site from "fast enough" to "instant". The Hover-Prerender pattern pairs cleanly with the existing Cross-Document View Transitions research (P2) — the next page paints already-rendered and morphs in.

🏷️ Pre-order hover prerender

  • Hover any product card on /store for 200 ms → the matching /products/<slug> detail page is fully rendered in a hidden tab.
  • Click the card → activation is essentially zero-cost; the user sees no loading state at all.
  • Add .no-prerender to "Add to Cart" and "Subscribe to Back-in-Stock" buttons — those trigger analytics events and must not be prerendered.
  • Pair with Web Share Target for "share this Arc" — the share intent doesn't change the prerendered state.

🚁 Mission Control: prerender the next likely flight detail

  • Hover a mission card on the dashboard for 200 ms → the detail page with WebGPU 3D airspace view + telemetry timeline prerenders.
  • Drop into eagerness: "moderate" for prefetch of all telemetry exports (CSV, GPX) on the same card — keeps memory under the FIFO cap.
  • Pair with Compression Streams API (P2) to prebuild a compressed mission JSON before activation — bandwidth-free on click.
  • CSP: add "inline-speculation-rules" to script-src in the OpenDrones middleware.ts.
// OpenDrones: Mission Control — speculative loader for next flights
<script type="speculationrules">
{
  "prefetch": [
    { "where": { "selector_matches": ".mission-card" }, "eagerness": "immediate" }
  ],
  "prerender": [
    { "where": { "and": [
        { "selector_matches": ".mission-card__detail-link" },
        { "not": { "selector_matches": ".no-prerender" } }
    ]}, "eagerness": "moderate" }
  ]
}
</script>

06 Molt Studios: Prerendered Case-Study Navigation

Every client portfolio site we ship could immediately feel 2 × faster on in-site navigation. The pattern below is a 6-line drop-in for the agency template.

📁 Portfolio index → case study

  • The portfolio index page is the highest-traffic page on every client site. Visitors land, see 8–24 cards, click 1–2.
  • Add eagerness: "moderate" prerender to all in-site links → the case-study hero, project gallery, and testimonials all paint instantly on click.
  • Skip the rule on any link to /contact (form-side-effects) and external links automatically (cross-site requires the user's consent).

🛒 E-commerce checkout funnel

  • Prerender the next cart page the user is most likely to navigate to (Cart → Details → Shipping → Pay) on hover of the current "Continue" button.
  • Pair with eagerness: "conservative" on the final Checkout → Confirmation step (irreversible side-effects).
  • Add where: { not: { selector_matches: ".remove, .qty-input" } } so quantity changes don't trigger prerenders of the cart itself.
// Molt: agency-wide rules — append to the layout's <head>
<script type="speculationrules">
{
  "prerender": [
    { "where": { "and": [
        { "href_matches": "/case-studies/*" },
        { "not": { "selector_matches": ".no-prerender, [data-form]" } }
    ]}, "eagerness": "moderate" },
    { "where": { "selector_matches": "a.continue-cta" }, "eagerness": "conservative" }
  ],
  "prefetch": [
    { "where": { "selector_matches": "a[href^='/blog/']" }, "eagerness": "eager" }
  ]
}
</script>

07 Framework Integration Patterns

Six idiomatic wiring patterns — pick the one that matches your stack.

Next.js (App Router)

// app/layout.tsx — global rules
<Script type="speculationrules" id="rules" strategy="afterInteractive">{JSON.stringify(rules)}</Script>

// Or via middleware (no HTML changes)
response.headers.set("Speculation-Rules", "/api/speculation-rules");

Astro / SvelteKit (static-friendly)

<!-- src/layouts/Base.astro -->
<script type="speculationrules" set:html={JSON.stringify(rules)}></script>

{/* Or via the Speculation-Rules HTTP header from your edge — no HTML edits */}

Vite / static HTML

<!-- index.html, served as-is -->
<script type="speculationrules">
{
  "prefetch": [{ "urls":["/about"], "eagerness":"immediate" }],
  "prerender": [{ "where": {"href_matches":"/*"}, "eagerness":"moderate" }]
}
</script>

HTTP header (CDN-friendly)

# nginx — set the response header on every page
add_header Speculation-Rules '/rules.json';
add_header Content-Type    application/speculationrules+json;

# /rules.json served with the right MIME
{ "prerender": [{ "where":{"href_matches":"/*"}, "eagerness":"moderate" }] }
Combine <script> + Speculation-Rules header: both sources are parsed and added to the same rules list. The CDN path is the cleanest way for legacy sites — the rules update without touching any HTML.

08 When NOT to Speculate — The Safety List

The browser refuses to prerender pages that change visible state on load (it auto-declares them unsafe). For everything else, it's up to you. The four categories below are the canonical "do not prerender or prefetch" set.

Side-effect pages

Any URL that writes on load — analytics events, CSRF tokens minted, email confirmation pages, "you've been here" timers. These will fire twice if the user reactivates the prerender accidentally.

Mark: .no-prerender on the wrapping <a> or { "not": {"href_matches":"/confirm-email"} }.

Authentication pages

/login, /logout, /auth/callback, SSO redirects, password reset confirmations. A prerendered login page that silently triggers a token-refresh will log the user out of the wrong session.

Rule: always exclude /logout and /auth/* via href_matches exclude clauses.

State-changing actions

POST endpoints exposed via <a> links (rare but real in legacy apps), file delete URLs, "remove from cart" actions, any link that fires an analytics-beacon on click.

Pattern: only prerender GET-only routes. Make sure your framework enforces this.

Heavy-resource pages

200 MB LiDAR scan, a 4K hero video, a full WebGPU mission replay. Prerender burns ~the same resources as an iframe — fine for 5 MB, punishing for 200 MB.

Strategy: use prefetch for the HTML, let <link rel="preload"> handle the heavy subresources on the actual page after activation.

Cross-site privacy: cross-site prefetch requires that the destination has no cookies set for the user — preventing third-party tracking via speculative loads. Same-origin sites are unaffected. As of July 2026 there is no opt-in for cross-site cookies via the Supports-Loading-Mode header (planned, not shipped).

10 Recap & Why P2

Speculation Rules is the production answer for "instant navigation" — the missing primitive that complements View Transitions (P2), Cross-Document View Transitions (P2), Compression Streams (P2), OPFS (P2), WebTransport (P2), and Document Picture-in-Picture (P3) as the navigation/perf leg of the modern web platform stack.

OpenDrones applications

  • Pre-order hover prerender (Arc battery detail on store card hover)
  • Mission Control next-detail prerender (3D airspace + telemetry warm)
  • Hover-prefetch of telemetry export endpoints (CSV, GPX, KML)
  • Lazy prerender of pilot dashboards on first login
  • Speculative prebuild of compression-streamed mission JSONs (Pairs with Compression Streams API, P2)

Molt Studios applications

  • Portfolio index prerender of every case-study link (universal)
  • E-commerce hover-prefetch of next cart step
  • Blog reader: eager-prefetch of "next post" link in footer
  • Client intake form hover-prefetch of FAQ page
  • Documentation site: prerender of /docs/<next-section> on sidebar hover
  • Pitch differentiator: "instant nav" as a 1-day add-on to any build ($1.5k-3k shippable)

Why P2 (not P1)

Universal value but the existing P1 entries (Highlight API, Subgrid, Web Push, @property) have a more direct path into every client project on day 1.

Why not P3+

~95% global support, no JS bundle cost, and clean adoption. Anything below P2 would undervalue the production win for both OpenDrones marketing pages and Molt client portfolios.

Pairs with

Cross-Document View Transitions (P2), Compression Streams (P2), OPFS (P2), WebTransport (P2), Document PiP (P3), Highlighter API (P1), @scope (P2), CSS-only scaffolding & View Transitions L2 (P4).

Migration story from <link rel="prefetch">: the spec author (Chrome) explicitly recommends replacing <link>-based prefetch with speculation rules for navigations. The bigger payoff is the prerender half — which <link> could never do — turning the browser into a true pre-renderer instead of a pre-fetcher.
