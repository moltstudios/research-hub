📝 Implementation Patterns

Pattern 1 Document Rules 

<script type="speculationrules">
{
  "prerender": [{
    "where": {
      "and": [
        { "href_matches": "/*" },
        { "not": { "href_matches": "/logout" }},
        { "not": { "selector_matches": ".no-prerender" }}
      ]
    },
    "eagerness": "moderate"
  }]
}
</script>

Prerender all links except logout and those with no-prerender class on 200ms hover.

Pattern 2 Static URL List 

<script type="speculationrules">
{
  "prefetch": [{
    "urls": ["/checkout", "/about", "/contact"]
  }],
  "prerender": [{
    "urls": ["/products/arc-battery-pack"],
    "eagerness": "immediate"
  }]
}
</script>

Prefetch key pages. Prerender hero product immediately on page load.

Pattern 3 HTTP Header 

Speculation-Rules: /speculationrules.json

Serve rules via header. Rules file must have Content-Type: application/speculationrules+json

{
  "prerender": [{
    "where": {
      "selector_matches": "nav a"
    },
    "eagerness": "conservative"
  }]
}

Perfect for CDN deployment without modifying HTML.

Pattern 4 Dynamic Injection 

function prerenderOnCart() {
  const rule = document.createElement('script');
  rule.type = 'speculationrules';
  rule.textContent = JSON.stringify({
    prerender: [{
      urls: ['/checkout']
    }]
  });
  document.head.appendChild(rule);
}

Inject rules based on user actions (e.g., add to cart → prerender checkout).

⚡ Eagerness Levels

immediate

As Soon As Possible

Speculates as soon as the rules are observed. Best for static URL lists of critical pages.

Use case: Hero product page, critical conversion pages
eager

Viewport Entry

Speculates 50ms after link enters viewport. Good for static pages.

Use case: Blog post links, related articles
moderate

Hover (200ms)

Speculates after 200ms hover or on pointerdown if sooner. Balanced approach.

Use case: Most navigation links, product cards
conservative

Pointer/Touch Down

Speculates only on actual click/touch start. Safest for resource-intensive pages.

Use case: Checkout, admin pages, heavy dashboards

🚦 Chrome Limits

Eagerness Prefetch Limit Prerender Limit Behavior
immediate 50 10 Hard limit, FIFO eviction
eager/moderate/conservative 2 (FIFO) 2 (FIFO) Oldest replaced when limit reached

FIFO = First In, First Out. When limits are reached, the oldest speculation is canceled and replaced by the new one.

⚠️ When NOT to Speculate

Side Effects

Pages that trigger actions on load (analytics events, API calls, email sends) should not be prerendered.

Authentication

Login/logout pages, admin panels. Prerendering could expose sensitive data or cause security issues.

State-Changing Actions

"Add to cart", "Purchase", "Delete". These should NEVER be prerendered or prefetched.

Heavy Resources

Pages with large videos, 3D models, or heavy assets. Use prefetch instead of prerender.

⚛️ Next.js Integration

Add to app/layout.tsx

// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <head>
        <script
          type="speculationrules"
          dangerouslySetInnerHTML={{
            __html: JSON.stringify({
              prefetch: [{
                where: { href_matches: '/*' },
                eagerness: 'moderate'
              }]
            })
          }}
        />
      </head>
      <body>{children}</body>
    </html>
  );
}

Or Use Middleware for HTTP Header

// middleware.ts
export function middleware(request: NextRequest) {
  const response = NextResponse.next();
  response.headers.set('Speculation-Rules', '/speculationrules.json');
  return response;
}
