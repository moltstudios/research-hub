Every app formats numbers, money, durations, lists and "3 min ago" strings — and almost every team hand-rolls them with string surgery that break the moment a locale changes. §02 · NumberFormat anatomy — defaults, fallbacks, and the RangeError

The default formatter is not "print the number": it rounds to 3 fraction digits, groups thousands, and resolves options you never passed. And a bogus locale string never throws — it silently falls back to the runtime default locale, which means a typo like "en-USA" ships to production without a single console error:

Resolution + fallback probes

Digit options are validated eagerly at construction: minimumFractionDigits > maximumFractionDigits is a RangeError, not a silent clamp. When you need the pieces (icons between groups, animated counters), formatToParts() gives you typed atoms — integer, group, decimal, fraction — instead of regex-splitting the output string.

§03 · Units & compounds — the telemetry formatter

style: "unit" formats quantities with sanctioned unit identifiers: meter, kilometer, percent, degree, byte, and — the drone-telemetry superpower — compound chains joined with -per-: kilometer-per-hour. Three display widths: long ("kilometers per hour"), short ("km/h"), narrow ("km/h", collision-tolerant, designed for tight HUDs).

Validation asymmetry, probed: an invalid unit throws RangeError eagerly ("Invalid unit argument"), but an unknown currency code formats happily (§05). The unit list is closed; the currency list is open.

§05 · Currency — narrow symbols and the CAD trap

Four currencyDisplay modes: symbol, code, name, and narrowSymbol — the shortest local glyph. The trap: narrow symbols collide. In en-US, CAD's narrow symbol is the same "$" as USD — a Canadian dollar price renders identically to a US dollar price. For any currency that isn't the viewer's own, use symbol ("CA$"). EUR in en-US doesn't collide (€ is unambiguous) — the collision is per-currency, not systemic:

Currency battery

Probed truth: currency: "XYZ" (a syntactically valid but non-ISO code) formats as its own literal — "XYZ 5.00" — no throw, no warning. Currency codes are canonicalized to upper case in resolvedOptions() but never validated against the ISO registry.

§06 · DurationFormat — "1:46:40" without string surgery

The Baseline-2025 finisher. Takes a duration record ({hours, minutes, seconds, milliseconds, …}), four styles: long, short, narrow, digital (clock style). Its zero-handling is the part nobody guesses: zero-valued units are dropped everywhere — leading, trailing, and even between non-zero units ("1 hr, 5 sec" for 1h 0m 5s). An all-zero duration formats to the empty string — guard for it. Digital style keeps zero leading slots ("0:46:40") because clock layout demands them:

§07 · RelativeTimeFormat — "yesterday", not Date.now() - x math

Formats a quantity and unit relative to now: format(-1, "day"). With numeric: "auto" it uses natural words where the locale has them — "yesterday", "today", "tomorrow" — and it pluralizes for free. Fractions work. It is format-only: you compute the delta (usually Math.round((then - now) / 60000) minutes), it does grammar:

§08 · Segmenter — the word splitter you keep writing by hand

Intl.Segmenter splits text by grapheme, word, or sentence using locale rules. Three truths it encodes: (1) .split(" ") is whitespace-splitting, which returns the whole string as one word for Japanese, Chinese, Thai — languages without spaces; (2) grapheme mode treats a ZWJ emoji family (7 code points!) as one human character, where spread gives you 7; (3) word mode emits punctuation and whitespace as their own segments with isWordLike: false, so word counts are filter(s => s.isWordLike).length — not length:

§09 · DateTimeFormat — formatRange dedup & the hour-cycle ladder

formatRange(a, b) is not "format a + ' – ' + format b": the engine drops redundant fields. Same-day range → the date prints once, times only after the dash. Hour cycles are the classic silent bug: h12 midnight is "12:30 AM", h11 midnight is "0:30 AM" (0–11), h23 is "00:30". en-US resolves h12; forcing hour12: false resolves h23 — there is no h24 in the wild:

§10 · Collator — natural sort for humans

Default Array.sort() compares UTF-16 code units: "file10" < "file2". Humans expect file2 first. new Intl.Collator("en", {numeric: true}).compare is natural sort, and sensitivity: "base" folds accents for search ("café" matches "cafe"). Punctuation-aware, case-foldable (caseFirst), and dramatically faster than localeCompare in a loop because you build it once:

§11 · The grammar glue — ListFormat, PluralRules, DisplayNames, Locale

The constructors that replace string joins and hard-coded suffixes. ListFormat does "Alice, Bob, and Carol" (conjunction) / "or" (disjunction) — including the Oxford comma, per-locale. PluralRules is the engine's plural-category oracle: English cardinal has exactly two forms (one/other — and 0 is "other"); ordinal mode has four (1st→one, 2nd→two, 3rd→few, 4th→other) with the teen exception: 11th, 12th, 13th are all other, then 21st is one again. DisplayNames translates codes ("US" → "United States"). Locale parses/canonicalizes tags — fixing case, filling subtags via .maximize():
