§0 — Surface census (auto-probed)

The whole API is three constants (CONNECTING=0 OPEN=1 CLOSED=2), close(), readyState, url, withCredentials and three on* handlers. There is no lastEventId on the object — ids arrive per-event (e.lastEventId), which is the resume currency.

§1 — The wire grammar, live

The server streams 18 hostile frames — BOM, multi-line data:, no-space values, a NUL inside an id:, a lonely id with no data, CR-only terminators, a 1 MB message. Watch what the engine's parser actually does:

idle
Ghost events vanish. event: ghost with no data: field is never dispatched — not even an empty message. Data-less frames are dropped silently.
A NUL in an id kills the whole field. id: n␀ul is discarded — the previous id (42) survives and keeps riding every subsequent event.
Lonely ids commit at parse time. id: 9 with no data still sticks — Chromium commits ids when parsed, not when an event dispatches (the spec's clear-on-empty-dispatch step never observes it).
Every terminator is legal. LF, CRLF, and bare CR all end fields and frames. And there is no message-size cap — the 1 MB frame lands intact.

§2 — The reconnect engine, measured

The server drops the connection mid-stream (after 3 ticks). Each lane measures the real gap between last event and reconnect — the only clocks that matter are yours:

The default is ~3000 ms and nobody configures it. Measured on h1.1 local: 3004 ms / 3107 ms after the error event. A dropped dashboard silently goes dark for 3 s unless the server says retry:.
Malformed retry values fail silent. 12x, -5, and a 20-digit overflow all reconnect at the 3000 ms default — no console warning, no error event. Your typo becomes a latency bug.
Clean ends reconnect too. A graceful res.end() after events fires the same error event + reconnect as a hard socket kill. FIN is not a goodbye in SSE — only close() or a wall (§4) stops the loop.

§3 — Last-Event-ID: the resume protocol

On every reconnect the browser replays the last dispatched id as the Last-Event-ID request header — free durable resume, no client state. The server echoes it back on its first resume event:

idle
Ids ride per-event and persist. After id: 42, events without id fields still report lastEventId "42" — the server sets the cursor once and every later event inherits it.

§4 — Walls: where reconnect refuses

Folklore says "EventSource retries forever." It doesn't. Every bad response is terminal — error event, readyState 2, and the server is hit exactly once:

Content-Type is a hard gate. A 200 response with a perfectly valid SSE body in text/plain is refused — no event, no retry, CLOSED. Your proxy that rewrites MIME types just killed the feed.
No retry storms. 204/404/500 all close after one request (verified via server request counters). The auto-reconnect only covers lost connections, never bad responses — a dead endpoint goes quiet, not loud.

§5 — The six-socket wall (h1.1's dirty secret)

Browsers cap 6 HTTP/1.1 connections per host. An open EventSource holds one — forever. Open 7 streams and everything else queues:

6 sockets — all held by EventSources
ES#7 queued · fetch() queued — 4 s timeout: BLOCKED
after es1.close() → ES#7 takes the freed socket — the fetch stays BLOCKED
measured: fetch blocked >4 s with 7 ES open (h1.1) freed socket eaten by queued stream #7 — fetch still blocked h2 multiplexes — no per-host socket wall (this host serves h2)
The fix is boring: HTTP/2 (one TCP connection, many streams) — or fan-in through one stream with event: types as channels. Hitting a plain-h1.1 origin (internal tools, port-forwarded devices, some proxies) with many live feeds is the classic sudden-outage nobody expects.

§6 — The fetch-stream lane — & the Molt AI capstone

EventSource can't POST, exposes no response headers, and can't be aborted mid-reconnect. The modern lane for AI token streams is fetch() + a reader — same wire grammar, full request control. This widget streams the answer over POST (impossible with EventSource):

fetch never reconnects. After the stream ends the reader reports done and that's it — server counters stay at 1. Retry, backoff and Last-Event-ID replay become your code (the price of POST + headers + AbortSignal).
Headers exist here. content-type, rate-limit hints, trace ids — all readable on the Response. EventSource exposes exactly nothing from the wire.
