CSS :state() & :active-view-transition

Two pseudo-classes that close the gap between component logic and CSS. :state() lets custom elements expose internal state as a pure-CSS selector (no attribute reflection, no DOM pollution). :active-view-transition matches the document root only while a view transition snapshot is being morphed — perfect for the transition-phase affordances no other selector can express.

01 The "reflect-to-attribute" hack

For a decade, the only way to style a custom element based on its internal state was to mirror that state into an HTML attribute and write a CSS selector against the attribute. That meant two sources of truth, attribute mutation overhead, and the user being able to break your UI by deleting the attribute in DevTools.

❌ Old way — attribute reflection
// JS
this.setAttribute('loading', '');
this.removeAttribute('loading');

// CSS
my-button[loading] {
  background: gray;
  cursor: progress;
}

Public attribute. User can removeAttribute('loading') and your UI lies. DOM panel is full of dummy attributes. Selector invalidates React reconciliation.

✅ New way — :state()
// JS — internal-only state
this._internals.states.add('loading');
this._internals.states.delete('loading');

// CSS
my-button:state(loading) {
  background: gray;
  cursor: progress;
}

Private to the element. Not visible in DevTools as an attribute. Optimized for the CSS engine. Set operations are O(1).

05 The 4-step recipe for :state()

Adding custom states to a web component takes four lines of JavaScript and zero CSS framework.

// 1. Define a custom element
class MyWidget extends HTMLElement {
  constructor() {
    super();
    // 2. Attach internals (gives access to .states)
    this._internals = this.attachInternals();
  }

  set loading(value) {
    // 3. Add/remove the state — O(1) on a CustomStateSet
    if (value) this._internals.states.add('loading');
    else      this._internals.states.delete('loading');
  }
}
customElements.define('my-widget', MyWidget);

// 4. CSS — no attribute selector needed
my-widget:state(loading) { opacity: 0.5; cursor: progress; }

06 :active-view-transition — the transition-phase selector

The View Transitions API (P2 research) gave us document.startViewTransition() to morph between two DOM states. But until :active-view-transition shipped (Baseline 2025), there was no way to style the page while the snapshot was being animated. The selector matches :root from the moment a transition starts until the last pseudo-element animation finishes — typically 200–600ms.

Watch the indicator in the hero bar 👆 — it lights up while a transition is active.
/* Style the root ONLY while a view transition snapshot is being morphed */
:root:active-view-transition {
  --bg: #0c0a1a;
  --accent: #a29bfe;
}

:root:active-view-transition body::before {
  content: "";
  position: fixed; inset: 0;
  background: linear-gradient(135deg, rgba(162,155,254,0.06), transparent);
  animation: vt-shimmer 400ms ease-out;
}

/* JS — start the transition */
document.startViewTransition(() => updateAccent());

Why this matters: Without :active-view-transition, you have to wire transition-end listeners in JS to undo the cosmetic changes you made. With it, the CSS automatically snaps back the moment the morph finishes. Zero JS bookkeeping.

09 Decision matrix

✅ Use :state() when
  • · You're building web components (custom elements)
  • · State should be internal (not user-mutable from DevTools)
  • · You need ≥2 derived visual states (loading, success, error, etc.)
  • · You're building a state machine (wizard, stepper, multi-stage form)
  • · You want a single CSS rule-set for many component variants
❌ Stick with attributes when
  • · You're not using custom elements (use :checked, :disabled, :user-invalid etc.)
  • · The state needs to be queryable from the public DOM (URL state, persistence)
  • · You need full Safari < 17.4 or Firefox < 126 support
  • · You're styling a single, non-component element (an attribute is fine)
✅ Use :active-view-transition when
  • · You want cosmetic "transitioning" affordances (cursor, glow, gradient)
  • · You need to disable interaction during the morph
  • · You want a flash/highlight effect without wiring transitionend in JS
❌ Don't bother when
  • · You're not using startViewTransition() at all
  • · Your morph animation is <100ms (no perceivable "during" state)
  • · You can solve the same problem with a CSS transition on the morphed element itself

10 Recap

`:state(name)` · the modern replacement for attribute-reflection hacks. Internal-only state for custom elements, accessed via ElementInternals.states. Set operations are O(1); CSS selectors are engine-optimized; DOM is clean.

`:active-view-transition` · the selector that matches :root only while a view transition snapshot is being morphed. Eliminates transitionend bookkeeping for cosmetic "during" effects.

Together they form the state-based CSS primitive set for 2026 — alongside :has(), :user-invalid, :user-valid, :checked, and the Custom Highlight API. The CSS engine is finally the state-machine for components, not just a static style sheet.
