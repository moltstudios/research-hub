4 · The abort-reason echo

The strangest measured law on this tier.

ScenarioRejection value
signal pre-abortedAbortError: "signal is aborted without reason"
abort mid-flight, barean object with no name, no message — undefined: undefined
abort('REASON-X') mid-flightthe raw string "REASON-X" — a String, not an Error
abort YOUR signal while ANOTHER otp get pendsthe other get dies too — AbortError: "OTP retrieval was cancelled" — abort has frame-wide blast radius

Unlike fetch (which always materializes a DOMException), WebOTP mid-flight abort propagates signal.reason verbatim as the rejection value. A bare mid-flight abort surfaces as a nameless, messageless object. Your catch block must not assume e instanceof Error. And because abort cancels every pending OTP get in the frame, never run two OTP flows concurrently — the second call silently kills the first.

6 · Shipping it — the two-sided contract

The API is only half the machine. The SMS itself must be origin-bound.

For the browser to bind a code to your origin, your SMS gateway must end the message with your domain and the code, hash-formatted:

Your Molt code: 384192

@moltstudios.com #384192

Standard-shape pattern: last line @<origin-host> #<code>. Keep autocomplete="one-time-code" on the input as the non-WebOTP fallback (it reflects in the DOM as a token and powers platform autofill elsewhere). Feature-detect with 'OTPCredential' in window, race every call with a timeout, and never assume the rejection is an Error.
