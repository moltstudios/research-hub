02Source-type matrix — what actually decodes

Nine accepted lanes, two honest rejects. The two that bite in production: ArrayBuffer is not a source (wrap it in a Blob first) and a live <video> element is — decode the current frame without a canvas round-trip.

03The EXIF default — pixels arrive pre-rotated, and 'none' can't undo it

This page authors a 40×20 photo, injects a real EXIF orientation = 6 tag (rotate 90° CW) into the JPEG's APP1 segment byte-by-byte, then decodes it. Expect 20×40 pixels out — the orientation is baked in by default, same as <img> rendering. The trap: {imageOrientation:'none'} — documented as "no orientation applied" — is a no-op on this engine. If your pipeline needs the raw raster (image hashing, ML input, pixel forensics), this API will not give it to you.

FlipY proof included: 'flipY' flips vertically after EXIF orientation is applied — WebGL texture lane.

04Resize during decode — the default is 'low', byte-exact

Resize is free inside the decode call — no second canvas pass, no memory spike for the full-size intermediate. But the default quality is resizeQuality:'low', and this page proves it byte-for-byte. If your thumbnails look crunchy, this is why: one missing option.

The aspect law: give resizeWidth alone and the engine scales height proportionally (40×20 → 80×40, not 80×20). You never need to compute the second dimension.

05The crop overload — (source, sx, sy, sw, sh, options?)

The 3-to-6 argument form crops during decode — sprite sheets, contact sheets, ROI grabs. Three edge laws probed live: zero-size → RangeError (not InvalidStateError), negative origin clamps without throwing, and an overrun rect returns the requested size with transparent padding instead of clamping.

06Color & alpha — colorSpaceConversion:'none' is pixel-visible

A display-P3 PNG decoded with the default ICC conversion lands on one green; with 'none' the raw values pass through as a visibly different green. Meanwhile premultiplyAlpha shows no observable difference through a 2D canvas — the canvas re-premultiplies on draw; the option only matters for WebGL texture uploads.

07Lifecycle laws — close, clone, transfer

close() is idempotent and turns the bitmap into a husk: dimensions read 0×0 (no throw), but any draw throws InvalidStateError with the word detached. An attached bitmap is both structured-cloneable and transferable — clone for a copy, transfer for zero-copy handoff (the sender's copy silently becomes 0×0).

Sibling: canvas.getContext('bitmaprenderer').transferFromImageBitmap(bmp) — zero-copy paint. Second transfer of the same bitmap throws.

08The SVG wall — blobs reject, elements don't

createImageBitmap(svgBlob) rejects with InvalidStateError: The source image could not be decoded. on this engine. The workaround is one hop: load the same bytes into an <img> element, then pass the element — decodes fine. Rasterize-at-the-boundary is the law.

09ImageDecoder — raw demux with µs timestamps (Chromium lane)

This page hand-crafts a 236-byte three-frame GIF89a — including writing the LZW stream — and demuxes it with ImageDecoder: frame count, animated flag, repetition count, per-frame VideoFrames with microsecond timestamp/duration, pixel-exact colors. No <img>, no DOM, no repaint — the DVR-scrub tier.

Format support, live: the only static is isTypeSupported() — isConfigSupported() does not exist on this engine.

10The wrapper quirk — decode() returns {complete, image}

Current spec text implies decode() resolves to the VideoFrame directly. This engine resolves to a legacy DTO with two own keys, complete and image — pass the wrapper to drawImage() and you get a type error even though VideoFrame is in the union. Unwrap .image. Decoding the same index twice yields two independent frame objects.

11Capstone A — OpenDrones evidence frame grabber

One synthetic mission clip (canvas → MediaRecorder webm), one seek, one line: createImageBitmap(videoEl, sx, sy, sw, sh, {resizeWidth…}) — crop + downscale + hash in a single decode, then a stamped PNG. This is the whole "frame N as evidence" pipeline with no canvas round-trip.

12Capstone B — Molt upload QC: EXIF-safe thumbnails

Client photo arrives sideways-tagged (orientation 6). Decode applies the rotation for free; the QC question is quality. Same source, two thumbnails: resizeQuality:'high' vs the default 'low' — then both blown up 5× with nearest-neighbor so you can see what shipped.
