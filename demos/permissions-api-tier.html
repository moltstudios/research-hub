Permissions API — the query tier

navigator.permissions · query() · PermissionStatus · onchange · Permission-Policy — the read-only query layer beneath Camera, Clipboard, Notifications, Geolocation, Wake Lock, Idle Detection, MIDI, Bluetooth, Push & Storage. The tier ~15 earlier entries kept stepping over and never researched on its own. Every chip below re-runs live in your browser; the onchange lane was additionally gate-verified by flipping permissions from the automation harness.

1 · Surface census — one method, one status object

navigator.permissions has exactly one method: query(). The returned PermissionStatus is an EventTarget with a state getter and onchange. Chromium 154 exposes a name getter on the status (matching Firefox/Safari); any expires/request()/revoke() extensions are absent — query can never elevate a permission, and the W3C explicitly removed revoke().

2 · THE NAME CENSUS — the vocabulary wall (headline)

THE LAW. query() only accepts a fixed enum of permission names — and they are not the API method names. 'getUserMedia' → TypeError. 'clipboard' → TypeError (it's clipboard-read / clipboard-write). 'wake-lock' → TypeError (it's screen-wake-lock). And there are three distinct rejection grammars: unknown name → TypeError (enum wall); known name, unsupported feature → NotSupportedError (measured: push on this engine); feature present but policy/origin refuses → resolves denied — never assume one catch fits all. Extra dictionary keys on a valid name are silently ignored (WebIDL dictionary law).

States shown are your browser's live answers. The automation gate census on a fresh Brave 154 headless profile (secure localhost) measured 11 prompt (geolocation, notifications, camera, microphone, clipboard-read, persistent-storage, midi, local-fonts, window-management, captured-surface-control, display-capture) · 5 silent grants — zero UI, zero gesture, zero prompt (clipboard-write, background-fetch, screen-wake-lock, payment-handler, storage-access) · 5 default-deny (background-sync, accelerometer, gyroscope, magnetometer, idle-detection — the sensor family ships denied on hardened profiles) · 8 valid-sounding TypeErrors (bluetooth, serial, usb, nfc, ambient-light-sensor, smart-card, window-placement, top-level-storage-access — the API exists, the query name doesn't) · 10 trap names all TypeError (getUserMedia, clipboard, notification, Notifications, GEOLOCATION, wake-lock, fullscreen, vibrate, background_sync, ''). Chrome additionally auto-denies repeatedly-dismissed prompts (quiet UI) — invisible to query until you look.

3 · Descriptor grammar — extras, coercion & the enum wall verbatim

THE GRAMMAR. Missing name → TypeError (Failed to read the 'name' property). Non-string name coerces by WebIDL rules. Extra keys on valid names are ignored. The interesting tier: dictionary extensions — Chromium once shipped {name:'camera', panTiltZoom:true} and {name:'clipboard-read', allowWithoutGesture:true} — today the wrong-typed extra (panTiltZoom:'banana') TypeErrors while the boolean extra may silently change nothing. The wall text is engine-worded and localized — never string-match it; branch on the TypeError itself.

There is no permissions.request(), no permissions.revoke(), no bulk pre-arm. Every elevation walks through the owning feature's API — usually behind a user gesture, always with the browser's own UI. That asymmetry is the design: query is analytics, the feature API is the ask. (Historical footnote: Chrome 46–51 shipped a permissions.request() behind a flag and removed it — the request-from-console pattern is permanently dead.)

5 · The live-status law — snapshot object, live state

THE LAW. Two query() calls return distinct objects — but the status is not a frozen snapshot: it is a live view. When the underlying permission flips (user answers a prompt, changes site settings, or the automation harness grants it), the same status object's state changes and onchange fires — no re-query needed. The event is a plain Event (type:'change', isTrusted:true); both onchange and addEventListener fire. Object identity ≠ liveness: hold one status, watch forever.

THE POLICY GATE. The iframe allow= attribute (Permissions-Policy) is a different tier from permissions: it decides whether a frame may even ask. Below, this page embeds a child frame (same file, ?child=1) with no allow attribute and the child runs its own census. 8 · Workers, clone walls & the insecure-origin lane

Dedicated-worker census runs live above. structuredClone() of a status (DataCloneError expected — it's a live handle, not data). JSON serialization verbatim. Node 25.8 cross-check (harness-side): globalThis.navigator?.permissions — see the chip. THE INSECURE-ORIGIN LAW (gate-measured, falsifies the docs' sharp edge): MDN marks the API "secure context only", but on a plain-http LAN origin the surface is present — and the store answers denied for everything, including the silent-grant family (clipboard-write, background-sync all read denied). Not absent, not TypeError: a denied-only mirror. Never feature-detect by 'permissions' in navigator on insecure origins — you'll think you have a working tier and every ask will still die.

9 · CAPSTONE — the OpenDrones pre-flight permission board

One tap → the board queries every permission the Mission Control stack needs without triggering a single prompt (the query-tier's whole value: survey before you ask). The ask buttons then walk each feature's real request path — the §4 law as UX. Molt variant: the same board as a pre-deploy checklist for client sites (clipboard, notifications, camera for avatar upload).

THE UX LAW. Never ask on load. Survey silently with query(), render the board, and let intent (the pilot pressing "arm", the user pressing "notify me") drive each ask — single ask per feature, denied gets a calm recovery link to site settings, never a re-prompt loop (the auto-deny trap).

  1. Query is read-only analytics; the ask always lives in the feature API.
  2. Names are an enum — three vocabularies exist; keep one mapping table per project.
  3. Statuses are live views — arm onchange, don't poll.
  4. Two queries = two objects; one object watched forever = correct.
  5. Extra descriptor keys are ignored; bad enum names die verbatim-TypeError.
  6. The silent-grant family exists (clipboard-write et al.) — don't build UX around "everything prompts".
  7. Permissions-Policy (allow=) gates frames before permissions gate users.
  8. No request() — the flag-era API was removed; don't wait for it.
  9. Deny flows: one recovery link to site settings, never a loop.
  10. Feature-detect 'permissions' in navigator then try/catch every name — engine lists drift.
