Wheel Events & Trackpad Gestures — the scroll-zoom tier

Every wheel turn is an event whose own cancelable flag is negotiated by your listeners, routed to a scroller picked by hit-testing, carrying a legacy wheelDelta field that means different things in different engines, on a tier where a default listener on window can never preventDefault and a sub-pixel delta vanishes entirely in WebKit. This is the tier under every map zoom, scroll surface and trackpad pinch — measured live across four engines.

§1 · The pixel law — deltaMode 0, scroll ≡ delta, 1:1

Scroll the pad below with a real wheel/trackpad. The event's deltaMode is 0 (DOM_DELTA_PIXEL) on every real event in every engine measured, and the scroll is exactly the delta:

THE PIXEL LAW. Measured (4/4 engines): deltaMode === 0 always; a 123px delta scrolls exactly 123px (+123 → −50 → 73, exact); a 140px horizontal delta scrolls scrollX exactly 140 (with real overflow). Fractional deltas accumulate — Chromium rounds the accumulated sum up (0.5 → 1px, 5×0.4 → 2px), WebKit drops sub-1px events entirely (§7). The payload itself is float32 on the wire: a dispatched 0.7 arrives as 0.699999988079071.
THE LINE-MODE GHOST. DOM_DELTA_LINE (1) and DOM_DELTA_PAGE (2) never occurred on any real event in any engine measured. Every if (e.deltaMode === 1) { lines… } branch in production code is dead on these platforms — Firefox is the line-mode engine (not in this probe set; documented lane limit). Never branch on deltaMode without a pixel fallback that actually runs.

§2 · The cancelable negotiation — the event's flag depends on YOUR listeners

This pad runs inside a clean sub-document (isolated iframe). With only passive listeners registered, real wheel events arrive cancelable:false. Flip the switch to register one non-passive listener — the same physical wheel now arrives cancelable:true, and preventDefault() works:

wheel in the frame…
THE NEGOTIATION LAW. The wheel event's own cancelable flag is negotiated by the page's listener set, not fixed by the platform: only-passive listeners → the engine dispatches a non-cancelable event (there is nothing to prevent); any non-passive listener on the propagation path → the event is born cancelable. Measured in all four engines, both directions. Consequences: (1) a passive spy/logger sees cancelable flip depending on other people's listeners; (2) event.cancelable is a property of the page, not the engine — never feature-detect "can this browser cancel wheel" from one event; (3) your {passive:false} listener changes what OTHER listeners on the page observe.

THE PASSIVE-WALL LAW. A wheel listener registered without options on window, document, body or documentElement is treated as passive in every engine measured (2026) — its preventDefault() is silently ignored and the page scrolls anyway. Chromium-family logs the console warning "Unable to preventDefault inside passive event listener due to target being treated as passive"; WebKit fails in complete silence. The IDL onwheel handler is equally passive. THE ELEMENT EXCEPTION: the same default-options listener on an actual element — your map div, your canvas — is not passive in any engine. The two-line fix for "my preventDefault does nothing": move the listener onto the element, or say {passive:false}.

THE TWO-FAMILY LAW. The deprecated-but-everywhere wheelDelta is magnitude-independent in the Chromium family — a fixed −120 per downward event (the old notch convention) whether the delta is 40 or 300 — and proportional in WebKit: wheelDelta = −3 × deltaY exactly. The two families agree at exactly deltaY = 40 (−120 = −3×40) — the delta most old test suites happened to use, which is why the split survived a decade of CI. Any code that divides wheelDelta by 120 to recover pixels is wrong by 3× on Safari and wrong by magnitude on Chrome. Use deltaY; let wheelDelta die.

§5 · Ctrl+wheel — the pinch channel & the zoom guard

A trackpad pinch arrives (on the engine side) as a wheel event with ctrlKey:true. Ctrl+scroll over the map — it zooms the map; the page does not zoom, does not scroll:

MAP ZOOM 1.00×pan: 0, 0last: —
THE CTRL+WHEEL PACT. The pinch signal rides the wheel tier: if (e.ctrlKey) is the zoom branch — measured arriving identically in all four engines, with the event's cancelable following the §2 negotiation (the guard's {passive:false} flips it to true, which is what lets a real browser's page-zoom be suppressed). Lane limit, honestly: the browser's own zoom animation is a UI-layer action and did not engage through the automation pipeline in any engine (dpr unchanged) — the event laws above are the engine truth; the zoom suppression is the guard's purpose on real hardware. On the element you don't even need passive:false (§3, the element exception).
// the shipped map layer (this map runs it)
map.addEventListener('wheel', e => {          // ON THE ELEMENT — never passive-walled
  e.preventDefault();                         // page never scrolls/zooms under the HUD
  if (e.ctrlKey) {                        // pinch or ctrl+wheel → zoom
    zoom *= Math.exp(-e.deltaY * 0.01);      // from deltaY — NEVER wheelDelta (§4)
  } else {                                    // plain wheel → pan
    panX -= e.deltaX; panY -= e.deltaY;
  }
}, { passive: false });

THE SATURATION-EDGE LAW. When the latched scroller is already at its edge when the event arrives, the entire delta chains to the parent scroller (inner at max + one 400px event → outer += exactly 400). But an event that saturates the scroller mid-flight drops its remainder (inner at 1300 + one 500px event → inner = 1420 max, outer += 0, the leftover 380px vanishes). Chaining is decided per-event from the scroller's position at dispatch — there is no remainder propagation. Identical in all four engines. overscroll-behavior: contain on the child kills the chained case (outer stays 0).

THE SUB-PIXEL SPLIT. Chromium-family: every fractional delta fires an event; the root scroller rounds the accumulated sum UP (0.5 → 1px, 1.5 → 2px) while an element scroller can eat it (0.5 → 0px, 1.5 → 1px) — the same delta scrolls differently on the page than inside your carousel. WebKit: |delta| < 1 produces no wheel event at all — not "no scroll", no dispatch, root or element alike (0.7, 0.99 and 5×0.7 all produced zero events); at ≥1 it floors. The event payload carries the full float (0.7 arrives as 0.699999988079071 — float32 on the wire). Production consequences: any wheel-injection tooling — e2e drivers, input emulation, remote-control streams like a browser-based drone cockpit relaying operator scroll — must emit |delta| ≥ 1 for WebKit and integer deltas for cross-engine parity; and never assert pixel-exact scroll positions from fractional wheel input.

THE SHADOW RETARGET LAW. A wheel over shadow-DOM content: outside listeners see event.target === the host; composedPath() pierces the open root (measured path: shadow-inner › #shadow-root › host › …, pathLen 9); the listener inside the root receives the full event (composed:true, exact deltas). The same wall as elementFromPoint — the outside world addresses the host; only your own code goes inside. Identical in all four engines.

THE IFRAME-WALL SPLIT. Wheel over a cross-origin iframe: Chromium-family — the parent document receives nothing (0 events; the gesture belongs entirely to the child). WebKit — the parent also receives the event, with target === the <iframe> element (measured: parent heard the wheel, target coframe, while the child heard it too). An overlay that dismisses on wheel behaves differently over embeds per engine: Safari can react (you even learn it's over the frame), Chrome is blind. Both frames get the event in WebKit — double-handling is possible.

§11 · The scroll stream — instant, not animated (the keyboard contrast)

Wheel over this scroller — one wheel event produces 1–2 scroll events and the position is final immediately:

THE STREAM LAW. A wheel scroll lands instantly — the position is final on the first observed frame and one wheel event produces 1–2 scroll events (measured: Chromium-family 2, WebKit 1). Contrast the keyboard tier: one End press animates through 16 frames of scroll events. A scroll-position assertion after mouse.wheel() can read immediately; after a keyboard End it must wait for the animation. (The 2-vs-1 scroll event split is itself an engine fingerprint.)
