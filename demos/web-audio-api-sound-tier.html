Web Audio — synthesis, analysis & telemetry alerting, all in the browser

The media tier transports and records video (WebRTC · MediaRecorder · WebCodecs), and Web Speech does voice I/O — but nothing in that stack makes or measures sound. The Web Audio API is the missing tier: an audio-rate graph of nodes running off the main thread, with sample-accurate automation, FFT analysis, spatialization, custom DSP in worklets, and offline rendering faster than realtime. Every sound on this page is synthesized live — zero audio files, zero uploads.

02 — The sound tier: why Web Audio exists

Four jobs, four APIs. Web Speech converts voice⇄text, MediaRecorder records, WebCodecs touches frames — Web Audio is the only one that synthesizes and analyzes signals at audio rate, on the audio thread, immune to main-thread jank.

🗣 Web Speech — voice I/O

Speech-to-text and TTS through the OS. High-level; you control neither the waveform nor the timing.

⏺ MediaRecorder — capture

Encodes whatever plays, realtime, into a container. A sink, not a source — it can't make a beep.

🎬 WebCodecs — frames

Frame-level video (and audio) chunks. For pixels, not performance: no scheduling, no param ramps.

🔊 Web Audio — signals

Sample-accurate synthesis, automation, FFT, spatialization, custom DSP. Runs while your main thread is frozen. This page.

The graph is the model: sources (oscillators, buffers, streams) → processors (gain, filters, panners, compressors, your DSP) → destinations (speakers, streams, offline buffers). Nodes are cheap; contexts are expensive — one per app, suspended when idle. Baseline everywhere: core nodes since ~2011-14, AudioWorklet since Chrome 66 / Firefox 76 / Safari 14.1 (2020-21) — ship ungated.

An AudioContext starts suspended under every modern autoplay policy — the graph runs only after a user gesture calls resume(). This page creates its context lazily on your first click, then reuses it for every lab below.

osc.connect(gain).connect(ctx.destination);  // .connect returns the destination node — chains!
osc.start(); osc.stop(ctx.currentTime + 0.4); // one-shot: a source fires once, ever

1 · One context per app

Each context opens a real hardware audio stream. Browsers cap them (~6 historically) and each costs memory + battery. Route everything through one master bus.

2 · Gesture = key, not door

One unlock lasts for the page lifetime. Create the context lazily on first interaction; resume() resolves instantly afterwards.

3 · Latency hints

latencyHint: 'interactive' (default) prioritizes low latency for synth UIs; 'playback' buffers more for smooth music. Read the truth: baseLatency + outputLatency.

04 — Lab ① · AudioParam automation: envelopes at sample accuracy

Every AudioParam carries its own timeline of scheduled events. Ramps interpolate between values on the audio thread — no rAF, no setTimeout drift, no main-thread jank can touch them. This is a live ADSR voice: drag the sliders, press play.

08 — Lab ⑤ · Spatialization: PannerNode HRTF orbit + stereo pan

Position sound in 3D with PannerNode (panningModel: 'HRTF' convolves head-related impulse responses; distanceModel: 'inverse' rolls off with range) or just left-right with StereoPannerNode. Headphones recommended — the beacon orbits your head.

idle

HRTF vs equalpower

HRTF = per-person convolution (real 3D "behind you" cues, costs CPU); equalpower = cheap amplitude blend. UI blips: equalpower. Situational audio: HRTF.

Positions are AudioParams

positionX/Y/Z ramp like any param — an orbit is linearRampToValueAtTime on X and Y in quadrature. No rAF loop.

OpenDrones angle

Geofence breach cues panned toward the breach bearing; RSSI loss fades with distance. The pilot's ears get the horizon the eyes don't have.

09 — Lab ⑥ · AudioWorklet: custom DSP on the audio thread

ScriptProcessorNode is deprecated; the modern DSP path is an AudioWorklet — a module of processor classes running on the dedicated realtime audio thread, message-passing to the page, with k-rate/a-rate AudioParams. This Geiger counter is a worklet: Poisson click train + one-pole highpass, intensity driven by a param — and the module is loaded from a Blob URL so the demo stays one file.

idle
// the worklet module (loaded via URL.createObjectURL(new Blob([src])))
class GeigerProcessor extends AudioWorkletProcessor {
  static get parameterDescriptors() { return [{ name: 'rate', defaultValue: 60, minValue: 0,
    maxValue: 1000, automationRate: 'k-rate' }] }
  constructor() { super(); this.env = 0; this.count = 0; this.tick = 0 }
  process(inputs, outputs, params) {
    const out = outputs[0], p = params.rate[0] / sampleRate;  // sampleRate = worklet global
    for (let i = 0; i < out[0].length; i++) {
      if (Math.random() < p) this.env = 1;                    // Poisson trigger
      const v = (Math.random() * 2 - 1) * this.env;            // click = burst noise…
      this.env *= 0.9992;                                      // …with one-pole decay
      for (let ch = 0; ch < out.length; ch++) out[ch][i] = v * 0.4;
    }
    this.count += p * out[0].length;
    if (++this.tick >= 20) { this.tick = 0; this.port.postMessage(Math.round(this.count)); }
    return true;                                              // false = retire this node
  }
}
registerProcessor('geiger', GeigerProcessor);
Rules of the lane: worklets must never allocate/GC-burst or touch the DOM, must return true to stay alive, and talk to the page only via port.postMessage (lock-free rings in real builds). Params declared a-rate interpolate per-sample by the engine — for free.

12 — Gotcha wall (live probes)

Every rule below is executable on this page — press the probe, watch the engine answer. These are the five that bite every first production build.

① Source nodes are one-shot

?

start() twice on the same node → InvalidStateError. Buffers/oscillators are instruments; source nodes are reeds — new reed per note.

② Exponential ramps can't reach 0

?

Mathematically undefined → RangeError. Fade-outs use setTargetAtTime(0) or a linear ramp.

③ decodeAudioData detaches your ArrayBuffer

?

The input buffer is transferred (neutered) — byteLength reads 0 afterwards. Keep a copy if you need it twice.

④ The audio clock is the only clock

?

Scheduling by Date.now()/rAF accrues jitter; ctx.currentTime advances with the audio device even under main-thread freeze.

⑤ iOS Safari: gesture discipline & the mute switch

resume() must be called synchronously inside the gesture handler (not after an await) or it never resolves; the hardware mute switch silences Web Audio (the classic fix plays a silent <audio> element on first touch); and Safari quietly suspends contexts after tab inactivity — watch statechange and re-resume.
