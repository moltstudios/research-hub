Relative Color Syntax

One seed color → an entire palette, computed by the browser: oklch(from var(--seed) calc(l + 0.15) c h). The preprocessor darken()/lighten() workflow, finally native — and theme-able through custom properties since Chrome 131 / Safari 18 / Firefox 133.

01 · Why this matters

The foundation the color tier was missing

We've cataloged oklch(), color-mix(), light-dark() and contrast-color() — the modern color stack. Relative color syntax (RCS) is the piece all of them lean on: it derives new colors from an existing one's channels with full calc() math, instead of blending two fixed colors.

Design systems stop shipping 11 hand-picked hex tokens per brand and start shipping one seed + formulas. Change the seed, the entire palette — buttons, borders, tints, focus rings, status bands — recomputes in the browser, live, with no build step and no JavaScript color library.

The one-liner: color-mix() blends two colors. RCS derives a ramp from one. Production systems need both, but every formula in color-mix(in oklch, X 80%, white) was secretly an RCS-shaped problem ("lighten X by 20%").

03 · Mechanics

Convert → destructure → calc → output

Every relative color runs the same four-step pipeline. The origin is converted into the output function's color space first, then broken into channel values you can read and compute against:

/*                ┌─ 1. output space = oklch
                 │        ┌─ 2. origin: converted TO oklch
                 │        │            ┌─ 3. channels as math values ──┐  4. alpha ─┐*/
background: oklch(from var(--seed) calc(l * 0.78) c h / calc(alpha * 0.9));
//               └── oklch lightness     └ chroma  └ hue  └ derived opacity
  • Origin can be anything — hex, named colors, var(), system colors, currentcolor, even another relative color. Input format never matters; conversion happens first.
  • Channels are values, not strings — they participate in calc(), clamp(), min()/max(), and even infinity tricks.
  • Omit or repeat freely — rgb(from green g g g) is legal (yields gray). You must supply all output channels, but they don't have to reference the origin at all.
  • Omitted alpha inherits from the origin — unlike absolute colors, where missing alpha means 100% (§8).
Serialization gotcha: outputs of the sRGB family (rgb(), hsl(), hwb()) serialize as color(srgb …) in computed style; oklch()/lab() outputs keep their own syntax. Verified live in §5's readout.

Keywords are case-sensitive and lowercase. Hue keywords resolve to plain degrees (0–360), so calc(h + 180) is a complement rotation — no deg unit inside the math. Percentage outputs are fine (oklch(from X 85% c h)); it's only percentages inside calc() with a number keyword that explode.

06 · The gotcha that split the matrix

var() origins — the partial-support era, live

In Chrome 119–130 (and Safari 16.4–17.6 / Firefox 128–132), oklch(from teal l c h) worked but oklch(from var(--brand) l c h) — the entire point for theming — did not. Custom-property substitution happened after relative-color parsing. Tutorials from 2023–24 said "RCS can't read custom properties"; that advice is ~2 years stale and it's why this entry exists.

Production rule: gate the theme-able form, not the syntax: @supports (color: oklch(from var(--x) l c h)) is unreliable for var-origin capability — some engines accept the at-rule but fail at substitution. The robust check is the runtime probe above (computed-value equality) run once at boot, or simply require the full-support versions and ship the static palette as fallback (§7).
07 · Type system

Number vs percentage — and fallback discipline

Channel keywords are typed numbers. calc(l + 0.2) is valid; calc(l + 20%) is a type error (number + percentage) that invalidates the whole color function. What happens next depends on the origin — and the var() case is the trap:

  • Literal origin (from teal …) — the error is caught at parse time → declaration dropped → the static line above survives. Classic progressive enhancement.
  • var() origin (from var(--seed) …) — substitution happens first, so the error surfaces at computed-value time → the property becomes unset (initial/inherited) → your static fallback does NOT save you. The property goes transparent/initial instead. Verified live below — swatch C.

Lesson: the "static line above" rule protects literal derivations only; for theme-able var() derivations, your only safety net is correct number math. Unit-test derivations, or gate with the §6 runtime probe before enabling derived tokens.

08 · Alpha semantics

Omitted alpha inherits from the origin

Surprising default: rgb(from rgba(0,128,0,.5) r g b) outputs 50%-alpha green, not opaque green. Absolute colors default missing alpha to 1; relative colors default it to the origin's alpha. Derive-only-chroma-and-keep-transparency becomes a one-liner — and so does accidentally inheriting translucency you didn't want.

origin · alpha 45%

13 · Adoption

Ship checklist

  • Seed first, palette second. Define --seed (or --brand) once in :root; every other color token becomes oklch(from var(--seed) …). Keep the old static tokens as the fallback block directly above.
  • Gate on var-origin, not syntax. @supports (color: oklch(from white l c h)) passes on partial-support engines (Samsung!). Runtime computed-value probe (§6) or UA-floor policy — pick one.
  • Number math only — and the var() trap. Channel keywords are numbers (oklch l: 0–1, lch l: 0–100, rgb: 0–255, h: degrees). A type error in a literal derivation drops the declaration (static line above survives); in a var() derivation the error surfaces at computed-value time and the property goes unset — transparent/initial, static line does not save you (§7C). Validate theme derivations in a test.
  • Remember alpha inheritance. Omit the slash → you inherit the origin's opacity. Explicit / 100% when you truly want opaque.
  • oklch for ramps, hsl for saturation tricks, rgb for channel inversion. Pick the output space for the transformation, not the input's format — conversion is automatic.
  • Interop path: pairs with if() (conditional channel math), @function (named derivations), light-dark(), contrast-color(), and @property-typed color tokens. PostCSS can pre-compile static derivations for the Samsung tail.

Bottom line: this is the last member of the color tier — and arguably its foundation. Universal in every current engine (one holdout), zero dependencies, and it deletes an entire class of "generate the palette" tooling from our builds.
