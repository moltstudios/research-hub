CSS field-sizing: content

Form fields that grow to fit their content — text, emails, files, textareas, even selects — all sized natively by the browser. Zero JavaScript, zero width measuring, zero hacky input event listeners.

CSS Basic UI L4 Chrome 123+ Edge 123+ Safari 26.2+ Firefox 152+ Baseline 2026

1 The form field sizing problem

For 30+ years, <input> width was controlled by the size attribute (a fixed character count). Make it too narrow → text scrolls. Make it too wide → ugly huge field with wasted space. JS solutions existed but were hacky.

❌ Before — fixed width

Looks cramped. Or worse — too wide if you set a generous fixed width.

✅ After — field-sizing: content

Same email — exact fit, no waste, no scroll. Edit it shorter → shrinks. Longer → grows. 

/* The fix is one CSS line */
.input {
  field-sizing: content;  /* grows to fit value, placeholder, or content */
}

2 Inline auto-growing fields

A short name = narrow field. A long URL = wide field. Each field sizes itself independently. Try editing — the row reflows without any layout jank.

input, select, textarea {
  field-sizing: content;
  min-width: 4ch;   /* never collapse below the cursor */
  max-width: 100%;  /* never overflow the container */
}

💡 Edit any value — the field reflows in real time. No JS resize observer.

3 Placeholders size the field too

An empty input sizes to fit its placeholder text — the field looks like a natural prompt. When the user starts typing, it grows from there.

4 Chip-style tag inputs (no JS!)

Each chip is a tiny <input> that grows with each character. Together they look like a tag input. Press Enter (or Tab) and a new chip appears. No library, no framework, no state management.

input.tag {
  field-sizing: content;
  min-width: 2ch;
  border: none;
  background: transparent;
}
autonomous × long-range × FPV ×
Each tag is a static chip. The trailing input is a real <input field-sizing:content> that grows as you type. Try it.

5 Constraints — min, max, fluid clamping

Auto-grow is opt-out via max-width and min-width. The field grows until it hits the cap, then scrolls. Combine with container queries for fully responsive forms.

min-width: 4ch · max-width: 24ch
min-width: 12ch · max-width: 40ch
min-width: 20ch · max-width: 100%

6 File inputs grow to fit the filename

A long filename no longer overflows the styled button. The native control scales naturally as the user selects different files.

Most browsers expose the chosen filename on the right-hand side — that label grows with the filename width.

7 Textareas grow with content (no JS autoresize!)

The classic "auto-resize textarea" library is now a single CSS line. The browser handles all the math. When the field can't grow (container capped), a scrollbar appears.

/* Replaces the entire autoresize.js ecosystem */
textarea {
  field-sizing: content;
  min-height: 2.5em;
  resize: vertical;  /* let user still drag if they want */
}

8 Selects size to fit the selected option

The dropdown control grows or shrinks based on which option is currently selected. Perfect for short status labels that occasionally switch to long descriptions.

10 Why this matters for design systems

Forms are the highest-conversion-impact UI element on the web. Auto-sizing inputs feel native, look intentional, and remove an entire class of "input too narrow, can't see what I typed" UX bugs.
