Chrome ships a small foundation-model family as built-in browser APIs (LanguageModel, Summarizer, Translator, LanguageDetector, Writer, Rewriter, Proofreader). Input never leaves the device. Privacy-first, latency-free, zero server cost — the production answer for OpenDrones pilot logs, Molt Studios regulated-industry clients, and any tool where a third-party LLM is a deal-breaker.

02 Live Prompt API — Natural Language On Device

The flagship API. LanguageModel.create() instantiates Gemini Nano as a session. Pass prompt(text) for a one-shot completion, or promptStreaming(text) for token-by-token streaming. Sessions are resumable via initialPrompts.

Try a prompt

Output will appear here. Time-to-first-token, tokens/sec, and total elapsed time are reported below the output.
// The Prompt API — 5 lines that talk to Gemini Nano
const session = await LanguageModel.create();
const text   = await session.prompt("Explain on-device AI in one sentence");
console.log(text);

// Streaming variant — same call, token by token
const stream = await session.promptStreaming("Write a haiku about drones");
for await (const chunk of stream) process.stdout.write(chunk);

04 Live Translator + Language Detector — First Pair Stable in Chrome 138

Translate user input between any pair of languages. Language Detector identifies the input language (handy when your textbox can receive any-language input — DJI pilots submit flight logs in EN / ES / PT / ZH). Translator converts to the chosen target. All on-device, zero network.

// Pair: detect-then-translate
const detector = await LanguageDetector.create();
const { detectedLanguage, confidence } = await detector.detect(text);

if (confidence > 0.5 && detectedLanguage !== target) {
  const translator = await Translator.create({
    sourceLanguage: detectedLanguage,
    targetLanguage: target,
  });
  output = await translator.translate(text);
}

05 Live Writer API — Compose New Content

Generate first-draft content with a specified writing task. Useful for: composing pilot field reports, auto-drafting customer support replies, generating instruction text for onboarding flows. Pairs with the Rewriter API to make existing text longer/shorter/formal/casual — fully on-device, no server required.

Compose a pilot field report

Output will appear here. (Writer + Rewriter are in developer trial as of July 2026 — they ship to Chrome 148 stable in late 2026.)
// Writer API
const writer = await Writer.create({
  tone: "formal",
  format: "plain-text",
  length: "medium",
  sharedContext: "Pilot field report writing for OpenDrones Mission Control",
});
const draft = await writer.write(
  "Tower T-12 thermal deviation 5.2°C, battery swap at min 16, +5kt winds.",
  { context: "Audience: maintenance manager" },
);

// Rewriter API — same loop, opposite direction
const rewriter = await Rewriter.create({ tone: "more-formal", length: "as-is" });
const polished = await rewriter.rewrite(draft);

06 Multimodal Vision — Describe an Image With Gemini Nano

The Prompt API in Chrome 148 accepts image, audio, and video input in addition to text — the same prompt call can take an HTMLImageElement, HTMLVideoElement, ImageBitmap, OffscreenCanvas, VideoFrame, AudioBuffer, or Blob. For OpenDrones this unlocks on-device drone-vision (describe the frame, classify anomalies) without sending frames to a server.

Drop or pick an image

Output will appear here.
// Multimodal Prompt API — text + image in one call
const session = await LanguageModel.create({
  expectedInputs: [
    { type: "text", languages: ["en"] },
    { type: "image" },
  ],
});

const frame = await fetch("thermal-capture.jpg");
const blob = await frame.blob();

const result = await session.prompt([{
  role: "user",
  content: [
    { type: "text", value: "List visible thermal anomalies." },
    { type: "image", value: blob },
  ],
}]);

07 The 5-line Recipe Book — Every Task You'll Ever Ship

Every API in the window.ai family is 4-7 lines. Here is the full sheet:

✍️ Prompt (general reasoning)

const s = await LanguageModel.create();
return await s.prompt(q);

📖 Summarizer (long → short)

const s = await Summarizer.create();
return await s.summarize(text);

🌐 Translator (en ↔ es)

const t = await Translator.create({
  sourceLanguage: "en",
  targetLanguage: "es",
});
return await t.translate(text);

🗣️ Language Detector (text → code)

const d = await LanguageDetector.create();
return await d.detect(text);
// → { detectedLanguage: "es", confidence: 0.99 }

📝 Writer (compose from idea)

const w = await Writer.create({
  tone: "formal",
  sharedContext: "...",
});
return await w.write(idea, { context });

✏️ Rewriter (transform text)

const r = await Rewriter.create({
  tone: "more-formal",
  length: "as-is",
});
return await r.rewrite(text);

📚 Proofreader (fix grammar)

const p = await Proofreader.create({
  expectedInputLanguages: ["en"],
});
return await p.proofread(text);

🧠 Hybrid (local → cloud)

// Local first, cloud fallback
if (await LanguageDetector.availability() === "readily") {
  return onDevice(text);
}
return await fetch("/api", { ... });

Ship it like this: window.ai as primary when available → Transformers.js as fallback when model is cached → server LLM for users who need long-context reasoning. Each path is 5-10 lines. The Privacy budget is set first, not negotiated after.

10 The Hybrid Pattern — Local First, Cloud Fallback

Most production apps want privacy where available, capability where needed. The clean way to express this is a capability probe at session start:

// Feature-detect at app boot — runs once
const aiStatus = await LanguageModel.availability();
// → "unavailable" | "downloadable" | "downloading" | "available"

async function smartSummarize(text) {
  // Path 1: on-device, free, private
  if ("Summarizer" in self) {
    const avail = await Summarizer.availability();
    if (avail === "readily" || avail === "available") {
      const s = await Summarizer.create();
      return { source: "on-device", text: await s.summarize(text) };
    }
    // If "downloadable", maybe prompt the user to install the model
    if (avail === "downloadable" && navigator.userActivation) {
      await Summarizer.create({
        monitor(m) { m.addEventListener("downloadprogress", e =>
          ui.showDownloadProgress(e.loaded)); },
      });
      return { source: "on-device (just installed)", text: ... };
    }
  }

  // Path 2: client-side fallback (Transformers.js, on-device via WASM/WebGPU)
  if ("pipeline" in self) {
    const { pipeline } = await import("@huggingface/transformers");
    const s = await pipeline("summarization");
    return { source: "transformers.js", text: (await s(text))[0].summary_text };
  }

  // Path 3: server LLM (only when needed and user consents)
  const ack = await ui.confirmCloud("This will send text to OpenAI. Continue?");
  if (!ack) return null;
  const r = await fetch("/api/summarize", {
    method: "POST",
    body: JSON.stringify({ text }),
    headers: { "content-type": "application/json" },
  });
  return { source: "server", text: (await r.json()).summary };
}

Same call site, three implementations, privacy and cost budgets under developer control. Pair the choice with a UI affordance that says "On device" or "Server" so the user knows.

  • Multilingual support. OpenDrones Latam expansion means ES / PT / EN pilot reports. LanguageDetector identifies; Translator renders the dashboard in pilot's preferred language.

  • Field-note composer. Pilot types a terse note ("T-12 thermal +5°C, battery swap @16"). Writer(tone="formal", audience="maintenance manager") drafts the report. Proofreader cleans it.

12 Recap — How It Fits The Stack

Three on-device AI tiers in 2026. Pick by capability ceiling + browser coverage needs:

Tier What Coverage Use when
1 window.ai (built-in) ~37% Pilot logs, intake forms, privacy-sensitive UX on Chrome
2 Transformers.js v4 — bring your own model via WASM/WebGPU ~95% (WASM) / ~82% (WebGPU) Custom-model domains: embeddings, classification, vision
3 Server LLM (OpenAI / Anthropic / vLLM) 100% Long-context reasoning, RAG, code, agents
The pair is concrete: window.ai as the privacy-first default for short-form text + image + audio (when Chrome desktop available) → Transformers.js v4 as the broad-coverage fallback for custom models and vision tasks → server LLMs as the heavy-reasoning escape hatch. Each is 5-10 lines to integrate. Each sets a different privacy / cost / latency profile.
