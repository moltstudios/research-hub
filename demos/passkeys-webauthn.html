2 The 30-Second Mental Model

A passkey is a cryptographic key pair. The private key stays on the user's device (locked behind Face ID / Touch ID / Windows Hello / device PIN). The public key lives on your server. During login, the device proves it holds the private key by signing a server-issued challenge — without ever sending the key anywhere.

1
Register
Server generates random challenge. Browser asks the authenticator to create a key pair. Public key + credential ID stored on server.
2
Challenge
User returns. Server generates a fresh random challenge tied to their credential ID and sends it.
3
Sign
Authenticator prompts biometric. Device signs the challenge locally. Private key never leaves the device.
4
Verify
Server verifies signature against stored public key. Authenticated. No password ever typed.

3 Registration Flow (Frontend)

The minimum viable WebAuthn registration call. Three lines of code wrap what used to be a 2-week integration.

// 1. Ask server for registration options
const opts = await ( await fetch('/webauthn/register/begin') ).json();

// 2. Decode base64url → ArrayBuffer (WebAuthn spec requirement)
opts.challenge  = _b64uToBuf(opts.challenge);
opts.user.id    = _b64uToBuf(opts.user.id);

// 3. Ask the browser's authenticator to create the credential
const credential = await navigator.credentials.create({ publicKey: opts });

// 4. Send the resulting attestation back to the server for verification
await fetch('/webauthn/register/finish', {
  method: 'POST',
  body:   JSON.stringify(credential),
});

4 Conditional UI — Zero-Friction Login

This is the killer UX pattern. Add autocomplete="username webauthn" to your email input and the browser surfaces passkey suggestions inline in the autofill dropdown. Users who have a passkey tap it and authenticate with biometrics. Users who don't see nothing different — they type their password like normal.

<!-- Just one attribute — that's the whole integration -->
<input
  type="email"
  name="email"
  autocomplete="username webauthn"
  placeholder="you@example.com"

5 Authentication Call

The login side uses navigator.credentials.get() with mediation: "conditional" for autofill, or no mediation for a direct "Sign in with passkey" button. The browser handles the biometric prompt, key retrieval, and signature — your code just forwards the result.

const cred = await navigator.credentials.get({
  publicKey: optsFromServer,
  mediation: 'conditional',   // don't pop a modal

7 Passkeys vs Passwords + 2FA

Passkeys don't just replace passwords — they replace the entire attack surface that passwords create.

9 Implementation Gotchas

Things that cost real engineering hours if you don't know about them upfront.

  • Base64url ⇄ ArrayBuffer — the WebAuthn spec uses raw ArrayBuffer, but JSON transport requires base64url strings. Every implementer writes this helper. Don't try to be clever.
  • RP ID must be a registrable domain suffix — RP ID = "example.com" works on app.example.com, not the reverse. Pick the highest-level registrable domain you control.
  • Challenge storage — store the challenge server-side (session or short-lived KV) keyed by user, with 60s TTL. Don't try to round-trip it through a cookie.
  • Resident key vs non-resident — for conditional UI (autofill), you need residentKey: "preferred" or "required" at registration. Discoverable credentials = true passkeys.
  • Counter must increment — the signature counter prevents cloned authenticators. Server must reject if the counter doesn't increment.
  • User verification — "preferred" is the consumer-app sweet spot. "required" for high-security (banking, firmware updates).
  • Recovery strategy — passkeys can be lost (broken device). Always offer a fallback (password, email link, recovery codes). Passkey ≠ only auth method.
  • Don't roll your own crypto — use @simplewebauthn/server + @simplewebauthn/browser. The spec is dense, easy to get subtly wrong.

10 Libraries Worth Using

Don't implement the protocol yourself. These handle the spec edge cases, base64url juggling, and attestation parsing.

  • @simplewebauthn/server + @simplewebauthn/browser — the de-facto standard. v13+ supports all WebAuthn L2/L3 features. ~30KB total. Use this unless you have a reason not to.
  • @github/webauthn-json — older, lighter wrapper (~8KB). Works but being deprecated.
  • Hanko — opinionated auth-as-a-service with passkeys as the primary path. Good fit if you're starting fresh and want to skip building login entirely.
  • Corbado — enterprise-focused, adds passkey intelligence (detects passkey-eligible users, prompts them at the right moment).
  • WordPress: WP-WebAuthn (free, OSS) or Passwordless WP (commercial, ~$49/yr) — for client sites on WP.
