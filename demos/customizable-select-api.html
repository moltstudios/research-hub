Section 2

The 30-Year Problem

The <select> dropdown is one of the oldest controls on the web — and one of the least stylable. The drop-down picker, the arrow, and the checkmark were rendered by the operating system, invisible to CSS. Every design system hit the same wall.

What developers did instead (the graveyard)

  • appearance: none hacks — stripped the arrow, faked one with a background SVG. The open picker stayed OS-native and unstylable.
  • Select2 / Choices.js / Nice Select — 30–80 KB of JS that rebuilt the control out of divs. Broke mobile. Broke screen readers (when done badly). Broke native form semantics.
  • Headless rebuilds (Radix, Headless UI, downshift) — correct a11y, but you still re-implement keyboard nav, type-ahead, focus, popper positioning, and mobile behavior the platform already had.
  • "Just don't style it" — the reason 90% of production dropdowns still look wrong in an otherwise-polished design system.
The 2025–2026 fix: the Customizable Select feature set makes the entire control — button, picker, arrow, checkmark, every option — styleable with plain CSS, while staying a real <select> in the accessibility tree and the form submission model.
Section 3

Anatomy — 8 New Primitives

The feature is a small set of coordinated additions, not one property. Each maps to a piece you previously couldn't touch:

PrimitiveKindWhat it gives you
appearance: base-selectCSS opt-inRemoves OS rendering; opts select and picker into styleable base styles
::picker(select)Pseudo-elementThe dropdown panel itself — background, border, radius, shadow, position
:openPseudo-classTargets the button only while the picker is open (arrow rotation, open-state chrome)
::picker-iconPseudo-elementThe arrow inside the button — color, size, rotation
option:checkedPseudo-classStyles the currently-selected option row
::checkmarkPseudo-elementThe ✓ marker on the checked option — even its content
<button> + <selectedcontent>HTMLFirst child of select replaces the closed button; clones the selected option's content into it
Rich <option> contentHTMLOptions may now contain spans, images, SVG — not just text
<!-- the markup pattern -->
<select id="demo">
  <!-- 1. the closed-state button -->
  <button><selectedcontent></selectedcontent></button>

  <!-- 2. options can now be rich -->
  <option value="cat">
    <span aria-hidden="true">🐱</span> <span>Cat</span>
  </option>
</select>

/* the two-line opt-in — this is the whole commitment */
select,
::picker(select) {
  appearance: base-select;
}
Fallback is automatic. In browsers without support, the <button>/<selectedcontent> pair is ignored and rich option content degrades to its text nodes. You ship one markup file; legacy browsers get a classic working dropdown.

Section 5

Live — Design-Token Swatches

The pattern every design system needs. The closed button shows a live clone of the selected option via <selectedcontent> — swatch included, hex code stripped with a one-line display rule.

/* hide the hex chip only inside the closed button clone */
.csel selectedcontent .tok-hex { display: none; }
/* shrink the swatch the same way */
.csel selectedcontent .swatch  { width: 14px; height: 14px; }
Golden-rule check: the color name stays visible. An icon-only or swatch-only option is unusable for screen readers, color-blind users, and identical-looking swatches — and renders as an empty row in fallback browsers.

Section 7

Playground — Arrow, Checkmark, Position

The three knobs teams ask for first. Flip the toggles and open the select to feel each one. All state is a single class swap on the control or <body>.

/* arrow rotation — the pattern everyone ships first */
select::picker-icon { color: #6c6c85; transition: rotate .3s ease; }
select:open::picker-icon { rotate: 180deg; }

/* swap the platform checkmark for your own glyph */
option::checkmark { content: '+ '; font-weight: 800; }

/* flip the panel — anchor positioning is built in */
select.pos-top::picker(select) { position-area: top; }
Section 8

Under the Hood — Popover + Anchor Positioning

The picker isn't a new positioning engine; it's built on primitives this research catalog already tracks. When the select opens, ::picker(select) contents are promoted to the top layer (the Popover API's layer — no z-index arms race, renders above every dialog and sticky header).

  • Implicit anchor — the picker is automatically anchored to the select. No anchor-name wiring required; browser default styles handle it.
  • position-area — customize placement with the same anchor-positioning property from our P1 CSS Anchor Positioning entry.
  • position-try fallbacks — browser defaults already reposition the picker if it would overflow the viewport (e.g. flip above the button near the screen bottom). No Popper.js needed.
  • Top layer + light dismiss — closes on outside click or Escape, exactly like a popover. Interops with other popovers correctly (closes unrelated ones).
  • @starting-style entry animations — the picker supports transition + @starting-style, so it can fade/slide in on open (this page does: 0.18s opacity + translate).
Composability note: Customizable Select = Popover API (top layer, light dismiss) + CSS Anchor Positioning (placement + try fallbacks) + interpolate-size/@starting-style (animation) — four catalog entries composing into one control.
Section 9

The Golden Rule — Keep the Text

WebKit's own guidance for the feature, and the difference between a select that works everywhere and one that silently breaks three audiences at once:

Remove the text label?Who breaks
Screen-reader / braille usersOption has no accessible name — the menu becomes "button, button, button"
Fallback browsers (no base-select)Rich content collapses to text nodes → a dropdown full of empty rows
CSS fails to load (proxy, custom styles)Icons are enhancements; without CSS they may vanish entirely
<!-- enhancement: icon ADDED to text, never replacing it -->
<option value="wildlife">
  <img src="bird.svg" alt="">  <!-- decorative: alt="" -->
  <span>Wildlife</span>          <!-- the meaning lives here -->
</option>

<!-- visual-only text is fine too — a11y tree keeps it -->
<span class="visually-hidden">Wildlife</span>
Also from WebKit: wrap enhancements in @supports (appearance: base-select) and keep plain text as the baseline. "Adding a swatch is an enhancement. Removing the color name to make room for it is a regression."

The 80% case: marketing sites, filters, settings, checkout, dashboards — every dropdown that just needed to look right. That's the majority of what Select2 installs were doing, and it's now zero dependencies.
