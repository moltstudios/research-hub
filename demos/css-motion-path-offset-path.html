CSS Motion Path — offset-path, ray(), shape()

Move and rotate elements along curves, rays, circles and SVG geometry with plain CSS — no rAF loops, no GSAP MotionPath. The where-in-space primitive the animation tier was missing: linear() is the easing, scroll timelines are the clock, motion path is the road.

02What it is & why it matters

offset-path pins an element to a geometry — an SVG path(), a ray() from a point, a basic shape like circle()/polygon(), the new shape() function, or even the outline of an SVG element via url(#id). offset-distance (0–100%) slides the element along it, and offset-rotate: auto turns the element to face its direction of travel. It replaces the classic JS pattern: sample a bezier, translate() to the point, rotate() to the tangent, 60 times a second.

Production fit:

Use case
OpenDronesMission replay: the actual flight route as path(), a drone marker scrubbed by offset-distance, waypoints that light as the playhead passes. Radar sweep = ray(). Zero rAF code.
Molt StudiosSignature motion: orbiting badges (circle()), paper-plane hero travel with banked turns (path() + auto), scroll-linked journeys (pair with animation-timeline: scroll()).

Tier placement: linear() easing (Aug 20) defines how motion feels, scroll-driven animations define when it happens, motion path defines where it happens. All three compose on the same keyframes.

Identical S-curve, identical arrow traveler, four facing modes. Scrub and watch which arrows stay tangent to the road.

Drones/planes want auto. Speech-bubble tails and labels want auto 90deg or auto -90deg so they stay readable while following the curve. reverse is auto + 180° for "play the route backwards". A bare angle never follows the path — it just tilts constantly.

06Lab C — ray() radar (angle · size · contain)

ray(<angle> <size>? contain? at <position>?) shoots a line from a point. It's the natural fit for radial UI: radar sweeps, gauges, "distance from home" rings. 0deg points up, angles run clockwise.

Size keywords measure a distance from the origin, not along the ray: closest-side = distance to the nearest edge in any direction (live-probed here: a 90° ray in a 386×250 panel gets length 125px — the vertical distance — not the 193px to the wall it points at). So 100% travel only touches a wall when the ray aims at the nearest side. contain additionally pulls the end in by the rider's own radius so it never clips. sides is the exception — it ends where the ray actually intersects the box outline in its direction, which is why it's the gauge keyword.

07Lab D — basic shapes as roads (circle, ellipse, inset, polygon, rect, xywh)

Since Chrome 116 / Firefox 122 / Safari 18, every CSS basic shape is a valid path — with % coordinates, so they're responsive by nature. Circle/ellipse roads start at the 3 o'clock point and run clockwise; polygon starts at its first vertex. All riders below are pure CSS keyframe animations — no JS.

Check the circle lane: the dot starts at the rightmost point. If you need a different start, rotate the geometry or animate offset-distance from a custom base (from { offset-distance: calc(75% ) }).

08Lab E — shape(): bezier authoring with real units (the 2026 tier)

shape() is the modern replacement for hand-written SVG path strings: comma-separated commands — from <start>, line to …, curve to … with ctrl1 / ctrl2, hline, vline, smooth, arc, close — using % / px / calc() in the coord box. Chrome 135 · Firefox 148 · Safari 18.4 (Baseline Jan 2026).

Authoring: curve to X with C1 / C2 is cubic (two controls), one control = quadratic. by = relative to the previous point, to = absolute in the box. ⚠️ Never put a <fill-rule> (nonzero/evenodd) in an offset-path shape() — it invalidates the whole value (it's only valid for clip-path/shape-outside).

Two drones fly the same loop for 3s. A rides a CSS keyframe animation of offset-distance. B is the classic naive JS driver: += 0.9% per requestAnimationFrame tick. We freeze the main thread for 700ms mid-flight and measure who ends up where. The lesson that generalizes: declarative timelines (CSS animations, WAAPI, scroll timelines) are anchored to wall-clock or scroll position, so congestion delays a frame but never desynchronizes the journey. Per-frame JS integration (pos += step) loses time permanently — the drone is late forever. If you must drive from JS, integrate against timestamps (now - start), not tick counts.

Gotchas that bite

  • Coordinate space: path() uses px in the containing block — not element-relative, not responsive. Scale the stage on small screens (see Lab F) or use % shapes (circle, shape()).
  • Start points differ per road: circle/ellipse start at 3 o'clock going clockwise; polygon at the first vertex; path() at M. offset-distance % is total-length based — a closed loop is the only geometry where 100% lands exactly where 0% started.
  • Stacking context: any non-none offset-path creates one (like transform) — z-index inside the rider changes meaning.
  • Interaction with transform: the path transform composes with your transform (path first). Fine for pop/hover effects — but don't also translate the rider, you'll double-move it.
  • DevTools: select a rider in Chrome Elements panel → the road is drawn as an overlay with distance markers; scrub offset-distance with the slow-motion replay. Debugging motion path without this is masochism.
  • Accessibility: motion path is presentation. Never encode meaningful state changes purely as flight position; pair with text/ARIA and gate ambient loops behind prefers-reduced-motion.
  • Baseline vs your users: core tier is ~8 years old on Chromium — no gate needed. Gate shape() behind @supports (offset-path: shape(from 0 0, line to 1px 1px)) with a path() or static fallback.

Fallback ladder

@supports (offset-path: path("M0,0 L10,10")) {
  .rider { offset-path: path("M0,0 L560,0"); animation: fly 3s linear infinite; }
}
@supports not (offset-path: path("M0,0 L10,10")) {
  .rider { /* static position or a plain transform translateX loop */ }
}

The failure mode of ignoring support entirely: on old engines the rider sits at its static position and the road SVG renders alone — usually acceptable, which is why motion path is a low-risk enhancement.
