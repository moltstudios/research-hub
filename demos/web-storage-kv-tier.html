2 · The 10 MiB law — the quota wall, measured

"localStorage is 5MB" is the most-repeated number in frontend. Measured single-key wall on Brave 154: 5,243,010 characters = 10,486,020 UTF-16 bytes — 10 MiB, byte-stable across fresh profiles. The folklore confuses characters with bytes: the engine accounts every key and value as UTF-16 (2 bytes/char).

3 · The other-document event law

The storage event is the oldest cross-tab messaging channel on the web — and it has a strict perimeter: the writing document never hears its own writes. Same-origin iframes and other tabs do. Press the buttons; the srcdoc child below (same origin — it inherits, §5) records the tape.

The identical-value skip is free change-detection: a theme writer that re-writes the same JSON fires zero events — other tabs don't re-render. But it also means "I wrote, therefore they heard" is false when the value didn't change. Branch on newValue !== oldValue in the receiver, not on "I called setItem".

4 · The session perimeter — the clone law

sessionStorage is per-tab history, not per-origin: it survives reloads, dies with the tab, and is copied — not shared — at window.open. Measured: the popup saw values seeded before the open; its writes never reached back ('tab-A' stayed 'tab-A'); the storage objects are different JS objects on both areas, in every tab.

Rule of thumb: localStorage = broadcast (all tabs, one store), sessionStorage = single-tab state that must survive reload (form wizard, pre-auth nonce). Neither is a security boundary — both are readable by any same-origin script.

6 · The shadow footgun — you can break your own storage

Measured lifecycle: localStorage.setItem = 'x' succeeds (sloppy AND strict mode), silently shadows the method — the next call dies with TypeError: localStorage.setItem is not a function — and the shadow never enters the map (getItem('setItem') → null). delete localStorage.setItem restores the real method; a reload clears it too.

Split routing: property writes whose name isn't a Storage member (localStorage.theme = 'dark') route into the map — getItem('theme') finds them. Member-name writes route into a JS-level expando that only shadows. Never mix the two grammars; one typo'd assignment in a loop can take a tab's storage offline until delete/reload.

10 · The ten-rule checklist

  1. Budget for 10 MiB as UTF-16 (key + value, both areas separate) — "5MB" is a characters/bytes mix-up.
  2. Wrap every unbounded write in a QuotaExceededError catch; prune oldest-first, then retry once.
  3. setItem is atomic — a failed write never half-lands; don't build rollback code that can't fire.
  4. Values are strings, coerced by ToString: undefined → the string "undefined", null → "null", objects → "[object Object]". JSON is manual both ways.
  5. getItem on a miss returns null, not undefined — x ?? fallback and x || fallback behave identically here, but typeof checks must expect "object".
  6. Never rely on key(i) order — enumeration is hash order, not insertion (measured: wrote a,b,c → read c,a,b).
  7. The writing document never receives its own storage event; identical-value writes fire nothing anywhere. Receivers branch on value change.
  8. clear() is one triple-null event — and it wipes the WHOLE origin store, including keys you didn't write. Namespace + remove-item-by-item instead.
  9. Feature-detect inside try/catch — the window.localStorage getter throws on opaque origins (data:, sandboxed frames).
  10. Never assign to member names (localStorage.key = … shadows the method until delete/reload), and never store secrets — same-origin script reads all.
