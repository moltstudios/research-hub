Push streams (Observable, 18 composable operators, EventTarget.when()) and pull streams (Iterator helpers) share one operator vocabulary — map · filter · take · drop · flatMap · reduce · toArray — now in the platform itself. The 47M-downloads-a-week RxJS core, native.

01The reactive quadrant — where Observable sits

Every way a program consumes values fits a 2×2 (the WICG explainer's table, refined from A General Theory of Reactivity). Promise = one value, pushed later. Function = one value, pulled now. Iterable = many values, pulled. Observable = many values, pushed. That last cell is the one the platform never had a primitive for — we've been renting it from RxJS, which grew to ~47 million npm downloads per week.

02Anatomy — subscriber, observer, teardown

new Observable(subscriberFn) does nothing until .subscribe() is called. Each subscription invokes subscriberFn with a subscriber object: .next(v) feeds values, .error(e) / .complete() each fire at most once and end the stream, .addTeardown(fn) registers cleanup that runs on any termination, and subscriber.signal is an AbortSignal that aborts when the subscription dies — so cleanup logic and async work can react to it.

const obs = new Observable(sub => {
  sub.next(1);  sub.next(2);  sub.complete();
  sub.addTeardown(() => log('cleanup'));   // runs on complete | error | unsubscribe
});
const subscription = obs.subscribe({
  next:     v => …,   // or a bare fn:  obs.subscribe(v => …)
  error:    e => …,
  complete: () => …
}, { signal: myAbortController.signal });   // unsubscribe = abort()
subscription.unsubscribe();  subscription.closed;

03Lazy, cold, synchronous — three semantics that surprise everyone

① Lazy — no subscribe, no work

The subscriber function runs per subscription, at subscription time. An unobserved observable costs zero.

subscriber ran 0 times · subscribed 0

② Cold — each subscription is independent

Two subscribers to the same interval observable each get their own producer run (A: 1,2,3… B: 1,2,3…). No sharing, no multicasting — that's share(), which is userland.

③ Synchronous start — the "One · Two · Three" ordering

Promises always deliver on a microtask. Observables can deliver synchronously during subscribe() — which is why the platform example logs One before Two even though the click happens "between" statements. Terminators like first() return a Promise, so they land on the microtask (Three) — that asymmetry is §06's headline.

04The firehose problem — aborting a synchronous infinite stream

The design detail that killed the 2015 proposal and got solved by 2019: an observable can emit unlimited values synchronously, during subscribe(). The loop below literally never returns — the only way out is the consumer aborting from inside its own next handler, watched by the subscriber's signal. This is the pattern that makes "stream every frame / every WebSocket message" safe: backpressure-free push with a guaranteed kill switch.

const firehose = new Observable(sub => {
  let i = 0;
  while (!sub.signal.aborted) { sub.next(i++); }   // exits ONLY via abort
});
const ctl = new AbortController();
firehose.subscribe({
  next: v => { if (v >= 101) ctl.abort(); }        // consumer pulls the cord…
}, { signal: ctl.signal });                                 // …teardown runs, loop exits

05Operators — the chain, live

Same names as iterator helpers, same lazy semantics, but push. Each operator returns a new observable; nothing runs until subscribe; upstream tears down when downstream unsubscribes.

ticks.map(n => n * 10).filter(n => n % 20 === 0).drop(1).take(3).subscribe(…)

source: 0…9

map(×10) → filter(even) → drop(1) → take(3)

The unsubscription cascade: when take(3) completes, it unsubscribes from drop, which unsubscribes from filter… all the way to the source — automatically. The manual "removeEventListener bookkeeping in the right order" bug class doesn't exist here. Watch the teardown log during the run.

06Terminators return Promises — and that's a footgun

every · some · find · first · last · reduce · toArray · forEach end a stream and hand you a Promise. It's the bridge back to async/await — await a .reduce() over a takeUntil race and you have readable async history. But the Promise schedules on a microtask, so anything time-critical inside it (like e.preventDefault()) runs too late. The explainer calls this out explicitly — it's the API's most-cited concern.

07EventTarget.when() — addEventListener, but composable

el.when(type) returns an observable backed by a real event listener created at subscribe time and removed at teardown. Same underlying mechanism as addEventListener, but it plugs into the operator world. This is the drop-in migration path: every event handler you have is already a one-operator chain away.

button.when('click')
  .filter(e => !e.disabled)
  .map(e => ({ x: e.clientX, y: e.clientY }))
  .subscribe(handleClick);

09switchMap — the typeahead killer demo

The classic race-condition bug: type fast, and an early slow response resolves after a later fast one, overwriting fresh results with stale ones. switchMap unsubscribes from the previous inner observable on every new value — stale in-flight responses are discarded by construction, not by if-statement.

input.when('input')
  .map(() => input.value)
  .filter(q => q.length >= 2)
  .switchMap(q => fakeFetch(q))   // each keystroke kills the previous fetch
  .subscribe(render);
requests: 0 rendered: 0 stale discarded: 0
—

Fake API: 250–700 ms random latency, results stamped with the query that produced them. A rendered result never contains a query older than the input's current value — the invariant manual code forgets to enforce.

10Racing streams — first() bridges into Promise.race

Two mission uplinks, one question: which answers first? Terminators make observables first-class in the existing async world — Promise.race([a.first(), b.first()]) — while the pure-stream version is takeUntil. Both below, same race, two idioms.

Promise.race + first()

await Promise.race([upA.first(), upB.first()])
—

pure stream: takeUntil

upA.takeUntil(upB).subscribe(win)
—

Honest difference: takeUntil only declares "A wins unless B emits first" — B's value isn't raced into the output. For true either-way racing you need both directions or the Promise bridge. Knowing which tool is which is the point of the lab.

11The pull twin — Iterator helpers (all engines)

Iterator helpers are the same operator vocabulary on pull streams — and unlike Observable they're Baseline across every engine (Chrome 122 · Firefox 131 · Safari 18.4 · Node 22, shipped 2024–25). Generators compose lazily; Iterator.from() adapts any iterable; toArray() collects. If Observables are RxJS's push core, this is lodash-chain's lazy core, standardized.

function* waypoints() { yield* mission; }
waypoints().filter(w => w.alt > 80).map(w => w.name).take(3).toArray()
// same names, same laziness — values flow only when pulled

Push vs pull, one sentence: pull when the consumer's pace should govern (pagination, large files, backpressure) — push when the producer's pace governs (events, sockets, telemetry). Same operators either way; Observable.from(iterable) converts pull→push for free.

12OpenDrones — the MAVLink telemetry hub

A simulated telemetry bus: one observable emitting interleaved frame types (~8 Hz, jittered) — attitude, battery, altitude, link. Each panel is an independent subscription chain: unsubscribe one and its filters vanish while the bus keeps feeding the others. The battery watchdog is a filter().first() one-shot Promise; the altitude tape completes on takeUntil(landing); "end mission" completes the bus and every teardown fires in cascade.

Molt Studios

Typeahead, drag gestures, scroll/pointer choreography, "everything until X" interactions — all currently hand-rolled listener state machines. The typeahead pattern alone (§09) deletes a whole class of stale-response bugs from every marketing site search box.

Migration is incremental: one when() chain per component, ponyfilled on the two missing engines until they ship (proposal is WICG-active with Chrome implementing; history says years, not months).

OpenDrones

Telemetry is push by nature: MAVLink over WebTransport, WS video stats, geofence events. The hub pattern (§12) gives every panel its own filter chain with guaranteed teardown — the exact leak class that bites long-running mission dashboards.

Watchdogs as filter().first() one-shots, mission replay as reduce(), uplink failover as the §10 race — all one-expression patterns.

Honest framing: RxJS isn't going anywhere — the native set omits the entire combinator zoo (merge/combineLatest/debounce/share), deliberately. The win is the contract: libraries, framework signals (Solid/Preact/XState already use this exact observable shape), and platform events converging on one subscribe/next/error/complete + teardown + signal vocabulary. Learn it once, meet it everywhere.
