§1 — Surface census & the secure-context split-brain

AudioEncoder / AudioDecoder expose exactly one static each (isConfigSupported) and one event each (ondequeue). The data classes carry the payloads.

THE SPLIT-BRAIN LAW. WebCodecs is secure-context-gated, but only half of it: on a plain-http:// LAN origin, AudioEncoder, AudioDecoder, VideoEncoder and VideoDecoder are undefined while AudioData, EncodedAudioChunk and VideoFrame are present (measured on http://192.168.68.59, CfT 148). Feature-detecting typeof AudioData tells you nothing about whether you can decode. Detect the codec classes, not the data classes. OpenDrones LAN ground stations need localhost or TLS for any codec work.

§2 — The config matrix: the opus-only encode wall

Live isConfigSupported() sweep. The engine will encode exactly one audio codec family; decode is broad but has holes.

THE AAC HOLE & THE DESCRIPTION GATE. On this engine (macOS, CfT 148): aac decodes to no — even with a valid AudioSpecificConfig description ([0x13,0x20]) — and configure({codec:'aac'}) accepts, then fails async with NotSupportedError: Unknown or ambiguous codec name. Meanwhile flac/vorbis/multi-channel opus require a description (TypeError without it: “Invalid config; description is required”) and flac answers YES once given a 34-byte STREAMINFO. Three different rejection grammars before a single sample moves.

§3 — AudioData construction grammar

AudioData is the PCM currency: 8 formats × channels × frames × µs timestamps. The constructor validates hard, synchronously, with byte-exact messages.

§4 — The plane law, the copy law & the husk law

Interleaved formats are one plane (the whole buffer); planar formats are N planes (one per channel). allocationSize() prices the copy in bytes; the constructor copies your data; close() zeroes everything.

§5 — The encode lab: +1 chunk, the ts grid, the format-freedom law

This lab encodes 1 second of 440/880 Hz sine (deterministic, same formula ffmpeg got) in 50 × 20 ms frames, then sweeps bitrates and feeds all 8 input formats.

THE +1 CHUNK LAW. 50 inputs → 51 output chunks. The flush tail emits one extra packet at the next grid slot (ts = 50×20000µs), advancing the timeline past your last input. Muxers that allocate n packets for n frames under-allocate on every flush.

THE FORMAT-FREEDOM LAW. The opus encoder accepts all eight AudioData formats — f32/f32-planar/s16/s32/u8 and their planar siblings — and converts internally. The codec contract is the config, not the buffer layout (channel-count mismatch is still a hard error: EncodingError: Input audio buffer is incompatible with codec parameters, thrown synchronously from encode()).

§6 — The decode lab: the ts-anchor law, the bare DataError & the mp3 parser

Feeds real opus packets with deliberately wild timestamps; then mp3 frames — whole-file style and per-frame style.

THE TS-ANCHOR LAW. The decoder takes its timestamp from the first chunk and then ignores yours: outputs advance by their own durations (anchor + Σ dur). Fed [1.000s, 1.020s, 1.040s, 9.000s, 9.020s], the outputs came back [1.000, 1.020, 1.040, 1.060, 1.080] — the 9-second feeds silently discarded. One decoder = one monotonic timeline; re-anchoring mid-stream is impossible without a new decoder (or reset() + re-configure + key chunk).

THE BARE DATAERROR. Audio's key-first error carries no hint — verbatim DataError: Failed to execute 'decode' on 'AudioDecoder' — unlike video's “a key frame is needed…” message. And it applies after every flush() too: flush resets the key-needed state.

§7 — The fatal-corruption law (the video inversion)

Video's silent-junk law (garbage → no error, decoder keeps running) is inverted for audio: corruption is fatal and the decoder closes itself.

THE AUTO-CLOSE CHAIN. One corrupt packet: EncodingError: Decoding error. on the error callback → flush() rejects → state = "closed" → close() itself throws InvalidStateError → every later decode() throws. The one soft exception: 40 zero-bytes decode fine (a valid silence packet) and a 5-byte truncation of a real packet conceals (libopus PLC synthesizes a frame, no error). Valid TOC + corrupt body = conceal; invalid TOC = death.

§8 — THE 312 LAW: the untrimmed stream, ULP-exact vs ffmpeg

Decodes the full embedded ffmpeg opus stream (51 packets, 1.0 s input) and aligns the browser's PCM against ffmpeg's own decode, sample for sample.

Teal: browser AudioDecoder PCM. Orange dashes: ffmpeg reference decode (first 4,800 frames). They differ by ≤ ~1 ULP of f32 — visually one line.

THE 312 LAW. ffmpeg trims the opus codec delay; the browser does not. A 48,000-frame input decodes to 48,960 frames — exactly 312 head frames (the pre-skip, read live from OpusHead bytes 10–11 below) plus 648 tail frames. Every consumer that joins browser-decoded audio to a timeline must skip the pre-skip and drop the tail, or drift 6.5 ms per stream start. And the PCM itself is ULP-exact: max |browser − ffmpeg| ≈ 1.8e-7 ≈ 2⁻²³ across the reference window — same math, different SIMD rounding, never bit-identical (25.9% of float bits coincide).

§9 — State machines & the validation split

unconfigured → configured → closed, with reset() as the soft reset that lands you back at unconfigured (not configured). Validation splits three ways: sync TypeErrors at the config boundary, supported:false for legal-but-absent, async NotSupportedError + auto-close for the rest.

§10 — Workers & serialization: the whole tier moves

The full codec surface exists in dedicated workers, and the data classes cross postMessage both ways — AudioData is serializable and transferable; EncodedAudioChunk serializes.

§11 — Capstones

  • OpenDrones radio-audio pipeline — opus frames over the wire (WebSocketStream/WebTransport) → decode in a worker → waveform HUD. Three laws to build around: (1) corruption is fatal, so radio links need the silent-drop + auto-reconfigure watchdog (§7) — one flipped bit kills the decoder, not the frame; (2) the ts-anchor law means each burst gets its own decoder or a reset()+key restart (§6); (3) trim the 312-sample pre-skip when joining streams or muxing (§8). Voice lane: 6 kbps opus measured 1,134 B/s — a 30 s flight-call is 34 kB.
  • Molt in-browser media pipeline — decode-anywhere (opus/mp3/flac/alaw/ulaw/pcm) with zero server: waveform extraction, loudness scan, transcode preview (opus the only encode target — §2), podcast/paused-audio posters. The insecure-origin wall (§1) means staging demos need localhost or a real cert, never the LAN IP.
  • Sellable: “audio pipeline audit” — 3–4 h per site: where audio decodes, who trims the pre-skip, what dies on corruption.

§12 — The ten rules

  1. Detect codec classes (typeof AudioEncoder), never AudioData — §1.
  2. Encode budget = opus. Everything else is a server concern — §2.
  3. Never migrate a login-session mental model of timestamps: first chunk anchors, the rest are ignored — §6.
  4. After every flush(), feed a key chunk first — delta-first is a bare DataError — §6.
  5. Expect n+1 packets out of n frames in — the flush tail — §5.
  6. Corruption is fatal, not concealment: your watchdog owns reconfigure — §7.
  7. Zero-bytes is valid silence; test corruption with garbage TOCs, not zeros — §7.
  8. Browser decode is untrimmed: skip OpusHead pre-skip (312 here), drop the tail — §8.
  9. Browser PCM is ULP-exact vs ffmpeg but never bit-equal — compare with tolerance ~2⁻²², not SHA — §8.
  10. mp3 needs no framing: the decoder parses a whole file from one chunk; opus needs per-packet chunks — §6.
