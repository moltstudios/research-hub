02 — PRESSURE STATES

Four states, one signal

The API reports high-level pressure states — not raw CPU percentages. This is intentional: the browser fuses hardware counters (CPU utilization, thermal sensors, frequency scaling) into a single semantic value that maps directly to user-facing impact.

⚪ Nominal
Acceptable level. No adverse effects. Device can take on more work.
🟢 Fair
Slightly elevated. Fans may become audible. Battery life reduced. System running flawlessly.
🟡 Serious
Consistently highly elevated. System may be throttling to reduce thermals.
🔴 Critical
Significantly elevated temperature. System needs to cool down to avoid damage.
03 — THE RECIPE

Observe in 5 lines

The entire API surface is two interfaces: PressureObserver (the watcher) and PressureRecord (a single reading). Create, observe, react.

// 1. Create — callback fires on state transitions
const observer = new PressureObserver((records) => {
  const r = records.at(-1);
  console.log(`CPU: ${r.state} at ${r.time}`);
  adaptPerformance(r.state); // your function
});

// 2. Observe — sample at most every 1000ms
await observer.observe("cpu", { sampleInterval: 1000 });

// 3. Stop when done
observer.disconnect();

05 — DEGRADATION LADDER

The OpenDrones adaptation matrix

When the system pressure changes, the Mission Control UI must react instantly. This is the degradation ladder — features disabled in reverse order of criticality.

✅
Nominal — Full Mission Control
4K video feeds · WebGPU particles · ML inspection · All features
🔄
Fair — Shed non-essential effects
Drop to 1080p · Reduce particle density · Keep ML + all feeds
⚠️
Serious — Core ops only
2 primary feeds @ 720p · Freeze 3D view · Pause ML inference
🚨
Critical — Survival mode
1 feed @ 480p · Telemetry text only · Disable WebGPU · Emergency landing prompt
// The degradation function — called from PressureObserver
function adaptPerformance(state) {
  const modes = {
    'nominal':  { videoFeeds: 4, resolution: '4K',  mlEnabled: true,  particles: 5000  },
    'fair':     { videoFeeds: 4, resolution: '1080p', mlEnabled: true,  particles: 1000  },
    'serious':  { videoFeeds: 2, resolution: '720p',  mlEnabled: false, particles: 0     },
    'critical': { videoFeeds: 1, resolution: '480p',  mlEnabled: false, particles: 0     },
  };
  applyMode(modes[state] ?? modes.nominal);
}

07 — WORKER INTEGRATION

Observe from a Dedicated Worker

The Compute Pressure API runs in Window, DedicatedWorker, and SharedWorker. For the OpenDrones v2 stack, the observer lives inside the same Worker that manages WebTransport telemetry and OPFS writes — so pressure adaptation happens at the data layer, not just the UI layer.

// worker.js — the "Mission Control Worker"
let pressureState = 'nominal';

const observer = new PressureObserver((records) => {
  const r = records.at(-1);
  pressureState = r.state;

  // Broadcast to main thread for UI adaptation
  self.postMessage({ type: 'pressure', state: r.state });

  // Adapt THIS worker's workload immediately
  if (r.state === 'serious' || r.state === 'critical') {
    // Reduce OPFS write frequency from 30Hz to 10Hz
    opfsWriteInterval = 100;
    // Skip ML frame inspection
    skipMLInference = true;
  } else {
    opfsWriteInterval = 33;
    skipMLInference = false;
  }
});

await observer.observe("cpu", { sampleInterval: 1000 });

// Meanwhile, the main thread also runs its own observer
// for UI-level decisions (which feeds to show, particle count, etc.)
08 — BROWSER SUPPORT

Chrome / Edge only (July 2026)

The Compute Pressure API is a Chromium-first feature. Shipped in Chrome 125 (May 2024). Not Baseline as of July 2026 because Safari and Firefox have not shipped it. This makes it a progressive-enhancement play — detect, adapt, and fall back to conservative defaults.

⚠️ Not Baseline. Use progressive enhancement: detect the API, use it when available, fall back to conservative resource settings when not. OpenDrones Mission Control targets Chrome/Edge, so this API is production-ready for that build target.

The safe fallback pattern

// Safe adaptation — works everywhere
function setupAdaptivePerformance() {
  if (!('PressureObserver' in globalThis)) {
    // No API → conservative defaults
    applyMode({
      videoFeeds: 2, resolution: '1080p',
      mlEnabled: false, particles: 500,
    });
    return;
  }
  // API available → start aggressive, degrade on pressure
  applyMode(MODE_NOMINAL);
  const obs = new PressureObserver((records) => {
    adaptPerformance(records.at(-1).state);
  });
  obs.observe("cpu", { sampleInterval: 1000 });
}

🚁 OpenDrones Mission Control (5 patterns)

  • Reduce video feed count and resolution per pressure state
  • Pause WebCodecs ML frame inspection on serious/critical
  • Throttle OPFS telemetry writes from 30Hz to 10Hz under thermal stress
  • Simplify WebGPU airspace rendering (drop particles, reduce LOD)
  • Trigger emergency landing prompt on sustained critical pressure

🎨 Molt Studios (6 deliverables)

  • 3D product configurators — reduce texture LOD, disable reflections
  • Animation-heavy landing pages — skip non-critical Framer Motion effects
  • Live commerce video — reduce stream quality, hide filter effects
  • Interactive maps — simplify tile layers, disable fly-over animations
  • Real-time dashboards — switch from live charts to periodic snapshots
  • PWA media apps — pre-cache lower-quality variants under pressure
