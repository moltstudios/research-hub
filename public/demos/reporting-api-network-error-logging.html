Reporting API + NEL — the observability tier

The browser has an out-of-band telemetry bus for things your JavaScript cannot see: CSP violations, deprecations about to break your stack, engine interventions, renderer crashes — and, via NEL, network failures that happen before your JS ever loads. This is the tier the whole 2020s told you was "Chromium-only." That folklore died in March 2026 — ReportingObserver hit Baseline 2026 (Firefox 149 shipped it; Safari has had it since 16.4). Live-probed below on a flag-clean Chromium 154.

ReportingObserver: Ch 69+ · FF 149+ · SF 16.4+ — Baseline 2026 Reporting-Endpoints header: Ch 96+ · FF 130+ · SF 16.4+ — Baseline 2024 NEL: Chromium-only (71+), experimental — still keyed to legacy Report-To Report-To (v0): deprecated — keep only during migration

01Engine introspection — what this browser gives you

Live probes on the page you are reading. Two doors into the bus: the in-page ReportingObserver and the HTTP-header-configured Reporting-Endpoints. They observe the same reports.

Law: observer and endpoint see the same stream. Reports are generated once by the engine and fanned out to (a) any ReportingObserver in the document/worker and (b) the configured endpoint. One exception: crash reports can never reach an observer — the page that would observe them is the thing that crashed (§02).

Law: buffer first, observe second. Reports generated during early page load — CSP violations from inline scripts, deprecations fired by your bootstrap — happen before your observer hook runs. buffered: true is the only replay mechanism; there is no getAllReports(). In prod, register the observer as the first statement of the entry script or you lose everything before it.

06Observer shape vs wire shape — the age/user_agent transform

Same report, two serializations. The in-page observer hands you the object; the endpoint receives a POST envelope with two added fields and one stripped field:

Why age exists: clocks lie. The endpoint envelope carries age — milliseconds between generation and upload — instead of trusting wall-clock timestamps, because client clocks skew. Batch delivery can hold reports for minutes; compute occurrence time as received_at − age server-side. And note user_agent is the UA of the page request, not of the upload — a "request desktop site" page reports the desktop UA.
What never crosses the wire: destination, timestamp, attempts. The spec models each report with an endpoint destination, a generation timestamp, and an attempts counter — engine-internal bookkeeping for retries and routing. The observer sees none of these either; only type/url/body are yours.

07LIVE — workers see reports too (the off-thread observer)

A dedicated worker was spun up on load; it constructed its own ReportingObserver and reported back. Worker support matters: telemetry can live off the main thread, and worker-context deprecations (e.g. APIs removed from worker scopes) are observable where they happen.

…
Observers are per-environment. A document observer never sees reports from an iframe or a worker, and vice versa — each ReportingObserver only receives reports from its own environment settings object. Cross-frame aggregation is a job for the endpoint, where every report arrives tagged with its url.

08v0 → v1 — the Report-To → Reporting-Endpoints migration map

Two generations of endpoint configuration coexist in 2026. The header rewrite changed the scope semantics — that is where migrations break.

v0 · Report-To (2018)v1 · Reporting-Endpoints (2021)
Shape{ group, max_age, endpoints:[{url},…] } — groups, failover listsname="url" pairs — one URL per named endpoint, no failover
Scopeorigin — set once, other documents inherit ambient endpointsdocument — must be on every response that might generate reports
Batchingcross-document/cross-origin reports batched into one POSTisolated per document — one document's reports per delivery
Report typesall, incl. NELall except network-error (NEL) — "a new mechanism will be developed"
EnginesCh 70+ · FF 149+ · deprecated, non-standardCh 96+ · FF 130+ · SF 16.4+ · Baseline 2024
The #1 migration footgun: document scope. Under v0 you set Report-To on the HTML document and ambient inheritance carried it to subresources and sibling documents. Under v1 a report generated by a response that lacked the header is simply dropped. Set Reporting-Endpoints on all responses that can generate reports — HTML, iframes, workers, XHR/JSON endpoints — or your collector will silently starve for exactly those origins.
Keep both headers during migration — but for one reason only: NEL. Chrome's own guidance: keep Report-To "for some time" alongside the new header. The concrete dependency is NEL — it still routes through v0 groups and has no v1 path (§10). Everything else moves cleanly.

09The endpoint contract — what your collector owes the browser

The browser POSTs application/reports+json — a JSON array of report objects. Delivery is best-effort, out-of-band, de-prioritized: the spec explicitly says reporting is not a reliable channel.

# one endpoint for everything (default carries deprecation/intervention/crash)
Reporting-Endpoints: default="https://reports.example.com/collect"

# per-type routing via the report-to directive
Reporting-Endpoints: csp="https://reports.example.com/csp", default="https://reports.example.com/collect"
Content-Security-Policy: default-src 'self'; report-to csp

# vercel.json — headers on every response (the document-scope law)
{ "headers": [{ "source": "/(.*)", "headers": [
  { "key": "Reporting-Endpoints",
    "value": "default=\"https://reports.example.com/collect\"" }] }] }
Collector duties: 2xx fast, no body needed. Respond with 200–299 (or declare extra success codes via Success-Status if your stack allows) — anything else counts as a delivery failure. The engine tracks consecutive failures per endpoint and backs off / stops delivering. Reports are queued in memory, retried, and silently dropped under pressure — never build billing on report delivery.
Named endpoints are just labels. The name (default, csp, crash-reporting) is matched by the report-to directive of the policy header. default is the fallback for the three header-less types (deprecation, intervention, crash). Chromium 139+ adds a dedicated crash-reporting name so crashes can route separately.

10NEL — the network layer's black box (the API your RUM cannot be)

Your analytics script cannot report that your analytics script never loaded. NEL inverts the model: the browser remembers the policy from your last successful visit and reports network failures on future requests to your origin — DNS failures, TCP resets, TLS handshake errors — even when the page never renders. Chromium-only since 71, still experimental, and excluded from v1.

# the policy (response header) — registers with the browser for max_age seconds
NEL: { "report_to": "network-errors",       // names a v0 Report-To group — NOT Reporting-Endpoints
       "max_age": 86400 }                    # policy lifetime; 0 unregisters
Report-To: { "group": "network-errors", "max_age": 86400,
             "endpoints": [{ "url": "https://reports.example.com/nel" }] }

# an actual report delivered later (spec example)
{ "type": "network-error", "age": 84, "url": "https://www.example.com/",
  "user_agent": "…", "body": {
    "referrer": "https://referrer.com/",
    "sampling_fraction": 1.0, "server_ip": "192.0.2.42",
    "protocol": "http/1.1", "elapsed_time": 321,
    "phase": "connection", "type": "tcp.aborted" } }
The phase vocabulary is the debugging tree. phase answers where it died: dns (resolution — dns.address_not_found, NXDOMAIN-class), connection (TCP+TLS — the spec's own tcp.aborted, handshake failures), application (request/response transmission — HTTP protocol errors, aborted transfers). server_ip + elapsed_time + protocol turn "site feels down" into a triage row.
The blind spots are spec'd, not bugs. No NEL report when the UA is offline (navigator.onLine === false — nothing to send through), none for requests blocked by mixed-content or CORS. Preflights count as their own network requests. You still need client RUM for slow-but-successful loads — NEL only speaks failure (plus optional success sampling via success_fraction in newer drafts).
NEL in the wild, Sep 2026: Cloudflare serves one on every response. Probed while building this page: nel: {"report_to":"cf-nel","success_fraction":0.0,"max_age":604800} — a 7-day policy with success sampling off. That is the pattern: CDN-scale origin monitoring that survives the page being unreachable.

11Capstones — OpenDrones fleet ops · Molt client watchdog

Two production shapes for the agency.

OpenDrones — fleet operations telemetry. Remote flight sites run captive portals, poisoned DNS, and metered links. When api.opendrones.dev fails DNS at a site, the cockpit JS never loads and your RUM is blind — but the browser remembers the NEL policy from the last healthy session and files dns.* reports on the next visit to any page on the origin. Pair it with: default endpoint deprecation radar on the cockpit (the unload endgame proved platform APIs die on published schedules — reports arrive a quarter early), a named crash-reporting endpoint (Ch 139+) for map/GPU renderer crashes, and CrashReportContext (Ch 145+) stamping the mission id into every crash report so the post-mortem knows which flight died.

Molt — client-site watchdog. One collector, per-client routing: Reporting-Endpoints: default="…/collect?client=acme", csp="…/csp" with CSP report-to csp — third-party script violations land separated from platform noise. Start every engagement in report-only mode (Content-Security-Policy-Report-Only + Permissions-Policy-Report-Only) and read violations for a week before enforcing. In dev, a 12-line ReportingObserver panel (§03–§05) is the free tier — zero infra, works on localhost, prints every violation as it happens.

13Ship checklist

Ten rules, learned the hard way across the catalog:

1Set Reporting-Endpoints on every report-generating response — document scope, no ambient inheritance (§08).
2Keep Report-To only while NEL still needs it; drop the rest of v0.
3One URL per named endpoint in v1 — failover is your collector's job now.
4default carries deprecation / intervention / crash — define it or those reports vanish.
5Observer first, code second — buffered: true replays only what the buffer kept (§04).
6Never await or depend on report delivery — best-effort by spec, dropped under pressure.
7Compute event time as received_at − age; do not trust client timestamps (§06).
8Trend deprecations by stable body.id, not message prose.
9Crashes are endpoint-only — no observer can see the page that died.
10NEL is Chromium-only bonus signal, never an SLA source — and needs v0 (§10).
