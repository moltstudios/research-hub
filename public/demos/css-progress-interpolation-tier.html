progress() — the ratio engine that shipped alone

A pure-CSS proportion calculator: progress(value, start, end) returns (value−start)/(end−start) clamped to [0,1]. Its siblings media-progress(), container-progress(), and timeline-progress() never shipped — but they're all fully bridgeable, measured below.

§02 The compensation law — the unshipped siblings, bridged

media-progress(width, a, b) ≡ progress(100vw, a, b). container-progress(width, a, b) ≡ progress(100cqi, a, b) on descendants of a container. Viewport and container query units are plain lengths — progress() takes them natively, measured on both engines.

§03 The serialization split — your CSS text gets rewritten

With absolute inputs, progress() is resolved eagerly and erased from every readback path — style attribute, cssText, even stylesheet rules. With viewport/container-relative inputs it can't be pre-computed, so it serializes verbatim. Live readback:

A · absolute inputs
el.style.opacity =
  'progress(100px, 0px, 200px)'

el.style.opacity     → —
cssText              → —
attributeStyleMap    → —
function erased — resolved to a number
B · viewport-relative inputs
el.style.opacity =
  'progress(100vw, 0px, 1280px)'

el.style.opacity     → —
computed             → —
serializes verbatim — re-resolves per layout

Consequence: don't rely on reading back authored progress() from the CSSOM — keep your source, or register a <number> custom property to read the computed ratio from JS (that's how §01's ratio readout works, no math in JS).

The 10 rules
  1. Gate with @supports (line-height: progress(1px, 0px, 2px)); give old engines a static value.
  2. Assume [0,1] always — over pins to 1, under pins to 0, zero-width range gives ±∞ → still 1/0.
  3. no-clamp doesn't exist in engines — scale with a wider end value instead.
  4. Never mix % with px inside progress(); all-% ratios are valid and scale-invariant.
  5. Outputs are numbers — multiply by a unit inside calc() for length properties.
  6. Bridge the unshipped siblings: 100vw ↔ media-progress, 100cqi ↔ container-progress (values on descendants).
  7. Register drive variables with @property; transition the variable for synced multi-property motion.
  8. Don't trust CSSOM readback of absolute progress() — it serializes resolved; read ratios via a registered <number> var.
  9. sibling-index/count are 1-based, own-siblings-only, live on DOM change; type-checked out of content.
  10. Zero-JS updates: flipping the input var re-resolves gradients, colors, transforms — measured.
