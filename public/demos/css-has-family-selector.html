CSS :has() — the family selector

Style an element by what it contains or what follows it — the parent selector the web wanted for 25 years. Form validation, selected-row toolbars and safety interlocks with zero JavaScript.

§1 · Why it matters

A parent selector was "impossible" for 25 years

Selectors could only look down and right — descendants, later siblings. "Style the card that contains an image," "tighten the heading that precedes a subheading" — impossible in pure CSS. The request dates to the earliest Selectors drafts; it was deferred for two decades over cyclic-reference and invalidation-cost concerns (a child change must re-check every matching ancestor).

Engines cracked it with scoped invalidation sets: Safari 15.4 shipped :has() first (Mar 2022), Chrome/Edge 105 followed (Aug 2022), Firefox 121 completed the set (Dec 2023) → Baseline Dec 2023, ≈96–97% of traffic today. Samsung Internet since 20, iOS since 15.4.

Before — JS state mirroring 
el.addEventListener('change', () => {
  el.closest('.field')
    .classList.toggle(
      'has-error',
      !el.checkValidity());
});

A listener per input, a mirrored class, a re-render path — and it breaks on reset(), autofill and paste.

After — one declaration 
.field:has(input:user-invalid) label {
  color: var(--bad);
}

The engine keeps the relationship live — autofill, reset, dynamic rows, shadow DOM events all just work. No state to mirror.

Rule of thumb: if a component's JS exists only to copy DOM state into classes, :has() deletes that JS.
§2 · Anatomy

Five forms, one pseudo-class

:has() takes a relative selector list — every argument is matched against the element's descendants or siblings, and the element itself is styled when any argument matches. Click a form to see it hit this tree:

card-a
img

note

Active selector

.tnode:has(.cap)
matched: group, card-a

Sibling forms (+, ~) make :has() a lookahead, like abc(?=xyz) in regex: it tests what comes after the element, then styles the element itself. :not(:has(+ x)) is a negative lookahead.

§7 · Gotchas — live probes

Four failure modes, tested in your browser

:has() has sharp edges. Each probe below ran on this page load against the real engine:

… Unsupported engine = rule death

In a browser without :has(), the whole selector is invalid — and if you comma-join it with a fallback, the fallback dies too. Shown live with a fake pseudo on the boxes below.

… :is()/:where() are forgiving

Wrap :has() in :is()/:where() and an old engine drops the argument instead of the rule — the progressive-enhancement escape hatch.

:where(.card):where(:has(.cap)) { … }
… No :has() inside :has()

Nested relational queries are banned by spec — cyclic matching. Deep chains must stay flat or use different anchors.

CSS.supports('selector(a:has(b:has(c)))')
… No pseudo-elements

:has(::before) and pseudo-element anchors are invalid — their existence depends on ancestor styling (cyclic again). Style the host element instead.

CSS.supports('selector(a:has(b::before))')

The comma-kill, demonstrated

Safe: fallback in its own rule
.fallback { color: green }            /* separate rule — safe */
.x:has(.cap) { color: teal }      /* dies alone if unsupported */
Killed: comma-joined with an invalid selector
.fallback,
.x:bogus-pseudo(.cap) { color: green }  /* WHOLE list invalid */

Box B proves the mechanism today: its green color rule is comma-joined with an (always) invalid pseudo, so the engine drops the entire selector list — exactly what happens to .card, .card:has(img) in a pre-:has() browser.

Also banned: :visited inside :has() is treated as :link (history privacy), and argument validity follows the forgiving list rule — one bad argument is skipped, not fatal.
§8 · Lab — honest numbers

Invalidation cost, measured here

The historical objection to :has() was cost: a descendant change can invalidate ancestors. Engines have optimized this heavily since 2023. Run the benchmark on this machine — 1,000 generated rows, 2,000 state mutations, forced style+layout recalc per batch, comparing a class toggle vs scoped vs unscoped :has():

    idle — run to collect
    /* what is measured */
scoped:   #benchList li:has(input:checked) { … }
unscoped: li:has(input:checked) { … }   /* walks every ancestor */
class:    li.sel { … }                     /* JS mirrors state */
    Reading it: scoped :has() ≈ class-based on modern engines — invalidation sets are bounded. The unscoped form is the real cost multiplier: every ancestor of every checked input becomes a candidate. Production rule: scope :has() to the nearest container that owns the state, prefer > / sibling forms, and avoid ancestor queries over 10k-node subtrees.

    Copy-paste recipes

    /* 1 · Ship-safe: fallback lives in its OWN rule */
.field .err { display: none }                       /* fallback, everywhere */
.field:has(input:user-invalid) .err { display: block } /* enhancement */

/* 2 · Selected count with no state */
.list { counter-reset: sel }
.list .row:has(:checked) { counter-increment: sel }
.bar::after { content: counter(sel) " selected" }

/* 3 · Negative lookahead spacing */
.item:not(:has(+ .item)) { margin-bottom: 0 }          /* last item knows */

/* 4 · Container-scoped state (tabs, pricing, interlocks) */
.wrap:has(#opt-a:checked) .panel-a { display: block }

/* 5 · Old-engine-safe comma join via :where() */
.card, .card:where(:has(.cap)) { border-color: teal }   /* fallback never killed */

    When not to use :has()

    ■ Value matching — you cannot select by input value, slider position or text content (attributes only, e.g. :has([data-state=crit]) — reflect state to an attribute). ■ Nested relational queries — :has(:has()) is banned. ■ Huge ancestor chains — avoid unscoped :root:has(...)-style rules on 10k+ node subtrees. ■ Pseudo-element anchors — impossible by design.

    Pairs with: :user-invalid/:user-valid (MC 5a3aff81) · container style queries (3562ee7f) · @scope (56e5e693) · if() (22c820c1) · Customizable Select — :has(option:checked) styles the button from the chosen row. Together these cover most "small JS state manager" work on marketing and dashboard UI.
