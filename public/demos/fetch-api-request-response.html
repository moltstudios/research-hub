Fetch API — the request/response tier

fetch() is the most-used web API in production and the tier every other transport builds on — WebSocket upgrades from its handshake, WebTransport rides the same HTTP/3 session, sendBeacon is a fire-and-forget wrapper, and fetchLater (Chromium 135+) is fetch with a timer. One promise in, one Response out — and under that simplicity: body locks, opaque filters, redirect mode contracts, a 64 KiB keepalive ceiling, and a streaming-upload path that still only exists on Chromium over HTTP/2.

fetch() duplex:'half' uploads Request.body stream fetchLater() keepalive (unload-proof) headers.getSetCookie() AbortSignal.timeout() AbortSignal.any() Request.integrity enforced fetch priority option

Every chip on this page is a live probe against this origin's /api/* lab routes (served by a real HTTP/2 endpoint) — no claims copied from docs without firing them. Badges = capability truth on THIS engine.

04 · The body lock

One read per Response — clone() is the tee

A Response body is a one-shot stream. Every consumer method (text() json() blob() arrayBuffer() formData()) and getReader() all pull from the same underlying source — second consumer hits TypeError. clone() tees it, but only before the first read.

06 · Streaming uploads — the Chromium-only tier

duplex:'half' — a ReadableStream body over HTTP/2

Uploading while still producing is the tier fetch opened last and narrowest: Chromium-only (105+ streams, 131+ the duplex reflection), requires HTTP/2+ (HTTP/1.1 would deadlock without Content-Length), Firefox/Safari reject stream bodies entirely. And fetch exposes no upload progress event — your generator is the only progress signal (XHR still owns that event).

07 · Redirects

follow · manual · error — and the 301 POST→GET rewrite

Default mode follows transparently (res.redirected === true, res.url is the final URL) — but 301/302/303 rewrite POST to GET while 307/308 preserve the method and body. manual hands you an opaqueredirect: status 0, no headers, no body, no URL — proof the browser followed policy, not proof of where it went.

09 · Cache modes & 304

no-store · force-cache · only-if-cached — and the revalidation contract

fetch's cache option drives the HTTP cache: only-if-cached hard-requires mode:'same-origin' (any other mode throws at fetch time) and has no network fallback — no cached entry means TypeError, not a trip to the wire. A conditional If-None-Match that hits gives you a real 304: ok:false, empty body — the response IS the status.

10 · Abort & timeout

AbortError vs TimeoutError — they are NOT the same rejection

Manual controller.abort() rejects with a DOMException named AbortError. AbortSignal.timeout(n) rejects with one named TimeoutError — code that branches on err.name === 'AbortError' silently mis-handles every timeout. Both land on signal.reason; both tear down body streams mid-read.

11 · Past the page: keepalive & fetchLater

Requests that outlive their context

keepalive:true lets a request finish after the page unloads (analytics on exit, the sendBeacon replacement) — capped at 64 KiB in-flight body; past the cap fetch throws immediately. fetchLater() (Chromium 135+, FF/Safari ✗) queues a deferred fetch that fires on activateAfter expiry or page close — no surviving context needed at all, with its own QuotaExceededError budget to guard.
