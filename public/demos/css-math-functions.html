The Tie Law — halves go toward +∞

A value exactly halfway between two multiples rounds up (toward +∞), like Math.round: round(3,2)=4 but round(-3,2)=-2. And watch the classic false tie: 2.5 with interval 2 is not halfway between 2 and 4 (3 is) — it simply rounds to 2.

The Invalidity Split — parse-drop vs IACVT

Two different failure modes, and they don't behave alike. Number-vs-length mismatches are dropped at parse time (the CSSOM setter rejects the string outright). Percent-vs-length mismatches parse fine and fail at computed-value time (IACVT) — the declaration silently becomes unset. In a registered custom property, that means the initial value comes back, not an error.

Infinity & NaN — the Clamp Laws

Math functions can produce ∞ and NaN, and Chromium handles them with three distinct clamps. Rounding interval 0 → NaN. Typed <number> properties coerce NaN → 0. Infinite lengths clamp to ±2²⁵ px (≈ ±33.55 million px) — and used width additionally floors at 0.

--n: calc(1/0)∞ clamps to DBL_MAX on typed numbers

--l: round(down, -5px, ∞px)negative mirror → −2²⁵

pow · sqrt · log · exp — Numbers Only

The exponential family accepts pure numbers — a unit anywhere (even pow(2px, 2)) is invalid. log() takes an optional base as its 2nd arg. The one exception to "no units": hypot(), the Euclidean magnitude, does accept same-type units — hypot(3px, 4px) = 5px — which is exactly what physics HUDs need.

The Twelve Laws

L1
mod() takes the divisor's sign; rem() takes the dividend's — and rem() ≡ JS %. mod(-1,5)=4 but rem(-1,5)=-1. Compasses and wrap-around math want mod(); anything mirroring JS arithmetic wants rem().
L2
True ties round toward +∞ (Math.round semantics). round(3,2)=4, round(-3,2)=-2. Beware false ties: 2.5 is not halfway between 2 and 4 — 3 is.
L3
Four strategies, JS twins: nearest|up|down|to-zero = round|ceil|floor|trunc. Keywords are case-insensitive; nearest is the default.
L4
Omitting the interval is numbers-only. round(5) → 5. round(100px) is parse-invalid — dimensions demand an explicit interval.
L5
The invalidity split: number↔length mismatches parse-drop; %↔length mismatches IACVT. round(10px,3) never enters the CSSOM. round(1px,2%) enters, then silently unsets — in a registered property it returns the initial value.
L6
Percentages mix with lengths only where the property allows them — and round after resolution. width: round(53.7%,10px) resolves 53.7% against the container, then snaps to a 10px multiple.
L7
Interval 0 → NaN; typed numbers coerce NaN → 0; CSSOM serializes it as calc(NaN * 1px). Not an IACVT — you get 0, not the initial value.
L8
Infinite lengths clamp at ±2²⁵ px (≈ ±3.3554e7px); used width floors at 0. calc(1px/0) computes to 33554432px; negative infinity widths read 0px.
L9
pow/sqrt/log/exp are pure-number functions; hypot() is the unit exception. pow(2px,2) is invalid, but hypot(3px,4px)=5px — exactly what vector magnitudes need.
L10
abs()/sign() are the latecomers: Chrome 138, 13 versions after round(). Firefox 118 and Safari 15.4 shipped the whole family at once. On Chrome 125–137, round works and abs/sign IACVT — feature-test, don't assume family unity.
L11
Chromium quantizes used lengths to 1/64px. calc(1px/128) → 0px, calc(100px/3) → 33.328125px. round(x, 1px) buys back crisp tracks and hairline-free grids.
L12
Everything composes: math functions nest in calc(), clamp(), and each other — including grid tracks. repeat(3, round(100.5px/3, 1px)) renders three exact 34px columns. Specified values always serialize as calc(...) wrappers.
