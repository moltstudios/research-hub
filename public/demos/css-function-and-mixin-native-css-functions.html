01 — The Primitive

What is CSS @function?

The @function at-rule lets you define reusable, typed CSS functions that evaluate at runtime in the browser. You name them with a --dashed-name, pass arguments, and they return a computed value via the result: descriptor. No preprocessor, no build step, no JavaScript.

The key difference from Sass: A Sass function bakes its answer into the stylesheet at compile time. A CSS @function evaluates live in the browser — when a custom property changes from a media query, container query, :hover, or JavaScript, the function recalculates automatically.

The 5-line recipe

@function --double(--value <length>) returns <length> { result: calc(var(--value) * 2); } /* Usage */ .card { padding: --double(1rem); /* → 2rem */ margin: --double(0.75rem); /* → 1.5rem */ }

That's it. Define once, call anywhere. The function is scoped to the cascade layer it's defined in, follows source-order resolution, and can be overridden by stronger layers.

03 — Typed Parameters

Type safety, defaults, and overloading

Parameters can carry a CSS data type (<color>, <length>, <number>, etc.) and an optional default value. If you pass the wrong type, the function returns its default or becomes invalid at computed-value time.

/* Typed parameters with defaults */ @function --alpha( --color <color>, --a <number>: 0.5 ) returns <color> { result: oklch(from var(--color) l c h / var(--a)); } /* Both calls valid — second uses default alpha 0.5 */ .overlay { background: --alpha(var(--brand), 0.2); border-color: --alpha(var(--brand)); /* → 0.5 alpha */ } /* Multiple accepted types via type() union */ @function --alpha( --color <color>, --a type(<number> | <percentage>) ) returns <color> { … }

04 — Conditional Logic

Functions with @media and if()

A function body can contain @media or @supports at-rules that change what result: resolves to. There are no early returns — last matching result wins, just like normal CSS cascade.

/* Responsive padding: 1.2rem on desktop, 0.8rem on mobile */ @function --pad(--scale <number>: 1) returns <length> { result: calc(var(--scale) * 1.2rem); @media (max-width: 500px) { result: calc(var(--scale) * 0.8rem); } } /* Same logic via if() one-liner */ @function --pad(--scale <number>: 1) returns <length> { result: if( media(width < 500px): calc(var(--scale) * 0.8rem) ; else: calc(var(--scale) * 1.2rem) ); }
Order matters: CSS cascade applies inside functions. If the @media block comes before the default result:, the default always wins (last in source order wins). Always put the default result first, then the conditional overrides after.
05 — Function Composition

Functions calling functions

Custom functions can call other custom functions. When they do, the inner function can access the outer function's parameters and local custom properties — closure-like scoping that's impossible with Sass.

@function --double(--v <length>) returns <length> { result: calc(var(--v) * 2); } /* --triple composes --double + adds the original */ @function --triple(--v <length>) returns <length> { result: calc(--double(var(--v)) + var(--v)); } /* Closure scoping: inner sees outer's params */ @function --outer(--base) { --local: 10px; result: --inner(); /* inner can read --base AND --local */ } @function --inner() returns <length> { result: calc(var(--base) + var(--local)); } .box { margin: --triple(5px); } /* → 15px */ .box { margin: --outer(20px); } /* → 30px */

This is the pattern that makes design-system tokens powerful: define atomic functions, then compose them into higher-level utilities — all in plain CSS, all evaluating live.

The cascade-based fallback

Browsers that don't recognize the --function-name() syntax treat the declaration as invalid and silently fall back to the previous value. This is the same progressive-enhancement pattern that carried CSS through gradients, flexbox, grid, and container queries:

.card { /* Fallback: everyone gets this */ padding: 2rem; /* Enhancement: only @function browsers use this */ padding: --pad(2); }
Detection in JavaScript: Check 'CSSFunctionRule' in window for API presence, or define a test function that returns a known value and check the computed style of a hidden element.
10 — Decision Matrix

When to use @function vs Sass vs custom properties

Need Best choice Why
Runtime-reactive value (changes with media query, container query, :hover) CSS @function Recalculates live — Sass can't
Complex build-time math (loops, color manipulation pipelines) Sass Mature ecosystem, loops, maps, string ops
Simple reusable value (brand color, max-width) CSS custom properties Simpler. Don't over-engineer.
Typed design token (spacing scale, color ramp, fluid sizes) CSS @function Typed params + defaults = self-documenting API
Reusable declaration blocks (mixins) Sass @mixin CSS @mixin not yet shipped in any browser
Conditional value based on viewport CSS @function + @media One function, responsive result — no breakpoint duplication
Cross-browser production (must work in Firefox/Safari today) Sass with cascade fallback Ship Sass now, add CSS @function as enhancement
11 — Stack Composition

How @function joins the modern CSS toolkit

CSS @function is the logic layer that ties together every modern CSS primitive we've documented. Here's where it fits:

INPUT
@property

Typed custom properties with syntax, initial value, and inheritance control. Functions consume these as typed arguments.

P1 — Documented
LOGIC
@function

Typed, parameterized, composable functions with conditional logic. The reusable brain of the design system.

P2 — This entry
SCOPE
@scope

Component-scoped CSS. Functions defined inside a scope are local to that component tree — no leakage.

P2 — Documented
THEME
@container style()

Container queries on custom property values. Functions compute the value; container style queries react to it.

P2 — Documented
COLOR
oklch() + contrast-color()

Functions transform colors in OKLCH space. contrast-color() ensures accessibility on the result.

P1/P3 — Documented
CONDITIONAL
if() function

Inline conditional expressions inside function bodies. Pairs with @media for responsive logic.
