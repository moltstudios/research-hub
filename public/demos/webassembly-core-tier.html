01The 19-member surface — JSPI shipped, type reflection didn't

The WebAssembly namespace on CfT 148 has exactly 19 members. The surprise trio: Suspending, promising, SuspendError — JSPI (JavaScript Promise Integration) is shipped and unflagged. The absence: WebAssembly.Function (type reflection) is undefined — you cannot mint a wasm-typed JS function from script.

03The four-family error taxonomy — and which one you actually get

  
Wasm failures split into four DOMException families with byte-offset diagnostics (@+30) in every CompileError. The trap that trips everyone: a missing import namespace is a TypeError, not a LinkError — LinkError is reserved for kind mismatches. And INT_MIN / −1 traps as “divide result unrepresentable” — different message than divide-by-zero.

  






  
04Memory — the page law and the DETACH law

  
One page = 64 KiB, always. grow() returns the old page count — and detaches the old ArrayBuffer completely. Every stale Uint8Array, every WebGL texture upload pinned to the old buffer, dies with TypeError: Cannot perform Construct on a detached ArrayBuffer. This is the #1 wasm-GL crash in production.

  






  
05THE SAB LOOPHOLE — shared memory without SharedArrayBuffer

  
Without COOP/COEP headers, SharedArrayBuffer is undefined on the page — the entire worker-threads folklore says “no isolation, no shared memory.” But new WebAssembly.Memory({ shared: true }) works anyway, and its buffer reports constructor.name === 'SharedArrayBuffer'. The COOP/COEP gate guards the SAB constructor — not shared wasm memory. And shared growth inverts the detach law: old views stay readable at their old length.

  






  
06Table · Global · Tag — the vocabulary rejections nobody documents

  
new Table({ element: 'funcref' }) — the spec-text spelling — is REJECTED: “must be a WebAssembly reference type”. Only the legacy 'anyfunc' spelling constructs. Yet the OOB error message says funcref table — the engine rejects your vocabulary while speaking its own. Globals coerce (1.9→1, '5'→5), i64 demands BigInt with a verbatim wall, and new Exception(JSTag, …) is refused outright.

  






  
07The streaming tier — four walls, all TypeError, all verbatim

  
compileStreaming() overlaps network transfer with compilation — but every gate failure lands as a plain TypeError (not CompileError): wrong MIME, non-OK status, a disturbed body, a non-Response argument. Constructed Response objects with the right headers work fine — you can stream-compile from bytes you already hold, no server round-trip needed.

  

  






  
08The clone laws & the byte-keyed compile cache

  
WebAssembly.Module is structured-cloneable and postMessage-able — you can compile once on the main thread and hand the compiled module to a worker pool (no re-compilation). Instance is not cloneable — functions and imports can't cross. And the quiet one: compiling the same bytes repeatedly hits an in-memory cache — watch the third sync compile of a 189 KB module cost ~0.0 ms.

10JSPI — the newest door (and the one that's missing)

  
new WebAssembly.Suspending(fn) wraps a Promise-returning JS import so wasm can await it via WebAssembly.promising(exportedFn) — imported async, exported synchronous-looking. All shipped. The missing door: WebAssembly.Function (type reflection) — you cannot construct a wasm-signature JS function from script on this engine.

  






  
11The X25 capstone — MAVLink checksums: verify MATCH, and the 1.2× honesty benchmark

  
The 157-byte crc.wasm implements the exact X25 CRC every MAVLink v2 frame carries (poly 0x8408, init 0xFFFF), verified against a JS reference over random bytes. Then the folklore check: “wasm is near-native, expect 10×” — for a scalar byte-at-a-time loop, this engine's TurboFan'd JS is within 1.2× of the identical wasm. The wasm win is real but workload-shaped: SIMD, threads, or avoiding JS glue — not re-writing tight loops.

  

  






  
12Production rules — when the wasm tier earns its keep

  

    
    
      
  • Reach for wasm when the job is: compression levels the native API won't expose (the Compression Streams no-knob law), binary protocol parse/serialize at wire speed (MAVLink, CNC, DDS), codecs/filters/DSP, or running an existing C/Rust toolchain (font subsetting, image codecs).
    • 
      
  • Measure before migrating scalar loops — this page's X25 benchmark measured 1.2×. TurboFan is a compiler too; wasm's edge is SIMD/threads/GC-language runtimes, not beating optimized scalar JS.
    • 
      
  • Stream big modules — compileStreaming(fetch(url)) overlaps transfer and compile; keep the server MIME application/wasm or the gate slams shut with a bare TypeError.
    • 
      
  • Compile once, postMessage everywhere — Module is cloneable; Instance is not. Worker pools receive compiled modules, not bytes.
    • 
      
  • Re-acquire memory.buffer after every grow — the old buffer detaches; stale views throw the moment you touch them. Invert: shared memories never detach (old views read old length) — but there's no worker wall: shared wasm memory works even where SAB is undefined.
    • 
      
  • Feature-detect with validate(), not UA sniffing — every post-MVP feature above is one tiny crafted module away; the matrix runs on this page in microseconds.
