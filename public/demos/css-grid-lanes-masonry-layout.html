Section 2

The Problem Masonry Solves

Real content is not uniform. Photos have different aspect ratios, blog excerpts have different lengths, dashboard widgets have different densities. Regular grid stretches every row to its tallest item, leaving dead space everywhere:

Row gets stretched to the tallest card…
…because align-items defaults to stretch.
That dead space is why designers invented masonry.

For a decade the web answered with three workarounds — the CSS columns hack (broken ordering), JS libraries like Masonry.js and Isotope (layout thrash + bundle cost), or flex column tricks that break on reflow. Grid Lanes moves the packing algorithm into the browser layout engine, where it belongs.

Section 3

The Syntax Timeline — Three Generations

The feature shipped under three different names across nine years. Knowing all three matters because every one of them is still in blog posts, Stack Overflow answers, and detection code you will meet in production.

2017 → 2024 · Generation 1

The Grid Proposal — grid-template-rows: masonry

Masonry as a value on an existing grid property. Firefox implemented it behind a flag in 2017 and carried it for years. Simple, but vendors debated whether it belonged in Grid at all.

2025 · Generation 2

Interim Chromium — display: masonry

Chromium 140 shipped a standalone display: masonry value with its own masonry-* properties, behind experimental flags. Treated as a stepping stone.

2025 → 2026 · Generation 3 — FINAL

CSS Grid Level 3 — display: grid-lanes

The spec settled on new display values grid-lanes / inline-grid-lanes (css-grid-3). Safari 26 is the first stable browser. Chromium is migrating from its interim syntax; Firefox keeps its long-running flag. MDN documents Grid Lanes under this name.

/* ── Generation 1: the old proposal (2017–2024) ───────────── */
.masonry {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: masonry;  /* packing on the row axis */
}

/* ── Generation 3: final spec syntax (css-grid-3, 2026) ──── */
.masonry {
  display: grid-lanes;          /* or inline-grid-lanes */
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));
  gap: 1rem;
}
Axis rule (memorize this). For column-based masonry — Pinterest style, items flow into the shortest column — the row axis is masonry, so the old syntax writes grid-template-rows: masonry. For row-based masonry (items flow into the shortest row), it's grid-template-columns: masonry. With the final display: grid-lanes, the packing applies to whichever axis has no explicit tracks.
Section 4

The Production Recipe — Progressive Enhancement

This is the pattern to ship today. Unsupported browsers get a clean start-aligned grid. Safari 26 gets true packing. When Chromium and Firefox go stable, your sites upgrade automatically — zero code changes.

/* 1 — The fallback: works everywhere, looks decent */
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
  gap: 1rem;
  align-items: start;          /* ← prevents row stretch, the crucial line */
}

/* 2 — Enhancement A: legacy syntax (Safari 26 recognizes it) */
@supports (grid-template-rows: masonry) {
  .card-grid { grid-template-rows: masonry; }
}

/* 3 — Enhancement B: final syntax, wins when supported */
@supports (display: grid-lanes) {
  .card-grid {
    display: grid-lanes;
    grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
    gap: 1rem;
  }
}

JS detection, if you need telemetry or badges:

const legacy  = CSS.supports('grid-template-rows', 'masonry');
const final_ = CSS.supports('display', 'grid-lanes');
const native = legacy || final_;

Section 6

The Ordering Problem — Why the Columns Hack Fails A11y

The classic CSS columns: 3 hack flows content top-to-bottom down column one, then column two. The visual order diverges from the DOM order — screen readers announce item 4 after item 3 even though it's rendered far below item 9, and keyboard focus teleports across the page. Grid Lanes places items into the shortest lane while preserving DOM order.

1DOM 1
2DOM 2
3DOM 3
4DOM 4
5DOM 5
6DOM 6

Reading the rows above, your eye follows 1 → 2 → 3 left to right, matching the numbers. Under the columns hack the same DOM would render 1-2 stacked in column one, and your eye would read 1 → 4 while a screen reader reads 1 → 2. That mismatch is an accessibility failure — and the reason native packing (which flows 1 into the first lane, 2 into the next shortest lane, and so on, in order) is the right default.

A11y win: with Grid Lanes, sequential focus order and visual order agree, because placement follows DOM order. No order gymnastics, no reading-mode surprises.

Section 8

Performance — What You Delete

JS masonry libraries position items with position: absolute and top/left math, recomputed on every resize, image load, filter change, and content mutation. Each recompute forces synchronous layout (read offsetHeight → write styles → read again) — the classic layout-thrash loop. Native packing runs inside the browser's layout engine: incremental, main-thread-cheap, and image-load aware by default.

React + Tailwind component

// components/MasonryGrid.tsx — progressive enhancement, zero deps
export function MasonryGrid({ children, min = '280px' }) {
  return (
    <div className="grid gap-4 [grid-template-columns:repeat(auto-fill,minmax(var(--min),1fr))]
                         [align-items:start] supports-[grid-template-rows:masonry]:[grid-template-rows:masonry]
                         supports-[display:grid-lanes]:[display:grid-lanes]"
         style={{ '--min': min }}>
      {children}
    </div>
  );
}

When NOT to use it

  • You need precise row alignment across columns — use regular grid.
  • Cards must have equal heights (pricing tables) — use grid with align-items: stretch.
  • Complex spanning behavior is central to the design.

Recap — the five things that matter

  • The spec name is Grid Lanes (css-grid-3): display: grid-lanes / inline-grid-lanes; the older grid-template-rows: masonry form is the Generation-1 syntax you'll still detect via @supports.
  • Safari 26 shipped first; Chromium and Firefox are flag-gated (Aug 2026). Baseline status: Limited.
  • Fallback is one line: align-items: start on the grid — everything else is enhancement.
  • It fixes accessibility the columns hack breaks: DOM order = visual order = focus order.
  • It deletes a JS dependency (~10–60 KB + forced-reflow packing) with engine-native layout.
