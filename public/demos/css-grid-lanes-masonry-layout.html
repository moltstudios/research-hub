Section 2 — Background

The 10-Year War for Native Masonry

Masonry layout — the "waterfall" pattern where items of different heights pack into columns without strict row alignment — has been the single most-requested CSS feature since Pinterest popularized it in 2012. For a decade, the only solutions were:

// The dark ages: 2012-2024 // 30KB of Masonry.js reading dimensions AFTER layout // 74KB of Isotope doing the same thing + jQuery transit // Resize listeners thrashing INP to 80-300ms // CLS scores through the roof as images "snap" into place // The dream: one line of CSS .gallery { display: grid-lanes; grid-template-columns: repeat(auto-fill, minmax(160px, 1fr)); }

2026 is the year it shipped. The W3C CSS Grid Level 3 spec introduced display: grid-lanes — a dedicated display mode where items flow into grid tracks in one axis but stack freely (like flexbox) in the other. Chrome 121+ and Safari 17.4+ ship it today. Firefox has it behind a flag. The era of JavaScript masonry libraries is officially over.

The spec evolution: three names, one idea

/* Era 1 (2019-2024): grid-template-rows: masonry */ .gallery { display: grid; grid-template-columns: repeat(3, 1fr); grid-template-rows: masonry; /* Firefox shipped this first */ } /* Era 2 (2024-2025): display: masonry */ .gallery { display: masonry; /* Chrome experimental flag */ masonry-template-tracks: repeat(3, 1fr); } /* Era 3 (2026 — CURRENT): display: grid-lanes */ .gallery { display: grid-lanes; /* W3C Draft 2026 — THE spec syntax */ grid-template-columns: repeat(3, 1fr); } /* All three coexist via @supports — we'll show you the cascade */

Section 4 — Implementation

The 3-Line Recipe

The entire native masonry API is three declarations. Everything else is styling.

/* The COMPLETE native masonry API: */ .gallery { display: grid-lanes; grid-template-columns: repeat(auto-fill, minmax(160px, 1fr)); gap: 12px; } /* That's it. Items flow into columns, packing into the column with the most remaining space automatically. No JS. No resize listeners. No dimension reading. The browser's layout engine does all the packing at compositor speed. */

The universal @supports cascade (ship today)

Until Firefox ships grid-lanes unflagged (~Q4 2026 estimate), use this progressive enhancement cascade. It works in 100% of browsers:

/* Tier 1: Universal base — CSS multi-column */ .gallery { columns: 180px; column-gap: 12px; } .gallery > * { break-inside: avoid; margin-bottom: 12px; } /* Tier 2: grid-template-rows: masonry (Firefox + older Safari) */ @supports (grid-template-rows: masonry) { .gallery { display: grid; grid-template-columns: repeat(auto-fill, minmax(160px, 1fr)); grid-template-rows: masonry; columns: initial; /* reset multicol */ } } /* Tier 3: display: grid-lanes (THE 2026 SPEC — Chrome 121+, Safari 17.4+) */ @supports (display: grid-lanes) { .gallery { display: grid-lanes; grid-template-columns: repeat(auto-fill, minmax(160px, 1fr)); grid-template-rows: initial; /* reset legacy */ } } /* Result: best available engine in every browser, zero JS */

Section 8 — Spec Deep Dive

Grid Lanes: More Than Just Masonry

The CSS Grid Level 3 spec is not just "masonry for grids." The working group renamed it "Grid Lanes Layout" because the pattern is more general than Pinterest-style waterfalls. Two distinct use cases drove the spec:

1. Waterfall layout (the classic)

Items auto-place into the column (or row) with the most remaining space. This is the Pinterest pattern. Items flow top-to-bottom, but the "shortest column wins" heuristic produces the tightly packed wall without strict row tracks.

/* Waterfall — items auto-place into shortest column */ .pinterest-wall { display: grid-lanes; grid-template-columns: repeat(auto-fill, minmax(200px, 1fr)); gap: 16px; }

2. One-dimensional grid layout (the new pattern)

Items are explicitly placed into columns by line-based positioning — but there are no rows. Items in each column stack one after another. This enables layouts that are impossible in regular grid (because spanning relationships depend on item heights) and impossible in flexbox (because source order goes back and forth between columns).

/* One-dimensional grid — explicit column placement, no rows */ .dashboard { display: grid-lanes; grid-template-columns: 2fr 1fr; } .dashboard > :nth-child(1) { grid-column: 1; } /* main feed */ .dashboard > :nth-child(2) { grid-column: 2; } /* sidebar */ .dashboard > :nth-child(3) { grid-column: 1; } /* next in feed */ .dashboard > :nth-child(4) { grid-column: 2; } /* next in sidebar */

Subgrid + Grid Lanes = the layout superweapon. The spec explicitly states subgrid items are supported — but subgridding only occurs in the grid axis. This means you can align items across columns (labels, icons, values) while letting them stack freely vertically. The combination of Subgrid (P1, already documented) + Grid Lanes is the most powerful CSS layout primitive set available.

The migration path is trivial. Replace the Masonry.js container with display: grid-lanes (or columns for the fallback). Delete the <script> tag. Add aspect-ratio to tiles. Done. The CSS engine handles all packing at compositor speed — no resize listeners, no image-load handlers, no absolute positioning. Sites that migrate see INP improvements of 80-300ms and CLS go to 0.

Section 10 — Recap

When to Use What

✅ Use Grid Lanes (display: grid-lanes) when…

  • Building new masonry walls in 2026+
  • Chrome/Safari/Edge are your target (>77% of traffic)
  • Reading order must match DOM order (accessibility)
  • You want zero-JS layout
  • You're building dashboards with one-dimensional grid patterns

✅ Use Multi-column when…

  • You need 100% browser support today
  • Gallery/wall pattern (browse, not chronological)
  • Simple Pinterest-style image walls
  • News/article card walls
  • As the Tier 1 fallback in the @supports cascade

✅ Use Grid row-span lattice when…

  • Strict chronological reading order is critical
  • You can quantize tile heights into row multiples
  • Building infinite scroll feeds (append-stable)
  • Accessibility (WCAG 1.3.2) is non-negotiable

❌ Never use Masonry.js / Isotope when…

  • It's 2026 and CSS can do it natively
  • INP and CLS scores matter (they always do)
  • Mobile performance matters (30-74KB + thrash)
  • Google Ad Quality Score affects your CPC
  • You care about accessibility (JS positioning breaks screen readers)
