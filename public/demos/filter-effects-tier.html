Filter Effects & backdrop-filter — the pixel-effects tier

The engine laws beneath every glassmorphism panel, frosted HUD and image treatment: the identity-value trap, the backdrop-root law, the two invalidation grammars, the serialization contract and the interpolation grammar — live-probed on Chromium 154.

00Tier map — what this entry covers

filter re-processes an element and everything inside it after paint (blur, color matrix ops, shadows, SVG filter graph references). backdrop-filter re-processes whatever is painted behind the element — the frosted-glass primitive. Same function grammar, opposite direction of effect.

The catalog had exactly two trend-layer entries touching this tier (Liquid Glass, Glassmorphism 2.0 — the LOOK) and zero coverage of the ENGINE LAWS: containing-block traps, backdrop roots, invalidation grammar, serialization and interpolation. This entry is the substrate beneath those two — and beneath every panel the liquid-glass work ships.

03THE IDENTITY-VALUE TRAP — layout effects with zero visual effect

The headline law: any computed filter other than none — including visually-identity values like blur(0px), grayscale(0), opacity(1), sepia(0) — creates a containing block for fixed/absolute descendants AND a stacking context. Same for any backdrop-filter ≠ none and for will-change: filter. Your fixed header silently becomes absolutely-positioned the moment an ancestor gains a no-op filter. To un-latch, set filter: none — a zero filter does not count as none.

Live measurement — a position:fixed; top:0; left:0 child inside an ancestor parked at (100,100). If the child measures (100,100), the ancestor forms its containing block:

Note the asymmetry: opacity: 0.99 creates a stacking context but NOT a containing block (row 7) — filter creates BOTH. And the stacking-context half is pixel-proven: a z-index:-1 child of a blur(0) host paints ABOVE the host background (measured #0000ff over #ff0000) — without the stacking context it would sink beneath it.

05THE BACKDROP-ROOT LAW — what kills frosted glass

backdrop-filter samples the painted content behind the element — but only up to the nearest backdrop root. An ancestor with any filter ≠ none, opacity < 1, a mask (even fully opaque), a clip-path (even inset(0)), or will-change of those becomes the backdrop root — the glass panel then samples only that ancestor (transparent) and the effect dies silently. No error, no warning — the panel just stops frosting.

The toggle buttons are the full census — probed by pixel sampling (probe 3):

The animation-safe lane: transform does NOT create a backdrop root on this engine — glass panels inside transform-animated parents keep their frosting (the floating panel in §12 runs on exactly this lane). Filter-animated parents kill it.

06drop-shadow follows alpha — box-shadow follows the box

filter: drop-shadow() shadows the alpha silhouette; box-shadow shadows the border box. For any non-rectangular content — transparent PNGs, canvas sprites, SVG glyphs, clipped shapes — they are different primitives. Pixel-probed on a canvas-generated star:

box-shadow — rectangle ring (corners filled)
drop-shadow — silhouette glow (corners empty)

Measured: outside the box corner: box-shadow paints #008000, drop-shadow paints #ffffff. Also probed: multiple drop-shadows stack (drop-shadow(...) drop-shadow(...) is legal), and the no-color form defaults to currentColor (computed rgb(0, 0, 0) here).

07The glass contract — opacity, radius, scroll

Three panels, all backdrop-filter: grayscale(1) over a red/blue split: opaque background = invisible effect (measured #ffffff — the backdrop is covered); semi-transparent = the design lane; no background at all = still works (grayscale measured through it). And backdrop-filter clips to border-radius — the circle panel corners show the raw red (#ff0000), unsampled.

The scroll law: pixel-probed with content scrolling under a fixed glass panel — the backdrop re-samples live on composited scroll (#9c40a3 → #a3409c as the stripes swapped). The historical frozen-backdrop bug class is gone on 154. backdrop-filter also creates a stacking context (same z:-1 pixel proof as §03) — glass panels isolate their children like filtered elements do.

08The two invalidation grammars — url() vs negative args

Two OPPOSITE failure grammars live in one property:

  • THE WHOLE-LIST KILL (parse time): a negative argument — blur(-5px), grayscale(-1), saturate(-1), brightness(-0.5) — invalidates the entire declaration. Computed reads none. Every function in the list is lost.
  • THE PER-ITEM NO-OP (reference time): url(#missing-id) — a reference to a filter that does not exist — is silently dropped from the list, and the remaining functions still apply. Measured: url(#missing-id) grayscale(1) → the red swatch renders gray (#363636). A pure missing reference renders the element unfiltered but visible (#ff0000) — falsifying the folklore that the element disappears (the spec says it should; Chromium 154 keeps painting).
url(#real) — feGaussianBlur 10
url(#missing)
url(#missing) grayscale(1)

The real reference works — an SVG feGaussianBlur via url() bleeds color past the border box (measured #ffafaf fringe at the corner) and can combine with function filters in one list. Rule of thumb: validate args at parse, references at runtime — and never build a design that depends on the missing-url element staying visible; other engines follow the spec and hide it.

09The interpolation grammar — matched lists only

Filter lists interpolate only when functions match pairwise — same functions, same order, same length. Anything else is a discrete jump. Measured mid-flight (200 ms into a 400 ms linear transition):

Design-system rule: keep hover/active state filters as the same function list with changed args (grayscale(.8) blur(0) → grayscale(0) blur(0)) — never change the function set mid-interaction, or the transition silently becomes a hard cut.

10Canvas ctx.filter — the same grammar, second surface

Canvas 2D contexts accept the same function list in ctx.filter (Chromium + Firefox; Safari trails). Probed: readback round-trips blur(4px), accepts url() references — and an invalid assignment is a silent no-op retaining the previous value (assigning blur(nope) leaves the last valid filter in place). Reset with ctx.filter = 'none'.

11The html-root filter — page-wide reprocessing

A filter on <html> applies to the entire rendered page — pixel-probed: filter: sepia(1) on the root turned a cyan swatch #00ffff → #f4daaa. This is the dark-mode hack lane (invert(1) hue-rotate(180deg)) and the print-tint lane — one declaration, every pixel. Removing it restores exactly (computed returns to none).

—

Cost warning: the root filter re-runs on every repaint of everything — the most expensive possible filter placement. Ship it behind a toggle, never an animation.

The 10 rules:

  • 1. blur(0) is not "no filter" — layout effects persist; only filter: none un-latches.
  • 2. Ancestor filter/opacity<1/mask/clip-path/will-change = backdrop root = dead glass, silently.
  • 3. Transform ancestors are the glass-safe animation lane.
  • 4. Opaque background hides backdrop-filter entirely; transparent works fine.
  • 5. backdrop-filter clips to border-radius; filter does not clip (it bleeds — margin accordingly).
  • 6. Negative args kill the whole declaration at parse; missing url() refs no-op per-item at runtime.
  • 7. Transition filters as matched lists only — same functions, same order.
  • 8. Computed filter is a rewrite — never string-compare against your authored value.
  • 9. drop-shadow for silhouettes, box-shadow for boxes; both stack.
  • 10. Repaint-triggering content under a big blur re-runs the filter every frame — verify on real devices; transform-only animation does not.
