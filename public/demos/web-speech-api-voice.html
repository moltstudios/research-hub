The whole API, in one screen

// OUT — speechSynthesis (every browser since ~2014, Baseline)
const u = new SpeechSynthesisUtterance("Telemetry nominal.");
u.voice = speechSynthesis.getVoices().find(v => v.lang.startsWith("en"));
u.rate = 1; u.pitch = 1;
u.onboundary = e => highlightWord(e.charIndex);  // word-level timing
speechSynthesis.speak(u);            // queued, not fired-and-forgotten
speechSynthesis.pause(); speechSynthesis.resume(); speechSynthesis.cancel();

// IN — SpeechRecognition (Chrome/Edge 33+, Safari 14.1+; Firefox ✗)
const SR = window.SpeechRecognition || window.webkitSpeechRecognition;
const r = new SR();
r.continuous = true;      // keep listening across pauses
r.interimResults = true;  // stream partials as you speak
r.lang = "en-US";
r.onresult = e => {
  for (const res of e.results) {
    if (res.isFinal) console.log(res[0].transcript, res[0].confidence);
  }
};
r.start();  // requires user gesture + mic permission

Key gotchas the demo encodes: voices populate async (listen for voiceschanged); Chrome's recognition is server-assisted (network-dependent) while Safari's is on-device; iOS needs a direct user gesture per start().

Where it earns its keep

  • OpenDrones Mission Control — spoken preflight checklists and battery alerts (hands stay on the sticks); "arm", "RTL", "hold" voice commands with confirmation echo.
  • Accessibility — instant audio versions of any article, form errors read aloud, eyes-free kiosk modes. Screen-reader users get alternatives, not replacements.
  • Voice-driven UI — hands-busy workflows: cooking sites, field inspections, warehouse pick lists.
  • Language learning — pronunciation comparison with the confidence score as instant feedback.
  • Zero-cost IVR — prototype phone-tree flows in the browser before committing to telephony infra.
