🔬 Web Platform Research — Cross-Tab Coordination

Web Locks API + BroadcastChannel — one tab flies the drone, the rest just watch

navigator.locks is the platform's same-origin mutex: it works across tabs, windows, and workers, releases locks automatically when a holder closes or crashes, and gives you exclusive vs shared modes, ifAvailable, steal, and AbortSignal timeouts. Pair it with BroadcastChannel for instant tab-to-tab messaging and you get leader election, hardware-port ownership, and cross-tab state sync — no server, no libraries.

02 — The problem

Two tabs, one resource, zero coordination

Mission Control opens in multiple tabs by design — inspector, map, logs. Every exclusive resource in that app has a multi-tab failure mode.

🔌 Web Serial port

Tab A opens the USB telemetry port. Tab B opens the same port — the OS allows it in some drivers, both streams corrupt, or B errors with a confusing PermissionDenied. Two "pilots" on one stick.

📡 Duplicate subscriptions

Every tab connects its own WebTransport/WebSocket to the telemetry relay. Double subscriptions, double cost, and duplicate commands sent to the aircraft — the dangerous one.

💾 Storage write races

Two tabs sync OPFS/IndexedDB flight logs concurrently. Last-writer-wins clobbers records. localStorage flag hacks ("isAnotherTabOpen") are racy and never clean up after a crash.

The old hacks, and why they fail

  • localStorage sentinel keys — require heartbeat polling to detect a crashed tab; leave stale locks after force-quit; race between get/set.
  • "Check before connect" — TOCTOU race: both tabs check, both connect.
  • Doing nothing — works until a pilot duplicates a tab to compare missions, then commands double-fire.

The platform's answer: a lock manager built into the browser, one per storage bucket, that the browser itself keeps consistent and cleans up on tab death — free.

03 — The API in 60 seconds

Request → hold → auto-release

One method does everything: navigator.locks.request(name, options?, callback). The callback runs when the lock is granted; the lock is released when the callback's promise settles. That's the whole mental model.

// The one-liner everyone starts with:
await navigator.locks.request('telemetry-sync', async (lock) => {
  // granted — nobody else on this origin can hold 'telemetry-sync' now
  await syncDatabase();
  // returning ⟶ promise settles ⟶ lock released automatically
});
// released — queued requests in OTHER tabs get granted next

// Hold for an arbitrary time (the "primary tab" pattern):
const { promise, resolve } = Promise.withResolvers();
navigator.locks.request('leader', (lock) => {
  isLeader = true;
  return promise;  // held until resolve() is called OR this tab dies
});

// Try without waiting; bail out instantly if taken:
await navigator.locks.request('serial:ttyACM0', { ifAvailable: true }, async (lock) => {
  if (!lock) return showNotice('Port already in use by another tab');
  await usePort();
});

Lifecycle guarantees

Lock released when: callback promise settles, the request's AbortSignal fires while pending, steal preempts, or the holding tab/worker closes or crashes. No heartbeats. No cleanup code.

Scope

One lock manager per storage bucket — for normal first-party pages that means the origin: all tabs, iframes, and workers of this origin share the same lock namespace. Different browsers, profiles, and private windows are separate.

Rules

Secure context (HTTPS/localhost) only. Names are any string — but names starting with - are reserved and throw. Works in dedicated/shared/service workers.

06 — Modes & options

Exclusive vs shared, ifAvailable, steal, signal

Four options make the primitive production-grade. mode: 'shared' implements the classic readers-writer lock: many shared holders OR exactly one exclusive holder.

🧰 The four options, one line each

mode'exclusive' (default) — mutual exclusion. 'shared' — coexists with other shared, blocks exclusive. Readers-writer pattern.
ifAvailableNever wait: callback gets null if the lock is held. Perfect for "the other tab is already on it, do nothing."
stealForce-take: releases the current holder (their request rejects with AbortError) and preempts the queue. Admin override — use sparingly.
signalAbortSignal that cancels the request while it's still pending. How you build timeouts without hanging forever.

07 — The centerpiece: multi-tab tug-of-war

Two tabs, one telemetry link

This is the Mission Control problem in miniature: an exclusive resource (mc-telemetry-link) that only one tab may own. Open a partner tab, fight over the lock, then close the holder's tab mid-flight and watch failover happen with zero cleanup code.

📋 The drill

  1. Tab 1: Acquire (wait) → holds the link
  2. Tab 2: Acquire (wait) → pends (yellow)
  3. Tab 1: Release → Tab 2 auto-granted ✓
  4. Failover test: Tab 1 re-acquires, Tab 2 queues… then close Tab 1 entirely — the browser releases its locks and Tab 2 takes over instantly. No heartbeat. No stale state.

08 — Leader election & failover

The "primary tab" pattern, live

Every tab queues for the wl-leader lock. Exactly one is granted — it holds forever. Close the leader tab and the next tab in the queue is promoted automatically. This is the spec's own motivating use case, and it's the backbone of single-subscriber telemetry, one-tab sync, and "who owns the WebSocket."

NOT PARTICIPATING
💡
Open the partner tab from §7 and join there too — leadership badges update in both tabs via BroadcastChannel. Then close whichever tab is leader and watch the survivor promote itself.
// Production leader election — the whole thing:
const chan = new BroadcastChannel('app-state');
let releaseLeadership;
navigator.locks.request('app-leader', async () => {
  // I'm the primary tab now — do the exclusive work:
  // telemetry subscription, periodic sync, badge broadcasts
  chan.postMessage({ type: 'leader', tab: tabId });
  await new Promise(r => releaseLeadership = r); // hold forever
}).catch(() => {}); // preempted by steal or aborted — fall back to follower
09 — BroadcastChannel: the message bus

Locks decide who, channels say what

BroadcastChannel is postMessage for every same-origin context at once: tabs, windows, iframes, workers — no BroadcastChannel object sharing needed, no localStorage storage event hacks, structured-clone payloads. It doesn't coordinate anything by itself; paired with Web Locks it carries the state that follows the decision.

🏓 Ping / pong (needs 2 tabs)

Partner tab auto-replies to pings. Every message lands in both tabs' logs.

What each primitive is for

10 — Production pattern — OpenDrones Mission Control

Hardware ownership + single subscriber + shared readers

Three lock conventions turn Mission Control from "please don't open two tabs" into "open as many tabs as you want, exactly one is flying."

// ── 1. Exclusive hardware ownership (Web Serial port):
//    lock name = resource path ⟹ conflict impossible by construction
async function withSerialPort(path, fn) {
  return navigator.locks.request(
    `serial:${path}`, { ifAvailable: true },
    async (lock) => {
      if (!lock) throw new Error(`port ${path} owned by another tab — read-only mode`);
      const port = await openPort(path);
      try { return await fn(port); } finally { await port.close(); }
    }
  );
}

// ── 2. Single telemetry subscriber (leader pattern):
//    one connection per aircraft; every tab renders via BroadcastChannel
await navigator.locks.request(`telemetry:${droneId}`, async () => {
  const conn = await transport.connect(relayUrl);
  conn.onTelemetry = (frame) => chan.postMessage({ type: 'telemetry', frame });
  await holdUntilPageDeath;          // tab closes ⟶ lock + connection die together
});                                       // queued tab auto-promotes ⟶ reconnects

// ── 3. Flight log writes: exclusive writer, shared readers
async function appendFlightLog(entry) {
  return navigator.locks.request(`log:${missionId}`, async () => {
    await opfsAppend(entry);            // serialized — no interleaved writes, ever
  });
}
async function readFlightLog() {
  return navigator.locks.request(`log:${missionId}`,
    { mode: 'shared' }, () => opfsRead());  // parallel reads, blocked during writes
}

Naming convention

resource:id — serial:, telemetry:, log:, sync:. Self-documenting in query() output; deadlocks impossible if you never nest two different lock names.

Failover semantics

Holder dies ⟶ browser releases ⟶ next queued tab granted ⟶ it reconnects and broadcasts "I'm primary." The reconnect script belongs in the grant callback.

Pilot UX

ifAvailable + a banner: "This tab is observing — flying happens in the other tab." Never silently own hardware twice.

Add to cart in one tab → every tab updates instantly via BroadcastChannel. No library, no websocket, works offline. The one-liner most clients actually want.

CMS/quote-builder forms: acquire edit:{docId} with ifAvailable. Second tab gets read-only + a notice with a "take over" button (steal). Kills silent last-write-wins clobbering.

Duplicate-tab submit races are a real e-commerce support ticket. A checkout:{cartId} lock around payment init makes double-charge structurally impossible.

Leader-elected tab is the only one that shows toasts/plays sounds for push events — no echo chorus across five tabs.

🌗 Instant theme/locale fan-out

Toggle dark mode or language in one tab; every tab repaints the same frame via channel message. No re-read from storage.

Broadcast a logout message; all tabs clear UI state and redirect — the classic SPA "log me out of all my tabs" feature in 6 lines.

⚠️ Gotchas worth memorizing

  • Secure context only — HTTPS or localhost. file:// won't have it.
  • Names starting with - throw NotSupportedError — reserved namespace.
  • Deadlocks are possible if you nest different lock names out of order (Tab1 holds A wants B; Tab2 holds B wants A). Never nest, or always acquire in sorted order, or always pass signal timeouts.
  • steal is rude — the victim's request rejects AbortError; their callback may be mid-work. Reserve for admin overrides.
  • Per storage bucket — partitioned third-party iframes get their own lock namespace (privacy feature, not a bug). First-party tabs all share one namespace.
  • Not cross-browser/profile/private — separate user agents = separate lock managers, by design.
  • Hold-forever needs a promise — return Promise.withResolvers().promise; a callback that returns nothing releases immediately.
