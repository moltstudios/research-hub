2 · The 5-Line Graph Recipe

WebNN models neural networks as computational graphs — directed graphs where nodes are operations (matmul, conv2d, relu, softmax) and edges carry tensors. Four phases: Build → Compile → Execute → Read.

// C = 0.2 × A + B  (element-wise tensor operation)

// 1. Create context + builder
const context = await navigator.ml.createContext();
const builder = new MLGraphBuilder(context);

// 2. Build the graph
const desc = { dataType: 'float32', shape: [2, 2] };
const scale = builder.constant(desc, new Float32Array(4).fill(0.2));
const A = builder.input('A', desc);
const B = builder.input('B', desc);
const C = builder.add(builder.mul(A, scale), B);

// 3. Compile the graph
const graph = await builder.build({ 'C': C });

// 4. Create tensors + write inputs
const tA = context.createTensor({ ...desc, writable: true });
const tB = context.createTensor({ ...desc, writable: true });
const tC = context.createTensor({ ...desc, readable: true });
context.writeTensor(tA, new Float32Array([1,1,1,1]));
context.writeTensor(tB, new Float32Array([0.8,0.8,0.8,0.8]));

// 5. Dispatch + read result
context.dispatch(graph, { 'A': tA, 'B': tB }, { 'C': tC });
const result = await context.readTensor(tC);
console.log(new Float32Array(result)); // [1, 1, 1, 1]

Key insight: WebNN is NOT a model format or a model zoo. It's a low-level graph execution engine. You define operations (matmul, conv2d, relu, softmax, pool, normalize…) and the browser routes them to the fastest available hardware accelerator. Think of it as WebGPU Compute Shaders, but purpose-built for ML — with native NPU access, fused operations, and OS-level ML framework integration (Core ML on macOS, DirectML on Windows, NNAPI on Android).

// OpenDrones Mission Control — WebNN Vision Pipeline
const pipeline = {
  async init() {
    this.session = await ort.InferenceSession.create(yolov8NanoModel, {
      executionProviders: ['webnn', 'webgpu', 'wasm'],

    // 4. Draw overlays
    drawBoxes(this.overlay, detections);
    logAnomalies(detections); // → OPFS compliance buffer
  }
};

The Universal Fallback Chain

// Production-grade device selection
async function createSession(modelUri) {
  const backends = [];

  // 1. WebNN — try NPU first, then GPU, then CPU
  if ('ml' in navigator) {
    for (const deviceType of ['npu', 'gpu', 'cpu']) {
      try {
        const ctx = await navigator.ml.createContext({ deviceType });
        backends.push({ name: `webnn-${deviceType}`, ctx });
        break;
      } catch {}
    }
  }

  // 2. WebGPU — general GPU compute
  if ('gpu' in navigator) {
    backends.push({ name: 'webgpu' });
  }

  // 3. WASM — universal fallback
  backends.push({ name: 'wasm' });

  return await ort.InferenceSession.create(modelUri, {
    executionProviders: backends.map(b => b.name),
  });
}

Architecture pattern: Always offer ['webnn', 'webgpu', 'wasm'] as an ordered preference list. ONNX Runtime Web and Transformers.js both try each provider in sequence until one works. The user gets the fastest available backend transparently — no feature detection code needed in your app layer.
