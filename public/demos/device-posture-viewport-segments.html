§02 · The two-channel truth split

THE HEADLINE LAW. CSS reads the posture provider directly; the JS object is a cache updated by the change-event pump. Measured: a posture flip reaches type in 0–50 ms when a listener is armed (43 ms measured), can lag past 250 ms in a listener-free document after a reload, and a freshly-navigated document always gets the correct initial value. Paint from CSS; treat type as a subscription, not a read.

§05 · env(viewport-segment-*) geometry

Index semantics: env(viewport-segment-left|top|width|height <column> <row>, fallback) — column index first, row second. Out-of-range index → fallback. No index → fallback even when segments exist. No fallback, no segments → the custom property is guaranteed-invalid (computes to the empty string, not 0px). These are live computed values on this page:

Measured geometry (vertical hinge, offset 400, maskLength 24, viewport 800×600): segment (0,0) = [0,400) w=400px; segment (1,0) left edge = 424px (mask eats 400–424), w=376px; heights 600px. maskLength 0 → segments touch (seg 1 left = 400 not 424). Horizontal hinge @300 mask20 → row 1 top = 320px, h = 280px. Edge-fit hinge (776+24=800) → segment 2 is legally zero-width (left=800px).

The parser lie: CSS.supports() accepted every malformed variant probed — no index, one index, three indices. Validation happens at computed-value time, not parse time. Never gate on CSS.supports('left','env(viewport-segment-left)').

THE SILENT-REPOSITION LAW (measured, §10 lane): hinge moved 400→500 — env() values updated (424→524px) while (horizontal-viewport-segments: 2) fired zero change events. MQ tracks segment count; geometry moves are invisible to MQ listeners. Remove the hinge → count flips 2→1 → events fire. MQ-driven layouts don't reflow on repositioning; env()-driven ones do.

§07 · Fold-aware layout cookbook

The spanning question

Should content cross the hinge? Book/laptop folds: no (mask region is dead or awkward). Flat/flex mode: yes.

/* dead-zone guard — never paint over the mask */
.spanning { margin-inline: 0; }
@media (horizontal-viewport-segments: 2) {
  .spanning {
    margin-left: env(viewport-segment-width 0 0);
    margin-right: calc(-1 * (100vw - env(viewport-segment-left 1 0)));
  }
}

Two-pane from geometry

.panes { display: grid; }
@media (vertical-viewport-segments: 2) {
  .panes { grid-template-columns:
    env(viewport-segment-width 0 0)
    env(viewport-segment-width 1 0); }
}
@media (device-posture: folded) {
  .panes { grid-template-columns: 1fr; }
}

Posture for intent (fold = compact), segments for geometry (where to split). They are independent axes.

§10 · The emulation lane — CI recipes & the ordering traps

The fold lane is fully CI-drivable over CDP — but the display-features override has ordering laws that cost this probe suite two false "no-op" conclusions before the matrix below pinned them.

// posture (works standalone, fast, survives navigation)
await cdp.send('Emulation.setDevicePostureOverride', { posture: { type: 'folded' } });
await cdp.send('Emulation.clearDevicePostureOverride');

// THE RELIABLE hinge lane — displayFeature rides setDeviceMetricsOverride
await cdp.send('Emulation.setDeviceMetricsOverride', {
  width: 800, height: 600, deviceScaleFactor: 1, mobile: false,
  displayFeature: { orientation: 'vertical', offset: 400, maskLength: 24 }
});
// survives page reload (measured). clear with a metrics override
// that OMITS displayFeature, or clearDeviceMetricsOverride.
sequence (measured, Chromium 154)segments live?
fresh page → setDisplayFeaturesOverride only❌ silent no-op
…then clearDeviceMetricsOverride → re-set features❌ still dead
metrics override WITHOUT displayFeature after features set❌ wipes
metrics override WITH displayFeature (combined)✅ the lane
combined → page reload✅ survives
Playwright mid-test setViewportSize (sends its own metrics)⚠️ can silently wipe

Validation rejections (verbatim): overhanging hinge → Display feature viewport segments outside screen width · negative offset → Negative display feature offset · bogus orientation → Invalid display feature orientation · two features → Only one display feature is supported · bogus posture → Invalid posture type. Geometry is validated at the protocol boundary — one feature max, offset+mask must fit the screen.

Also on this tier: Overlay.setShowHinge paints a visual hinge for headed DevTools flows · DevTools device toolbar has a fold preset (the zero-code demo lane) · the JS object is secure-context-gated (plain-HTTP LAN → object-absent, never rejected) while the CSS MQ family still evaluated there — and workers get nothing: navigator exists, devicePosture absent.

§12 · Fallback ladder

  1. @media (device-posture) — the progressive-enhancement base: flat is the default posture, folded is the enhancement.
  2. Segments MQ + env() — geometry upgrades; on non-foldables every MQ is false and env() falls back — author fallbacks that already look right.
  3. JS: matchMedia('(device-posture: folded)') listener (works even where the JS object is absent — insecure origins).
  4. Aspect heuristics: span 2/aspect-ratio < 0.9 ≈ book fold; innerHeight/innerWidth > 1 && wide media ≈ laptop fold.
  5. Do nothing — the flat layout is the layout. The tier's defaults are the graceful path.

§13 · Ship checklist — 10 rules

  1. Default to flat. Folded is an enhancement, never a requirement.
  2. Paint from CSS; JS type is an event subscription, not a state read (§02).
  3. Never branch business logic on posture alone — check segments too; they're independent axes.
  4. Never paint the mask: hinge-adjacent padding from env(), not hard-coded px.
  5. Don't gate on CSS.supports() for env() — the parser accepts malformed variants (§05).
  6. Out-of-range env indices fall back — audit fallback strings so broken geometry is visible.
  7. Repositioning fires no MQ events — if hinge moves matter, observe env()/resize (§06).
  8. Same-posture re-set fires no change event — the engine dedupes; don't build retry counters on it.
  9. Feature-detect: 'devicePosture' in navigator for JS, MQ-in-@media for CSS. Object-absent on insecure origins and in workers — always.
  10. CI: use the combined metrics lane, one feature max, geometry inside the screen, no mid-test viewport resizes (§10).

§14 · Falsification ledger & provenance

  • Docs implication falsified: "type updates on posture change" — it updates eventually, via the pump; CSS is the truth channel (§02).
  • My own probe conclusions reversed twice: "direct features override is a no-op" (false — order-dependent) and "first override lags CSS by 250 ms+" (measurement artifact — the fresh-navigation control read correct at t=0). The §10 matrix is the post-reversal truth.
  • CSS.supports() accepts malformed env() — parse-time acceptance is meaningless on this tier.
  • Enumerable lie family: Object.keys(navigator.devicePosture) → []; JSON → {}; proto props only.
