Cookie Store API — the async cookie tier

cookieStore replaces the synchronous document.cookie string-parser with promise-based get / getAll / set / delete, structured CookieListItem objects, a change event that kills polling, and a Service Worker subscription lane. Live-probed headless on Chrome for Testing 154 — every green chip below re-verifies live in your browser on this page.

§01 · Capability & surface census

Secure-context-gated (Windows + Service Workers). Absent as an object (never a rejection) in dedicated Workers and on insecure non-loopback origins — typeof cookieStore === 'undefined' there, while document.cookie keeps working. The prototype census is exactly five members + constructor — no has() (the old explainer's has() never shipped).

// The whole surface (CfT 154, live):

→ ["delete", "get", "getAll", "set", "constructor", "onchange"]
cookieStore.has?.('x')   // TypeError: cookieStore.has is not a function

§02 · The 8-key CookieListItem shape

Every get()/getAll() hit returns the full structured cookie — not just name+value. domain:null = host-only (origin-locked). expires:null = session cookie. partitioned exposes CHIPS state.

probing…
await cookieStore.set('mrt_a', 'hello');   // → undefined (NOT the cookie!)
await cookieStore.get('mrt_a');
→ { name:"mrt_a", value:"hello", domain:null, path:"/",
    expires:null, sameSite:"strict", secure:true, partitioned:false }

MDN's caveat "some browsers will only return name and value" is stale for Chrome 154 — all 8 keys ship.

§03 · THE AUTO-SECURE LAW (headline #1)

Every cookieStore.set() write is Secure — always, by spec. The spec's set-a-cookie algorithm unconditionally appends the Secure attribute (§ Secure cookies: "This API only allows writes for Secure cookies"). There is no secure option in CookieInit — passing {secure:false} is silently ignored (unknown dictionary members never throw), and the readback is secure:true anyway.

probing…
await cookieStore.set({name:'x', value:'v', secure:false});  // accepted… silent ignore
await cookieStore.get('x');   // → { secure:true, … }   ← forced, no error, no warning

// document.cookie contrast (prefix rules NOT enforced on the string path — CfT 154):
document.cookie = '__Host_doc=1; path=/';         // STORED — but as a NON-Secure cookie!
document.cookie = '__Host_doc=1; path=/; Secure'; // stored, Secure

// but via cookieStore the prefix is trivially satisfied (Secure auto-appended,
// defaults domain:null + path:"/" already comply):
await cookieStore.set('__Host_cs', 'v');          // stored. __Host- for free.
The prefix-posture contrast: cookieStore.set() always writes Secure (prefix claims are always true by construction), while document.cookie will happily store a non-Secure cookie wearing a __Host- name — never trust a prefix name as proof of attributes when mixed writers touch the jar.
Production consequence: cookies written via cookieStore.set() are never sent over plain HTTP. On an http:// LAN control plane (OpenDrones ground stations!), cookieStore-written session cookies will simply not ride the requests — while document.cookie-written non-Secure ones will. Pick your writer API to match your transport, or half your auth will silently vanish.

§04 · sameSite defaults to "strict" (headline #2)

document.cookie writes default to Lax-by-default (RFC 6265bis). cookieStore.set() defaults to Strict (spec IDL default). Migrating a login cookie from string-slinging to cookieStore.set() without an explicit sameSite silently tightens CSRF posture — top-level navigation clicks from email links will stop carrying the cookie.

probing…
await cookieStore.set('s', 'v');               // → sameSite:"strict"  (spec default)
document.cookie = 's_doc=v; path=/';            // → Lax-by-default on readback
await cookieStore.set({name:'s2', value:'v', sameSite:'laxx'});
// TypeError: … "The provided value 'laxx' is not a valid enum value of type CookieSameSite"
// sameSite:'none' needs NO explicit secure:true here — auto-Secure (§03) legalizes it.

§05 · get / getAll grammar & the empty-name cookie

getAll() with no args → every in-scope cookie. get() with no args → TypeError (verbatim: "CookieStoreGetOptions must not be empty"). A miss resolves null — it never rejects. The empty-string name is legal: spec allows set('', 'val') if the value is non-empty, has no =, and doesn't start with a reserved prefix — and document.cookie then renders it as a bare value with no =.

§06 · Name/value laws: trimming, =, the 4096 cap

Names and values are normalized — leading/trailing TAB+SPACE stripped on both. A name containing =, or ;, or control chars → malformed TypeError. Name+value over 4096 bytes → malformed TypeError (the classic cap, now with a real error instead of silent drop). domain must not start with a dot and must be a registrable suffix of the host; expires + maxAge together → TypeError.

§07 · The url option: exact-document-URL only

In Documents, get({url}) must pass the document's own URL — same-origin-but-different-path throws. Service Workers get the superpower: any in-scope URL. Path visibility follows cookie-path rules: a cookie at /demos is visible from this page; one at /elsewhere is not — regardless of writer.

probing…
await cookieStore.get({url: location.href, name:'mrt_a'});          // ok (resolves or null)
await cookieStore.get({url: location.origin + '/other', name:'mrt_a'});
// TypeError: Failed to execute 'get' on 'CookieStore': URL must match the document URL

§08 · The change event — own writes fire, and so do other documents'

Unlike BroadcastChannel-style APIs, your own set()/delete() fire your own change — no echo suppression. The event carries changed[] + deleted[] of full CookieListItems. Writes via document.cookie fire it too (with their real attributes — typically secure:false). And delivery is origin-wide: other tabs and same-origin iframes receive events for your writes (live-verified cross-tab and cross-iframe on CfT 154) — cookie-sync UIs without storage events or polling.

§09 · Path scoping & the delete() path trap (headline #3)

delete(name) deletes at path "/" by default — a same-named cookie scoped to a deeper path survives. MDN's own set() example stores theme@/ and theme@/docs; delete('theme') leaves the /docs one untouched. Always delete with the full identity you set: delete({name, path}).

probing…
await cookieStore.set({name:'mrt_p', value:'deep', path: location.pathname.replace(/[^/]*$/,'') || '/'});
await cookieStore.delete('mrt_p');                        // aims at path "/"…
await cookieStore.getAll();                               // …mrt_p@/demos SURVIVES
await cookieStore.delete({name:'mrt_p', path:'/demos'});  // full-identity delete → gone

§10 · The Service Worker lane — subscriptions + the container-message law

SW gets self.cookieStore (read/write inside the worker) plus registration.cookies = CookieStoreManager. The shipped shape on CfT 154 is the spec shape — subscribe() / unsubscribe() / getSubscriptions(), cumulative, persisted with the registration. Old Chrome-87-era tutorials call setSubscriptions() → TypeError: not a function on current Chrome. Live-verified end-to-end on CfT 154: page sets a subscribed cookie → SW's cookiechange fires → SW broadcasts.

The integration bug I shipped twice: a SW's client.postMessage() lands on navigator.serviceWorker's "message" event — NOT window's. If your SW replies never arrive, check which target you listened on. (Page→SW: reg.active.postMessage() as usual.)
// sw.js — subscribe & listen (spec shape, Chrome 154 live-verified)
self.addEventListener('activate', e => e.waitUntil((async () => {
  const subs = await self.registration.cookies.getSubscriptions();
  await self.registration.cookies.unsubscribe(subs);          // reset
  await self.registration.cookies.subscribe([{ name: 'session_id' }]);
})()));
self.addEventListener('cookiechange', e => {
  // e.changed[] / e.deleted[] — full CookieListItem each
  self.clients.matchAll({ includeUncontrolled: true })
    .then(cs => cs.forEach(c => c.postMessage({ changed: e.changed })));
});

// page.js — SW→page arrives HERE, not on window:
navigator.serviceWorker.addEventListener('message', e => console.log(e.data));

Also live-verified: onchange is [Exposed=Window] — inside a SW use the cookiechange event; HttpOnly cookies stay invisible to cookieStore exactly like to document.cookie.

§11 · Capstones — OpenDrones & Molt Studios

🛩️ OpenDrones — consent & session on the ground station

Do: gate telemetry uploads on a consent cookie read via cookieStore.get('od_consent') in a module script (async, no parser); sync pilot-console tabs with change events (approach vector, no-fly popups — every tab updates when one grants consent); let a SW subscribe to the session cookie to hard-logout all consoles on expiry.

Don't: write auth cookies with cookieStore.set() on an http:// LAN deployment — §03's auto-Secure law makes them unsendable. On http control planes, write via document.cookie; on https, prefer cookieStore.

🎨 Molt Studios — hydration before first paint

Theme/auth state readable at module-eval time with top-level await: const theme = (await cookieStore.get('mrt_theme'))?.value ?? 'light' — applied before the first paint, zero cookie-string parsing, zero FOUC. The 8-key shape gives expiry for free: session cookies (expires:null) vs remembered ones — drive "remember me" UI from expires, not a second flag cookie.

§12 · Ship checklist

  1. Capability-detect typeof cookieStore !== 'undefined' — object-absent law, never a rejection.
  2. Never pass secure to set() — it doesn't exist; you cannot write non-Secure with this API.
  3. Always pass sameSite explicitly — the default is "strict", not Lax.
  4. set() resolves undefined — read back with get() if you need proof.
  1. Delete with full identity: delete({name, path, domain}) — default path is /.
  2. get() no-arg is a TypeError; misses resolve null — branch on null, not catch.
  3. In Documents, {url} must equal location.href; SWs may use any in-scope URL.
  4. SW replies arrive on navigator.serviceWorker's message event — not window.
  5. Old tutorials' setSubscriptions() → gone; the shipped shape is subscribe/unsubscribe/getSubscriptions.
  6. HttpOnly stays invisible; name+value ≤ 4096 bytes; names can't contain =.
