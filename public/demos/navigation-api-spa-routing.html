1 Live Capability Detection

The Navigation API hangs off window.navigation. If present, you get the full suite: navigate event, intercept(), history traversal, entry state, and scroll restoration — all built in.

// One-line feature detection
if ('navigation' in window) {
  // ✅ Navigation API is available
  navigation.addEventListener('navigate', handleNavigate);
} else {
  // ⚠️ Fall back to History API + popstate
  window.addEventListener('popstate', handlePopState);
}

2 The Old Way vs The New Way

The History API was never designed for SPAs. Building client-side routing meant wiring together three separate concerns manually. The Navigation API collapses all three into one event.

❌ History API (3 moving parts)

  • Global click listener on all <a> tags
  • Manual pushState() + preventDefault()
  • Separate popstate listener for back/forward
  • popstate doesn't fire on pushState
  • Can't read full history stack
  • Can't edit non-current entries
  • No scroll restoration API
  • No form submission handling

✅ Navigation API (1 event)

  • Single navigate event catches ALL navigations
  • Link clicks, back/forward, navigate() calls
  • intercept() handles URL + DOM + history
  • Full history stack via navigation.entries()
  • Per-entry state via getState()
  • Manual or automatic scroll restoration
  • Form POST caught via event.formData
  • Pairs natively with View Transitions API
// ── OLD: 3 separate concerns, manually wired ──
document.addEventListener('click', e => {
  const link = e.target.closest('a[data-route]');
  if (!link) return;
  e.preventDefault();
  history.pushState(null, '', link.href);
  renderRoute(new URL(link.href).pathname);
});
window.addEventListener('popstate', e => {
  renderRoute(location.pathname);
});
renderRoute(location.pathname); // initial render

// ── NEW: 1 centralized event ──
navigation.addEventListener('navigate', e => {
  if (!e.canIntercept) return;
  const url = new URL(e.destination.url);
  e.intercept({
    async handler() {
      await renderRoute(url.pathname);
    }
  });
});

5 Form Submission Without Page Reload

The navigate event catches all same-document form submissions. No onsubmit, no e.preventDefault(), no fetch() boilerplate — the event.formData property hands you the submitted data directly.

Quick Drone Registration

// Standard HTML form — NO JavaScript event handlers needed
// <form action="/register" method="POST"> ...

navigation.addEventListener('navigate', e => {
  if (e.formData && e.canIntercept) {
    e.intercept({
      async handler() {
        const data = e.formData;
        const name = data.get('drone_name');
        await api.registerDrone(data);
        showToast(`✅ ${name} registered`);
      }
    });
  }
});

6 Async Scroll Restoration

When a user hits Back after scrolling through a long list, the browser tries to restore scroll immediately — before async content loads. scroll: 'manual' lets you defer the scroll until data is ready.

navigation.addEventListener('navigate', e => {
  if (!e.canIntercept) return;

  e.intercept({
    scroll: 'manual',  // "I'll handle scroll timing"

    async handler() {
      // 1. Fetch the data for the route
      const items = await fetchTelemetryLog(url.pathname);

      // 2. Render — page now has its full height
      renderLog(items);

      // 3. NOW restore scroll position
      e.scroll();
    }
  });
});
Why this matters: Without this, a user scrolling a 500-item mission log, clicking into an entry, then hitting Back would land at the top of the page — not where they left off. scroll: 'manual' + event.scroll() solves this with zero state management.

7 View Transitions Integration

The Navigation API and View Transitions API are designed to work together. Wrap your DOM update in document.startViewTransition() inside the navigate handler for app-like morph animations.

navigation.addEventListener('navigate', e => {
  if (!e.canIntercept) return;
  const url = new URL(e.destination.url);

  e.intercept({
    async handler() {
      // 1. Fetch new content
      const html = await fetchPage(url.pathname);

      // 2. Wrap DOM update in view transition
      document.startViewTransition(() => {
        app.innerHTML = html;
      });
    }
  });
});
The pairing: Navigation API handles when to swap content (intercept). View Transitions handle how it looks (snapshot → morph). Together: zero-library SPA with native page transitions. Pairs with our existing Cross-Document View Transitions research (P2, MC c089f375).

8 OpenDrones Mission Control Router

The production pattern: route guards (auth check), telemetry data loading, view transitions, and per-route state — all in one centralized handler.

// OpenDrones Mission Control — production router
navigation.addEventListener('navigate', e => {
  if (!e.canIntercept || e.hashChange) return;

  const url = new URL(e.destination.url);
  const path = url.pathname;

  e.intercept({
    scroll: 'manual',

    async handler() {
      // 1. Auth guard — redirect to login if not signed in
      if (path.startsWith('/mission') && !auth.isAuthenticated) {
        navigation.navigate('/login', {
          state: { redirectTarget: path }
        });
        return;
      }

      // 2. Load route-specific data
      const data = await loadRouteData(path);

      // 3. Render with view transition
      document.startViewTransition(() => {
        renderApp(data);
      });

      // 4. Restore scroll after content is in the DOM
      e.scroll();
    }
  });
});

// Per-entry state: track visit counts for analytics
navigation.addEventListener('currententrychange', () => {
  const entry = navigation.currentEntry;
  const state = entry.getState() ?? {};
  navigation.updateCurrentEntry({
    state: { ...state, visits: (state.visits ?? 0) + 1 }
  });
  analytics.track('page_view', {
    path: new URL(entry.url).pathname,
    visits: state.visits + 1
  });
});

Why P2 (not P1 / not P3)

Not P1 — Next.js App Router already handles routing for our main projects. The Navigation API is a platform improvement, not a missing capability. Most client work runs on Next.js which abstracts routing.

Not P3 — It's Baseline newly available with ~93% support and directly replaces common dependencies (React Router, TanStack Router, custom History API hacks). High impact for non-framework builds.

Yes P2 — Ship-today for standalone SPAs, client sites that don't need Next.js, and OpenDrones Mission Control. Pairs with View Transitions (P2, MC c089f375), Custom Highlight API (P1), and Subgrid (P1) as the modern no-framework SPA toolkit.
