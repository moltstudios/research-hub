View Transitions API — the promise triple, the pseudo-tree, snapshot truth & the skip gauntlet

Same-document sVT() live-probed end to end: which promise settles first, what the old snapshot really contains, what duplicate names do to your DOM change, what skipTransition() leaves behind, how types/view-transition-class/view-transition-group compose — and the async-callback frozen-render trap, measured. Baseline core: Ch 111 · FF 144 · SF 18. Two prior catalog entries cover the React/Next layer and cross-document MPA morphs — this battery is the raw engine contract underneath both.

§01 — Detection ladder & engine badges

Eight capability gates probed live. The at-rule is the interesting one: CSS.supports() has no at-rule form — cross-document opt-in is detected by injecting a real @view-transition rule and reading the parsed constructor.

§02 — The promise triple: updateCallbackDone → ready → finished

A ViewTransition hands you three promises with three different meanings. Order of settlement, measured with a 1.6s-stretched transition so timing is unambiguous. Plus the zero-argument form and document.activeViewTransition.

§03 — Pseudo-tree anatomy: the six-layer shadow you can only style

The transition renders into ::view-transition → -group(name) → -image-pair → -old/-new pseudo-elements hanging off the root. You cannot querySelector them; you can read them with getComputedStyle and count their animations mid-flight.

§04 — Default 0.25s & the geometry channel

The UA default crossfade is 250ms; the group morph animates transform/width/height, never top/left. And the classic bug: stretching only the group leaves the fade at default length — measured both ways.

§05 — Snapshot truth: old is a frozen image, new is the live DOM

After ready, your page keeps running — scripts, rAF, layout. The old side is a bitmap that will never update again; the new side is the actual document. A canvas, a checkbox and a rAF counter prove which side lives.

§06 — The uniqueness wall: duplicate names skip the transition, not your change

Two live elements wearing the same view-transition-name is a capture-time violation. What actually breaks: the animations are skipped and ready rejects — but the DOM change from your update callback is already applied and stays applied. No rollback.

§07 — Skip, reject & the frozen-render trap

skipTransition() before/after ready, a rejecting update callback, and the async-callback trap: rendering is suppressed while the engine awaits your callback — rAF starves, the page is frozen, and a slow callback reads as a blank stall.

§08 — Types: one API, many choreographies

startViewTransition({ update, types: ['vt-typed-a','vt-typed-b'] }) tags the transition; html:active-view-transition-type(x) matches only during it. Direction-aware styling (push vs back) without globals — and the negative control: untyped transitions match nothing.

§09 — view-transition-class: style groups without naming every element

Give ten elements the same class and one ::view-transition-group(.cls) rule styles all ten — but each still needs its own unique name. The class is a styling hook, not an identity.

§10 — view-transition-group property: children ride the parent's morph (Ch 140+)

An unnamed child can declare view-transition-group: parent-name and be captured INTO the parent's group — one morphing unit, no per-child animation cost.

§11 — Scoped transitions: Element.startViewTransition() (Ch 147+)

The 2026 addition: transition a subtree only. What the engine actually does at document level — probed live, whatever the answer is.

§12 — The frontier: entry/exit, name: auto, reduced motion

Entry-only elements (name appears just in the new state), exit-only (gone after update), view-transition-name: auto unique-ification, and the prefers-reduced-motion twin — injected by the headless gate, since a page cannot emulate its own media query.

§13 — Capstones: OpenDrones fleet morph + Molt portfolio lightbox

Two production patterns using the exact mechanics probed above: dynamic naming (the name must exist at call time to be captured in the old snapshot — set inside the callback and it's entry-only), shared-element row→detail, and a reduced-motion-safe grid→overlay morph.
