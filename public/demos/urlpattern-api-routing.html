URLPattern API — the URL routing primitive that finally shipped everywhere

One constructor compiles an Express-style pattern (/books/:id(\d+), /posts/*, {/:page}+) into a matcher you can .test() and .exec() against any URL — no framework, no regex soup, no split('/'). Chromium had it since 2021; Firefox 142 and Safari 26 landed in late 2025 and quietly made it universal. This page live-probes the engine on ~30 chips — including three assumptions the shipped engine falsified on camera: repeated groups come back as joined strings, not arrays; pattern components read back as plain strings; and a pattern passed into exec() usually fails for a reason nobody documents.

1. Why URLPattern exists — the code you stop writing

Every app that shows different things at different URLs eventually reinvents this:

const u = new URL(location.href);
const parts = u.pathname.split('/').filter(Boolean);   // ['', 'work', 'evosta'] — wait, which index?
if (parts[0] === 'work' && /^\d+$/.test(parts[1])) { … }  // regex soup, no types, no groups
else if (u.pathname.startsWith('/blog/')) { … }

URLPattern replaces the split/regex/startsWith stack with a compiled pattern object: build once at module scope, match millions of URLs. The syntax is lifted from path-to-regexp — the same lineage as Express, Next.js and Rails routes — so it already lives in every full-stack developer's fingers. It slots directly under our Navigation API entry: Navigation owns when a route change happens; URLPattern owns which route it is.

Pattern → data

exec() returns structured groups ({id:'123'}), not regex match arrays.

protocol, username, password, hostname, port, pathname, search, hash — each patternable.

2. Anatomy — three constructor forms, one component model

Object form (omitted parts become * wildcards), string form (absolute), and string + baseURL (relative patterns).

new URLPattern({ pathname: '/books/:id' })                    // everything else = '*'
new URLPattern('https://example.com/books/:id(\\d+)')         // absolute string form
new URLPattern('/books/:id(\\d+)', 'https://example.com')     // relative string + baseURL
new URLPattern({ pathname: '/x' }, { ignoreCase: true })      // options form
// readback: p.pathname → '/books/:id'  (plain STRING — see chip below)

The TypeError matrix is load-bearing: a relative string without baseURL throws; an object form with a separate baseURL argument also throws (per MDN) — but an object form with its own baseURL property is legal. Three near-identical calls, two of them errors.

3. test() vs exec() — boolean vs full autopsy

test() answers "does it match"; exec() returns the structured result: an inputs array plus one object per URL part, each with .input (the matched text) and .groups (the extracted values).

const p = new URLPattern({ pathname: '/books/:id(\\d+)' });
p.test('https://a.com/books/123');          // true
const r = p.exec('https://a.com/books/123');
r.pathname.input;                            // '/books/123'
r.pathname.groups;                           // { id: '123' }
p.exec('https://a.com/books/abc');           // null  (not a partial result, not an error)

4. Named groups & regex matchers — constrain and extract

A bare :id matches one segment of anything. Wrap a regex in parens to constrain it — and remember the pathname always starts with /, which is MDN's own favorite trap:

new URLPattern({ pathname: '/books/:id(\\d+)' })   // digits only
new URLPattern({ pathname: '(\\/b.*)' })           // full-part regex: MUST include the leading /
new URLPattern({ pathname: '(b.*)' })              // never matches — no leading slash in pattern

5. Wildcards — the per-part separator rules nobody remembers

Two different "match anything" tokens, and the difference is the separator: * (full wildcard) crosses everything; a named group :name stops at the part's separator — / in pathname, . in hostname, nothing in search/hash/port.

PartNamed group stops at* wildcard
pathname/ — :a can't span /x/ycrosses slashes, non-greedy
hostname. — :sub stops at first dotcrosses dots
search / hash / portnothing — group matches allsame, but anonymous
new URLPattern({ pathname: '/posts/*' })      // matches /posts/a/b/c — groups key is '0' (numbered!)
new URLPattern({ pathname: '/posts/:rest' })  // does NOT match /posts/a/b — segment stops at slash
new URLPattern({ hostname: ':name.b.com' })   // exec('https://a.b.com/') → { name: 'a' } — label by label

Unnamed groups — including * and bare (...) regex — come back as numbered group keys (groups[0], groups[1]…), per MDN. Only named groups give you string keys. If you destructure expecting names, you get undefined.

6. Modifiers — {…}?, {…}+, {…}* and the day groups stay strings

Wrap a segment in braces and suffix a modifier: ? optional (0–1), + repeated (1+), * optional-repeated (0+). Two live surprises live here: braces around a literal ({/old}?) make the literal optional with no group at all, and repeated groups ({/:page}+) collect into a joined string with separators — 'p1/p2' — not an array, falsifying the path-to-regexp expectation on camera.

new URLPattern({ pathname: '/books{/old}?' })      // literal-optional: matches /books + /books/old, groups = {}
new URLPattern({ pathname: '/books{/:section}?' })  // group-optional: absent → key present, value undefined
new URLPattern({ pathname: '/report{/:page}+' })    // '/report/p1/p2' → groups.page = 'p1/p2' (string!)
new URLPattern({ pathname: '/report{/:page}*' })    // '/report' → page: undefined; '/report/a/b' → 'a/b'
probe pending…
Group values are always strings — repeats join with their separators; need a list? groups.page.split('/') it yourself. An absent optional group is a key present with value undefined — which JSON.stringify silently erases (a debugging trap this very page fell into): use 'section' in groups to distinguish "absent" from "matched empty".

7. The case lab — ignoreCase, and what URL parsing already lowercases for you

Matching is case-sensitive by default. But the input string is parsed as a URL first, and URL parsing canonicalizes scheme and hostname to lowercase — while pathname, search and hash keep their case. So case-sensitivity is not uniform across parts:

new URLPattern({ pathname: '/Books' }).test('https://a.com/books')   // false
new URLPattern({ pathname: '/Books' }, { ignoreCase: true })
       .test('https://a.com/books')                                   // true
new URLPattern({ hostname: 'example.com' })
       .test('https://EXAMPLE.com/x')                                 // true — host was lowercased

9. The 30-line router — Molt marketing site, zero dependencies

A route table is just an array of patterns with handlers, first match wins. Type a URL (or pick a sample) and watch it route — this is the whole router, running live on this page.

const routes = [
  { p: new URLPattern({ pathname: '/work/:slug' }),            h: (g) => `Case study: ${g.slug}` },
  { p: new URLPattern({ pathname: '/blog/:year(\\d{4})/:slug' }), h: (g) => `Post ${g.year}: ${g.slug}` },
  { p: new URLPattern({ pathname: '/services/:service{/tier}?' }), h: (g) => … },
  { p: new URLPattern({ pathname: '/' }),                      h: () => 'Home' },
  { p: new URLPattern({ pathname: '/*' }),                     h: () => '404' },
];
function route(url) { for (const r of routes) { const m = r.p.exec(url); if (m) return r.h(m.pathname.groups); } }

Service-worker fetch routing (the textbook pairing)

// sw.js — route network requests by pattern, no string surgery
const CACHE_TILES = new URLPattern({ pathname: '/tiles/:z/:x/:y.png' });
const MISSION_API = new URLPattern({ protocol: 'https', hostname: 'api.opendrones.dev',
                                     pathname: '/v1/fleet/:id/missions/:mid' });
self.addEventListener('fetch', (e) => {
  const tiles = CACHE_TILES.exec(e.request.url);
  if (tiles) { e.respondWith(caches.match(e.request)); return; }          // z/x/y captured, unused
  const mission = MISSION_API.exec(e.request.url);
  if (mission) { e.respondWith(syncThenCache(e.request, mission.groups.id)); }
});

URLPattern is exposed to workers (probe §8) — build the tables at SW top level, once per SW lifetime.

12. Gotcha wall & ship map

☠ Gotchas (all live-probed on this page)

  • Relative string pattern without baseURL → TypeError at construction
  • Object form + baseURL as 2nd argument → TypeError (use the baseURL property)
  • * and bare (…) groups come back numbered, not named
  • {…}+ / {…}* group values are joined strings ('p1/p2') — split yourself
  • Absent optional groups = undefined-valued keys (JSON.stringify erases them — debug trap)
  • Braces around literals ({/old}?) capture nothing — put :name inside braces to capture
  • Pattern components read back as plain strings — group names exist only on exec() results
  • Full-part pathname regex must include the leading / (regex quantifier braces \d{4} are safe inside parens)
  • Hostname groups stop at dots; pathname groups stop at slashes — per-part separators
  • Case rules differ per part: scheme/host pre-lowercased by URL parsing, path/search/hash not
  • exec() returns null on no-match — null-check before reading groups

📦 Where we ship it

  • Molt: marketing-site router (30 lines, §9), SW precache/fetch routing, campaign deep-link parsing (?utm_* via search groups)
  • OpenDrones: Mission Control deep links (§10), fleet route tables, custom-scheme telemetry addressing, SW tile-cache routing
  • MC dashboard: replace the hand-rolled startsWith tab/agent routes
  • Rule: construct patterns at module scope; never inside a loop (construction parses, matching is cheap)
  • Gate: 'URLPattern' in globalThis + urlpattern-polyfill fallback ≈ 97% + tail
Verdict: ship-today, ungated, both clients. The syntax is already the industry default; the engine support quietly completed a year ago and almost nobody noticed.
