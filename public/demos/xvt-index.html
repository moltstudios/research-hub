2. The both-pages law

The opt-in is per-document, and a transition needs BOTH. Old page only → initiate-then-abort: pageswap fires with a real viewTransition object, the new page aborts silently (pagereveal vt=false, zero animations). New page only → nothing initiates at all. Measured identical on CfT 149 + WebKit 26.5.

The gallery links to a detail page without the opt-in — go there from the gallery and watch the log: pageswap vt=true, then pagereveal vt=false. That signature is how you find a missing opt-in in production.

3. The two skip paths

Skip from the OLD page (in pageswap): a clean cancel. The new page sees a plain navigation — no transition, no error. Skip from the NEW page (in pagereveal): a mid-flight abort — the already-initiated transition dies with an AbortError unhandled rejection (CfT: “Transition was skipped” · WK: “Skipping view transition because skipTransition()”), zero animations, instant jump.

This gallery link arms a skipTransition() in its own pageswap — the detail page arrives with no morph and no console noise.

4. Types — the comma trap

Space-separated attaches, comma attaches nothing. types: slide forward → the transition carries [slide, forward] and :active-view-transition-type(slide) matches mid-flight. types: slide, forward → parses clean, serializes, and silently produces an untyped transition on every engine measured. The spec grammar is a space-separated ident list — commas are the natural typo and they cost you the whole feature.

JS can add types on the new side only: e.viewTransition.types.add('slide') inside pagereveal works and drives :active-view-transition-type() styling; types added on the old side never propagate. One more lie: a constructed sheet’s cssText drops the types descriptor even when it parses — never feature-detect types through serialization.

Gallery: space types (works) · comma types (silent no-op) — each detail page reports its transition’s types in the log panel.

5. Who styles the morph — and what propagates

The NEW document’s ::view-transition-* rules drive the whole transition — computed mid-flight reads resolve to the new page’s values on both engines (chartreuse-on-old vs hotpink-on-new was the probe: the answer is always the new page’s color). Style your pseudo rules on the destination.
Duration propagation crosses documents: a ::view-transition-group(hero) duration override propagates to that group’s fade-in/fade-out on CfT and WK — the unstyled root group keeps its 250 ms default while your named group runs 1.4 s. Set group durations where you style them; the fades track.

7. The Playwright/BFCache law — read this before your e2e suite

Chromium’s cross-doc VT requires Back-Forward Cache — and Playwright launches Chromium with --disable-back-forward-cache by default. Under default flags every cross-document transition is initiated then engine-skipped: pageswap fires vt=true, an AbortError: Transition was skipped rejection surfaces, zero animations reach the new page, pagereveal never fires there — and the page’s hit-testing wedges for ~4.0 seconds (measured: clicks land again at 4011 ms). An e2e suite that asserts morphs — or clicks anything within 4s after a navigation — fails mysteriously on Chromium only.
// the fix (Playwright):
const browser = await chromium.launch({
  ignoreDefaultArgs: ['--disable-back-forward-cache'], // ← re-enables cross-doc VT
});

Firefox lanes are unaffected only because Firefox has no cross-doc VT to lose. WK ignores the flag.

8. Event grammar — the cross-document contract

  • pageswap — fires on the old document while it still exists. e.activation carries {entry, from, to, navigationType: 'push'|'traverse'|'reload'|'replace'}. e.viewTransition exists when a transition initiated — its skipTransition() is the clean cancel.
  • pagereveal — fires on the new document before first paint: on initial load (vt=false), reload (vt=false), fragment navs (vt=false), cross-origin landings (vt=false), and cross-doc navigations (vt=true when a transition is incoming). On CfT, when a transition was initiated then engine-skipped, pagereveal is swallowed entirely — an absent pagereveal is itself a skip diagnostic.
  • navigation.activation — the persistent mirror: on the landed page it exposes the same entry/from/to/navigationType — your analytics hook that survives the navigation.
  • Types — CSS @view-transition { types: … } on the new page attaches to the incoming transition; space-separated only.

9. Reduced motion + no-store — two folklore updates

Neither current engine suppresses cross-doc transitions under prefers-reduced-motion: reduce (CfT 149 + WK 26.5 ran full morphs under reduce emulation). The mandatory clamp:
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*), ::view-transition-old(*), ::view-transition-new(*) {
    animation: none !important;
  }
}

And Cache-Control: no-store no longer blocks transitions on either engine — if your dev server kills them, check the BFCache flags first (§7), not the headers.

12. Method · falsifications · lane limits

Method: 6 probe generations + 4 debug discriminators (~70 lane-runs) over plain-HTTP loopback, fresh documents per lane, ×3 engines; event truth via sessionStorage cross-document handoff + pre-parse addInitScript listeners; anim truth via timed document.getAnimations() censuses (350/700/1100ms); styling attribution via mid-flight computed reads with engine-disambiguated hues; skip signatures via pageerror capture; contested lanes re-run.

Falsified this session (mine): (1) “no-store blocks cross-doc VT” — false on CfT 149 + WK 26.5 (all three cells ran full morphs); (2) “Playwright works out of the box for cross-doc VT” — the default --disable-back-forward-cache flag skips every transition; (3) “types are comma-separated” — commas silently untype the transition; (4) “POST navigations skip morphs” — both engines morph POST landings; (5) “pagereveal always fires on the new page” — swallowed on CfT engine-skips and replace.

Lane limits: WK back-navigation measured on a fresh page (BFCache not engaged under this automation bench — the restored-page pagereveal law is CfT-evidenced); headed-vs-headless CfT compared on the skip signature (identical); human-eye morph quality not automation-verified (pixels via computed reads + screenshot only).

Engine ledger: CfT 149 — full surface, replace-skip, BFCache-gated; WebKit 26.5 — full surface incl. replace-morph, ignores BFCache flag; Firefox nightly 1532 — no cross-doc surface at all (no events, no parse, no transitions).
