How Intercepting Routes Work

When a user clicks an in-app link, the intercepting route catches the navigation and renders a modal overlay. Direct URL access loads the full page. The URL always reflects the current state.

File Structure

The @ prefix creates named slots (parallel routes). The (.) prefix intercepts sibling routes.

app/
drones/
layout.tsx ← receives { children, modal }
page.tsx ← drone listing
[slug]/page.tsx ← full drone detail (direct URL)
@modal/ ← parallel route slot
(.)[slug]/page.tsx ← intercepted modal version
default.tsx ← empty fallback (required!)

Traditional Modals vs Intercepting Routes

Feature Traditional Modal Intercepting Route
URL updates ✗ Stays same ✓ Updates to /drones/phantom
Shareable links ✗ No deep link ✓ URL is shareable
Back button works ✗ Leaves page ✓ Closes modal
Direct access fallback ✗ 404 or broken ✓ Full page renders
SEO indexable ✗ Content hidden ✓ Full page indexed
Browser history ✗ Not tracked ✓ Full history
Refresh behavior N/A ✓ Shows full page

Common Gotchas

Missing default.tsx

Every parallel route slot MUST have a default.tsx. Without it, Next.js errors when the slot has no matching route.

Refresh Shows Full Page

Refreshing an intercepted route loads the FULL page, not the modal. This is by design but can surprise users.

@ Prefix Convention

Slots use @ in the filesystem (@modal) but the prop name drops it (modal). Don't mix them up.

Active Slot Tracking

Next.js tracks which slot was 'last active' for URL purposes. Navigate to understand which slot owns the URL.
