CSS Cascade Layers - @layer, Declaration Order, the !important Inversion & revert-layer

The native end of specificity wars: statement rules fix layer order up front, blocks append to layers, and everything you know about "last rule wins" gets two inversions - un-layered beats layered, and !important flips layer order backwards. Every claim on this page is probed live in your engine.

Baseline March 2022 (Chrome 99 · Firefox 97 · Safari 15.4) ≈ universal - probes run on page load · research by jin

§1The author cascade ladder - where layers sit

Before layers, author CSS had two knobs: specificity and source order. Layers add a third axis between origin and specificity. Within the author origin, the full precedence for normal declarations is:

1Un-layered styles - any selector, any specificity, any source position
2Last-declared layer - @layer ..., util; → util rules win among layers
3First-declared layer - the natural home of resets and vendor CSS
4...then only UA/user normal styles below

Inline styles, animations and !important each reshuffle this ladder - §3 and §4 probe exactly how. And note the two inversions live in this page's own stylesheet, isolated in the #labcss block.

blue - lb (later layer) beat la · purple - un-layered beat both layers

§2Order is fixed by first declaration - not by where blocks sit

The single most load-bearing fact: the order of layers is established the moment each layer name is first seen (by a statement or its first block) and can never change again. Where you later put the style blocks is irrelevant.

/* the statement is the contract */
@layer zo1, zo2;

@layer zo2 { .zz { color: blue;  } }   /* block written FIRST  */
@layer zo1 { .zz { color: red;   } }   /* block written LAST - and loses */
<p class="zz"> - this text is blue

Without any statement, first-mention of the block itself sets the order - nz2 was mentioned before nz1, so nz1 is the later layer and its red wins: red text. And with the four-layer statement, blocks written in complete reverse still resolve to the statement's order: green - util wins from the last-resort position.

§3Un-layered supremacy & the specificity jail

Three rules that rewrite override strategy:

1. Un-layered beats every layer. A plain un-layered rule wins against any layered rule - even one with higher specificity written later (the MDN classic below).
.lv-box p { color: purple; }                 /* un-layered, (0,0,1), FIRST */
@layer type { .lv-box p { color: green; } } /* layered,   (0,1,1), LAST  → loses */

un-layered purple beats layered green

2. Specificity only competes inside a layer. A (0,1,0) class selector in a later layer destroys an ID-based (1,1,1) selector in an earlier one.
later-layer class beats earlier-layer ID cascade
3. Inline style sits above all author-normal styles - layers included (probed in §10 together with animations).

§4The !important inversion - the matrix nobody remembers

!important flips both axes of the layer ladder:

DeclarationsWinnerWhy
layer A normal vs layer B normallater layernormal: last-declared layer is strongest
layer A normal vs un-layered normalun-layeredun-layered outranks all layers
layer A important vs layer B importantearlier layerimportant: order INVERTS among layers
layer A important vs un-layered importantlayer Aany layered important beats un-layered important
any important vs any normalimportantimportance still outranks layering entirely

The same three declarations compete in the lab below - one element, three fighting rules:

@layer ia, ib;
@layer ia { .i1 { color: amber  !important; } }  /* FIRST layer  */
@layer ib { .i1 { color: blue   !important; } }  /* LAST layer   */
.i1 { color: purple !important; }                /* un-layered   */
this is amber - first layer's !important beat them all · blue - any !important beats any normal · blue - utilities !important was the weakest !important
The utilities trap: the canonical Tailwind-style order @layer reset, base, utilities; makes utilities the strongest layer for normal declarations - and therefore the weakest layer for !important. A .u4{color:green!important} utility loses to base's !important. Probe below proves it.

§5Nested layers - a.b, sublayer priority, dotted appends

Layers nest, and nested order hides the exact opposite of what most people assume: the parent’s own rules are added to an implicit final sublayer — they outrank every explicitly nested sublayer, regardless of source order (css-cascade-5 §6.1). The engine probes below prove both directions:

@layer fw {
  @layer sub  { .n7  { color: green; } }  /* sublayer first  → core STILL beats it */
  .n7         { color: red;   }
}
@layer fw {
  .n7b        { color: red;   }            /* core first → sublayer STILL loses   */
  @layer subb { .n7b { color: green; } }
}
@layer fw.sub2 { .n6 { … } }              /* dotted name APPENDS into the nest */
red (core beats sub — core written after) · red (core beats sub — core written before) · green (dotted append fw.sub2) · green (fb beat fa; top2 beat fw) · amber (sibling top2 beats fw’s sublayer)

The .n5 cell shows grouping: inside fw, sublayer fb beat fa, but the whole fw family still lost to top-level top2. The .n7c cell drives it home: even a sublayer — the strongest thing a layer contains — cannot escape its parent’s rank in the ladder. But the parent’s own defaults are even stronger than its sublayers: your @layer framework { @layer theme { … } ; /* defaults */ } defaults are NOT overridable by theme — name a sublayer like framework.base instead.

§6Anonymous layers - real, ordered, un-appendable

@layer { ... } with no name creates an anonymous layer: it participates in layer order at its position of first appearance, but you can never add rules to it later - there's nothing to address. Each bare block is its own separate layer.

@layer   { .an1 { color: red;    } }   /* anonymous #1          */
@layer namedmid { .an1 { color: purple; } }  /* named - created between them */
@layer   { .an1 { color: green;  } }   /* anonymous #2 - LATER → wins */
green - second anonymous block wins

Order among anonymous blocks is source order of first appearance; a named layer first mentioned between them slots in at its first mention. CSSOM truth probed in §9: both anonymous blocks read back with an empty-string name.

§7@import url() layer(vendor) - importing CSS straight into a cage

The production killer feature: third-party CSS loaded into a layer so it can never out-specificity your system again. layer() or layer(name) on the import; anonymous if unnamed. We inject a real data-URL stylesheet into the vendor layer at runtime and watch it lose:

sheet.insertRule('@import url("data:text/css,.imp{color:purple}") layer(vendor);', 0);
/* vendor layer is FIRST-declared on this page → an un-layered rule crushes it */
vendor import text (purple if the import applied) · same vendor rule + one un-layered green counter

The @import at-rule must precede all other rules (except @charset/@layer statements) - we probe what the CSSOM does when you try to sneak one in late.

§8revert-layer - surgical rollback up the ladder

The CSS-wide keyword that says "pretend the current layer never touched this property" and take the value from the previous layer that did:

@layer r1, r2, r3;
@layer r1 { .rv  { color: red;  } .rv2 { color: red; } }
@layer r2 { .rv  { color: blue; } }                       /* no .rv2 rule here */
@layer r3 { .rv  { color: revert-layer; } }               /* → blue (r2)        */
@layer r3 { .rv2 { color: revert-layer; } }               /* → red  (r1 - r2 had no match) */
@layer r3 { .rv3 { color: revert-layer; } }               /* no layer above → rolls to previous ORIGIN */
blue (r2) · red (r1) · inherited purple?

Edge semantics: when no earlier layer matched, revert-layer rolls back to the previous style origin (user/UA) - for an inherited property with nothing there, that means the inherited value. And outside any layer it does not behave like revert for presentational hints - probed live on links below.

§10Gotcha wall - the six traps that bite real builds

  
1 Keyframes (and font-faces) are not style rules - layers don't cage them. @keyframes defined inside util below is referenced by an un-layered rule; the name resolves globally, the animation runs.

  
2 Animations outrank ALL author-normal styles - layers included. An animation to green beats a red set un-layered (origin beats layering).

  
3 ...but any !important beats animations. The author-important origin sits above the animation origin.

  
4 Inline style still beats every author-normal rule, layered or not.

  
5 Layers never change inheritance. A layered rule on a parent inherits to children exactly as an un-layered one would.

  
6 The forgotten un-layered file. One normalize.css or legacy stylesheet loaded outside layers outranks your entire layered system - the #1 migration bug.

  
animated green (beats un-layered red) · red (!important beats the same animation) · inline slate (beats un-layered purple)

  
parent blue (set in a layer) → child inherited blue, untouched by layering

OpenDrones Mission Control - the vendor-neutralizer matrix

    
Vendor telemetry widgets ship hostile CSS. With @layer pilot, vendor; (vendor last), you can hold both levers deliberately:

    
Normal fight: blue - vendor (later layer) wins normal

    
Important fight: green - pilot (earlier layer) wins !important

    
Layer order alone can never win both rows - that's the arithmetic of the inversion. The production recipe: declare the override layer first and use !important there only to cancel vendor !important, while normal overrides live un-layered (strongest normal).
