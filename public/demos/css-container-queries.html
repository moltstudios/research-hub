CSS Implementation

/* 1. Define the container */
.query-container {
  container-type: inline-size;
  container-name: demo-container;
}

/* 2. Write the container query */
@container (min-width: 500px) {
  .card {
    flex-direction: row;
    display: flex;
  }
}

@container (max-width: 499px) {
  .card {
    flex-direction: column;
    display: flex;
  }
}

Key: Use container-type: inline-size to track container width. Use @container to write queries. Named containers prevent query collisions in nested layouts.

⚙️ Container Type Options

size

Both Dimensions

Tracks both width and height. Applies layout, style, and size containment.

container-type: size;

Use for components that need both dimensions (e.g., square avatars, fixed-ratio images).

inline-size

Width Only

Most common option. Tracks horizontal width. Best for most layouts.

container-type: inline-size;

Use for card components, grids, flex layouts (RECOMMENDED).

normal

None

Not a container for size queries, but remains a container for style queries.

container-type: normal;

Use when you only need style queries (not size queries).

📏 Container Query Length Units

Units that measure relative to the query container's dimensions. Perfect for fluid typography and spacing.

Unit Description Use Case
cqw 1% of container width Fluid widths, responsive borders
cqh 1% of container height Responsive heights, animations
cqi 1% of container inline size Horizontal measurements
cqb 1% of container block size Vertical measurements
cqmin Min of cqi/cqb Responsive padding/margins
cqmax Max of cqi/cqb Responsive sizing

Fluid Typography Example

/* Font size grows with container width */
@container (min-width: 400px) {
  .card {
    font-size: max(1.5em, 1.23em + 2cqi);
    padding: 1.5cqi;
  }
}

/* Font size shrinks in narrow containers */
@container (max-width: 399px) {
  .card {
    font-size: max(1.2em, 1em + 1cqi);
    padding: 1cqi;
  }
}

✨ Best Practices for 2026

1

Use Named Containers

Prevent query collisions in nested layouts by naming containers explicitly.

.sidebar {
  container-type: inline-size;
  container-name: sidebar;  /* Named container */
}

@container sidebar (min-width: 400px) {
  .card { /* Targets sidebar's cards */ }
}
2

Container-First Design

Design components in isolation. Define breakpoints based on when the design breaks, not device widths.

Instead of 768px, use 400px when the card starts to overflow its container.

3

Use Container Units

Leverage cqw, cqh, cqi, cqb, cqmin, cqmax for fluid typography and spacing that adapts to container size.

This eliminates the need for complex media query math and JavaScript calculations.

4

Combine with Media Queries

Use container queries for component-specific responsiveness and media queries for page-level changes.

Container queries = component-level, Media queries = page-level. They complement each other.

5

Provide Fallbacks

For older browsers, use media queries as fallback.

@container (min-width: 500px) {
  .card {
    display: flex;
  }
}

/* Fallback for browsers without container queries */
@media (min-width: 500px) {
  .card {
    display: flex;
  }
}

⚡ Performance Benefits

CSS-Based (Container Queries)

  • ✓ No JavaScript needed
  • ✓ Runs on compositor thread
  • ✓ Hardware accelerated
  • ✓ Less main-thread overhead
  • ✓ Lower bundle size (no ResizeObserver lib)

JavaScript-Based (ResizeObserver)

  • ✗ Requires JavaScript
  • ✗ Runs on main thread
  • ✗ Can cause layout thrashing
  • ✗ Higher CPU usage
  • ✗ Larger bundle size

⚖️ Media Queries vs Container Queries

Aspect Media Queries Container Queries
Target Viewport (browser window) Container element
Scope Page-level Component-level
Reusability Low (components adapt to page) High (components adapt to context)
Complexity High (need media query overrides) Low (self-contained component)
Use Case Page layout, device-specific styles Component layout, adaptive UI
Best For Global layout changes Component-specific responsiveness

Rule of thumb: Use media queries for page-level changes (e.g., responsive nav, global layout). Use container queries for component-level changes (e.g., card layout, widget adaptation). They work together, not against each other.

💡 Real-World Examples

Example 1: Card Component with Adaptive Layout

/* Define card container */
.card-wrapper {
  container-type: inline-size;
  container-name: card-container;
}

/* Card adapts layout based on container width */
@container (min-width: 400px) {
  .card {
    display: grid;
    grid-template-columns: 2fr 1fr;
    grid-template-rows: auto auto;
  }
}

@container (max-width: 399px) {
  .card {
    display: flex;
    flex-direction: column;
  }
}

Example 2: Fluid Typography with Container Units

/* Typography scales with container */
@container (min-width: 500px) {
  .hero-title {
    font-size: clamp(2.5rem, 5cqi, 6rem);
    line-height: 1.1;
  }
}

@container (max-width: 499px) {
  .hero-title {
    font-size: clamp(1.8rem, 3cqi, 2.5rem);
    line-height: 1.2;
  }
}

Example 3: Sidebar Widgets

/* Sidebar container */
.sidebar {
  container-type: inline-size;
  container-name: sidebar;
}

/* Widgets adapt when sidebar is collapsed */
@container sidebar (max-width: 200px) {
  .widget {
    flex-direction: column;
    text-align: center;
  }
  .widget-title {
    display: none;  /* Hide title in collapsed mode */
  }
}
