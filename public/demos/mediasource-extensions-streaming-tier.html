MediaSource Extensions — the streaming container tier

The engine under every serious <video>: you feed it media byte segments at runtime, it buffers them on a timeline you control, and the element plays/seek through data that arrived minutes or milliseconds ago. hls.js, dash.js, YouTube, Netflix — all MSE underneath. This page generates its own webm stream in-page (zero network), then measures every contract live: the append-state gate, the silent reopen, the execution laws, the placement primitives, and a working in-page DVR.

01Engine introspection — the surface census

Live probes on the page you are reading. MediaSource (2 statics, 13 prototype members), SourceBuffer (17 members incl. changeType), and the mime-type gate that decides everything before a single byte moves.

The codecs-required law. isTypeSupported('video/webm') is false. So is video/mp4 bare. Chromium will not create a SourceBuffer unless the string carries an explicit codec (video/webm; codecs="vp8", video/mp4; codecs="avc1.42E01E"). The MDN examples that pass bare containers fail here — probe the exact string you will send to addSourceBuffer, never the family name.
iPhone is a different door. Classic MSE never shipped on iPhone Safari (documented — not live-probed here). iOS 17.1+ ships ManagedMediaSource, the low-power variant that buffers only when the source is attached and visible. Feature-detect both: window.MediaSource || window.ManagedMediaSource, and remember MMS constraints (no background buffering, different eviction behavior). iPadOS has classic MSE.

The EOS duration-snapshot law. Before endOfStream(), ms.duration read Infinity (nothing declared). After EOS on this engine, duration snapped to exactly the highest buffered end — measured equal to the last buffered frame. The media element mirrors it (video.duration = same number). If your UI wants a finite total, either append everything and EOS, or set ms.duration explicitly yourself.

03The lifecycle ladder — and the silent reopen

closed → open → ended, with sourceopen / sourceended / sourceclose as the three state announcements. Then the falsification: what happens when you append onto an ended source.

THE SILENT REOPEN (spec falsification). The spec text says appendBuffer() on readyState === 'ended' must throw InvalidStateError. Measured on Chromium 154: it is accepted — the append runs a full update cycle, readyState returns to 'open', and sourceopen fires a second time (sourceopen count: 2). remove() on ended behaves the same. Append-on-ended is effectively the reopen primitive — but do not build on it: it is the documented-divergence family, and a state machine keyed on a single sourceopen will drift. Track readyState in the event, not a boolean.

04THE APPEND-STATE GATE — the hidden fourth state

updateend means "your bytes were accepted." It does not mean the segment parser went home. A hidden append state (PARSING_MEDIA_SEGMENT) outlives every append on this engine — and it gates exactly two setters while leaving two others untouched.

The non-uniform gate. After an append's updateend (updating already false, 250 ms waited): timestampOffset and mode setters both throw InvalidStateError: … append state is 'PARSING_MEDIA_SEGMENT'. Meanwhile appendWindowStart/End and changeType() set freely. Then abort() — idle, no args — resets the parser state and both setters go through. Production rule: abort() before reconfiguring placement (tso/mode), not just before abandoning an append.

05timestampOffset — the placement primitive

One recorded 2.2 s stream, appended twice onto two sources — once at offset 0, once at offset +5 s. The timeline bars below are drawn from the measured buffered ranges, not hardcoded.

Exact placement, on this engine, for webm clusters. tso=5 + a 0–2.18 s recording → buffered [5.00, 7.18]. The offset applies to the internal media timestamps — it is how you slot an ad into a gap or splice a mid-roll at a chosen wall-clock position. Pair it with §04: set it after an abort(), or it throws.

06appendWindow — an input filter, not a trim

Set appendWindowStart/End to [1 s, 2 s], then append a 0–2.2 s recording. Folklore expectation: you keep the middle second. Measured truth below.

The starvation law. Window [1, 2] over a single-cluster MediaRecorder webm → buffered.length === 0. The window is a filter on incoming frames evaluated as the parser demuxes — with one webm cluster spanning the whole stream, nothing survives. It is not a post-hoc trim (that's remove()). In production the window trick is used with per-cluster segments (fMP4), where each appended segment carries only in-window frames.
The activation law. activeSourceBuffers was 0 after addSourceBuffer and became 1 after the first append even though every frame was windowed away. Activation tracks append participation, not data presence.

07THE EXECUTION LAWS — how an MSE session dies

Two live executions, each on its own isolated source (they do not survive). First: 4 KB of literal 0x42 garbage appended after a valid init segment. Second: changeType('vp9') followed by vp8 bytes.

A failed append kills the session — in one of two grades. Event sequence measured: updatestart → SourceBuffer error → updateend — the error fires between the cycle events. The kill grade is timing-dependent: landing the garbage while the parser still holds the last cluster → hard grade (source closed, SourceBuffer removed — every later read throws InvalidStateError: removed from the parent media source); landing it on a settled parser → soft grade (source ended + error). Both end playback; neither is per-SB undoable. Recovery is a new MediaSource + new object URL + re-append from the last good segment.
The error message leaks the demuxer. video.error.message carried the internal PipelineStatus::CHUNK_DEMUXER_ERROR_APPEND_FAILED: Unexpected element ID 0x4242 — naming the literal garbage bytes — and for the codec mismatch: PipelineStatus::…: Video stream codec vp8 doesn't match SourceBuffer codecs. Two different kill grades: garbage closes the source; a changeType mismatch fires the same SB error but leaves readyState 'ended'. Log video.error.message in the field — it is the single richest debugging signal MSE gives you.

08remove() — eviction, with cluster-granularity surprises

The DVR memory primitive: remove(start, end) evicts buffered ranges. The validation matrix throws honestly; the granularity of what actually leaves is the honest warning.

Cluster granularity is real. Measured on a single-cluster webm [0, 2.18]: remove(0.5, 1.5) left only [0, ~0.51] — the trailing [1.5, 2.18] did not survive even though the range said it should. Eviction operates at the engine's container granularity (cluster/GOP), not at arbitrary frame boundaries. Production stacks ship fMP4 segments precisely because its granularity is the segment. Treat buffered as the source of truth after every remove — never assume the arithmetic.

09duration — the four walls

One setter, four distinct rejection shapes measured. The ladder order matters: the updating wall fires before the open wall; NaN and negative have their own TypeErrors.

Infinity is legal and meaningful. ms.duration = Infinity sets the live-stream posture: the element reports an unknown end, seekable collapses to what you expose (see setLiveSeekableRange), and your DVR window is whatever buffered says. This is the setting for §12's console.

10URL & attachment laws — one source, one element

object URLs are the attach mechanism, and the attachment contract is stricter than it looks: two URLs can exist for the same source, but only one element can hold it.

The single-attachment law. A second createObjectURL(ms) yields a second, distinct URL (no throw). Assign it to a second <video> while the first still holds the source → the second element fires an error event immediately; the first element and the source are untouched. One MediaSource, one media element. To hand off, detach first (v.src=''; v.load() → sourceclose fires, sourceBuffers cleared, readyState closed) then attach elsewhere — with a fresh URL if the old one was revoked (a revoked URL re-attaches as MEDIA_ELEMENT_ERROR: Format error, code 4).
Revoke while attached is safe. Calling URL.revokeObjectURL(u) after attachment does not disturb a live session — the element already holds the source. Standard practice: create → attach → revoke immediately, exactly like blob downloads.

11The worker pipeline — handles, not URLs

MSE construction works in dedicated workers (canConstructInDedicatedWorker shipped true on this engine), but the worker's source can only reach the DOM through a MediaSourceHandle — a transfer-only object.

Handles are transferable, not cloneable. A bare postMessage(handle) rejects with DataCloneError: A MediaSourceHandle could not be cloned because it was not transferred — the File System Access-handle family. Correct flow: worker creates the MediaSource, posts ms.handle with a transfer list; the main thread assigns it with video.srcObject = handle. Measured end-to-end: worker-side sourceopen → worker-side appendBuffer → buffered [0, 2.18] → element plays. The demux/parse cost lives entirely in the worker — the OpenDrones replay lane for long missions.

The gap-seek pend. Seeking into seekable but unbuffered time: currentTime jumps instantly, but seeked never fires — the element sits at HAVE_METADATA waiting for data that will never come. Measured recovery: seek back into a buffered range and everything resumes. Your DVR UI must derive "can I scrub here" from buffered, never from seekable alone.

13CAPSTONE — Molt instant-play hero loader

The pattern for client-site video heroes: append only the first segment, start playback the moment canplay arrives, then fill the rest behind the playhead. First-frame time becomes "first segment downloaded," not "whole file."

changeType is the adaptive ladder. changeType() mid-stream (measured: vp8→vp9 ok, webm→mp4/avc1 ok, bogus → NotSupportedError) is how a player switches codec/container when bandwidth changes profile — without tearing down the source. The contract that kills you: the next appended bytes must match the declared type (§07, second execution). Switch type, then switch segments, atomically.

15The ten-rule ship checklist

Everything this page measured, as rules.

1 · isTypeSupported the exact codec string — bare containers are false.
2 · Feature-detect MediaSource and ManagedMediaSource; iPhone only has the managed door.
3 · Sequence every append: one appendBuffer → wait updateend → next. The updating wall throws otherwise.
4 · abort() before touching timestampOffset or mode — the append-state gate outlives updateend.
5 · appendWindow filters incoming frames (starvation is real); remove() trims what's stored (cluster-granular).
6 · After any append failure, expect session death: rebuild source + URL + re-append; log video.error.message (it names the cause).
7 · changeType atomically: declared type must match the next segment's bytes, or the pipeline executes.
8 · Duration: Infinity for live posture; EOS snapshots duration to buffered-end; NaN/negative are TypeErrors.
9 · One source per element; revoke the object URL right after attach; revoked URLs re-attach as Format errors.
10 · Scrub-ability comes from buffered, not seekable — gap-seeks pend forever at HAVE_METADATA.
