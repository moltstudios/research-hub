§3 · THE ONE-THREE LAW — R3F and your code share one Three.js

The classic R3F bug is a duplicate Three.js: the bundle resolves three twice, so instanceof checks fail, plugins reject your objects, and errors read like "THREE.Object3D is not a constructor". The fix is an import map that maps three to one URL, and passing ?external=three to the R3F CDN build so it does not bundle its own copy.

<script type="importmap">{"imports":{
  "react": "https://esm.sh/react@18.3.1",
  "react/jsx-runtime": "https://esm.sh/react@18.3.1/jsx-runtime",
  "react-dom/client": "https://esm.sh/react-dom@18.3.1/client",
  "three": "https://unpkg.com/three@0.169.0/build/three.module.js",
  "three/addons/": "https://unpkg.com/three@0.169.0/examples/jsm/",
  "@react-three/fiber": "https://esm.sh/@react-three/fiber@8.17.10?external=react,react-dom,three"
}}</script>
THE LAW: if a Three.js object you created with your own import * as THREE passes instanceof THREE.Object3D inside R3F's scene graph, both sides are running the same module instance. One import-map entry + ?external=three is the whole fix.

§5 · THE DISPOSAL LAW — GPU memory does not forgive you

A product page swaps products, finish, and accessories. Every geometry, material, and texture you create is GPU memory until you dispose() it. The renderer's own info.memory counter is the receipt.

THE LAW: renderer.info.memory.geometries and .textures are the only honest leak meter. If geometries climbs and never falls, you are leaking — and on mobile Safari that is a tab-kill, not a slow page.
THE FRUSTUM TRAP: the counter only counts what the GPU actually uploaded. A mesh parked outside the camera frustum never uploads — so it costs you heap, not VRAM, and it never shows up in info.memory. This lab deliberately places every allocated mesh inside the frustum: the counters move only because the GPU really took the resources. An off-screen "leak" that reads zero on the memory counter is still a heap leak — the counter is not the whole story.

§6 · THE FILL-RATE LAW — device pixel ratio is a rendering budget

Math.min(devicePixelRatio, 2) is standard advice and it is a quality lever, not a free win. Rendering the same frame at pixel ratio 3 multiplies the fragments by nine against ratio 1. The lab below renders the same scene at three ratios and reports measured milliseconds per frame.

running…

Interpretation, honestly stated: this is a fill-rate measurement on your GPU at your canvas size. The ratio between ratios is hardware-dependent; the direction is not. Read your own numbers, then choose the ratio your target device can hold.

THE SUB-LINEARITY LAW: watch how the cost grows slower than the pixel count — a small scene is geometry-bound, so extra resolution is nearly free until you cross into fill-bound territory. That is why "just render at 3×" is not the disaster it looks like on a simple product, and equally why it is on a dense one. The crossover point is scene-specific; measure it, do not guess it.

§8 · THE CONTEXT-LOSS LAW — a GPU reset is a normal event

Drivers reset, laptops switch GPUs, the browser evicts a context under pressure. The webglcontextlost event fires and the canvas goes blank. Handling it is three lines: preventDefault(), stop the loop, rebuild on webglcontextrestored. This page probes both events on an offscreen canvas — the live showcase above is never disturbed.

canvas.addEventListener('webglcontextlost', (e) => {
  e.preventDefault();          // required, or the context is never restored
  renderer.setAnimationLoop(null);
});
canvas.addEventListener('webglcontextrestored', () => {
  renderer.setAnimationLoop(animate);   // rebuild GL resources, then resume
});

§9 · Mobile & the shipping checklist

The mobile tier is not the desktop tier with smaller text. The budgets are different and the failure is different: desktop fails as a dropped frame, mobile fails as a killed tab.

Pixel ratiomin(dpr, 2)min(dpr, 1.5)One clamped setPixelRatio
Textures2K1K + KTX2Resize per variant, not one big atlas
First frame< 1.5s< 2.5sSkeleton poster, then lazy GLB
Animations60fps30fpsHalf-rate on prefers-reduced-motion

Checklist

  • One Three.js. One import-map entry; R3F built with ?external=three. Prove it with instanceof before shipping.
  • Count the cost, don't assume it. renderer.info in the console: calls, triangles, programs, memory.
  • Dispose everything you create on product swap, not just on unmount.
  • Clamp pixel ratio once, at creation, and never again.
  • Ship a poster. A 2D fallback renders instantly while the GLB streams — and it is the AR/asset-free fallback.
  • Handle context loss with preventDefault() + rebuild.
  • Half-rate on reduced motion, and do not auto-spin on touch by default.

§10 · Capstones — what to actually build

OpenDrones — the hardware product page

One drone model, six finishes, two payload accessories. Design: the GLB is lazy-loaded behind a poster; the accessory toggle adds a mesh from a second small GLB rather than baking every variant into one file.

Budget: 90k tris, 40 draw calls, dpr 1.5 on mobile, 1K KTX2 textures.

Molt — the client configurator

A furniture-range visualiser for a client site. Design: one instanced mesh for the shelving options (1 draw call for 40 SKUs), finish colour via instanceColor, camera limits clamped so the camera never clips into geometry.

Budget: 150k tris, 60 draw calls, poster frame under 400ms.

The measurement harness

Whatever you ship, ship the counters. A renderer.info readout in a corner of the demo page turns "it feels heavy" into a number you can put in a budget document.

Cost: one useFrame that writes four numbers a second.
