02 — The Core API

Build → Compile → Dispatch

WebNN models the entire ML inference lifecycle in three phases. Each maps to one API call. The graph is hardware-agnostic — the browser picks the best backend (NPU → GPU → CPU) at compile time.

1

Build: Define the Computational Graph

Create Operand nodes (inputs, constants) and chain operations (mul, add, conv2d, matmul, …). The builder records the topology — nothing executes yet.

2

Compile: Hand Off to the Hardware

builder.build({'C': C}) returns an MLGraph. The browser inspects the graph, selects the best available hardware backend (Core ML on macOS, DirectML/ORT on Windows, TFLite on Android), and compiles an optimized execution plan.

3

Dispatch: Execute and Read Results

context.dispatch(graph, inputs, outputs) runs the compiled graph on the chosen hardware. Read results from output tensors via context.readTensor(). Zero JS during execution — pure hardware speed.

// C = 0.2 × A + B — the "hello world" of WebNN
const descriptor = { dataType: 'float32', shape: [2, 2] };
const context = await navigator.ml.createContext();
const builder = new MLGraphBuilder(context);

// 1. BUILD the graph
const constant = builder.constant(descriptor, new Float32Array(4).fill(0.2));
const A = builder.input('A', descriptor);
const B = builder.input('B', descriptor);
const C = builder.add(builder.mul(A, constant), B);

// 2. COMPILE to hardware
const graph = await builder.build({ 'C': C });

// 3. DISPATCH inputs → outputs
const [tensorA, tensorB, tensorC] = await Promise.all([
  context.createTensor({ dataType: 'float32', shape: [2,2], writable: true }),
  context.createTensor({ dataType: 'float32', shape: [2,2], writable: true }),
  context.createTensor({ dataType: 'float32', shape: [2,2], readable: true }),
]);
context.writeTensor(tensorA, [1,1,1,1]);
context.writeTensor(tensorB, [0.8,0.8,0.8,0.8]);
context.dispatch(graph, { 'A': tensorA, 'B': tensorB }, { 'C': tensorC });

const result = await context.readTensor(tensorC);
console.log(new Float32Array(result)); // [1, 1, 1, 1] ✓

06 — OpenDrones

NPU-Accelerated Drone Vision Pipeline

Every frame from a drone camera can be processed on-device: crack detection, thermal anomaly identification, NFZ boundary recognition. WebNN routes the inference to the NPU — 10-50× faster than GPU with a fraction of the power draw. Critical for battery-limited field operations.

Why NPU matters for drones: A DJI Mavic 3 delivers 4K video at 60fps. Running frame-level defect detection on GPU drains battery ~30% faster. NPU inference uses 5-10× less power per inference — extending mission time from 31 min to ~43 min on the same battery.

// OpenDrones: real-time crack detection via WebNN + WebRTC
// The WebRTC VideoFrame (P3) feeds directly into the WebNN graph

async function initDroneVision() {
  // 1. Load MobileNet-V3 weights from OPFS (P2 storage layer)
  const root = await navigator.storage.getDirectory();
  const fh = await root.getFileHandle('mobilenet-v3-opdr.onnx');
  const modelBuffer = await (await fh.getFile()).arrayBuffer();

  // 2. Build WebNN graph (conv2d → relu → pool → ... → softmax)
  const context = await navigator.ml.createContext({
    deviceType: 'npu',  // Prefer NPU for battery efficiency
    powerPreference: 'low-power',
  });
  const builder = new MLGraphBuilder(context);
  // ... build conv2d layers from model weights ...
  const graph = await builder.build({ output: detectionHead });

  // 3. Feed frames from WebRTC stream (P3, 2026-07-11)
  const trackProcessor = new MediaStreamTrackProcessor({ track: droneVideoTrack });
  const reader = trackProcessor.readable.getReader();

  while (true) {
    const { value: frame } = await reader.read();
    const inputTensor = await context.createTensor({
      dataType: 'float32', shape: [1,3,224,224], writable: true
    });
    const pixels = extractRGBFromFrame(frame);
    context.writeTensor(inputTensor, pixels);

    const outputTensor = await context.createTensor({
      dataType: 'float32', shape: [1,4], readable: true
    });
    context.dispatch(graph, { input: inputTensor }, { output: outputTensor });

    const result = await context.readTensor(outputTensor);
    const [crack, thermal, nfz, clear] = new Float32Array(result);

    if (crack > 0.7) flagForReview(frame, 'crack');
    if (thermal > 0.7) flagForReview(frame, 'thermal-anomaly');
    if (nfz > 0.7) triggerNFZAlert();

    frame.close(); // Free the VideoFrame
  }
}
07 — Framework Integration

WebNN as the Hardware Layer for JS ML Frameworks

You rarely write raw WebNN graphs. Instead, you use a JS ML framework that compiles your model down to WebNN operations. The framework handles model loading, tokenization, and pre/post-processing — WebNN handles the raw math at hardware speed.

🔗 ONNX Runtime Web

Microsoft's inference engine. Load any PyTorch/TensorFlow model exported to ONNX. Explicit WebNN execution provider.

const session = await ort.InferenceSession.create(
  modelBuffer,
  { executionProvider: ['webnn', 'webgpu', 'wasm'] }
);

🤗 Transformers.js v4

Hugging Face models in-browser. Automatic WebNN backend when available. (Already documented P2, 2026-07-15.)

const { pipeline } = await import('@huggingface/transformers');
const detector = await pipeline('object-detection',
  'onnx-community/yolov10n',
  { device: 'webnn' });

📱 LiteRT (TFLite)

Google's lightweight runtime for TensorFlow Lite models. WebNN execution provider for browser deployment.

const model = await tflite.loadTFLiteModel(
  'model.tflite',
  { delegate: 'webnn' }
);

🧪 Vanilla WebNN

Direct API for custom graphs. Zero framework overhead — smallest bundle size. Full control over topology.

08 — Stack Composition

The 4-Tier On-Device AI Stack (August 2026)

WebNN completes the on-device AI hardware acceleration story. Combined with Chrome Built-in AI (P3) and Transformers.js v4 (P2), every layer from high-level model APIs down to the silicon is now web-accessible.

🧠 Tier 1 — WebNN (Hardware Acceleration) This entry
Raw ML graph execution on NPU/GPU/CPU. Hardware-agnostic. W3C spec. Chrome/Edge shipping across Windows, macOS, Android, ChromeOS. The only web API with NPU access. Frameworks (ONNX Runtime, Transformers.js, LiteRT) compile down to WebNN operations.
🤗 Tier 2 — Transformers.js v4 (Model Runtime) P2 · 2026-07-15
Hugging Face models in-browser. 500+ pre-trained models (BERT, Whisper, YOLO, Stable Diffusion). Automatic WebNN backend selection. ~95% WASM / ~82% WebGPU / growing WebNN coverage. Pairs with WebNN for NPU-accelerated inference.
✨ Tier 3 — Chrome Built-in AI (High-Level Tasks) P3 · 2026-07-15
7 task-level APIs (Summarizer, Translator, Prompt, Writer, Rewriter, Proofreader, LanguageDetector). Powered by Gemini Nano on-device. Chrome 138+ desktop (~37% traffic). Zero model loading — the browser ships the model. Privacy-first: data never leaves the device.
☁️ Tier 4 — Server LLM Fallback 100% coverage
OpenAI / Anthropic / vLLM for long-context reasoning, RAG, and code generation. The hybrid cascade: try Tier 3 → Tier 2 → Tier 1 → Tier 4. Each tier is a progressive enhancement. Privacy-sensitive workloads stop at Tiers 1-3.

The cascade pattern: Always try the most local tier first. Summarizer.availability() → Tier 3. 'ml' in navigator → Tier 1. Transformers.js pipeline → Tier 2. Fall through to server only when every local tier is unavailable. This is the architecture for every Molt Studios privacy-first AI feature.
