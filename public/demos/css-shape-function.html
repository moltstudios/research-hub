02 — COMPARISON

shape() vs path() — The Responsive Revolution

The biggest win: shape() uses CSS units (%, rem, em, calc, var) while path() is locked to pixel values in a single SVG string. Resize the browser to see the difference.

clip-path: path() — Fixed pixels, NOT responsive 
/* Fixed 200×120 box — doesn't adapt */
clip-path: path("M 0 20 C 50 0 150 40 200 20 V 100 C 150 120 50 80 0 100 Z");
clip-path: shape() — Percentages, FULLY responsive 
/* Mixes % and px — curves stay 20px, edges adapt */
clip-path: shape(
  from 0% 20px,
  curve to 100% 20px with 25% 0px / 75% 40px,
  vline to calc(100% - 20px),
  curve to 0% calc(100% - 20px) with 75% 100% / 25% calc(100% - 40px),
  close
);

Key Differences

❌ path() limitations
  • • Pixel units only — no %, rem, em, ch
  • • Single string — no CSS syntax highlighting
  • • No CSS custom properties
  • • No calc() or math functions
  • • SVG syntax — not human-readable
  • • Not responsive — fixed coordinate space
✅ shape() advantages
  • • All CSS units — %, rem, em, px, ch, vh, vw
  • • Standard CSS — syntax highlighting works
  • • Full custom property support
  • • calc(), min(), max(), clamp(), abs()
  • • Human-readable: curve to 50% 0%
  • • Fully responsive — percentages adapt to container

04 — REFERENCE

The 7 Shape Commands

Every command accepts to (absolute) or by (relative) coordinates, using any CSS unit.

move [by|to] x y

Lift the pen and move. Doesn't draw. Like SVG M.

line [by|to] x y

Straight line to point. Like SVG L.

hline [by|to] x

Horizontal line — only X changes. Like SVG H.

vline [by|to] y

Vertical line — only Y changes. Like SVG V.

curve [by|to] x y with cx1 cy1 / cx2 cy2

Bézier curve. One control point = quadratic (SVG Q). Two = cubic (SVG C).

smooth [by|to] x y [with cx cy]

Smooth Bézier — mirrors previous curve's control point. SVG T / S.

arc [by|to] x y of rx ry [cw|ccw] [large|small] rotate deg

Elliptical arc between two points. Like SVG A.

close

Close the path back to the starting point. Like SVG Z.

The 5-Line Recipe

/* A wavy card edge in 5 lines of CSS */
clip-path: shape(
  from 0% 10%,
  curve to 100% 10% with 30% 0% / 70% 20%,
  vline to 90%,
  curve to 0% 90% with 70% 100% / 30% 80%,
  close
);

06 — ANIMATION

Animated Shapes with @property

Pair shape() with @property to animate shape parameters. The wave height animates via a registered custom property — the browser knows how to interpolate it.

/* Register the animatable property */
@property --wave-h {
  syntax: "<length>";
  inherits: false;
  initial-value: 30px;
}

/* Animate the custom property */
@keyframes wave-anim {
  from { --wave-h: 10px; }
  to   { --wave-h: 60px; }
}

/* Use it inside shape() */
clip-path: shape(
  from 0px var(--wave-h),
  curve to 100% var(--wave-h) with 25% 0px / 75% calc(var(--wave-h) * 2),
  vline to calc(100% - var(--wave-h)),
  curve to 0px calc(100% - var(--wave-h)) with 75% 100% / 25% calc(100% - (var(--wave-h) * 2)),
  close
);

animation: wave-anim 3s ease-in-out infinite alternate;

Why this is powerful: Before shape(), animating a clip-path required JS to recalculate SVG path strings on every frame. Now it's pure CSS — the browser handles interpolation natively via @property.

07 — MOTION

offset-path: shape() — Motion Along a Path

Use shape() with offset-path to send elements along a custom trajectory. Perfect for UI animations, floating notifications, and drone flight paths.

/* Element travels along the shape() path */
offset-path: shape(
  from 10% 50%,
  curve to 90% 50% with 30% 10% / 70% 90%,
  curve to 10% 50% with 70% 90% / 30% 10%,
  close
);
offset-distance: 0%;
animation: travel-path 4s linear infinite;

@keyframes travel-path {
  from { offset-distance: 0%; }
  to   { offset-distance: 100%; }
}

Baseline 2026 Newly Available

"Newly Available" means the feature works in the current stable versions of Chrome, Edge, Firefox, and Safari. It has not yet reached "Widely Available" (typically 30 months after first baseline). For Molt Studios client work, shape() is safe to use with a @supports fallback.

@supports (clip-path: shape(from 0 0, close)) {
  /* shape() is supported — use the fancy clips */
  clip-path: shape(from 0% 10%, curve to 100% 10% with 30% 0%, close);
}

@supports not (clip-path: shape(from 0 0, close)) {
  /* Fallback — polygon or border-radius */
  clip-path: polygon(0% 10%, 100% 10%, 100% 90%, 0% 90%);
  border-radius: 24px;
}
11 — DECISIONS

When to Use shape() vs Alternatives

Need Best Choice Why
Responsive custom clip (adapts to container) shape() Percentage units + calc()
Fixed-size SVG-like shape path() Simpler for one-off pixel shapes
Simple geometric clip (circle, ellipse) circle(), ellipse(), polygon() Less verbose for basic shapes
Animated clip morphing shape() + @property Native CSS property animation
Motion along a custom path offset-path: shape() Responsive, CSS-unit compatible
Complex border shapes (future) border-shape: shape() Spec'd but not yet shipped
Text wrapping around a shape shape-outside shape() not yet supported here
