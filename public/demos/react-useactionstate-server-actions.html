React 19 + Next.js Server Actions

useActionState & Server Actions
Pattern Guide

The new way to handle forms, mutations, and pending states in React 19 — replacing useState + useEffect boilerplate with a single hook.

⚡Before vs After

❌ Old Way (React 18)

  • Manual useState for pending, error, data
  • useEffect for side effects
  • Try/catch with loading state management
  • Form reset handled manually
  • Optimistic updates need custom logic
  • 5-6 hooks for one form

✅ New Way (React 19)

  • Single useActionState hook
  • Built-in isPending state
  • Auto error handling with Error Boundaries
  • Form auto-resets on success
  • useOptimistic for instant feedback
  • 1 hook + 1 server function

The browser sends the FormData to the server function. React handles pending state, errors, and re-renders automatically. No API route needed.

🧩Key Features

⏳

Automatic Pending

isPending is true during server execution, false when done. No manual loading state.

🔄

Auto Form Reset

Uncontrolled form inputs reset automatically on successful submission.

🛡️

Error Boundaries

Thrown errors caught by nearest Error Boundary. No try/catch needed in component.

🚀

Progressive Enhancement

Forms work before JS hydrates. Server receives the FormData directly via POST.

📦

No API Routes

Server Actions replace /api routes for mutations. Less boilerplate, better types.

🔐

Built-in CSRF

Next.js Server Actions have built-in CSRF protection. No tokens needed.

🔧Migration Tips

  • Replace useState + fetch forms → Move fetch logic into a Server Action with 'use server'
  • Replace useFormState → Renamed to useActionState in React 19 (import from 'react', not 'react-dom')
  • Replace /api/* routes → Server Actions handle mutations. Keep API routes for webhooks (Stripe, etc.)
  • Add useOptimistic → For instant feedback on list operations (add/remove items, status toggles)
  • Validation: Use Zod schemas in Server Actions — errors returned as state, no client-side schema needed
