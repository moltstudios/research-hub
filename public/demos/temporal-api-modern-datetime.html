2 · The Date Problem — Why Temporal Exists

JavaScript's Date has been the source of timezone bugs, parsing confusion, and mutable-state headaches for 25 years. Temporal fixes every one.

The 7 Fatal Flaws of Date

✗ MutablesetMonth() mutates in place → race conditions
✗ No timezoneOnly UTC and local — no America/New_York
✗ No DurationSubtracting dates gives ms — no "2 months"
✗ Parsing hellnew Date("2026-03-15") → midnight UTC, not local
✗ Month 0-indexedJanuary = 0. The classic off-by-one bug.
✗ No calendarGregorian only — no Hebrew, Chinese, Japanese
✗ No Plain date"March 15" always drags a time + timezone

4 · The Temporal Type System

Temporal introduces 5 main types, each for a specific use case. The key insight: separate wall-clock time from exact time.

TypeRepresentsExample
Temporal.Instant Exact moment in history
UTC nanoseconds since epoch		 2026-08-09T13:05:00Z
Temporal.ZonedDateTime Instant + timezone + calendar
The "full picture" type		 2026-08-09T09:05:00-04:00[America/New_York]
Temporal.PlainDateTime Wall-clock date+time
No timezone — "8:00 AM"		 2026-08-09T09:05:00
Temporal.PlainDate Calendar date only
No time, no timezone		 2026-08-09
Temporal.Duration Span of time
Years, days, hours, nanoseconds		 P1Y2M10DT4H30M 
// The mental model — which type to use?

// "When does the flight start?" → Instant (exact moment)
const launch = Temporal.Instant.from('2026-08-09T13:05:00Z');

// "What does the pilot see on their clock?" → ZonedDateTime
const pilotView = launch.toZonedDateTimeISO('America/New_York');
// 2026-08-09T09:05:00-04:00[America/New_York]

// "What day is the flight?" → PlainDate (calendar, no timezone)
const flightDay = pilotView.toPlainDate();
// 2026-08-09

// "How long was the flight?" → Duration
const flightTime = launch1.until(launch2);
// PT2H30M (2 hours, 30 minutes)

5 · Duration Arithmetic — Flight Time Calculations

Temporal.Duration handles the hardest part of date math: months with different lengths, DST transitions, leap years.

Calculate Flight Duration

Duration Operations

// Create durations
const battery = Temporal.Duration.from({ hours: 2, minutes: 30 });
const charging = Temporal.Duration.from({ hours: 1, minutes: 15 });

// Add durations
battery.add(charging); // PT3H45M

// Subtract
battery.subtract(charging); // PT1H15M

// Round to nearest minute
flightTime.round({ smallestUnit: 'minute', roundingMode: 'ceil' });

// Total in seconds (non-calendar durations only)
flightTime.total({ unit: 'second' }); // 5400

// ISO 8601 duration format
Temporal.Duration.from({ hours: 2, minutes: 30 }).toString();
// "PT2H30M"

// Parse ISO 8601 duration
Temporal.Duration.from('P1Y2M10DT4H30M15S');
// 1 year, 2 months, 10 days, 4 hours, 30 minutes, 15 seconds

6 · OpenDrones Mission Control — FAA Part 107 Compliance

Every regulated flight requires precise UTC timestamps. Temporal makes timezone conversion trivial — no more moment-timezone dependency.

Active Missions (Live Temporal)

The Compliance Pattern

// FAA Part 107 requires UTC timestamps for all flight logs.
// Every entry must be unambiguous and timezone-correct.

// Before Temporal — the legacy mess
const log = {
  timestamp: new Date().toISOString(),  // "2026-08-09T13:05:00.000Z"
  localTime: new Date().toLocaleString(),  // inconsistent across browsers
  pilotTZ: pilotTimezone,  // separate variable, disconnected from the timestamp
};
// Problems: toISOString shifts to UTC, losing the local context.
// Reconstructing "what the pilot saw" requires manual offset math.

// After Temporal — one source of truth
const now = Temporal.Now.zonedDateTimeISO(pilotTZ);
const log = {
  // RFC 9557 format — instant + timezone + offset, all in one string
  full: now.toString(),
  // "2026-08-09T09:05:00-04:00[America/New_York]"

  // UTC instant for FAA database
  utc: now.toInstant().toString(),
  // "2026-08-09T13:05:00Z"

  // What the pilot sees on their clock
  local: now.toLocaleString('en-US', {
    timeZone: now.timeZoneId,
    dateStyle: 'full',
    timeStyle: 'long',
  }),

  // Mission date for calendar queries
  flightDate: now.toPlainDate().toString(),  // "2026-08-09"
};

// Cross-timezone mission scheduling
function scheduleMission(localDateTime, pilotTZ, missionTZ) {
  const pilotTime = Temporal.PlainDateTime.from(localDateTime);
  const pilotZoned = pilotTime.toZonedDateTime({
    timeZone: pilotTZ,
    // Disambiguate DST overlaps/gaps
    disambiguation: 'earlier',  // or 'later', 'compatible', 'reject'
  });

  return {
    pilotStart: pilotZoned,
    missionLocal: pilotZoned.withTimeZone(missionTZ),
    utcInstant: pilotZoned.toInstant(),
    iso8601: pilotZoned.toString(),
  };
}

7 · Molt Studios — Client Booking System Pattern

Every service-business client site (dental, HVAC, salon, consultant) needs appointment scheduling. Temporal eliminates the timezone ambiguity that causes double-bookings.

Appointment Scheduler (Demo)

// The booking pattern — store the full ZonedDateTime string
const appt = Temporal.PlainDateTime.from('2026-08-15T14:30')
  .toZonedDateTime({ timeZone: 'America/New_York' });

// Store this ONE string in your database — it contains everything:
appt.toString();
// "2026-08-15T14:30:00-04:00[America/New_York]"

// Display in any timezone for staff in different locations
appt.withTimeZone('America/Los_Angeles').toLocaleString('en-US');
// "8/15/2026, 11:30:00 AM PDT"

// Reminder notification 24 hours before
const reminder = appt.subtract({ hours: 24 });
// Correctly handles DST transition — 24 real hours, not 24 clock hours

// Recurring appointments — "every 2 weeks"
let next = appt;
for (let i = 0; i < 12; i++) {
  next = next.add({ weeks: 2 });
  console.log(next.toLocaleString('en-US'));
  // Each occurrence correctly adjusts for DST if it falls on different sides
}

8 · The 5-Line Recipe Book

Every common Temporal operation in 5 lines or less.

Get the current time

const now = Temporal.Now.zonedDateTimeISO();
// Uses system timezone by default
const utc = Temporal.Now.instant();
// UTC nanoseconds — the global truth

Create a date

const date = Temporal.PlainDate.from('2026-08-09');
const datetime = Temporal.PlainDateTime.from({
  year: 2026, month: 8, day: 9,
  hour: 9, minute: 5
});

Convert between timezones

const ny = Temporal.ZonedDateTime.from(
  '2026-08-09T09:05[America/New_York]'
);
const tokyo = ny.withTimeZone('Asia/Tokyo');
console.log(tokyo.toLocaleString('ja-JP'));

Add/subtract time

const meeting = Temporal.PlainDateTime.from({
  year: 2026, month: 8, day: 9, hour: 14
});
const nextWeek = meeting.add({ weeks: 1 });
const earlier = meeting.subtract({ hours: 2, minutes: 30 });

Format for display

const zdt = Temporal.Now.zonedDateTimeISO();
zdt.toLocaleString('en-US', {
  dateStyle: 'full', timeStyle: 'long'
});
// "Sunday, August 9, 2026 at 9:05:00 AM EDT"

Duration between two dates

const start = Temporal.PlainDate.from('2026-01-01');
const end = Temporal.PlainDate.from('2026-12-31');
const duration = start.until(end);
console.log(duration.toString()); // P364D

Compare two instants

const a = Temporal.Instant.from('2026-08-09T13:05Z');
const b = Temporal.Instant.from('2026-08-09T14:00Z');
Temporal.Instant.compare(a, b); // -1 (a is earlier)
a.equals(b);              // false

~65% global traffic. Chrome 144 shipped Temporal in mid-2026. Firefox 139 followed. Safari has it in Technology Preview (disabled by default) — full release expected 2026-2027. Not yet Baseline (requires Safari stable), but the API is frozen and the polyfill is production-ready.

Polyfill: @js-temporal/polyfill provides the complete Temporal API for all browsers. It's a faithful spec implementation maintained by the TC39 champions. ~40KB minified+gzipped. Use it today for production code that needs to work in Safari.

The Progressive Enhancement Pattern

// Feature-detect Temporal, fall back to polyfill or Date
const hasTemporal = typeof Temporal !== 'undefined';

if (hasTemporal) {
  // Native — zero-cost, fastest path
  const now = Temporal.Now.zonedDateTimeISO();
} else {
  // Dynamic-import the polyfill (~40KB gzipped)
  const { Temporal } = await import('@js-temporal/polyfill');
  const now = Temporal.Now.zonedDateTimeISO();
}

// Or for bundle simplicity, just import the polyfill always —
// it's a no-op when native Temporal is present.
import { Temporal } from '@js-temporal/polyfill';

10 · Decision Matrix & Applications

When to use what

Use CaseBest TypeWhy
FAA / regulatory timestampsInstantUnambiguous UTC, database-storable
Schedule a meetingZonedDateTimeNeeds both the instant AND the local wall-clock
"August 15, 2026" (birthday)PlainDateNo time, no timezone — a calendar date
"Every morning at 8 AM"PlainTimeWall-clock time, no date, no zone

OpenDrones Applications

  • FAA Part 107 flight logs — every entry timestamped with Instant.toString() in UTC. No ambiguity.
  • Cross-timezone mission scheduling — pilot in JST, mission in EST, ATC in UTC — all derive from one ZonedDateTime.
  • Flight duration compliance — Duration handles the "how long was the flight" question without manual ms math.
  • DST-safe recurring missions — weekly flights automatically adjust for DST transitions via .add({weeks:1}).
  • Mission replay timestamps — frame-accurate telemetry playback with nanosecond precision.

Molt Studios Applications

  • Client booking systems — dental, HVAC, salon, consulting. One ZonedDateTime string stores everything.
  • Event calendars — multi-day events with timezone-aware start/end. No more "wrong day" bugs for international clients.
  • E-commerce flash sales — "sale starts at 9 AM ET" → exact instant calculation, no off-by-one for PST users.
  • Analytics dashboards — "today" means the right day for every user, regardless of timezone.
  • Bundle reduction — drop moment-timezone (70KB) or date-fns (15-30KB) → 0KB native.

Why Priority 3

  • Not P1/P2 — only ~65% browser support (no Safari yet). Not Baseline. Requires polyfill for production.
  • Yes P3 — the API is frozen, Chrome+Firefox shipped it, polyfill is production-ready. High-impact for both companies.
  • Upgrade to P2 when Safari ships stable (expected 2026-2027), or when a specific client project needs it.
  • Pairs with — Intl API (formatting), Navigation API (route-aware timestamps), Web Push (scheduled reminders), OPFS (offline timestamp caching).
The bottom line: Temporal is the most important JavaScript standard library addition since Promise. Every date bug you've ever debugged — the timezone confusion, the mutable Date, the month-off-by-one, the parsing inconsistency — is fixed by design.
