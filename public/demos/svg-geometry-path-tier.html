The Vector Tier — SVG geometry & path math

Every icon, logo, flight path and chart the two clients ship is SVG — yet the catalog had zero coverage of the SVG geometry engine itself: getTotalLength(), getPointAtLength(), isPointInFill(), the CTM ladder, getBBox(), SMIL, and the <use> shadow tree. This page live-probes all of it on the engine you're reading it in. It is the measurement layer beneath CSS Motion Path (the WHERE-in-space tier) and the native alternative to canvas for anything that needs to scale.

§01 · The length engine — getTotalLength() on every geometry element

SVG 2 moved getTotalLength() from SVGPathElement down to SVGGeometryElement, so basic shapes speak path math natively — no hand-rolled perimeter formulas, no converting a circle to a <path> to measure it. The engine is the source of truth.

The pathLength wall: pathLength="100" is an author normalization for dash and text-offset math — it does not change what getTotalLength() reports (probe below). When you need "50% along the path" in JS, keep using fractions of getTotalLength(); pathLength only rescales the stroke/text attribute space.

§02 · The point walker — getPointAtLength(): clamping, sub-path jumps & closepath

The walker converts a distance into coordinates — the primitive behind "place the drone at 62% of the mission path" and every draw-on stroke effect. Three engine rules, all probed live:

probe battery

Clamping at the ends

Asking past the end returns the endpoint (no throw, no wrap); asking 0 returns the start.

Negative distance

Spec-era docs disagree on whether negative input throws IndexSizeError or clamps to start. This engine answers below — recorded either way.

Sub-path jump

M 0 0 L 100 0 M 200 0 L 300 0: total length 200 counts only drawn segments — the gap is skipped, the walker teleports at the second M.

Closepath contributes

M0 0 L100 0 L100 100 Z: the implicit closing segment adds its full diagonal length and the walker walks it.

const L = path.getTotalLength();          // real user-unit length
const mid = path.getPointAtLength(L/2);   // DOMPoint {x, y}
const end = path.getPointAtLength(1e9);   // clamps → last point

§03 · Hit-testing — isPointInFill() / isPointInStroke(): plain objects in, local coordinates, the pointer-events claim

Geometry hit-testing without rendering or DOM events: is this (x,y) inside the shape? Geofencing, chart hover, canvas-free collision. Four engine truths probed:

probe battery

1 · A plain {x, y} works

Modern engines dict-convert the point to DOMPoint — no legacy createSVGPoint() needed (the old API still works; §10).

2 · Coordinates are LOCAL — the element's own transform is ignored

Rect at (10,10,50,50) with transform="translate(100,0)": the walker asks in pre-transform user units. The visually-moved location is NOT what the API tests.

3 · Stroke truth: isPointInStroke honors stroke-width

A hairline's stroke test is nearly the fill boundary; a 24-unit stroke accepts points 12 units outside the outline.

4 · The pointer-events claim

MDN says "normal hit testing rules apply — pointer-events determines whether a point is considered within the fill." Probed live with pointer-events:none below.

§04 · The CTM ladder — getCTM(), getScreenCTM() & the removed getTransformToElement()

SVG coordinate systems nest: element → viewBox scale → ancestor transforms → CSS → viewport → screen. The CTM methods hand you the composed matrix for the hops that matter — note the return type, probed below: this engine still returns the legacy SVGMatrix, not DOMMatrix. And one method is gone — removed from every engine, still the #1 StackOverflow answer for "transform point between SVG elements."

probe battery

getCTM = viewport hop

Element inside viewBox="0 0 100 100" rendered at 200×100: the meet/slice choice is readable straight off getCTM().a/.d.

getScreenCTM = client pixels

At the top of the page, ctm.e/.f match getBoundingClientRect().left/.top — CSS-pixel space, the same space your mouse events speak.

The inverse round-trip

screen→local via ctm.inverse().transformPoint() recovers user coordinates from a click — the geofence pattern in §11.

§06 · getBBox() — geometry bounds without the stroke, the transform & the CSS

The bounding box is pure user-unit geometry: default excludes stroke, ignores the element's own transform, and is unreadable when the element isn't rendered (display:none / detached). SVG 2 defined an options dictionary ({stroke:true, …}) — engine support is split, probed here.

§07 · SMIL — declared dead in 2015, shipping everywhere in 2026: beginElement() & the animVal/baseVal split

The declarative animation layer Chrome announced it would remove (then un-deprecated in 2016) still ships in every engine — and it's the only animation system whose animated values are first-class readable state (animVal vs baseVal on typed attributes). Programmatic control: beginElement() starts an indefinite timeline, endElement() stops it, fill="freeze" holds the last value.

base path 180 units; the animation collapses it to 0. After freeze: does getTotalLength() read the animated geometry or the base value?

The split: circle.r.baseVal.value never changes during a SMIL run — circle.r.animVal.value is the live number. Reading the wrong one is why "my value won't update" bugs live in every SMIL codebase.

§08 · The <use> shadow — cloned, not copied: reach, styling & retargeting

<use> instantiates its reference in a shadow tree: the clone isn't in the document (querySelector can't find it, ids don't collide), events retarget to the <use> element itself, and only inheritable CSS pierces in. It's the native icon system — one definition, N instances, currentColor theming.

probe battery + live icon row

The reach test

Source <g id="use-src"> referenced by a <use>: getElementById finds exactly one element — the original. The clone is unreachable by DOM queries; and use.getTotalLength doesn't exist (use is a graphics element, not a geometry element — measure the reference).

Retargeting

A dispatched click lands on the <use>, never the cloned shape — synthetic-probed here, real-input-probed in the gate.

§09 · Text metrics — getComputedTextLength(), per-character boxes & the pathLength normalizer, measured

textLength forcing

textLength="300" squeezes or stretches the whole string to exactly 300 user units — the engine reads back the forced number.

textPath + pathLength discriminator

Two identical curved paths (real length L). One carries pathLength="100"; both get startOffset="50" (absolute). If the first character lands at getPointAtLength(50·L/100) on the normalized path but at raw 50 units on the plain path, offset math is normalized — the dash/text contract is real.

§11 · Capstone — OpenDrones flight path: distance, position, heading & geofence from raw path math

The mission console pattern: waypoints become one smooth path; mission distance is getTotalLength() scaled by the viewBox ratio; the drone sits at getPointAtLength(t·L); heading is the derivative of two nearby points; the geofence is a polygon and containment is isPointInFill() after a screen→local CTM inverse. Zero animation libraries — the same math runs in a worker, on the server (via node-canvas/DOM-free libs), or in the browser.
