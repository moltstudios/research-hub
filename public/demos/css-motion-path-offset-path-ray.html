2 The 5 Properties of CSS Motion Path

The entire API is five CSS properties plus the offset shorthand. No JS, no SVG required (though SVG paths work too).

offset-path
Defines the path: ray(), path(), circle(), ellipse(), polygon(), inset(), rect(), xywh(), shape(), url(#svg-id), or a coord-box keyword. The fundamental property — everything else modifies this.
offset-distance
How far along the path the element sits: 0% = start, 50% = middle, 100% = end. Animate this to move. Also accepts lengths (150px).
offset-rotate
How the element rotates to match the path direction. auto (default, follows path), auto 45deg (offset angle), 0deg (no rotation), or reverse.
offset-position
Starting position for ray() and basic shapes. Defaults to normal (center of containing block). Set to auto to use the element's normal position.
offset-anchor
Which point on the element follows the path. Default is center. Set to top left, 50% 100%, etc. Like transform-origin but for motion path.
/* The shorthand */
.mover {
  offset: path("M 0,0 Q 50,-80 100,0 T 200,0") auto 0deg;
  /* offset-path offset-rotate offset-distance */
}

/* Equivalent expanded */
.mover {
  offset-path: path("M 0,0 Q 50,-80 100,0 T 200,0");
  offset-rotate: auto;
  offset-distance: 0%;
}

/* Animate it in one line */
.mover {
  animation: travel 3s linear infinite;
}
@keyframes travel {
  to { offset-distance: 100%; }
}

3 The ray() Function — Polar Coordinate Motion

ray() is the killer addition. Instead of defining an SVG path string, you specify a direction (angle) and a size. The element shoots along that ray from a starting position. Perfect for radial layouts, particle effects, and drone path projections.

/* Syntax: ray(angle && size? && contain? && at position?) */
offset-path: ray(45deg);                           /* 45° ray, default closest-side */
offset-path: ray(0deg farthest-corner);               /* up, to far corner */
offset-path: ray(180deg closest-side contain);          /* down, contained */
offset-path: ray(90deg at 30% 70%);                   /* right, from 30%,70% */

/* Size keywords (same as radial-gradient): */
/* closest-side · closest-corner · farthest-side · farthest-corner · sides */

5 Shape Gallery — path(), polygon(), inset()

Switch between different path types. Every shape that works in clip-path also works in offset-path.

/* path() — SVG path string (Bezier curves) */
offset-path: path("M 0,170 C 100,50 200,290 300,170 S 600,170 800,170");

/* Animate: just offset-distance */
animation: travel 4s linear infinite;
@keyframes travel { to { offset-distance: 100%; } }

9 offset-rotate — Path Direction Following

The element's rotation can follow the path (auto), stay fixed (0deg), or follow with an offset angle. This is what makes drones point nose-first along their flight path.

offset-rotate: auto
Arrow follows path direction (default)
offset-rotate: 0deg
Arrow stays fixed — never rotates
offset-rotate: auto 90deg
Follows path + 90° offset

Decision Matrix: Motion Path vs GSAP vs Lottie vs JS

Need Best Tool Why
Element follows a simple path CSS Motion Path Zero deps. One property + one keyframe. Animates on the compositor thread.
Element follows dynamic JS-generated path CSS Motion Path + CSS var Set --waypoints from JS, use offset-path: path(var(--waypoints))
Radial / spoke pattern CSS ray() Polar coordinates natively. No trig math.
Scroll-driven path animation CSS Motion Path + Scroll-Driven Animations animation-timeline: scroll() drives offset-distance
Complex multi-element choreography GSAP Timeline control, stagger tuning, scrubbing — still worth the KB
Designer-authored After Effects animation Lottie If the motion can't be expressed as a single path
Physics-based / collision motion JS + requestAnimationFrame Motion Path is declarative — no physics solver

Fallback Strategy

/* Progressive enhancement with @supports */
@supports (offset-path: ray(0deg)) {
  .drone-icon {
    offset-path: path(var(--flight-path));
    animation: fly 8s linear infinite;
  }
}

@supports not (offset-path: ray(0deg)) {
  /* Fallback: simple transform translate animation */
  .drone-icon {
    animation: fly-fallback 8s linear infinite;
  }
  @keyframes fly-fallback {
    0%   { transform: translate(0, 0); }
    100% { transform: translate(800px, 0); }
  }
}

Stack Composition

CSS Motion Path composes with the existing documented toolkit:

● Scroll-Driven Animations (P2) — animation-timeline: scroll() drives offset-distance
● View Transitions (P2) — outgoing element follows a path during the transition
● MapLibre GL (P2) — overlay drone markers on the 3D map with CSS motion paths
● WebGPU (P2) — GPU renders the airspace, CSS handles the marker animation
● Anchor Positioning (P1) — anchor tooltips to elements that follow paths
● @property (P1) — animate --path-progress as a registered custom property
● Container Style Queries (P2) — switch path shapes based on container queries
● shape() function (2026) — modern path syntax with CSS units and math

Why Priority 3

  • Not P1: Most Molt client sites need standard layout/animation first. Motion Path is an enhancement, not infrastructure.
  • Not P2: The production use case is strongest for OpenDrones (flight path viz), which is still pre-launch. For general client work it's a progressive enhancement.
  • Yes P3: Ship-today (~93% traffic). Replaces GSAP MotionPath plugin ($0 license savings). Killer feature for OpenDrones flight visualization. Pairs with Scroll-Driven Animations (P2) and MapLibre (P2). The ray() function is unique — no other CSS primitive does polar coordinate positioning.
