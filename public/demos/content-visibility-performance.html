content-visibility

The CSS property that skips rendering off-screen content — 7x faster initial load with zero JavaScript

Baseline 2024 • 94%+ browser support

What is content-visibility?

Tells the browser to skip layout, painting, and hit-testing for off-screen elements. The browser renders only what's visible, deferring the rest until it scrolls near the viewport. Result: dramatically faster initial page loads, especially on long content-heavy pages.

The Three Values

👁️

visible (default)

content-visibility: visible;

No effect. Element renders normally as it always has. All layout, painting, and hit-testing happens.

🙈

hidden

content-visibility: hidden;

Skips rendering entirely. Similar to display:none but preserves rendering state — showing again is instant, no re-layout needed. Content remains in DOM.

⚡

auto (the magic)

content-visibility: auto;

Automatically skips rendering when off-screen, renders when near viewport. The browser handles everything. This is the money value.

How auto Works

The browser automatically applies containment based on viewport proximity:

Off-screen section
Size only
Skipped (no layout, no paint, no hit-test)
Approaching viewport
Full render begins (just in time)
On-screen
Fully rendered, interactive
Scrolled past
Size only
Skipped again (retains rendered size)

The Missing Piece: contain-intrinsic-size

When content-visibility skips rendering, the element has zero intrinsic size. This causes layout shift (jank) when content loads. contain-intrinsic-size provides an estimate so the browser reserves space.

/* Basic: fixed estimate */ section { content-visibility: auto; contain-intrinsic-size: auto 500px; } /* How it works: */ /* "auto" = remember last rendered size */ /* "500px" = fallback estimate before first render */ /* Best practice for heterogeneous sections */ .story-card { content-visibility: auto; contain-intrinsic-size: auto 300px; } /* For fixed-height sections */ .product-section { content-visibility: auto; contain-intrinsic-size: 600px; }

Animating content-visibility (2026)

content-visibility can now be animated with CSS transitions. Combined with transition-behavior: allow-discrete, you get smooth show/hide without display:none hacks.

Use Cases for Molt Studios & OpenDrones

🏗️ Contractor Portfolios

Long project gallery pages with 50+ project cards. content-visibility: auto renders only visible cards, cutting initial render by 70%+.

🛒 Product Grids

E-commerce category pages with hundreds of products. Only render products near the viewport. Faster LCP, better INP.

📝 Blog / Docs Pages

Long-form articles with many sections. Each section skips rendering until scrolled to. Reader never notices the difference.

📊 Dashboard Widgets

Collapsible dashboard panels. Use content-visibility: hidden for minimized panels — instant expand, no re-layout.

🔔 Notification Lists

Animated show/hide for notification toasts. Transition between visible and hidden states smoothly without display:none.

📱 Mobile Performance

Mobile CPUs are 3-5x slower than desktop. Skipping off-screen rendering on mobile provides the biggest absolute gains.
