Web Share API — the OS handoff tier

navigator.share() is the only door from a web page to the operating system's own share sheet — one call, every target the user has installed (iMessage, AirDrop, WhatsApp, Mail, Save to Files…). No permissions prompt, no permission revoke UI, no query state. The entire security model is one consumed user gesture per attempt. Live-probed below on a flag-clean Chromium 154 — including the consumption law that breaks every try/catch fallback loop, the in-flight singleton lock, and the wall ladder measured in order.

01Engine introspection — what this browser gives you

Live probes on the page you are reading. The API is two functions on Navigator.prototype — nothing else. No events, no observers, no managers.

02The wall ladder — five walls, measured in order

Every share() call climbs a ladder of walls. The order below is measured on CfT 154, not documented. Wall 1 is upstream of the gesture gate — the opposite layering of the Bluetooth tier, where activation masks validation.

#WallGesture-free?Outcome (verbatim)
1known-fields validationfires with NO gestureTypeError: No known share data fields supplied…
2in-flight singletonchecked before gestureInvalidStateError: An earlier share has not yet completed.
3transient activationthe gesture wallNotAllowedError: Must be handling a user gesture to perform a share request.
4policy / file-securityper-frame + headless file blockNotAllowedError: Permission denied
5the share sheet itselfOS UIpromise pends until the user acts — resolves undefined, or AbortError on cancel / no targets
The layering inversion vs BLE. Web Bluetooth runs activation → validation: pre-gesture, every malformed call hides behind SecurityError. Web Share runs validation → in-flight → activation: the no-known-fields TypeError fires gesture-free (you can test data shapes without a click), but a malformed call still consumes the gesture (§03) — one shot per click, hit or miss.
Walls 3 and 4 share one exception name. Policy wall (cross-origin frame without allow="web-share"), the headless file-security block, and the activation wall are ALL NotAllowedError. Distinguish by message: "Permission denied" = policy/security; "Must be handling a user gesture" = activation. Same family as Window Management's two-wall/one-enum law.

03LIVE — the activation-consumption law (the headline)

A validation-FAILED share() still consumes the transient activation. Click once and watch the gesture die inside the failed call — the fallback-retry anti-pattern is structurally impossible without a second click.

waiting for a real click…
Anti-pattern made visible. try { await navigator.share(a) } catch { await navigator.share(b) } — the second call dies NotAllowedError even though the user just clicked. Every retry path (smaller payload, no-files fallback, URL-only fallback) needs its own gesture. Budget your UX: one click = one attempt, and the fallback must be a different primitive (clipboard, download) inside the same handler.

04LIVE — the in-gesture battery (each button = one fresh gesture)

Real clicks, one case per button. In a real browser the sheet opens; headless, text/URL shares pend at the sheet and file shares hit the security wall — both settles are labeled honestly below. Every chip prints this engine's observed truth.

each button reports: data keys · activation before → outcome · activation after
MDN's bad-URL TypeError did not fire pre-sheet. The docs list TypeError for "a URL is badly formatted" — on CfT 154, share({text:'x', url:'::nope::'}) in-gesture advanced to the sheet (pend) instead. URL hygiene happens at/after the sheet, if at all. Don't rely on the engine to validate your URL — do it yourself.
title-only is a legal share on this engine. Tutorials insist you need text or url — measured: canShare({title:'t'}) === true and in-gesture share({title:'t'}) advances to the sheet. Title is a known field; it just "may be ignored" by targets.

05canShare — the sync truth table (no gesture needed)

canShare() is synchronous, gesture-free, and never throws except WebIDL conversion errors. It answers three things: field presence, frame policy, platform capability. It does NOT validate values.

No file-type gate on macOS desktop. Measured: canShare({files}) returns true for .zip, a fake .exe, an .exe named a.png, a typeless blob — everything. The MDN "usually shareable" list (images/audio/video/PDF/text) is enforced on Android Chrome, not by macOS desktop. Never hardcode a format list — canShare is the contract, and it answers per-platform truth.
canShare does not validate URLs. canShare({url:'http:::bad::'}) === true — malformed URLs pass. And url: '' passes too (it means "the current page URL" per spec).

06LIVE — the frame battery: policy wall as a boolean

Cross-origin frames get the objects but not the capability, and the policy wall surfaces as canShare() → false — a silent false, not a throw. Click to embed three children: same-origin, cross-origin without allow, cross-origin WITH allow="web-share".

the cross-origin child is a copy of this probe served from the GitHub Pages mirror (deploy lag ⇒ honest skip)
The zero-cost policy detector. A disallowed frame's canShare({text:'x'}) returns false — no throw, no console error, no gesture. A widget can silently learn "I can't share here" and switch to its fallback ladder before ever burning a user click on wall 4.

07The jail census — workers, insecure origins, surface

Where the API lives and where it is deleted. Same shape as the camera/geolocation family: secure-context-gated by object-absence, main-thread-only by undefined-in-worker.

Object-absent law on insecure origins. Plain http:// on a LAN IP: navigator.share === undefined, navigator.canShare === undefined — the functions are deleted, not denied. Feature-detect with typeof, never with a try/catch around a call.

08Resolution semantics — what "resolved" actually means

The promise resolves undefined — but the moment differs by OS, and that moment is your success-signal. Cancel and no-targets share one exception.

Never await share() unguarded in automation. Headless there is no sheet, so valid calls pend forever — the same silent-hang family as EyeDropper's gesture pend and getDisplayMedia's unprimed pend. In CI: race a timeout; in prod: your button should return to a neutral state on a timeout too.

10The fallback ladder — what to do when share() is gone

Ordered by capability preserved. The law from §03 applies: the fallback must fire inside the same click handler — a second share() can never be the fallback.

// the canonical guarded button (one gesture, one attempt, same-handler fallback):
btn.addEventListener('click', async () => {
  const data = { title, text, url: location.href, files };
  if (navigator.canShare?.(data)) {
    try { await navigator.share(data); return; }        // resolves: sheet flow done
    catch (e) { if (e.name === 'AbortError') return; }   // user cancel is not an error
  }
  await navigator.clipboard.writeText(data.url);         // fallback INSIDE the click
  toast('Link copied');
});

12Capstone B — OpenDrones: the mission report

Field ops need the flight summary in the pilot's group chat, not in a browser tab. A telemetry CSV is generated at click time (battery/altitude/speed sim, 40 rows), then shared as title + summary text + file. One click, one attempt, honest fallback.

mission brief: simulated 40-row telemetry log, FNV-checksummed, generated locally
Why share() beats a download for ops. A download lands in a Files app nobody opens mid-mission; the share sheet lands the CSV in the chat where the crew already is. And canShare({files:[csv]}) is honest on Android (text formats OK since Chrome 128) and desktop Chromium — the gate decides, not a UA sniff.

14The ship checklist — 10 rules

#Rule
1typeof navigator.share === 'function' before anything — object-absent on insecure origins and desktop Firefox
2Gate files through canShare({files}) — never a hardcoded format list (macOS accepts everything; Android enforces)
3One click = one share attempt; the fallback is clipboard/download in the same handler
4Treat AbortError as user-cancel: silent return, no error toast
5Timeout-wrap every await — the sheet can pend forever (headless/CI) and cancel detection needs a neutral-state exit
6title alone is legal; url:'' means the current page — but ship text or url for cross-target sanity
7Cross-origin widget? canShare() === false is your silent policy signal — degrade before the click, not after
8Delegate deliberately: <iframe allow="web-share">; default allowlist is self
9Validate URLs yourself — the engine does not reject malformed URLs pre-sheet
10In CI, assert the walls (TypeError/InvalidStateError/NotAllowedError verbatim) and race the pend — never assert resolution
