02 — The problem

border-radius can only draw quarter-ellipses

Every "rounded corner" on the web for 25 years has been a quarter ellipse — it starts curving immediately and never reaches the edge at full steepness. Apple's iconic continuous corner (the squircle) spends more of its arc near full width, then eases in at the very end. Look closely at the zoomed corners:

border-radius: 28px

Quarter ellipse — superellipse(1). Curves away too early; the "edge" gap is visible. Looks fine until you put it next to a native OS squircle.

+ corner-shape: squircle

Continuous curve — superellipse(2). Holds the flat edge longer, eases out at the end. This is the iOS app-icon corner every client means when they say "make it feel like Apple."

Until now the only way to get this was an SVG mask-image or a hand-computed clip-path: path(...) — both of which silently kill borders, outlines and shadows on the element. Native corner-shape keeps every box decoration intact (section 06).
03 — The six keywords

Every keyword is just a preset on one curve family

All corner shapes are superellipses, parameterized by one number: positive = convex, negative = concave, 0 = straight bevel. Click any card to see it large with its exact code.

border-radius: 26px;  /* size of the corner region */
corner-shape: squircle;  /* = superellipse(2) — the shape inside it */
04 — superellipse() playground

One number between −∞ and ∞

Drag the exponent. bevel = 0, round = 1, squircle = 2; higher approaches square (∞). Negative values flip the curve inward (scoop = −1, notch = −∞).

−5 · scoop-ish0 · bevel2 · squircle+5 · near square
border-radius: 44px;
corner-shape: superellipse(2);

border-radius sets how much corner gets shaped; corner-shape sets what curve fills it. With radius 0, corner-shape does nothing.

05 — Per-corner shaping

Four corners, four shapes, one declaration

Like border-radius, it takes 1–4 values (clockwise from top-left). Longhands exist per corner — including logical ones (corner-start-start-shape…) that follow writing direction for RTL layouts.

corner-shape: squircle notch round bevel;
/* longhand: */ corner-top-left-shape: squircle;
06 — Everything follows the shape

Borders, outlines, shadows, images — all of it

This is the part the old hacks could never do. The shape is a property of the box, not a clip: every box decoration renders along the superellipse.

4px border follows the curve
dashed outline follows too
outset shadow follows
bevel + border
scoop + border
Contrast with clip-path/mask: a clipped element paints its border before clipping — the border corners get cut off, and shadows are clipped away entirely. corner-shape is known to the painter, so the browser strokes the actual curve.
07 — Animated shape morphs

corner-shape interpolates

11 — What's next + ship-today pattern

The corner shorthand is coming

The spec (Working Draft, 26 Mar 2026 — co-edited by Apple's fantasai, Lea Verou, and Google's Noam Rosenthal) now defines a combined corner shorthand for size and shape in one declaration. Not shipped in any stable browser yet — but the editor lineup is the strongest possible signal that this reaches Baseline.

Spec-stage: corner shorthand

/* css-borders-4 §3.9.3 — size + shape: */
corner: 24px squircle;
/* per-corner: */
corner-top-left: 12px bevel;

Also in the draft: logical corner-start-* shorthands for writing-direction-aware corners.

Progressive enhancement (deploy today)

/* Base = exactly what we ship now */
.btn { border-radius: 14px; }

/* Chromium users get the upgrade for free */
@supports (corner-shape: squircle) {
  .btn { corner-shape: squircle; }
}

/* Tailwind arbitrary property one-liner: */
/* class="[corner-shape:squircle]" */

The fallback is the design system's existing corner — never a broken state. This is the safest enhancement we ship all year.
