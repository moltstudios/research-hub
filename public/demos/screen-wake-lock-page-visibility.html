4 · The Combined Pattern — Auto Re-Acquire

The canonical MDN-recommended pattern: when the tab becomes visible again, re-acquire the wake lock automatically. Wake Lock always releases on tab hide — Page Visibility catches the return and re-acquires. This is the 12-line recipe that every production app needs.

Auto-Reacquire on Visibility Change

When ON: wake lock is automatically re-acquired when you return to this tab.
When OFF: wake lock stays released until you manually toggle it again. 

// The 12-line production recipe
let wakeLock = null;

async function acquireWakeLock() {
  if (!'wakeLock' in navigator) return;
  try {
    wakeLock = await navigator.wakeLock.request('screen');
    wakeLock.addEventListener('release', () => {
      console.log('Wake lock released');
      wakeLock = null;
    });
  } catch (err) {
    console.error('Wake lock failed:', err);
  }
}

// Re-acquire when tab becomes visible again
document.addEventListener('visibilitychange', () => {
  if (wakeLock === null && document.visibilityState === 'visible') {
    acquireWakeLock();
  }
});
✓ This is exactly what Section 2 does when auto-reacquire is ON. Try it: toggle the wake lock on, switch tabs, come back — the lock re-acquires automatically.

9 · Decision Matrix — When to Use What

Use Wake Lock Alone

  • Recipe app — screen stays on while user cooks
  • Presentation mode — slide deck doesn't dim
  • QR / barcode scanner — camera stays active
  • Live dashboard (kiosk) — always-on display
  • Reading long-form — ebook reader app

Use Page Visibility Alone

  • Video player — pause on tab switch
  • Carousel — stop advancing when hidden
  • Polling — stop server requests when hidden
  • Audio player — optionally lower volume
  • Analytics — batch events when hidden

Use Both Together (The Power Combo)

OpenDrones Mission Control
  • Wake Lock: pilot's screen stays on during entire flight
  • Page Visibility: telemetry pauses when Mission Control tab is in background
  • Page Visibility: wake lock auto re-acquires when pilot returns
  • Net effect: zero missed telemetry, zero screen dimming, 100% operational
Molt Studios Clients
  • Live commerce: screen stays on during checkout flow
  • Event apps: schedule screen doesn't sleep during session
  • Restaurant menu: QR menu stays readable at the table
  • Fitness coaching: workout timer stays visible
  • Telehealth: consultation screen stays on

When NOT to Use Wake Lock

Avoid When…

  • Battery below 20% (respect power saving)
  • User hasn't interacted recently (no engagement signal)
  • Page only renders static content (no benefit)
  • Embedded in iframe without Permissions-Policy allowance

Best Practices

  • Always show a visible indicator when wake lock is active
  • Let users toggle it off (don't override their battery choice)
  • Re-acquire on visibilitychange (handles auto-release gracefully)
  • Handle rejection gracefully (low battery, power-save mode)

10 · Security & Privacy

Wake Lock Security

  • User activation required? No — can be acquired without a click (but best practice is to gate behind a toggle)
  • Permissions-Policy: Gated by screen-wake-lock directive in cross-origin iframes
  • Auto-release: Browser always releases when tab is hidden, minimized, or locked — prevents "always-on" abuse
  • Battery protection: OS may reject the request in low-power mode or when battery is below a threshold
  • No fingerprinting surface: Does not expose hardware info, device identity, or cross-site tracking data

Page Visibility Security

  • No permissions needed: Fully open API, no user consent required
  • Event-only: Only reports visible or hidden — no information about WHAT the user is doing in other tabs
  • CSS interaction: :focus-visible and :hover still work alongside visibility
  • Timing attacks: The visibility state is a boolean — no high-resolution timing data exposed
  • iframe inheritance: iframes inherit parent's visibility state
🔒 Both APIs are minimal-surface. Wake Lock has no fingerprinting or tracking capability. Page Visibility exposes only two states. Neither requires HTTPS (though Wake Lock is more reliable in secure contexts).
