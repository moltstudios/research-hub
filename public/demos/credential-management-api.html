§01

Surface census — four methods, one container

navigator.credentials is a CredentialsContainer: exactly four operations. The prototype order is alphabetical (create first — not the docs' narrative order), store() is the only one that takes an argument, and there are no events, no enums on the container, no statics.

§03

PasswordCredential — two ctor lanes, one still secret

The dict lane is documented. The form lane — new PasswordCredential(formElement) — was shipped for auto-sign-in forms and quietly dropped from most tutorials, but it still works on Chromium 154: it reads only the username + password fields (a hidden CSRF input does not leak into the credential). All data fields are prototype getters — Object.keys() is [] and JSON.stringify() is {} (the enumerable lie).

§05

The mediation ladder — and the no-creds null law

Four enum values parse on 154: silent, optional (the default), conditional, and the supposedly-legacy required (still accepted — still resolves). §06

store() & preventSilentAccess() — the fire-and-forget ghost law

store(pc) resolves undefined instantly, gesture-free — it is a notification ("this user just signed in"), not a database write you can read back. The proof: a silent get() immediately after still resolves null. The browser's password manager decides persistence, not your page — in a headless/incognito-class profile nothing lands at all.

The engine's own no-arg error message disagrees with the docs about itself — and live calls confirm it: password and federated lanes both construct real credentials through create(). The message names exactly three accepted lanes ("only exactly one of…").

§08

The WebAuthn door — origin split, singleton pend & the CI lane that works

Three engine truths the WebAuthn tutorials skip. (1) The rpId domain wall: on an IP origin (http://127.0.0.1) every ceremony rejects SecurityError: This is an invalid domain. — WebAuthn demands a registrable domain, and IPs are not domains. On localhost the same request is accepted… and pends forever headless (the sheet cannot render — the EyeDropper pend family). (2) The singleton law: while one ceremony pends, every later call rejects OperationError: A request is already pending. (3) The CI lane: CDP's WebAuthn.addVirtualAuthenticator (ctap2 · internal · resident key · auto UV) turns the same headless browser into a full passkey ceremony participant — create + get round-trip verified with the same credential id and real 72-byte DER signatures. This is the anti-Window-Management: the automation door here works.

§10

The frame matrix — same-origin-ancestry vs policy-delegable

Two different walls with the same error name, plus one nobody documents. The password/federated lanes are NOT delegable: in any cross-origin frame, get/store reject with the same-origin-ancestry law — allow= does nothing. The publicKey lane IS delegable (publickey-credentials-get, default self): without it you get the policy NotAllowedError that names its own directive; with it the error class shifts — the gate-passed proof. And preventSilentAccess() fails in cross-origin frames with an internal-service message we've never seen in any doc.

§11

The serial wall, the worker jail, the insecure void

Credentials are not serializable: structuredClone(pc) → DataCloneError, postMessage(pc) → DataCloneError thrown synchronously at the call, JSON.stringify(pc) → "{}". Ship a DTO. In dedicated workers the whole family is object-absent (navigator.credentials undefined — even though navigator exists). On plain-HTTP origins the entire tier vanishes the same way — presence checks first, always.

§14

The 10-rule ship checklist

  1. Feature-detect the lane, not the container — typeof PasswordCredential !== 'undefined', not navigator.credentials (present on FF/Safari for WebAuthn only).
  2. get() resolving null is a state, not an error — "no credentials for this origin" — branch on null, never catch.
  3. store() is fire-and-forget — resolves undefined; never assume persistence (ghost law); never read back to confirm.
  4. Conditional mediation is passkey-only — password+conditional is NotSupportedError; anchor with autocomplete="username webauthn".
  5. One ceremony at a time — a pending request blocks all later ones (OperationError); timeout-wrap every get/create.
  6. rpId must be a real domain — IP origins (and IP rpIds) reject "This is an invalid domain"; localhost pends headless.
  7. In CI, use the virtual authenticator — CDP WebAuthn.addVirtualAuthenticator makes modal ceremonies deterministic; conditional UI stays device-tier.
  8. Never ship credential objects across boundaries — DataCloneError on structuredClone/postMessage, {} from JSON — build a DTO.
  9. Password lane never leaves your frame tree — same-origin-ancestry law; third-party embeds get passkeys (policy-delegable) or nothing.
  10. Call preventSilentAccess() on manual sign-out — it's the only UX control you have over the auto-sign-in contract.
