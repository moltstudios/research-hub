HTMLMediaElement — the video element tier

Every streaming, drone-video, media-session and WebCodecs entry in the catalog sits on top of the <video>/<audio> element — but the element itself was never measured. The preload grammar

Bench: preload="none" fetches the resource slot but no data — loadstart › suspend, readyState 0, duration NaN, networkState already 1 (IDLE). metadata/auto/omitted/invalid all behave the same on a small file (the whole 53 KB arrives). §5

The play-promise grammar

Bench, universal on all three engines: pause() returns undefined — it never returns a promise. play() returns a fresh promise object per call (play() === play() is false — never identity-cache the "current" play promise). And the trap: pausing during a pending play rejects the play promise with AbortError — the classic "play-then-pause preload hack" ships an unhandled rejection unless it catches.

§6

The canPlayType census

The grammar is uniform — bare container → "maybe", container+codecs → "probably", unsupported → "" — but the per-codec rows split: audio/mpeg is probably on Chromium, maybe on Firefox/WebKit; HLS is maybe on Chromium + WebKit, "" on Firefox. Arguments are strictly typed: missing, undefined, null or an object → TypeError on every engine.

§7

The <source> cascade & the type-lie split

A failing <source> fires error on the source element, never on the video — the engine walks the list and only surfaces a video-level error when every source dies. Bench: [garbage.mp4 → bogus-type → test.webm] lands on webm and plays to the end. The split: a type= attribute that lies about the container is forgiven on Chromium + Firefox (bytes are sniffed, it plays) and FATAL on WebKit (networkState 3, stuck, and the video-level error never fires).

§8

The seek grammar

Bench, universal on a Range-capable server: the seeking event never fires inline (the setter returns first) but the read-back reflects the target immediately; a same-position seek is a REAL seek (seeking + seeked fire); beyond-duration clamps to duration then fires pause + ended; negative clamps to 0 without a throw; a seek issued before metadata is applied at loadedmetadata; a paused seek fires seeked while paused; a retargeted seek is last-wins (WebKit coalesces the intermediate seeked, Chromium/Firefox complete both). fastSeek is absent on Chromium and lands NEAR (not at) the target where it exists.

§9

The range-wall — one missing header, three different failures

Seeking speaks HTTP Range. Bench, on a server that answers 200-full-file with Accept-Ranges: none: Chromium-family: every seek silently restarts playback at 0 — the user's scrub becomes rewind-and-play, no error anywhere; Firefox: seeks within its buffer — works fine; WebKit: the seek never completes — playback freezes forever while currentTime already reads the target (the position display moves, the clock doesn't, nothing errors). With byte-range 206 support all three engines are byte-exact — even on a single-keyframe 3 s GOP (every engine decodes forward; the "browsers only seek to keyframes" folklore is dead). Bonus: WebKit re-fetches the entire mp4 via Range: 0- on every seek — even fully buffered — but not webm.

De-confound note (recorded): my first seek battery ran on a Range-less loopback server and produced "Chromium lands every seek at 0" — published only after the 206-vs-200 matrix isolated the server as the variable. Same lesson for any Vercel function / signed URL / CDN route serving video from a handler: if it can't answer 206, scrubbing breaks per-engine.

§10

The error taxonomy — and the 404 that isn't a network error

Bench: a 404 surfaces as code 4 (MEDIA_ERR_SRC_NOT_SUPPORTED), not code 2 — on every engine (the folk mapping is dead). A corrupt-but-openable mp4 is code 2 (NETWORK) on Chromium (with a PipelineStatus internal message for a demux failure!), code 4 on Firefox, and no error at all on WebKit. Garbage bytes: code 4 everywhere — with WebKit never filling error.message. A truncated file plays what it has and never errors on any engine. And video bytes served as text/plain play fine everywhere — content sniffing beats the MIME header.

§11

Ended, loop & the wrap-that-is-a-seek

Bench: at natural end the engine fires its own pause before ended (order: … timeupdate › pause › ended), state lands at paused:true, ended:true, ct==duration, and play() after ended restarts from 0 — universal. With loop=true: ended NEVER fires — the wrap is an internal seek to 0 (seeking events fire at each wrap; Firefox seeks to 0.011, not 0.000). A "loop finished" hook must watch seeking/timeupdate, not ended.

§12

Rate & volume — the clamp/throw split and the post-load reset

Bench: volume outside [0,1] throws IndexSizeError on every engine (spec-true; message wording differs); a non-number throws TypeError. playbackRate splits three ways: Chromium throws NotSupportedError outside [0.0625, 16] (and the old value survives the throw); Firefox accepts 0.05 and 32 without a blink and throws only on negatives; WebKit accepts −1 silently. And the folklore-killer: playbackRate resets to defaultPlaybackRate on every load() — on all three engines. The muted property reflects to the attribute live (attr becomes ""), but removing the attribute does not un-mute the property — one-way.

Molt — the client hero-video audit (12 checks, half a day; 1–5 invisible in code review):

  1. Every hero <video autoplay> without muted — blocked everywhere; the attr pairs or it ships dead.
  2. Every scroll-unmute handler — unmute without a gesture pauses the video on every engine; unmute must live on a real click/tap.
  3. Every video host/route behind a handler that can't 206 — the §9 range-wall: Chrome rewinds silently, Safari freezes.
  4. Every play-then-pause preload hack — the pending play rejects AbortError; catch it or ship an unhandled rejection.
  5. Every 404/telemetry mapping of error.code — 404 reads code 4, not 2; WebKit ships an empty message.
  6. Every <source type=> that guesses — WebKit dies on a lying type, others forgive.
  7. Every v.src = '' reset — it resolves against the page URL and errors; use removeAttribute('src') + load().
  8. Every await audioCtx.resume() before a gesture — the promise never settles; the caller hangs forever.
  9. Every loop-finished hook on ended — loop suppresses ended entirely; key on seeking.
  10. Every progress bar on timeupdate — it's ~4 Hz; ride rAF/rVFC for smoothness.
  11. Every rate assumption (min/max) — three-engine split; clamp-then-set, catch NotSupportedError.
  12. Every defaultPlaybackRate dismissal — it IS the post-load() rate on every engine.
