4 · THE 64-PIXEL CODED FLOOR — the law isConfigSupported can't see

THE LAW. On macOS Chromium, H.264 decode through the default hardware lane (VideoToolbox) silently rejects any stream whose coded dimensions are below 64 luma samples. Not display size — coded size. A 60×60 stream passes because its coded size is 64×64 with cropping; a 48×64 or 320×48 stream fails outright. The failure is an async EncodingError: Decoding error. — and isConfigSupported({codec:'avc1…'}) says YES the whole time, because the decoder config carries no dimensions: the truth lives in the SPS. The escape: hardwareAcceleration:'prefer-software' decodes sub-64 streams fine.

5 · THE DECODE LAB — 10 frames, byte-verified against ffmpeg

The SHA-16 chips are the honesty core: copyTo() native bytes of frame 0 and frame 9, hashed in your browser, compared against constants precomputed by ffmpeg's own decoder. GPU VideoToolbox decode ≡ ffmpeg decode, byte-for-byte, Y plane and interleaved UV.

THE NV12 LAW. macOS hardware decode hands you NV12 frames — not the I420 every tutorial assumes. And allocationSize({format:'I420'}) throws NotSupportedError: This pixel format conversion is not supported — planar→planar conversion is refused. Packed targets work: RGBA/BGRA convert fine. Write format-agnostic code: read frame.format, never assume I420.

6 · The conversion & close-law matrix

THE CLOSE-LAW SPLIT. After frame.close(): drawImage(frame) → InvalidStateError; copyTo() → rejection InvalidStateError; allocationSize() → sync throw; format → null; but timestamp and duration stay readable. Metadata survives close; pixels don't. And clone() buys an independent buffer — close the original, the clone still draws.

7 · THE SILENT-JUNK LAW & the sync DataError

THE SILENT-JUNK LAW. A syntactically-valid key chunk containing garbage slice data is silently swallowed: no error callback, state stays configured, flush() resolves — you just never get the frame. Corruption monitoring is your job: count outputs, diff against expectations. Contrast: a delta-first chunk throws synchronously from decode() — DataError, with the engine's own hint baked in: "A key frame is required after configure() or flush(). If you're using AVC formatted H.264 you must fill out the description field in the VideoDecoderConfig." — state survives; a subsequent key chunk decodes normally.

8 · THE ENCODE LAB — canvas → H.264 → back, live

Frames synthesized on a canvas, wrapped as new VideoFrame(canvas, {timestamp, duration}), encoded with the default config, then fed straight back through a decoder configured from the encoder's own decoderConfig metadata. The diff number is mean per-channel delta across all pixels — lossy, but structurally faithful.

THE AVCC/ANNEXB LAW. The encoder's default avc.format:'avc' emits AVCC chunks (length-prefixed, no start codes) and the first output carries metadata.decoderConfig.description — a 28-byte avcC record you MUST forward to your decoder. With avc:{format:'annexb'} the description is absent and chunks are start-code framed (radio/file streaming). Mixing the lanes is the #1 integration bug: annexb bytes into an AVCC-configured decoder → DataError. Press §7's delta button to see the engine spell it out.

9 · THE LIFECYCLE LAWS — state machine & memory

THE THREE LAWS. (1) unconfigured → configured → closed is one-way per instance: reset() returns to unconfigured (re-configure required — a key frame alone doesn't revive it), close() is terminal, and a failed configure() (bitrate 0, size 0) throws TypeError and leaves state unconfigured. (2) The encoder never closes your frames — every encode(frame) must pair with frame.close() or you leak GPU memory. (3) configure('bogus-codec') does NOT throw — the rejection arrives asynchronously on the error callback, state already flipped: capability-check with isConfigSupported, don't try/catch your way to safety.

11 · The rule bank

  1. Never assume I420 — read frame.format (macOS hw = NV12; planar→planan copyTo is refused).
  2. Sub-64 coded H.264 → prefer-software, or pad with crop. VP8 is exempt.
  3. isConfigSupported yes ≠ runtime yes — the floor lives in the SPS, not the config.
  4. Forward the first output's decoderConfig.description (avcC) to your decoder, or use annexb everywhere — never mix.
  5. Every encode(frame) pairs with frame.close() — the encoder won't do it.
  6. Count your outputs; junk is silent. Budget watchdogs on frame-rate, not error events.
  7. Timestamps are µs, signed 64-bit; negative and duplicate values are accepted silently.
  8. delta after configure/flush/reset throws sync DataError; state survives — reconfigure on key loss, then resume.
  9. close() nulls format but keeps timestamp — frame identity outlives pixels.
  10. Errors reach you only through ctor callbacks and promise rejections (copyTo!) — there is no onerror.
