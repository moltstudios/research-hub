§0 · Live engine census

The one-question census: is <model> a real element here, or an unknown tag that falls through to its children?

THE UNKNOWN-ELEMENT LAW. On engines without <model>, document.createElement('model') returns an HTMLUnknownElement — no interface, no renderer, no fetch. The tag is inert scaffolding and its children render. Same grammar as <video> fallbacks — which is the entire progressive-enhancement story of this page.

§1 · The element grammar + THE FALLBACK LAW (live)

A replaced element with a <source> ladder, exactly like <picture>/<video>: the browser picks the first format it supports — USDZ for Apple engines, GLB for glTF engines — and anything after the sources is fallback content for everyone else.

<model stagemode="orbit"
       alt="Brand prism, 3D">
  <source src="model-prism.usdz"
          type="model/vnd.usdz+zip">
  <source src="model-prism.glb"
          type="model/gltf-binary">
  <img src="…poster.svg" alt="Brand prism">
</model>
THE FALLBACK LAW. Where <model> is unsupported the element is not "broken" — it is transparent: the poster <img> renders in place (measured live below), <source> is void so it renders nothing, and the DOM keeps the ladder for the day the engine catches up. Ship the markup now; Safari users get 3D, everyone else gets a designed poster — nobody gets a gray box.

§2 · Hand-crafted GLB — the byte anatomy (verified live in-page)

This page ships its own fixture: model-prism.glb — 2,008 bytes, an 8-face flat-shaded octahedron with per-face brand colors, assembled by hand (no exporter). Fetched and parsed below in YOUR engine — these lanes run everywhere, because they test the file format, not the element:

Format law worth knowing: POSITION accessors must carry min/max — validators reject them without it (ours has it). Buffer views here are 4-byte aligned; indices are componentType 5123 (uint16) with target 34963 (ELEMENT_ARRAY_BUFFER).

§3 · Hand-crafted USDZ — the zip anatomy (verified live in-page)

model-prism.usdz — 782 bytes: an uncompressed ZIP (STORE, method 0, no extra fields) whose single entry is a hand-written USD ASCII scene (prism.usda) — the same octahedron, so both sources of the ladder describe the same object. Parsed live below:

THE UNCOMPRESSED-ZIP LAW. USDZ is a package contract, not a codec: ZIP with no compression (STORE only), no extra fields, textures un-flipped — so engines can memory-map it. A deflated USDZ is invalid no matter how well unzip tolerates it. 664 B of ASCII geometry + 118 B of zip scaffolding = a valid 3D asset smaller than most PNGs.

§4 · The JS surface — ready · boundingBox · entityTransform · playbackRate

The control surface per the W3C Immersive Web spec + WebKit explainer (Safari lanes marked spec), census-probed live where possible:

const model = document.querySelector('model');
await model.ready;                      // resolves when the source is loaded & processed
model.boundingBoxCenter;                // DOMPointReadOnly — label placement, custom framing
model.boundingBoxExtents;               // DOMPointReadOnly — "does it fit the box?" checks
model.entityTransform;                  // read-write DOMMatrixReadOnly — Y-up, CSS metres
model.entityTransform = initial
  .translate(0, 0, -0.05)               // derive; DOMMatrix methods return NEW matrices
  .rotate(0, 45, 0);
model.playbackRate = 1.5;               // embedded animations, <video>-style
THE STAGEMODE CONTRACT. stagemode="orbit" hands the transform to the USER (engine-managed turntable + pinch zoom); writes to entityTransform are ignored while any stagemode is active. Programmatic camera work requires no stagemode + deriving from the engine-computed initial matrix (it centers + fits the model for you). One unit = one CSS metre — a 0.1-unit object exactly fills a 10 cm portal at identity.

§6 · Capstones

🎨 Molt — product story card

Client product pages (furniture, hardware, merch): native 3D + AR on every iOS Safari visit — no viewer library, no 350 KB of three.js, no canvas hydration. Chromium visitors get the designed poster until <model> lands there.

3D · USDZ + GLB

The entire 3D line item: two hand-sized files (782 B + 2 KB here; real scans are MBs) + 6 lines of markup.

🛸 OpenDrones — payload fit check

Vendor publishes a drone/accessory as USDZ; the configurator loads it invisibly (display:none works — replaced element, no GL context leaked) and reads boundingBoxExtents after ready to answer "does this gimbal fit the bay envelope?" — dimension math that used to need a glTF parser in JS:

await payloadModel.ready;
const e = payloadModel.boundingBoxExtents;
const fits = e.x <= BAY.x && e.y <= BAY.y
          && e.z <= BAY.z;   // metres, Y-up

On Safari this is engine-native. On Chromium the same data comes from the GLB's POSITION min/max accessors — §2's parse lane already extracts exactly that pair, so the fallback uses the same numbers from the same file.

Rules

  • USDZ first, GLB second, poster last — the ladder is order-sensitive; the engine stops at the first thing it can render.
  • The fallback is content, not an apology — size it, style it, alt-text it; on Chromium it IS the component.
  • alt + aria-label — 3D is an image to assistive tech; the spec's a11y story is still maturing, carry the text yourself.
  • Never JS-gate the markup — no if (supportsModel) wrapper; the ladder already is the feature test.
  • One asset pipeline, two extensions — author once (USD/glTF toolchain), export both; the formats share geometry semantics.
  • stagemode or programmatic control — not both; the engine wins any tug-of-war over entityTransform.
  • Validate GLB accessors (min/max on POSITION) and USDZ STORE-compression before shipping; both fail closed in engines, silently in tooling.
  • Re-run this page per engine — the census chips are the support matrix, live.
