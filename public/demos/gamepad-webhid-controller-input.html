Section 2

Two native paths to physical input

For 20 years, "use a real controller in the browser" meant NPAPI plugins, then nothing. The platform now ships two complementary answers.

🕹️ Gamepad API — the universal one

Baseline widely available since March 2017. Chrome, Edge, Firefox, Safari (macOS + iOS 16.4+), Samsung, Opera.

  • Polling model: navigator.getGamepads() returns a snapshot array — read axes/buttons inside requestAnimationFrame.
  • Standard mapping: mapping === "standard" guarantees stick/trigger/button indices across vendors.
  • Analog everything: triggers and sticks are floats (−1…1), not key events.
  • Haptics: GamepadHapticActuator — dual-rumble (Chrome/Firefox), trigger-rumble (Chrome 126+, Microsoft spec).
  • Zero prompts: no permission dialog; pad appears after the first button press.

🔌 WebHID — the raw one (Chromium)

MDN: experimental, not Baseline. Chrome/Edge/Opera desktop; no Firefox (open request on Mozilla Connect), no Safari, no mobile. ~27% global traffic.

  • Any HID device: vendor-defined interfaces, button decks, LED panels, unusual RC hardware.
  • Parsed descriptors: device.collections gives the full usage tree the OS parser built.
  • Event-driven input: inputreport events carry raw DataView report bytes.
  • Outputs: sendReport() drives LEDs, force feedback, custom commands.
  • Guarded: browser picker + user gesture; protected device classes blocklisted; secure context only.
Division of labor: if the device presents as a joystick/gamepad → Gamepad API, everywhere. If it's anything else (or you need LEDs out) → WebHID, feature-gated. Serial links (MAVLink telemetry) stay on Web Serial.

Dual-stick visualizer — dead zones & expo curves

Raw stick floats are noisy near center. Every real ground station applies a radial dead zone and an exponential response curve — this is the exact math Mission Control would ship.

// Radial dead zone + expo — the two lines every stick UI needs
function shapeStick(x, y, dz = 0.08, expo = 1.5) {
  const mag = Math.hypot(x, y);
  if (mag < dz) return { x: 0, y: 0 };            // inside dead zone → centered
  const norm = (mag - dz) / (1 - dz);          // rescale so rim still = 1.0
  const curved = Math.pow(norm, expo);           // expo>1: gentle center, firm rim
  return { x: x / mag * curved, y: y / mag * curved };
}

Section 7

Haptics playground — feel the alerts

GamepadHapticActuator turns the controller into an output device: battery warnings, geofence pulses, arm confirmation. dual-rumble works in Chrome + Firefox; trigger-rumble landed in Chrome 126 (Microsoft-authored spec).

// Ground-station alert helper — fire-and-forget, promise resolves when done
async function hapticAlert(pad, kind) {
  const act = pad.vibrationActuator;
  if (!act) return;                          // silently degrade on Safari etc.
  if (kind === 'low-batt')
    for (let i = 0; i < 3; i++) {
      await act.playEffect('dual-rumble', { duration: 120, strongMagnitude: 1, weakMagnitude: 0 });
      await new Promise(r => setTimeout(r, 140));
    }
  if (kind === 'arm')
    act.playEffect('dual-rumble', { duration: 80, strongMagnitude: .2, weakMagnitude: .9 });
}

WebHID device inspector (Chromium)

For hardware that isn't a gamepad: request any HID device, walk its parsed descriptor tree, and watch raw input reports arrive as hex. This is the debugging tool for RC-transmitter and button-deck bring-up.

status: idle

No HID devices requested yet. The browser shows its native picker; nothing is accessed without an explicit user grant.

// WebHID bring-up in 5 lines (Chromium, secure context, user gesture)
const [dev] = await navigator.hid.requestDevice({ filters: [] }); // picker → grant
await dev.open();
dev.addEventListener('inputreport', e => {
  // e.reportId, e.device, e.data — a DataView over the raw report bytes
  const hex = [...new Uint8Array(e.data.buffer)].map(b => b.toString(16).padStart(2, '0')).join(' ');
});
await dev.sendReport(0x01, new Uint8Array([0xff]));   // e.g. light an LED
Descriptor already parsed: device.collections is a tree of { usagePage, usage, inputReports[], outputReports[], children[] } — you never parse HID report descriptors by hand. One physical device can expose several interfaces (several HIDDevice objects): a transmitter commonly shows one vendor-defined interface plus one consumer-control interface.
Section 9

The production patterns

Connection lifecycle, the polling loop, and the disconnect-failsafe — the three pieces that make controller input shippable.

// 1) Lifecycle — pads only appear AFTER the user presses a button (privacy model)
window.addEventListener('gamepadconnected', e => console.log('pad in:', e.gamepad.id));
window.addEventListener('gamepaddisconnected', e => failsafeZeroThrottle(e.gamepad.index));

// 2) Polling loop — getGamepads() is a SNAPSHOT; poll it every frame
function loop() {
  const pads = [...navigator.getGamepads()].filter(Boolean);
  for (const p of pads) {
    const [lx, ly, rx, ry] = p.axes;                // standard mapping order
    const L = shapeStick(lx, ly), R = shapeStick(rx, ry);
    sendChannels(L.y, L.x, R.y, R.x);              // throttle, yaw, pitch, roll
    if (p.buttons[9]?.pressed) toggleArm();      // Start button
  }
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);

// 3) Failsafe — zero throttle + RTL when the link (pad) vanishes
function failsafeZeroThrottle() { sendChannels(1000, 1500, 1500, 1500); triggerRtl(); }

// 4) Page Visibility — pause the sim when the tab hides (battery + CPU)
document.addEventListener('visibilitychange', () =>
  document.hidden ? failsafeZeroThrottle() : resume());

Gotchas that bite everyone once

  • getGamepads() returns a fixed-length array with null holes — filter before use.
  • Pads invisible until first button press; also re-press after OS sleep.
  • Trigger buttons can report value 0.5 without pressed: true — read value for analog.
  • Dead zone per-stick radial, never per-axis square (square dz distorts diagonals).
  • macOS Safari + Bluetooth drift: apply dz ≥ 0.06 in production.

Section 12

Recap & adoption checklist

Ship-it checklist

  • Feature-detect getGamepads; poll in rAF; filter nulls.
  • Show a "press any button" hint — pads start hidden.
  • Apply radial dead zone + expo before mapping to controls.
  • Handle connect/disconnect + visibilitychange → failsafe.
  • Gate haptics on vibrationActuator; never await in the input loop.
  • WebHID behind 'hid' in navigator + user gesture + secure context.
  • Keyboard fallback so the page demos on any machine.

The one-paragraph takeaway

Physical controller input is a solved, baseline web platform capability. The Gamepad API gives every browser dual-stick analog input and (mostly) haptics with zero permission friction — enough to ship a browser-based pilot trainer or console-feel product showcase today. WebHID extends Chromium ground stations to raw HID hardware: button decks, LED panels, odd RC interfaces, with the OS-parsed descriptor tree already done. Web Serial (Firefox 151 recently joined) remains the MAVLink telemetry path. The trio completes a browser-native ground station: sticks in, telemetry through, hardware panel alongside.
