The Snap Tier — CSS Scroll Snap: strictness, the mandatory trap, snap events & scroll-initial-target

Scroll snap is the browser's native paging layer — scroll-snap-type on the container, scroll-snap-align on the children, and the engine finds the nearest valid rest position for you. Baseline immemorial (Ch 69 / FF 39 / SF 11), and in 2025–26 it grew a JavaScript surface: scrollsnapchanging / scrollsnapchange events (Chromium 141+), scroll-initial-target (snap on first render, no JS), and a draft :snap-target selector. The catalog covered scroll-driven animations and scroll-markers but never snap itself. Every claim below is an executable chip, probed with real wheel/touch input on this engine.

Scroll labs say “harness: scroll” — they self-resolve when real scrolling reaches them (CDP wheel pipeline or your trackpad). Chips never fake their verdicts.

§00 · Capability badges

Engine-gated truth at load. Core snap is universal; the event layer + scroll-initial-target are Chromium-first (events Ch 141, Sep 2025); scrollend Ch 126+ / FF 150+ / SF ✗; :snap-target is a Level-3 draft with no MDN page — probed honestly below.

§01 · The anatomy — one property pair, three strictnesses

scroll-snap-type: <axis> <strictness> on a scroll container. Axis: x, y, block, inline, both. Strictness: none, proximity (snap if you're close), mandatory (you always end on a snap point). Children declare where they'd like to rest via scroll-snap-align: start | center | end | none (two values = block then inline). No snap-align children → snap-type is a no-op.

§03 · The mandatory edge trap — unreachable content at the ends

The #1 snap bug: with mandatory + children carrying scroll-snap-align, any content before the first snap point or after the last is unreachable — the engine yanks back to the nearest valid rest position, forever. §04 · scroll-padding vs scroll-margin — the snapport inset pair

Two different offsets, commonly confused. scroll-padding lives on the container: it insets the "snapport" — the region snap points are computed against — and ALSO affects scrollIntoView and anchor scrolling. scroll-margin lives on the child: an outset around that child's snap position only. Fixed headers use scroll-padding-top; the deck below insets left/right by 40px so cards can rest "centered" with breathing room at the edges.

§05 · scroll-snap-stop: always — no skipping pages on a fling

Default scroll-snap-stop: normal lets a fast fling skip arbitrary many snap points before resting. always forces each touched snap point to be a hard stop — the carousel UX where one gesture = one card, and the OpenDrones UX where a fling can't skip a mission frame. Two probes: a single 2600px wheel tick and a real velocity touch fling — the spec says always governs momentum, so the two gesture types are measured separately (and the wheel result is its own lesson).

§07 · Nested scrollers — which container's law applies?

Outer and inner are both mandatory. A gesture that starts inside the inner scroller scrolls the inner one; the outer only moves when the gesture starts in the outer's non-inner areas. The trap: overscroll-behavior chains — the inner scroll hands the fling to the outer AT ITS BOUNDARY unless you set overscroll-behavior: contain on the inner. The outer's mandatory re-snap then fires even though the user never touched it.

§08 · The snap events — scrollsnapchanging → scrollsnapchange → scrollend

Chromium 141+ (Sep 2025) gave snap a JS surface. During a drag, scrollsnapchanging fires on the container with the pending target (SnapEvent.snapTargetBlock / snapTargetInline) — the "this is where I'd rest if you let go now" signal. At commit, scrollsnapchange fires with the final target just before scrollend. UI that used to poll scroll position now gets the exact DOM node, free. §09 · scroll-initial-target — snapped on first paint, zero JS

CSS Scroll Snap Level 2: mark a child scroll-initial-target: nearest and the container renders already snapped to it — no layout-jank scrollTo on load, no "flash of first child". First child in tree order wins; it also beats place-content when both try to set the initial position. The stage below targets child 3; the readout is captured before any script-driven scroll. Chromium-only as of Sep 2026 — honest badge above.

§10 · :snap-target — style the resting element in CSS

Scroll Snap Level 3 drafts a :snap-target pseudo-class so the currently-snapped child can be styled with zero JS (today everyone fakes it with an event listener + class toggle). No MDN page, no shipping note found — the probe asks the engine directly via CSS.supports('selector(:snap-target)') and styles the stage live if the answer is yes.

§11 · Re-snap on resize & the RTL sign trap

Two production gotchas: (1) resizing a mandatory container re-evaluates the current snap — a responsive breakpoint can silently move you to a different child; a ResizeObserver + readback catches it. (2) In RTL (direction: rtl), Chromium reports scrollLeft as negative growing leftward from 0 at the right edge — snap math that assumes 0..max breaks. Both probed live.
