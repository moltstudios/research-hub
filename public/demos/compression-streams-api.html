02 The 3-line Recipe

The Compression Streams API is one of the smallest surface areas in modern web platform — a pair of TransformStream subclasses. Use them anywhere streams flow: Fetch, OPFS, WebTransport, WebCodecs, Service Worker, Worker message ports, even EventSource bodies.

Compress a Fetch response (gzip)
const compressed = (await fetch('/api/telemetry'))
  .body
  .pipeThrough(new CompressionStream('gzip'));
Decompress to Blob (gzip)
async function decompressBlob(blob) {
  const ds = new DecompressionStream('gzip');
  return await new Response(blob.stream().pipeThrough(ds)).blob();
}

04 Algorithm Decision: gzip vs deflate vs deflate-raw

All three algorithms are essentially the same deflate algorithm with different framing. The wrapper overhead is small (a dozen bytes for headers), but interoperability is the deciding factor.

Algorithm Format Overhead Best for Avoid for
gzip RFC 1952 ~20 B header + 8 B footer Cross-system transport. Send to a server, AWS, Cloudflare, NGINX — every HTTP middleware understands Content-Encoding: gzip out of the box. Standard for OPFS blobs sent over WebTransport. Sub-100-byte payloads (overhead dominates)
deflate RFC 1951 + 1950 (zlib wrapper) ~6 B zlib header + 4 B checksum HTTP Content-Encoding specifically. Historically the default for HTTP bodies. Still used by some legacy servers. Anything not HTTP (use gzip for portability)
deflate-raw RFC 1951 (no wrapper) 0 bytes When YOU control both ends. Smallest possible output. Pair with your own framing (length prefix + your own header). WebTransport streams where you've defined a private protocol. Cross-system transport (no standard wrapper, parsers will choke)
The rule: deflate-raw for private protocols, gzip for everything else. Skip plain deflate unless HTTP requires it.

// OPFS Worker pattern: compress → write → drain → decompress
async function writeCompressedMission(packets) {
  const json = new TextEncoder().encode(JSON.stringify(packets));

  // Pipe through CompressionStream — same shape as Fetch body, OPFS, anywhere
  const compressedStream = new ReadableStream({
    start(c) { c.enqueue(json); c.close(); }
  }).pipeThrough(new CompressionStream('gzip'));

  const compressed = await new Response(compressedStream).arrayBuffer();

  // Write to OPFS — 90% smaller than raw JSON
  const root = await navigator.storage.getDirectory();
  const fh = await root.getFileHandle('mission-001.gz', { create: true });
  const w = await fh.createWritable();
  await w.write(compressed);
  await w.close();
}

06 Fetch Integration: Decode Server-Sent gzip

The browser already auto-decompresses Content-Encoding: gzip on every Fetch response — that's not what this section is about. This is the opposite direction: reading a stream that has been pre-compressed client-side (e.g. an EventSource SSE body, a Worker message port, a WebTransport ReadableStream) and decoding it manually.

→ Manual gzip decode pipeline (5 lines)

// When the server/browser is sending already-gzipped bytes through a raw stream
const decompressed = compressedBody
  .pipeThrough(new DecompressionStream('gzip'))
  .pipeThrough(new TextDecoderStream());

for await (const chunk of decompressed) {
  console.log(chunk); // already decoded text
}

→ Encode before upload (3 lines)

// When uploading a large JSON payload, gzip-encode client-side to reduce transfer
const body = new Blob([JSON.stringify(largeObject)])
  .stream()
  .pipeThrough(new CompressionStream('gzip'));

await fetch('/api/upload', {
  method: 'POST',
  headers: { 'Content-Encoding': 'gzip', 'Content-Type': 'application/json' },
  body
});

07 WebTransport Compose: Compress Telemetry Packets

WebTransport (P2 entry) ships datagrams and bidirectional streams over HTTP/3 + QUIC. The transport itself doesn't compress — that's by design, low-latency wins over bandwidth. But the application payload can still be compressed client-side before being handed to the stream. 

// 30Hz telemetry packet: {ts, drone_id, lat, lon, alt, battery, heading, sats}
// JSON-stringified = ~140 B. gzipped batch of 60 packets = ~600 B instead of 8400 B.

const stream = transport.createBidirectionalStream();
const writer = stream.writable.getWriter();

// Batch 60 packets at once, gzip the batch, write
async function flushBatch(batch) {
  const payload = new TextEncoder().encode(JSON.stringify(batch));
  const compressed = await new Response(
    new ReadableStream({ start(c) { c.enqueue(payload); c.close(); } })
      .pipeThrough(new CompressionStream('deflate-raw'))
  ).arrayBuffer();
  await writer.write(new Uint8Array(compressed));
}

// Server reads: stream → DecompressionStream('deflate-raw') → JSON.parse

// The only safe fallback is a JS library — pako (4 KB gz), fflate (8 KB), or compress.js.
// Dynamic import keeps the bytes off the critical path.
async function gzip(data) {
  if (typeof CompressionStream !== 'undefined') {
    const stream = new Response(data).body
      .pipeThrough(new CompressionStream('gzip'));
    return new Response(stream).arrayBuffer();
  }
  const { default: pako } = await import('https://cdn.jsdelivr.net/npm/[email protected]/dist/pako.esm.mjs');
  return pako.gzip(data);
}

10 Direct Applications & Recap

Compression Streams is the small primitive that composes with everything in the documented stack. It is rarely the headline feature — but every P1/P2 entry that moves bytes through the browser benefits from it.

→ OpenDrones Mission Control (production paths)

  • Offline telemetry buffer — OPFS writes are 90%+ smaller when gzipped. 10× more missions per device before hitting the persistent storage quota.
  • WebTransport telemetry pipeline — batch 60 packets (2 sec at 30Hz), gzip the batch, write once. 800× bandwidth reduction vs raw packet-at-a-time writes.
  • Mission replay .ksplat compression — the Gaussian splat files (3-6 MB) compress 10-30% further. Fits more missions in the CDN cache.
  • Compliance recording buffer — WebCodecs video chunks can be optionally gzipped metadata-side (timestamps, GPS, battery annotations). 60-80% metadata savings.
  • Server fall-back for high-latency uplinks — when WebTransport is unavailable (corporate firewall, mobile network), batch + gzip + plain HTTPS POST.

→ Molt Studios client deliverables

  • PWA offline asset cache — compress client images, JSON config, font subsets before Service Worker cache write. 60-70% smaller cache footprint.
  • Form submission compress — multi-page survey / quote calculator / RFP form compresses the JSON payload before POST. Sells as "smart bandwidth saver" feature.
  • Image upload pre-compress metadata — EXIF / IPTC sidecar JSON gzipped before upload. 80%+ savings on verbose metadata.
  • Live-event chat backup — compress chat history to OPFS for offline replay. 10× more messages per device.
  • Documentation site search index — pre-compress the search index (Fuse.js / Pagefind). Same compression, smaller initial download.

→ Why P2 (not P1 / not P3)

  • Not P1 — Compression Streams is rarely the headline feature. It is a quiet workhorse that composes with everything but doesn't ship on its own.
  • Not P3 — Baseline Widely Available since May 2023. ~98% global traffic. Ship-today for every client.
  • Yes P2 — universally useful; composes with OPFS (P2), WebTransport (P2), WebRTC (P3), WebGPU (P2), MapLibre (P2), and every modern CSS / form / PWA entry. Direct OpenDrones production path. The compression layer of the v2 stack.

The Compression Streams API is what you reach for when you need to shrink bytes in flight or at rest. It is the lightest-weight piece of the modern web platform — two classes, three algorithms, zero dependencies. Every other entry on this site that moves data benefits from having it in the pipeline.
