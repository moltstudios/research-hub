0. The Six Headline Truths

  1. The format wall is exactly three formats — gzip, deflate (zlib-wrapped!), deflate-raw. No brotli, no level knob, case-sensitive, and every miss returns the same verbatim Unsupported compression format: 'X' TypeError. §2
  2. 'deflate' is ZLIB-wrapped, not raw — measured magic 78 9c (RFC 1950), verified by node inflateSync ✓ / inflateRawSync ✗. The Content-Encoding: deflate history trap does not apply here. §3
  3. The anti-cat law — concatenated gzip members (RFC 1952-legal, cat a.gz b.gz, node gunzip ✓) are REJECTED by the browser: "Junk found after end of compressed data." Even ONE trailing newline byte after a valid member = hard error. §6
  4. The two-lane error grammar — via getReader() you get real reasons ("incorrect header check", "Compressed input was truncated", "invalid block type", "incorrect data check" on CRC mismatch); via new Response(stream) everything collapses to TypeError: Failed to fetch. §7
  5. The write-deadlock law — await writer.write() or await writer.close() on a stream nobody is reading PENDS FOREVER (backpressure, hwm = 1 chunk, desiredSize 1 → 0). The MDN-canonical un-awaited pattern works; even abort() pends. §8
  6. No secure-context gate + full Worker support — ctors construct and round-trip on plain-HTTP LAN origins (probed on 2 interfaces) and inside a dedicated Worker. The OpenDrones LAN ground-station tier. §9–10

1. The Surface — 3 prototype members, 0 statics, not a TransformStream

The smallest API surface in the catalog alongside WebSocketStream: constructor, readable, writable. Both classes share the exact same 3-member prototype shape. Duck-typed for pipeThrough — but instanceof TransformStream is false.

const cs = new CompressionStream('gzip');
cs.readable instanceof ReadableStream;        // true
cs.writable instanceof WritableStream;        // true
cs instanceof TransformStream;                // false — own class, duck-type only
cs.readable === cs.readable;                  // true — cached identity
Object.getOwnPropertyNames(CompressionStream.prototype).sort();
// ['constructor', 'readable', 'writable']
CompressionStream.length;                     // 1 — exactly one arg, the format string

Enumerable-lie family: Object.keys(cs) is [] (the readable/writable getters live on the prototype), and the getters themselves are enumerable: true there. Symbol.toStringTag = 'CompressionStream' / 'DecompressionStream'. Zero statics on either constructor.

2. The Format Wall — three legal, everything else verbatim-rejected

Constructor validation is strict, case-sensitive, and stringly-typed: the argument is coerced to string first (an object argument surfaces as '[object Object]' in the error), then matched against exactly three identifiers.

Click any constructor lane — the chip records the engine's verbatim verdict.

// All of these throw TypeError with the SAME shape, verbatim:
new CompressionStream('br');        // Unsupported compression format: 'br'
new CompressionStream('GZIP');      // Unsupported compression format: 'GZIP'   ← case-sensitive
new CompressionStream({a:1});       // Unsupported compression format: '[object Object]'
new CompressionStream();            // 1 argument required, but only 0 present.
CompressionStream('gzip');          // Please use the 'new' operator… (no-call-without-new)
new DecompressionStream('br');      // same wall on the decode side

The no-knob law: the format string is the ONLY configuration. There is no {level}, no strategy, no dictionary, no flush hint — the engine picks its own defaults (measured §4: mid-level output, xfl=0). If you need gzip -9, you need WASM (fflate/pako), not this API.

The engine's own defaults, read off live bytes: no mtime (deterministic output — same input, same bytes, cache-friendly), xfl=0 (not max-compression-flagged), os=19. Throughput on 1.55 MB of repetitive telemetry JSON: 4,606 B output in ~2 ms — ratio 0.30%.

5. Streams Grammar — chunked writes, one output

Multiple write() calls merge into a single compressed member — there is no per-write framing. This is what makes the API a true stream transform, not a batch codec.

—
const cs = new CompressionStream('gzip');
const w = cs.writable.getWriter();
w.write(enc.encode('hello'));   // NOT awaited — see §8, the deadlock law
w.write(enc.encode(' '));
w.write(enc.encode('world'));
w.close();
const packed = new Uint8Array(await new Response(cs.readable).arrayBuffer());
// → single valid gzip member containing 'hello world'

Write-type validation is deferred: write('a string'), write(42), write(new Blob) all pass the writable's queue (it takes any) — the failure surfaces asynchronously. And it surfaces on both promises: the read rejects and the fired write/close itself rejects (gate-caught: un-awaited producers raise unhandledrejection unless you .catch them — the demo silences its own fired producers with a fire() helper). Double-getWriter() throws the inherited streams law: "Cannot create writer when WritableStream is locked."

6. THE ANTI-CAT LAW — concatenated members are rejected

RFC 1952 allows a .gz file to contain multiple members. cat a.gz b.gz > c.gz; gunzip c.gz works everywhere server-side — node's gunzipSync decodes both members of the exact bytes below. The browser decoder decodes exactly one member and hard-errors on whatever follows — even a single 0x0a newline.

Production consequence: server-side concatenated .gz logs (the daily-rotate default!) cannot be opened in-browser with this API. You must split on gzip magic boundaries (1f 8b scan, ignoring false positives inside compressed data is NOT safe — split server-side at write time, or ship single-member files).

7. The Two-Lane Error Grammar

Every decompression failure rejects the read, never the write. What you see depends entirely on how you consume the readable: getReader() surfaces the engine's real reason; new Response(readable) — the convenient MDN pattern — flattens everything into a generic fetch failure. 8. THE WRITE-DEADLOCK LAW — awaiting writes nobody reads

The writable's backpressure engages after one chunk (measured desiredSize: 1 → 0). Await a write — or a close, or even an abort() — while nobody consumes the readable, and the promise never settles. This is a textbook producer-consumer deadlock hiding inside a 3-member API.

—
// PENDS FOREVER (measured, 3 s ceiling, still pending):
const w = new CompressionStream('gzip').writable.getWriter();
await w.write(enc.encode('tiny'));   // ← no one is reading cs.readable
await w.close();                     // ← pends too. even w.abort() pends.

// WORKS (the MDN-canonical shape — fire, then read):
w.write(enc.encode('tiny')); w.close();
const out = await new Response(cs.readable).arrayBuffer();

// WORKS (concurrent consumer):
const [_, result] = await Promise.all([
  (async () => { await w.write(data); await w.close(); })(),
  new Response(cs.readable).arrayBuffer()
]);

structuredClone(stream) → DataCloneError (streams are not cloneable). Aborting the writable does error the readable (read rejects with Failed to fetch through the Response lane) — but the abort promise itself still pends if the queue is full and unread. Rule: always pair the producer with a concurrently-attached consumer, or never await the producer.

10. No Secure-Context Gate — the LAN tier

Unlike half the device/API tiers in this catalog, Compression Streams carry no SecureContext attribute — probed live on two plain-HTTP interfaces (utun0 CGNAT + en1 LAN): isSecureContext: false, constructors constructable, round-trips succeed. For OpenDrones this is the difference between "works on the bench LAN ground station" and "needs a certificate story" (the Cookie-Store and WebSerial lanes need one; this doesn't).

The 10-rule checklist

  1. Exactly three formats; everything else is a verbatim TypeError. Case-sensitive.
  2. deflate = zlib-wrapped (78 9c). deflate-raw = bare DEFLATE. gzip = full RFC 1952 file image.
  3. Constructor takes ONLY the format string — no level, no strategy, no options object.
  4. Output is deterministic (mtime=0) — safe for ETag/hash comparisons, not byte-identical to node's zlib.
  5. Never await write/close/abort unless a consumer is concurrently attached (deadlock law).
  6. Attach the reader before or concurrently with the producer; the canonical pattern fires writes un-awaited.
  7. Backpressure engages after 1 chunk (desiredSize 1→0) — pipeThrough propagates it upstream for free.
  8. One member per stream on decode; any trailing byte rejects. Concatenate at the application layer, never in .gz bytes.
  9. Diagnostics only through getReader(); the Response lane reports everything as Failed to fetch.
  10. No SecureContext, full Worker support, `structuredClone` refuses streams — postMessage the bytes, not the stream.

Pairs with: WebSocketStream (transport), OPFS (sink), File System Access (.gz save/open), WebTransport (framed HTTP/3), Deferred Work (background fetch of compressed assets).
