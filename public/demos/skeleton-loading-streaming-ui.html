Next.js Implementation

The file-based routing convention makes this trivial. Create a loading.tsx next to your page.tsx and Next.js wraps it in a Suspense boundary automatically.

// app/products/loading.tsx — Auto-wrapped in Suspense export default function ProductsLoading() { return ( <div className="grid grid-cols-3 gap-6"> {Array.from({ length: 6 }).map((_, i) => ( <ProductCardSkeleton key={i} /> ))} </div> ) } // components/ProductCardSkeleton.tsx export function ProductCardSkeleton() { return ( <div className="rounded-xl border p-4 space-y-3"> <div className="h-40 rounded-lg bg-muted animate-pulse" /> <div className="h-4 w-2/3 rounded bg-muted animate-pulse" /> <div className="h-4 w-1/3 rounded bg-muted animate-pulse" /> <div className="h-9 w-28 rounded-lg bg-muted animate-pulse mt-2" /> </div> ) } // app/products/[slug]/page.tsx — Streaming with Suspense import { Suspense } from 'react' export const unstable_instant = { prefetch: 'static' } export default async function ProductPage({ params }) { return ( <div> {/* Cached product info — resolves fast */} <Suspense fallback={<ProductInfoSkeleton />}> <ProductInfo slug={params.slug} /> </Suspense> {/* Live inventory — streams in separately */} <Suspense fallback={<InventorySkeleton />}> <Inventory slug={params.slug} /> </Suspense> {/* Reviews — heaviest, streams last */} <Suspense fallback={<ReviewsSkeleton />}> <Reviews slug={params.slug} /> </Suspense> </div> ) }

Custom Shimmer Animation

Tailwind's animate-pulse works, but a custom shimmer gradient feels more polished. Here's the CSS + Tailwind config.

/* app/globals.css — Shimmer animation */ @keyframes shimmer { 0% { background-position: -200% 0 } 100% { background-position: 200% 0 } } .skeleton-shimmer { background: linear-gradient( 90deg, var(--muted) 25%, var(--muted-hover) 50%, var(--muted) 75% ); background-size: 200% 100%; animation: shimmer 1.8s ease-in-out infinite; border-radius: 6px; } /* Dark mode variant */ :root { --muted: #1a1a2e; --muted-hover: #2a2a48; } [data-theme="light"] { --muted: #e2e2e8; --muted-hover: #f0f0f5; }

Best Practices

🎯 Match the skeleton to the content shape

Skeletons should mirror the final layout. A card skeleton should have image, title, and text blocks in the same positions as the loaded card.

⚡ Avoid layout shift (CLS)

Skeleton dimensions must match loaded content. Use fixed heights or aspect-ratio. If content varies, use the most common size as skeleton.

🧩 Use Suspense boundaries strategically

Wrap independent data sections in separate Suspense boundaries. Fast data appears first, slow data streams in without blocking the rest.

🎨 Match the design system

Skeleton colors should use the same muted tones as your design system. Dark mode skeletons need different base colors than light mode.

⏱️ Don't skeleton everything

Only use skeletons for data that takes >200ms to load. Static content rendered by the server should appear instantly — no skeleton needed.

🔄 Reveal content smoothly

Cross-fade skeleton → content with opacity transition. Avoid jarring pops. A 300ms opacity transition makes the swap feel polished.
