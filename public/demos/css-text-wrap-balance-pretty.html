Section 1 — The Problem

Ragged headlines have plagued the web for 30 years

When a headline wraps to multiple lines, the browser greedily fills each line until it runs out of space. The last line is often a single word — an orphan — creating visual asymmetry that screams "unprofessional." Print designers have had balanced text since the 1400s. The web finally caught up in 2023.

Section 3 — When to use which

Two algorithms, two purposes

The CSS Working Group designed two distinct algorithms. balance is for short text (headlines, titles, buttons) — it equalizes line widths. pretty is for long text (paragraphs, descriptions) — it prevents the last line from becoming an orphan. They solve different problems.

text-wrap: balance

For: Headlines, card titles, button labels, modal headers, tooltip text. Anything ≤4 lines.

Algorithm: Knuth-Plass dynamic programming. Finds the breakpoint set that minimizes the variance in line widths.

Cost: ~1ms per element. Browsers cap at 4–6 wrapped lines to prevent perf issues on very long text.

text-wrap: balance;

text-wrap: pretty

For: Body paragraphs, descriptions, captions. Anything >4 lines.

Algorithm: Greedy fill, but on the last line, pulls one word back from the preceding line if it prevents a single-word orphan.

Cost: Near-zero. Single-pass adjustment on the last line only.

text-wrap: pretty;
/* The ship-today global rule — 2 lines, every project */ h1, h2, h3, h4, h5, h6 { text-wrap: balance; } p, li, blockquote, figcaption { text-wrap: pretty; } /* Chrome 114+ and Firefox 121+ support both values */ /* Safari 17.5+ supports balance; Safari 26+ supports pretty */ /* Graceful degradation: unsupported values fall back to auto */
