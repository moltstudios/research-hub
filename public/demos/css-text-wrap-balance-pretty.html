One-line typography improvements that make every site look $5,000 richer.

01

The Problem

Bad wrapping happens to good content

Every browser uses the same greedy line-breaking algorithm — first-fit. It fills each line edge-to-edge without looking ahead. The result? Ugly orphans, lonely last words, and headlines that feel broken.

⚠️ Headline — last word stranded
OpenDrones Arc — The Professional Aerial Platform

The word "Platform" sits alone on its own line. Visually unbalanced.

⚠️ Paragraph — orphaned last word
Our new collection features handcrafted leather goods made from premium Italian leather. Each piece is stitched with care and designed to last for decades. Every item comes with a lifetime warranty.

"warranty." is the only word on the last line — a classic orphan.

⚠️ Contenteditable — lines shift while typing
Type something here to see lines above jump and shift as you add characters. The reflow cascades upward.

Click and type — watch lines above reflow unpredictably.

02

The Fix for Headlines

text-wrap: balance

The browser looks at all possible line breaks and picks the set that minimizes the difference in line width. Headlines become visually centered, with no lonely trailing words.

Default (wrap) Balanced
Product headline
OpenDrones Arc — The Professional Aerial Platform
Agency tagline
Molt Studios builds premium websites for modern brands
Pricing card
Everything you need to launch your SaaS today
Blog post title
Why we rebuilt our entire design system from scratch

⚡ Performance note: Chrome limits balance to 6 consecutive lines. Firefox allows up to 10 lines. This keeps the algorithm fast — you'll never notice the cost.

03

The Fix for Paragraphs

text-wrap: pretty

Uses a smarter algorithm that looks ahead to avoid orphaned words on the last line. It also prevents consecutive hyphenated breaks and improves justified text.

Default (wrap) Pretty
Orphaned last lines: 3 → 0
Product description

About section

Blog excerpt

💡 pretty has no line limit but uses a slower algorithm. Use it on body paragraphs — not entire page containers. It also improves text-align: justify quality.

04

The Fix for Editing

text-wrap: stable

When you type in a contenteditable or textarea, wrap reflows all lines — including ones above your cursor. stable locks already-wrapped lines in place.

wrap (shifty) stable (locked)

👇 Click below and type to feel the difference:

The quick brown fox jumps over the lazy dog. Pack my box with five dozen liquor jugs. How vexingly quick daft zebras jump.

In wrap mode, watch lines above shift as you type. In stable mode, prior lines stay locked in place.

Heads up: stable shipped in Chrome 137 (May 2025) and is still rolling out. Community reports indicate it doesn't fully prevent reflow in all edge cases yet. Test before shipping.

05

The One-Line Recipe

Four lines. That's the entire API.

Drop these into your CSS reset today. They're progressive enhancements — unsupported browsers simply ignore them.

/* Typography reset — add to your base.css */ h1, h2, h3, h4 { text-wrap: balance; } p, li, dd, blockquote { text-wrap: pretty; } [contenteditable], textarea { text-wrap: stable; } /* That's it. You're done. */

🚀 Ship it in 30 seconds

No JavaScript. No dependencies. No build step. No polyfill.

/* Progressive enhancement — safe in ALL browsers */
@supports (text-wrap: balance) {
  h1, h2, h3 { text-wrap: balance; }
}

08

Compatibility

Browser support & performance

All three values are progressive enhancements. Unsupported browsers silently fall back to wrap — your text still renders, just less elegantly.

Value Chrome Firefox Safari Global
balance 114+ 121+ 17.5+ ~96%
pretty 117+ ✗ 26.0+ ~78%
stable 137+ ✗ ✗ ~62%
avoid-short-last-lines ✗ ✗ ✗ 0%

balance

Limited to 6 lines (Chrome) / 10 lines (Firefox). The algorithm runs once on layout — negligible performance impact even on large pages.

pretty

No line limit, but uses a slower Knuth-Plass-style algorithm. Apply to body text sections, not entire page containers. Safe for articles, cards, and descriptions.

Progressive Enhancement

Both balance and pretty work as progressive enhancements. If a browser doesn't support them, text simply uses wrap — no breakage, no layout shift, no JS fallback needed.

/* Progressive enhancement pattern */ @supports (text-wrap: balance) { h1, h2, h3 { text-wrap: balance; } } @supports (text-wrap: pretty) { p, li { text-wrap: pretty; } } /* Browsers without support ignore these rules entirely */
09

When to use what

Decision matrix

🎯

balance → Headlines & titles

Use on any block of text ≤ 6 lines (Chrome) that acts as a heading. The browser evens out line widths so there's no straggler. Perfect for h1–h4, card titles, pricing labels.

✨

pretty → Paragraphs & body copy

Use on multi-line text blocks where you want to avoid orphaned last words. Articles, product descriptions, comment threads, list items. No line limit but slightly slower algorithm.

🔒

stable → Editable regions

Use on textarea and contenteditable elements. Prevents lines above the cursor from reflowing while the user types. Still maturing.

📄

wrap → The default

The browser's default greedy algorithm. Fast but ugly. You get this for free — no need to set it explicitly. Unsupported browsers will fall back to this.

📋 Add these 4 lines to your CSS reset today

Zero JavaScript. Zero dependencies. One line per element type.

h1, h2, h3          { text-wrap: balance; }
p, li, dd              { text-wrap: pretty; }
[contenteditable]      { text-wrap: stable; }
textarea               { text-wrap: stable; }
